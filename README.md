## What this is

A **self-contained, offline study textbook** for the four elective/core subjects of **Semester 7 (S7)** of the
**Kerala Technological University (KTU)** B.Tech programme. It is built as a small set of static websites — no
backend, no database, no build step, no external network calls. You can open it from a USB drive, a phone
bookmark, or a GitHub Pages URL, and it works the same with or without internet.

The goal was simple: turn a pile of scattered PDFs, handwritten scans, and past-question papers into one
navigable, readable, phone-friendly revision resource — with module pages, worked examples, and a searchable
question bank for each subject.

This is **not** an official KTU publication. It is a personal study companion produced by an AI agent from
the student's collected materials.

## How it was actually built

This section exists because "AI made it" is too vague to be useful. Here is the real pipeline, so you
understand where the content came from and where mistakes could hide.

1. **Source gathering.** The student placed source files in `C:/Users/Lenovo/Downloads/Study Materials/`:
   - KTU syllabus PDFs and class notes (a mix of clean text-PDFs and **handwritten scans**).
   - Past-question papers (some as PDFs, some as a **photo sent over WhatsApp**).
   - Two reference textbooks: **Alpaydın, *Introduction to Machine Learning*** and **Mitchell, *Machine Learning***.

2. **Text extraction.** Clean PDFs were read with PyMuPDF (`fitz`). Handwritten scans returned ~0 usable
   characters from text extraction — so the agent **rendered each scanned page to a PNG and read it with a
   vision model**, then transcribed the equations and worked problems by hand into the pages. This is why the
   Machine Learning module pages contain real worked examples (Naive Bayes Play-Tennis, ID3 entropy, k-means
   centroid updates, single-linkage, F1 = 4/11, coin-toss MLE) even though the source was illegible to a
   plain text extractor.

3. **Syllabus mapping.** Each module page was built to match the official KTU syllabus topics for that code,
   so the coverage follows the exam structure rather than the (sometimes disordered) source notes.

4. **Answering the student's questions.** The agent read the WhatsApp photo of ML theory questions and a
   "Tutorial 2" PDF, computed the numerical answers (linear regression, covariance matrices, MLE, gradient
   descent cost), and added both sets as expandable Q&A in the Machine Learning question bank.

5. **Textbook deepening.** Once the two textbooks were added, the agent extracted the relevant chapters
   (Alpaydın's parametric methods, trees, MLP/backprop, kernels/SVM, clustering, PCA, ensembles, Bayesian
   estimation, Bayesian decision theory) and deepened every ML module page with rigorous derivations and
   clean formulations — e.g. the SVM primal/dual, the kernel trick, the PCA eigen-decomposition, the
   bias–variance decomposition.

6. **Styling & layout.** A shared Swiss-style `assets/styles.css` + `assets/app.js` per site, no CDN, with
   a dark hero, monochrome body, and a single red accent. Later, answers were re-formatted as compact
   two-column **label | content** cards (`.ansrow`) for phone readability, and the question-bank answer
   blocks were given proper spacing so they no longer felt crowded.

7. **Validation.** A custom HTML-parser validator (`_validate.py`) checks every page for well-formed tag
   nesting and **dead links** (none found across all 40 pages). Pages were also rendered headless (Playwright)
   at desktop and phone widths to confirm no overflow and no cut-off tables.

8. **Publishing.** The agent committed to a Git repository and pushed to **GitHub Pages** so the site is
   reachable from a phone. The publish used a stored credential obtained after the student signed in to
   GitHub Desktop; no token was ever written into the repo or shown in chat.

## Design philosophy

- **Offline-first.** No CDN, no fonts loaded over the network, no analytics. Double-click and it works.
- **Text-forward, low decoration.** Per the student's explicit preference, pages favour readable prose and
  structured lists over heavy graphics. Diagrams are used only where they earn their place (CIA triad,
  pen-test phases, malware taxonomy, network perimeter, PCA/margin sketches).
- **One accent.** A single red is the only chromatic signal; everything else is ink-on-paper. This keeps the
  focus on content and reads as "document," not "startup landing page."
- **Answers as reference cards.** Q&A answers are compact two-column `label | content` rows so they scan
  like a quick-reference sheet on a phone.
- **Accessible enough.** Responsive to mobile, visible keyboard focus, and `prefers-reduced-motion` respected
  where animations are used.

per folder rather than centralised — intentional, for portability.

## How to use it

**On a laptop / desktop**
- Open the folder and **double-click `index.html`** (or `index-alt.html` if you prefer that design).
- It opens the hub; click any subject card to dive into its modules, then use each page's in-page
  navigation (Prev / Next) to move through a module sequence.

**On a phone**
- The repo is published via **GitHub Pages**. Open the published URL (bookmark it) and browse like any site.
- The layouts are responsive; the question-bank answers collapse into tidy two-column cards that fit a
  narrow screen.

**Finding answers fast**
- The Machine Learning `papers.html` has a **live search box** and expandable "Show answer" buttons.
- Each subject's `papers.html` groups questions by source (WhatsApp set, Tutorial 2, past papers, unit-wise).

## Content sources & provenance

| Source type | Treated as | Caveat |
|---|---|---|
| KTU syllabus PDFs | Authoritative topic list | Used to map module coverage. |
| Class notes (clean PDFs) | Primary content | Generally reliable; still verify against lectures. |
| Handwritten scan PDFs (CST413 M1–M5) | Transcribed via vision | **Highest error risk** — vision OCR of handwriting can misread symbols/numbers. Re-check any worked number. |
| Past-question papers | Real exam practice | Transcribed by the agent; minor transcription slips possible. |
| WhatsApp photo of questions | Student-posed | Answered by the agent; reasoning should be sound but verify. |
| Alpaydın & Mitchell textbooks | Rigorous deepening | Used to add derivations; consistent with standard ML theory. |

**Bottom line on trust:** the clean-PDF and textbook content is reasonably trustworthy; the
**handwritten-scan transcriptions are the weakest link** and deserve a careful read before an exam.

## Quality checks we ran

- **Well-formedness:** `_validate.py` parses every page with a real HTML parser (not regex) and confirms
  balanced tags. All 40 pages pass.
- **Dead links:** the same script checks every internal `href` resolves to a file. **0 dead links** reported.
- **Visual overflow:** pages were rendered at 1180px and 390px; tables use `table-layout:fixed` so they wrap
  inside the screen instead of spilling off the right edge (a bug we explicitly fixed after a table was found
  cut off on mobile).
- **Answer readability:** answer blocks were given explicit padding/line-height and converted to two-column
  cards after the student reported the original felt "crowded."

## Known limitations

- **AI authorship means unverified claims.** Despite validation, an AI can state something confidently and
  be wrong. This is study material, not a substitute for the textbook or lectures.
- **Handwritten-source risk.** See provenance above — numbers and symbols from scanned pages need a sanity
  check.
- **Syllabus drift.** KTU revises syllabi; this matches the version the student supplied (S7, 2026). A future
  revision could leave a page partially out of date.
- **No interactivity beyond Show-answer / search.** These are static pages; there are no quizzes, no
  progress tracking, no adaptive practice.
- **Fonts are local-only.** Named display/mono faces (Space Grotesk, JetBrains Mono) are *intended* but,
  because the site is offline with no CDN, they fall back to system fonts. The design still holds; the exact
  typeface may differ per device.
- **Covariance convention note.** In the ML question bank, the covariance-matrix answer leads with the
  **sample** form (divide by n−1) because that is what an estimated covariance matrix typically expects; the
  population form (divide by n) is given as a note. If your examiner uses the other convention, use that.

## Troubleshooting

- **Page looks unstyled / broken.** You opened a file directly but the relative `assets/` path is wrong, or
  you moved a single HTML file out of its subject folder. Keep each page inside its `*-site/` folder so it can
  find `assets/`.
- **GitHub Pages shows an old version.** Pages can take ~30–60s to rebuild after a push. Hard-refresh.
- **A link 404s.** Run `_validate.py` locally; if it reports 0 dead links, the issue is likely a cached
  Pages build, not a real broken link.
