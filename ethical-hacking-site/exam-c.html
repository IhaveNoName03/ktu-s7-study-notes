Q1

Definitions of Information Security Components

3 marks

Give definitions for the information security components.

Answer
Information security (InfoSec) is the practice and set of controls that protect data and information systems from unauthorised access, use, modification, disruption or destruction. The "components" examined are the properties we must preserve, known as the CIA triad, together with the supporting security services.
ComponentDefinitionMechanism / Example
ConfidentialityInformation is disclosed only to authorised parties.Encryption (AES), access control lists, least privilege; an encrypted backup cannot be read if stolen.
IntegrityData is accurate, complete and unaltered except by authorised changes.Hashing (SHA-256), digital signatures, version control; detecting tampering in a log file.
AvailabilityAuthorised users can access systems/data when needed.Redundancy, RAID, backups, load balancing; resisting a DoS attack.
AuthenticationVerifying the identity of a user or system.Passwords, biometrics, OTP, certificates.
Non-repudiationProof that an action occurred, so it cannot be denied.Digital signatures, audit logs with timestamps.
AccountabilityActions are traceable to a responsible entity.User IDs in event logs.

Mechanism: Policies define the required state, controls enforce it (technical, physical, administrative), and monitoring verifies it. A breach is any violation of one of these properties — stealing a password file breaks confidentiality, editing a marks database breaks integrity, and a DDoS attack breaks availability.

Exam takeaway: Always name the three CIA properties first, define each in one line, then add authentication and non-repudiation as the common "extra" services. A 3-mark answer should list and define, not merely name.

Exam tip: If a scenario is given (for example, an attacker defaces a website), classify it: defacement = integrity, data leak = confidentiality, site down = availability. Examiners reward this mapping.
Q2

Vulnerability Assessment in Penetration Testing

3 marks

What is vulnerability assessment in penetration testing?

Answer
Vulnerability assessment (VA) is the systematic process of discovering, classifying and prioritising security weaknesses in a system, network or application. Unlike a full penetration test, it identifies and reports flaws but does not necessarily exploit them.

Mechanism / procedure:

  1. Define scope — which hosts, networks or applications are in scope and what tooling is allowed.
  2. Discover assets — enumerate live hosts, open ports and running services (for example with a port scanner).
  3. Scan — automated scanners (Nessus, OpenVAS, Qualys) probe for known CVEs, misconfigurations and weak defaults.
  4. Analyse and validate — remove false positives and assign severity (CVSS score: Low / Medium / High / Critical).
  5. Report and remediate — rank by risk and recommend patches or configuration changes.

Example: A scan reveals an Apache server missing a security patch (a High CVE) and an FTP service allowing anonymous login (Medium). The report recommends patching and disabling anonymous access.

Note: VA is breadth-first and largely automated; penetration testing is depth-first and proves exploitability by chaining flaws. A VA answers "what is wrong?"; a pen test answers "can it actually be broken, and how far can an attacker get?"
Exam tip: Contrast VA with penetration testing in one sentence — VA = automated discovery + prioritisation; PT = manual exploitation + impact demonstration. Include the CVSS/CVE terms; they are high-value keywords.
Q3

Social Engineering and Example

3 marks

Define social engineering and give an example.

Answer
Social engineering is the psychological manipulation of people into performing actions or divulging confidential information. Instead of attacking software, the attacker exploits human traits such as trust, fear, curiosity, urgency, helpfulness and authority.

Mechanism: The attacker researches the target, adopts a credible pretext (a role or story), establishes trust or creates time pressure, extracts information or gains a physical/logical access, and then uses the obtained data for further attack. Common channels are phone (vishing), email (phishing), SMS (smishing), in person and social media.

Example: An attacker calls an employee, claims to be from the IT help desk, and says a "security audit" requires the employee to confirm their username and one-time password. The employee complies, and the attacker uses the credentials to log in from outside the network. No technical exploit was needed — the weakness was the person's willingness to trust an apparent authority figure.

Impact: Credential theft, unauthorised access, financial fraud and malware installation. Countermeasures: security-awareness training, verification procedures, least privilege and an obligation to report suspicious contact.

Exam tip: Define it as "hacking the human, not the machine". For the example, always show the chain: pretext → trust → information/access → misuse. One concrete example earns the mark; do not just list attack types.
Q4

Shoulder Surfing

3 marks

What is shoulder surfing in the context of social engineering attacks?

Answer
Shoulder surfing is a direct-observation social engineering technique in which an attacker secretly watches a victim to obtain sensitive information such as a PIN, password, OTP or confidential screen content.

Mechanism: The attacker positions themselves where they can see the victim's screen or keyboard — over a shoulder in a queue, across a train aisle, at an ATM, or through a window/reflection. They observe keystrokes, screen display, or even the pattern of a touchscreen, and later replay what they learned. It can be aided by binoculars, a phone camera or a small mirror; a related high-tech variant uses shoulder-surfing malware or screen-recording trojans.

Example: At an ATM, a person standing immediately behind a customer watches the keypad to record the 4-digit PIN, then later steals the card (or skims it) and withdraws cash. In an office, a visitor reading a colleague's monitor can note an admin password typed during a demonstration.

Countermeasures: Privacy screens/filters, careful positioning, shielding the keypad while typing, randomising keypads, biometric authentication, awareness training and challenging strangers in secure areas.

Exam tip: Classify shoulder surfing as a physical/direct observation technique (no conversation, unlike phishing or pretexting). A one-line definition plus the ATM example plus two defences is a complete 3-mark response.
Q5

ARP Spoofing

3 marks

What is ARP spoofing, and how does it work?

Answer
ARP spoofing (ARP poisoning) is an attack in which an adversary sends forged Address Resolution Protocol messages over a local area network to associate their own MAC address with the IP address of another host — typically the default gateway.

Mechanism: ARP maps a known IPv4 address to an unknown MAC address on a LAN and is stateless and unauthenticated — any host may announce an IP-to-MAC binding, and machines cache the answer. The attacker floods the victim's ARP cache with replies claiming that the gateway's IP maps to the attacker's MAC, and possibly claims to the gateway that the victim's IP maps to the attacker's MAC. The victim's cache is "poisoned". Subsequent frames destined for the gateway are sent to the attacker's NIC.

Result: The attacker can silently relay traffic (enabling a Man-in-the-Middle attack), sniff credentials, or simply drop the traffic to cause a denial of service. Because ARP only works inside a broadcast domain, the attack is limited to the local network segment.

Victim → intends to send to Gateway IP 192.168.1.1 Attacker advertises: "192.168.1.1 is at MAC AA:BB:CC:DD:EE:FF (attacker)" Victim's ARP cache now maps gateway IP → attacker MAC → traffic diverted.

Countermeasures: Static ARP entries for critical hosts, DHCP snooping, Dynamic ARP Inspection (DAI) on switches, port security, encryption (HTTPS/SSH/VPN), and ARP-monitoring tools.

Exam tip: The root cause to state explicitly is "ARP has no authentication". Mention that it works only on the local broadcast domain and that the payload is a forged ARP reply.
Q6

Man-in-the-Middle Attacks

3 marks

Define Man-in-the-Middle (MITM) attacks.

Answer
A Man-in-the-Middle (MITM) attack occurs when an attacker secretly inserts themselves into a communication channel between two parties who believe they are talking directly to each other. The attacker can listen to, capture, alter or inject the traffic, while both endpoints remain unaware.

Mechanism: The attacker must first position themselves on the path and then intercept the session. Common ways to achieve this position are ARP spoofing on a LAN, DNS spoofing/poisoning, rogue Wi-Fi access points (Evil Twin), HTTPS spoofing or malicious proxies. Once in the middle, the attacker relays messages between the victims to avoid suspicion while reading or modifying them — for example, capturing session cookies or changing the recipient's bank account number in a transaction.

Alice ⇄ [ ATTACKER ] ⇄ Bob Alice believes she talks to Bob; Bob believes he talks to Alice. Attacker can: eavesdrop ↓ modify ✎ inject + replay ↻

Example: On a public Wi-Fi network, an attacker sets up a rogue access point named like the cafe's real one. Victims connect, and all their HTTP traffic passes through the attacker, who steals login cookies.

Countermeasures: End-to-end encryption (TLS/HTTPS with HSTS), certificate pinning, mutual authentication, VPNs, disabling auto-connect to open Wi-Fi, and network IDS detection of ARP/DNS anomalies.

Exam tip: Distinguish passive MITM (only eavesdropping) from active MITM (modifying/injecting). Always pair the definition with one way the attacker gets into the middle (ARP/DNS/rogue AP) — that earns the mechanism mark.
Q7

SQL Injection

3 marks

What is SQL injection, and how does it affect web applications?

Answer
SQL injection (SQLi) is a web application vulnerability in which untrusted user input is concatenated into a SQL query and interpreted as code rather than as data. It arises when applications fail to validate or properly parameterise input.

Mechanism: The attacker submits input containing SQL syntax (for example a quote followed by an always-true condition such as ' OR '1'='1) into a form field or URL parameter. Because the input is built directly into the query string, the database executes the altered statement. By varying the input, the attacker can bypass authentication, read tables they should not see (UNION-based), infer data through true/false responses (blind SQLi), or, with sufficient privileges, modify or delete records.

Effect on web applications: Unauthorised access to user accounts, disclosure of entire databases (credentials, card data), data corruption or deletion, and in some configurations escalation to operating-system command execution and full server compromise. It also causes legal and reputational damage.

Countermeasures: Parameterised queries / prepared statements (the primary defence), stored procedures, input validation and allow-listing, least-privilege database accounts, ORM usage, disabling verbose error messages, and a WAF as defence in depth.

Pitfall: Escaping special characters alone is not a reliable fix. The single strongest answer is "use parameterised queries so data is never treated as code".
Exam tip: State the root cause (untrusted input concatenated into a query), one attack idea (authentication bypass or data theft), and the main fix (prepared statements). Keep any example conceptual — do not need to write a working payload.
Q8

Session Hijacking

3 marks

What is session hijacking, and how does it threaten web applications?

Answer
Session hijacking is an attack in which an adversary takes over a legitimate user's active session by stealing or predicting the session identifier (session ID / token), thereby gaining the same access as the authenticated user without knowing the password.

Mechanism: Web applications are stateless, so they track logged-in users with a session token stored in a cookie or URL. If an attacker obtains that token — by sniffing unencrypted traffic, cross-site scripting (XSS), a MITM/ARP-poisoning attack, predicting a weak token, or fixing a session ID — the attacker replays it in their own requests. The server sees a valid token and treats the attacker as the victim. Session fixation is the related variant where the attacker forces a known session ID on the victim first.

Threat: Account takeover, fraudulent transactions, access to personal or administrative functions, and bypass of two-factor authentication for the duration of the session. Because the attacker uses a genuine session, the activity can look legitimate in logs.

Countermeasures: Enforce HTTPS/HSTS with Secure and HttpOnly cookie flags, regenerate the session ID after login, use long random tokens, implement idle/absolute timeouts, bind sessions to IP/device heuristics, and log out on suspicious activity.

Exam tip: The key phrase is "stealing or predicting the session token, not the password". Link it to MITM and XSS as the usual delivery methods; that ties several syllabus topics together and earns full marks.
Q9

Event Logging

3 marks

What is event logging in the context of cybersecurity?

Answer
Event logging is the automatic recording of significant activities and events — login attempts, file access, process starts, configuration changes, errors and network connections — into a chronological log, so that the state and behaviour of a system can be reconstructed later.

Mechanism: Operating systems, applications, firewalls and IDSs generate log entries containing a timestamp, source, event ID, severity and relevant detail (user, IP, object). On Windows these appear in the Event Viewer (Security, System, Application logs); on Linux in syslog//var/log. Logs may be local or forwarded to a central SIEM for correlation. They support detection (spotting brute force or unusual traffic), incident investigation and forensics (timeline reconstruction), compliance/audit evidence, and troubleshooting.

Example: A series of Event ID 4625 "failed logon" entries from one IP, followed by a 4624 success, reveals a brute-force attack that finally guessed a password.

Defensive considerations: Protect logs from tampering by attackers (write-once storage, central collection, access control), synchronise time with NTP, retain them long enough, and monitor alerts. Attackers, conversely, try to clear or forge logs to cover their tracks.

Exam tip: Give the definition, then name the four purposes — detection, forensics, compliance, troubleshooting — and finish with the observation that logs themselves are a target for attackers (log wiping). That shows both Blue-team and Red-team awareness.
Q10

Password Cracking

3 marks

Explain the concept of password cracking.

Answer
Password cracking is the process of recovering a password from stored or transmitted data — usually a hash — without initially knowing it. It is the automated testing of candidate passwords against a target until the correct one is found.

Mechanism: Systems rarely store plaintext passwords; they store a one-way hash. An attacker who obtains the hash file (from a breach, a compromised host, or a captured authenticator) generates candidate passwords, hashes each one with the same algorithm and compares the result to the stored hash. A match reveals the plaintext. Methods include: dictionary attacks (word lists), brute force (all character combinations), hybrid attacks (words plus number/symbol substitutions), rule-based attacks, rainbow tables (precomputed hashes), and credential stuffing (reusing passwords leaked from other sites). GPUs and wordlist rules make this fast.

Example: An NTLM hash is captured; a dictionary attack tries common passwords and finds "Summer2024!", granting access to the account.

Why it matters / mitigation: Weak or reused passwords fall quickly. Defences: salted, slow password-hashing algorithms (bcrypt, scrypt, Argon2), strong password policy, multi-factor authentication, account lockout/rate limiting, and limiting hash exposure. Ethically it is used by auditors to test password strength and in forensics with authorisation.

Exam tip: Emphasise that cracking usually works on hashes, not plaintext, and that salting defeats rainbow tables while slow KDFs defeat brute force. One method + one mitigation completes the answer.

Hacker Types & Penetration-Test Categories

14 marks

Module I — Q11: (a) What are the main types of hackers, and how do they differ from ethical hackers? (b) Explain in detail the categories of penetration tests with relevant examples.

Answer
Part (a) — Types of hackers and how they differ from ethical hackers (6 marks)

A hacker is anyone who uses technical skills to analyse or bypass systems. The community is classified by intent, authorisation and skill:

TypeIntent / MotivationAuthorisationTypical behaviour
White hat (ethical hacker)Improve security, protect the organisationFull written permissionTests with scope, reports findings, helps remediate.
Black hatPersonal gain, malice, curiosityNone (illegal)Steals data, deploys malware, defaces systems.
Grey hatMixed; often recognitionNone or borderlineMay find and report flaws, but without permission or by intrusive means.
Script kiddieImitation, low skillNoneRuns ready-made tools without understanding.
HacktivistPolitical/social causeNoneDefacement, DDoS for protest.
Insider threatRevenge or gainAbuses legitimate accessMisuses credentials from inside the perimeter.
Suicide hackerCause damage regardless of detectionNoneDestructive, no concern for hiding.

Core difference — ethical vs unethical: The distinguishing factor is authorisation and intent, not skill. An ethical hacker works within a signed scope and rules of engagement, respects privacy, documents everything and aims to reduce risk. A malicious hacker has no permission and causes harm. Ethical hackers are often certified (CEH, OSCP) and bound by a code of conduct; the same techniques in unauthorised hands are crimes under the IT Act / computer-misuse laws.

Part (b) — Categories of penetration tests with examples (8 marks)

A penetration test (PT) is an authorised, simulated attack that evaluates security by actively exploiting vulnerabilities. Tests are categorised along several axes:

  1. By knowledge — Black-box: tester has no internal knowledge; simulates an outside attacker. Example: testing a bank's public website using only information obtainable on the internet.
  2. White-box: tester has full knowledge of source code, architecture and credentials. Example: a code-assisted audit of an application before release.
  3. Grey-box: partial knowledge (e.g., valid user credentials). Example: testing an intranet as a regular employee.
  4. By target/scope — Network (external & internal), web application, wireless, mobile, social engineering, physical and cloud tests. Example: attempting to tailgate into a data centre tests physical security.
  5. By approach — Compliance-driven vs red team: compliance tests follow a standard (PCI DSS, HIPAA); red-team exercises are goal-based and adversarial, measuring detection and response (blue team).

Phases of a PT: reconnaissance/footprinting → scanning & enumeration → vulnerability discovery → exploitation → post-exploitation (privilege escalation, pivoting, persistence) → reporting & remediation. Reporting converts technical findings into a risk-ranked action plan.

Exam tip: For (a), anchor the distinction in permission + intent, not tools. For (b), cover black/white/grey-box with one concrete example each, then list scope types and the PT phases. Tables and examples consistently earn full 14 marks.
Pitfall: Do not describe actual intrusion steps that cause damage; the exam rewards the methodology and the authorisation boundary (rules of engagement), not destructive detail.
Q12

OSSTMM vs NIST & Effects of Hacking

14 marks

Module I — Q12: (a) Compare the OSSTMM and NIST penetration testing methodologies. (b) Discuss the effects of hacking on individuals, organizations, and society.

Answer
Part (a) — OSSTMM vs NIST SP 800-115 comparison (6 marks)

Both are structured security-testing methodologies, but they differ in scope and style. OSSTMM (Open Source Security Testing Methodology Manual, by ISECOM) is a detailed, metrics-driven, open standard covering the full "security test" across five channels — information, interactive, process, physical and communications — with rigorous measurement (RAV = Risk Assessment Value). NIST SP 800-115 is a US government guide focused specifically on technical security testing of information systems, organised into planning, discovery, attack and reporting phases.

AspectOSSTMMNIST SP 800-115
Origin / ownerISECOM, open communityNIST (US government publication)
ScopeBroad: physical, process, human, communications, technicalTechnical testing of systems/networks
StructureModules and channels with metricsPhases: planning → discovery → attack → reporting
MeasurementFormal metrics (RAV, true/false positives)Qualitative findings and risk ratings
EmphasisThoroughness and repeatability across channelsOperational process, legal/privacy considerations
Best forComprehensive audits incl. physical/socialOrganisations needing a government-aligned framework

Comparison summary: OSSTMM is wider and more metric-heavy; NIST is narrower, phase-based and easier to map to compliance. Both agree on authorisation, scoped planning, systematic discovery, controlled execution and reporting — and both treat testing as a managed process rather than ad-hoc hacking.

Part (b) — Effects of hacking on individuals, organisations and society (8 marks)

Hacking produces layered harm. The same breach affects the person whose data is exposed, the organisation that failed to protect it, and wider society that depends on trust in digital systems.

LevelEffectsExample
IndividualsIdentity theft, financial loss, privacy invasion, reputational or emotional harm, loss of accountsStolen credentials used for bank fraud
OrganisationsData breach, downtime, lost productivity, revenue loss, legal/regulatory penalties (GDPR, IT Act), reputational damage, loss of customers, incident-response costRansomware halts a hospital's systems
SocietyDisruption of critical infrastructure (power, health, transport), erosion of public trust in e-governance and digital payments, economic loss, national-security risk, spread of cybercrimeDDoS on a national payment gateway

Countermeasures / positive effects: The same knowledge used defensively — ethical hacking, security awareness, strong encryption, patching, incident response and international cyber-law — reduces these harms. Notably, "white-hat" disclosure and bug-bounty programmes convert malicious potential into improved security.

Exam tip: Draw the comparison table for (a) with at least four rows — examiners look for the "five channels vs technical phases" and "metrics vs guidelines" contrast. For (b), give two or three distinct effects per level and one concrete example; finish with the defensive upside.
Q13

Footprinting Tools & Piggybacking

14 marks

Module II — Q13: (a) What are the key tools used for footprinting during reconnaissance? (b) Explain how social engineering attacks like piggybacking can compromise organizational security.

Answer
Part (a) — Key footprinting / reconnaissance tools (6 marks)

Footprinting is the first reconnaissance phase: collecting as much information as possible about a target passively (no direct contact) or actively, to build an attacker's map before any intrusion. Key tools and their uses:

Tool / techniqueWhat it reveals
whoisDomain registrant, registrar, dates, name servers
nslookup / digDNS records (A, MX, NS, CNAME), subdomains, zone data
tracerouteNetwork path and intermediate routers / topology
MaltegoVisual link analysis of domains, people, emails, infrastructure
theHarvesterEmails, subdomains, hosts and employee names from search engines
ShodanInternet-exposed devices, banners, open ports worldwide
NetcraftWeb server technology, hosting history, uptime
Google dorksIndexed sensitive files, misconfigurations via advanced search
NmapHost discovery, port and service/version scanning (active)

Procedure: (1) gather the domain and company name; (2) query whois and DNS; (3) enumerate subdomains and emails with theHarvester/Maltego; (4) map infrastructure with traceroute and Shodan; (5) record OS, services and technologies; (6) correlate into a target profile guiding later scanning. Passive sources leave no trace on the target; active scans may be logged.

Part (b) — Piggybacking and the threat to organisational security (8 marks)

Piggybacking is a physical social-engineering attack in which an unauthorised person gains entry to a restricted area by following closely behind an authorised employee through a door, turnstile or mantrap — often carrying a bundle or acting hurriedly to discourage challenge. (A close variant, tailgating, is entering without the authorised person's knowledge.) It exploits politeness, habit and the reluctance to confront strangers.

Authorised employee badges in → door opens Attacker steps in behind before it closes ──▶ inside the secure zone No credential of the attacker is ever verified.

How it compromises security:

  1. Perimeter bypass — physical access controls (badges, guards) are defeated without stealing a credential.
  2. On-site foothold — once inside, the attacker can plug into the internal network, access unattended workstations, read documents, plant a rogue device/keylogger or steal hardware.
  3. Escalation — physical presence enables further social engineering, password observation (shoulder surfing) or theft, leading to logical compromise of servers and data.
  4. Impact — data theft, malware insertion, sabotage and loss of confidentiality/integrity/availability.

Countermeasures: mantraps/turnstiles enforcing one-person-per-badge, security guards, anti-passback rules, CCTV, visitor logs and escorts, badge-on-demand challenges, security-awareness training ("challenge politely or report"), and clean-desk policies. Technical controls such as 802.1X and port-security limit damage if an outsider gets inside.

Exam tip: For (a), name at least six tools with a one-line purpose each and note the passive-vs-active distinction. For (b), define piggybacking, give the bypass→foothold→escalation chain, and list physical plus awareness defences. A small table like the one above scores highly.
Q14

DoS Attacks & Trojans vs Backdoors

14 marks

Module II — Q14: (a) Explain the concept of denial-of-service (DoS) attacks. (b) What are the differences between Trojans and backdoors, and how do they affect network security?

Answer
Part (a) — Denial-of-Service attacks (6 marks)

A Denial-of-Service (DoS) attack intentionally overwhelms a system, service or network so that legitimate users cannot access it — an attack on availability, one arm of the CIA triad. In a distributed DoS (DDoS), the flood originates from many compromised machines (a botnet), making it far harder to stop.

Categories:

  1. Volumetric / flooding — saturate bandwidth with traffic (UDP/ICMP floods, amplification via DNS/NTP/SSDP).
  2. Protocol attacks — exhaust connection state or resources (SYN flood, Ping of Death, fragmented packets).
  3. Application-layer attacks — target expensive functions (HTTP GET floods, slowloris) with few packets but high cost.
        [ Attacker / C&C ]
                 |
      commands thousands of
                 |
   +----+----+----+----+----+
   | Bot| Bot| Bot| Bot| Bot|   <- compromised hosts (botnet)
   +----+----+----+----+----+
        \    |    /  (simultaneous flood)
         \   |   /
          [ Target server ]  --> saturated : legit users denied

Example: A SYN flood sends thousands of half-open TCP connections until the server's connection table is full, so no genuine client can connect. Countermeasures: SYN cookies, rate limiting, ingress filtering (BCP 38), load balancing/anycast, CDNs and scrubbing services, IDS/IPS, over-provisioned bandwidth and an incident-response plan.

Part (b) — Trojans vs backdoors (8 marks)

A Trojan horse is malware that disguises itself as legitimate software to trick a user into installing it; once run it performs a hidden malicious action (data theft, keylogging, remote access). A backdoor is a hidden method of bypassing normal authentication to gain remote access to a system, installed by a Trojan, an attacker after intrusion, or even deliberately by a developer. A Trojan is a delivery vehicle; a backdoor is a persistent access mechanism — a Trojan often installs the backdoor.

BasisTrojanBackdoor
NatureDisguised malicious programHidden entry point / bypass
User interactionRequires the victim to run itNo user action once installed
PurposeDeceive, deliver payload, steal dataMaintain secret, recurring access
ExampleFree "game" that is actually a keyloggerReverse shell listening on a port; hardcoded admin account
LifetimeActive when executed; may be one-offPersists across reboots for later use

Effect on network security: Both create unauthorised remote control, data exfiltration and a foothold for lateral movement; they defeat perimeter controls because traffic may look legitimate or originate from inside. Countermeasures: up-to-date AV/EDR, application allow-listing, digital-signature checks, least privilege, firewall egress filtering, IDS signatures, patching and user education about untrusted downloads.

Exam tip: For (a), define availability-focused DoS, name the three categories, give one example and list defences. For (b), use the memorable line "a Trojan is the disguise, a backdoor is the hidden door it installs", then a comparison table. Both parts reward attack + countermeasure balance.
Q15

Remote Exploitation & MITM with Session Hijacking

14 marks

Module III — Q15: (a) Describe how remote exploitation works in the context of network attacks. (b) Explain the steps involved in conducting an MITM attack, including session hijacking.

Answer
Part (a) — How remote exploitation works (6 marks)

Remote exploitation is the act of compromising a machine or application over a network without prior physical or local access, by triggering a vulnerability in a service that listens on a port. It is the core of most network attacks because it turns information gathered during scanning into actual control.

Mechanism / steps:

  1. Discover a reachable host and enumerate open ports/services and versions (e.g., an unpatched web server or SMB service).
  2. Identify a vulnerability in that service — a known CVE, missing patch, weak configuration or logic flaw.
  3. Select or craft an exploit that reliably triggers the flaw (a payload delivered over the network to the listening port).
  4. Deliver the payload to obtain a shell or code execution on the target — this is Remote Code Execution (RCE).
  5. Post-exploitation: escalate privileges, dump credentials, pivot to other hosts and establish persistence.

Example: An unpatched, internet-facing service with a known buffer-overflow CVE is exploited, giving the attacker a remote shell as a low-privileged user. Countermeasures: prompt patching, hardening/disabling unused services, least privilege, network segmentation, IDS/IPS, WAF and exposure reduction (firewalls). Remote exploitation differs from local exploitation in that the attacker needs no account on the machine first.

Part (b) — Steps in an MITM attack including session hijacking (8 marks)

A Man-in-the-Middle attack places the attacker in the traffic path. When the goal is account takeover, it commonly leads to session hijacking — stealing the victim's session token and replaying it.

Victim ──(1 poison ARP)──▶ Attacker ──(relay)──▶ Gateway Victim's browser ──(2 plaintext HTTP cookie)──▶ passes through Attacker Attacker ──(3 replay cookie)──▶ Web server: "It's me, the victim!" → logged in

Steps:

  1. Position: poison the victim's ARP cache (or DNS, or run a rogue Wi-Fi AP / Evil Twin) so traffic flows through the attacker.
  2. Enable forwarding: transparently relay packets so the connection continues and neither side notices.
  3. Capture: sniff traffic for credentials and, critically, the session cookie — easy when the site uses plain HTTP; HTTPS requires certificate tricks/downgrade.
  4. Hijack: inject the stolen cookie into the attacker's own browser (cookie/session replay) to assume the authenticated identity; optionally use session fixation (force a known session ID first).
  5. Act & cover: perform fraudulent actions and hide traces in logs.

Countermeasures: HTTPS everywhere with HSTS, Secure/HttpOnly/SameSite cookies, certificate pinning, VPN on untrusted Wi-Fi, dynamic ARP inspection, IDS alerts for ARP/DNS anomalies, session-ID regeneration after login and short timeouts.

Exam tip: For (a), use the chain discover → find flaw → craft/deliver payload → shell → escalate; mention RCE explicitly. For (b), tie ARP spoofing to MITM to cookie capture to replay — examiners love seeing the topics linked. End both parts with defences.
Q16

Brute Force & ARP Spoofing to DoS

14 marks

Module III — Q16: (a) What are brute force attacks, and how do they compromise system security? (b) How does ARP spoofing lead to denial-of-service attacks, and what are its countermeasures?

Answer
Part (a) — Brute-force attacks (6 marks)

A brute-force attack tries every possible (or a large set of) credential combinations until the correct one works. It is exhaustive trial-and-error, automated by tools that test thousands of guesses per second, often accelerated by GPUs and distributed botnets.

Variants: pure brute force (all character combinations), dictionary attack (common words + rules), hybrid (words with appended digits/symbols), credential stuffing (reusing leaked username/password pairs), and password spraying (a few common passwords across many accounts to avoid lockouts). Against hashes offline, the attacker compares computed hashes to a stolen hash file; online, guesses are submitted to a login form.

How it compromises security: Once a password is guessed, the attacker gains unauthorised access, escalates privileges, exfiltrates data or pivots deeper. Weak, short or reused passwords fall quickly — the effective search space is small — and the attack is noisy but often detectable in logs as many failed logins.

Countermeasures: account lockout and exponential backoff/rate limiting, CAPTCHA, strong password policy and passphrases, salted slow hashing (bcrypt/Argon2) for stored passwords, MFA (which defeats a guessed password alone), monitoring/alerting on failed-login bursts, and breached-password checks.

Part (b) — ARP spoofing leading to DoS, and countermeasures (8 marks)

ARP spoofing poisons a host's IP-to-MAC cache with forged replies. Beyond enabling eavesdropping/MITM, it can directly cause a Denial of Service by making traffic disappear or be corrupted.

Normal: Victim → gateway's REAL MAC → Internet ✓ Poisoned: Victim → attacker's MAC (claimed as gateway) Case 1: attacker drops packets → victim offline (DoS) Case 2: attacker forwards to a wrong/dead MAC → no reply (DoS) Case 3: attacker floods forged ARP → cache thrashing, LAN instability Case 4: attacker impersonates the victim to the gateway → victim's traffic black-holed

Mechanism / steps:

  1. Attacker sends forged gratuitous ARP replies claiming the gateway IP maps to a non-existent or attacker MAC.
  2. Victim and/or switch caches the false binding; frames are sent to the wrong layer-2 destination.
  3. Because the real gateway never receives them, sessions time out and services become unreachable — availability is lost.
  4. Mass poisoning (ARP storm) can overwhelm switches and trigger network-wide outages.

Countermeasures: static ARP entries on critical hosts; switch features — DHCP snooping, Dynamic ARP Inspection (DAI), port security and VLAN segmentation; ARP-cache monitoring tools; encryption (HTTPS/VPN) so misdirected traffic is useless; and redundancy/IDS alerting. Note that encryption protects confidentiality but not availability — DAI/static ARP are the real fixes for the DoS.

Exam tip: For (b), make the causal chain explicit: forged ARP → wrong MAC → traffic misdirected/dropped → service unavailable. Then separate defences into host-level (static ARP), switch-level (DAI/DHCP snooping) and data-level (encryption), noting encryption alone does not stop the DoS — a nuance that impresses examiners.
Q17

Routers, Firewalls & Reverse Engineering

14 marks

Module IV — Q17: (a) Discuss the role of routers and firewalls in protecting a network. (b) Explain the process of reverse engineering and how it is used in identifying vulnerabilities.

Answer
Part (a) — Role of routers and firewalls (6 marks)

Routers operate at OSI Layer 3, forwarding packets between networks using IP addresses and routing tables. Their security role comes from Access Control Lists (ACLs) that permit or deny traffic by source/destination IP, protocol and port, plus NAT (hiding internal addressing), traffic segmentation through VLANs/subnets, rate limiting and logging. They shape what can reach a network at all.

Firewalls enforce a security policy at the network boundary — allowing trusted traffic and blocking untrusted traffic. Types: packet-filtering (stateless, ACL-based), stateful inspection (tracks connection state), proxy/application-level and Web Application Firewalls (inspect HTTP), and next-generation firewalls (deep packet inspection, IPS, app awareness). Firewalls implement default-deny, DMZ placement and egress filtering.

Internet
    |
 [Router]  - ACLs, NAT, rate-limiting
    |
 [Firewall]- stateful rules, DMZ, IDS/IPS
    |
  +-+-----------------+---------------+
  | DMZ: web/mail/DNS | Internal LAN  |
  +-------------------+---------------+

Combined protection: the router filters at the network edge and routes only allowed traffic; the firewall inspects and enforces policy statefully, isolating the DMZ from internal resources. Together they reduce the attack surface, contain lateral movement and generate logs for detection. Limitations: they cannot stop insiders, encrypted malicious traffic or application flaws behind allowed ports — hence defence in depth with IDS and hardening.

Part (b) — Reverse engineering and its role in finding vulnerabilities (8 marks)

Reverse engineering is the systematic analysis of a compiled program, binary or malware to understand its structure, behaviour and logic without the original source code. It deconstructs the artefact to reveal what it actually does.

Process:

  1. Static analysis — inspect the binary without running it: file type/strings, imports, headers, disassemblers (IDA Pro, Ghidra, radare2) and decompilers to recover pseudo-code and control flow.
  2. Dynamic analysis — run it in a safe sandbox/debugger (OllyDbg, x64dbg, GDB), tracing execution, registers, memory, API calls and network behaviour.
  3. Interpret and document — reconstruct algorithms, locate interesting functions (parsers, crypto, authentication) and map inputs to code paths.

How it identifies vulnerabilities: Analysts examine input-handling routines for unsafe calls (e.g., strcpy, unbounded copies) that indicate buffer overflows, inspect crypto for weak keys, check authorization logic for flaws, and use patch diffing — comparing a patched binary with the vulnerable one — to pinpoint the exact flaw a vendor fixed and derive a signature. Combined with fuzzing of the recovered input paths, reverse engineering exposes zero-day vulnerabilities, confirms exploitability of CVEs, and supports malware analysis (understanding C2, persistence, indicators of compromise). It also verifies that a fix is complete.

Ethical/legal note: Reverse engineering must be done on systems you own or are authorised to analyse; it is legitimate for malware research, interoperability and defensive patch analysis, but unauthorised analysis may breach licences/laws.

Exam tip: For (a), contrast the router's Layer-3 ACL/NAT role with the firewall's stateful policy enforcement, and draw the simple perimeter diagram. For (b), give static + dynamic analysis, name at least two tools, and explain patch diffing and fuzzing as the bridge from "understanding code" to "finding a vulnerability".
Q18

Buffer Overflow & Writing an Exploit

14 marks

Module IV — Q18: (a) What is buffer overflow, and what are its implications in web security? (b) Describe the steps involved in writing an exploit and its potential risks.

Answer
Part (a) — Buffer overflow and its web-security implications (6 marks)

A buffer overflow occurs when a program writes more data into a fixed-size memory buffer than it can hold, so the excess overwrites adjacent memory. It is caused by missing bounds checks in languages such as C/C++ (unsafe functions like strcpy, gets). In a stack overflow, the overflow can overwrite the saved return address (EIP/RIP), letting an attacker redirect execution to injected code; a heap overflow corrupts heap metadata or function pointers.

Stack grows down:
  [ local buffer 256 bytes ]  <-- user input (too long)
  [ saved EBP               ]
  [ return address (EIP)    ]  <-- overwritten -> jump to attacker's code
  [ function arguments      ]

Implications in web security: Many web servers, CGI binaries, native modules and embedded devices are written in C/C++; an overflow in an internet-facing component can give remote code execution, crashes/DoS, privilege escalation or data leakage. Classic web-related cases include overflows in server extensions, image/parser libraries and protocol handlers. Even where web apps use managed languages, the underlying stack (web server, interpreter) can be vulnerable.

Countermeasures: safe libraries and bounds-checked functions, input-length validation, ASLR (randomises addresses), DEP/NX (marks stack non-executable), stack canaries, compiler fortification, memory-safe languages (Rust, Go, Java), fuzzing and patching.

Part (b) — Steps in developing an exploit (conceptual) and its risks (8 marks)

An exploit is a program or script that takes advantage of a specific vulnerability to produce a desired effect (a shell, a crash, privilege escalation). Described conceptually, the development workflow is:

  1. Find the flaw — identify a vulnerable application/version and a reproducible crash or behaviour (via fuzzing, CVE research or code review).
  2. Control the instruction pointer — determine the exact input offset that overwrites the saved return address so execution can be redirected.
  3. Prepare a payload — choose a payload (shellcode / ROP chain) appropriate to the goal, avoiding "bad characters" that break it.
  4. Locate a reliable jump target — account for ASLR/DEP (e.g., ROP gadgets, jmp/call registers), and build the final input combining filler, redirect address and payload.
  5. Test and refine — run against a lab copy, handle variations, then package it as a reusable exploit module.
  6. Deliver — send it to the target service through the vulnerable input channel.

Potential risks: Exploits are fragile — a different OS, patch level, compiler or offset can crash the service (DoS) or simply fail; failed attempts are logged and may trigger intrusion detection; shellcode may be blocked by AV/EDR; and most importantly, using an exploit against systems without authorisation is illegal and can cause real damage. Ethical use is limited to authorised labs and engagements with rules of engagement.

Exam tip: For (a), include the stack layout diagram and pair each mechanism with its modern defence (canary ↔ overwrite, ASLR ↔ address, NX ↔ execution). For (b), present the numbered workflow but keep it conceptual — no real shellcode — and stress fragility, detection and legality as the "risks".
Q19

Hiding Files & Covering Tracks; Password Cracking

14 marks

Module V — Q19: (a) Discuss the methods used to hide files and cover tracks in system hacking. (b) Explain the importance of password cracking techniques in system hacking and ways to mitigate such attacks.

Answer
Part (a) — Hiding files and covering tracks (6 marks)

After gaining access, attackers hide their presence and artefacts. File hiding conceals data; track covering erases or falsifies evidence of the intrusion.

GoalTechniqueDescription
Hide filesHidden/system attributesSet hidden/System flags so normal listings skip files
Alternate Data Streams (ADS)NTFS feature: hide data in a stream attached to a normal file
SteganographyConceal data inside images/audio
Rootkits / encryptionHook the OS to hide processes, files and ports; encrypt contents
Cover tracksLog clearing/tamperingDelete or edit Security/System/application logs and web logs
Timestamp manipulationTimestomp — alter created/modified/accessed times to blend in
History/artefact cleanupRemove shell history, temp files, recent files, swap remnants

Additional tricks include storing data in slack space, using unnamed/null logs, disabling auditing, and living off legitimate system tools (LOLBins) so activity looks benign. The aim is to defeat both administrators and forensic investigators.

Part (b) — Importance of password cracking and mitigation (8 marks)

Password cracking is central to system hacking because access credentials are the gateway to the whole system. Its importance:

  1. Initial access — recover passwords from captured hashes to log in as a legitimate user.
  2. Privilege escalation — crack administrator or service-account hashes to gain higher rights.
  3. Pivoting / lateral movement — reused local admin passwords open other machines on the network.
  4. Persistence & value — credentials remain useful after malware is removed and enable access to email, cloud and financial systems.

Cracking techniques are dictionary, brute-force, hybrid/rule-based, rainbow tables, and credential stuffing against offline hash dumps (from SAM/NTDS, /etc/shadow, or application databases) or online login forms. Weak hashing (MD5, unsalted) makes this trivial; GPU clusters make it fast. Ethical testers use the same methods, with permission, to measure password strength.

Mitigations:

  • Strong, salted, slow password hashing — bcrypt, scrypt, Argon2 — so each guess is expensive and rainbow tables fail;
  • Enforce long passphrases, ban known-breached passwords, avoid reuse;
  • Enable MFA so a cracked password alone is insufficient;
  • Account lockout / rate limiting, CAPTCHA and alerting on failed logins;
  • Protect hash stores (least privilege, LAPS for unique local admin passwords), and patch to limit hash theft (e.g., credential guard).
Exam tip: For (a), split the answer into file-hiding and track-covering with two or three named techniques each. For (b), link cracking to the attack lifecycle (access → escalation → pivoting) and give at least three mitigations, naming salting + slow KDFs and MFA explicitly — those are the highest-value keywords.
Q20

Hiding Network Evidence & Covering Tracks

14 marks

Module V — Q20: (a) How can network evidence be hidden by attackers? (b) Describe the techniques used by attackers to cover their tracks after gaining access to a system.

Answer
Part (a) — Hiding network evidence (6 marks)

Network evidence is the traffic records, logs and flows that reveal an attack. Attackers hide it to avoid attribution and detection:

MethodHow it hides evidence
Encryption / VPN / tunnelsWraps traffic (even over DNS/ICMP covert channels) so payload content is invisible to passive monitoring
SteganographyEmbeds commands/data inside seemingly normal images or protocol fields
Traffic padding / noiseGenerates decoy traffic to blend the real session into background activity
Proxy chains / Tor / compromised relaysMulti-hop routing obscures the true source IP
Log suppression / deletionDisables firewall/IDS logging or removes firewall, proxy and NetFlow records
Fragmentation / mimickingSplits packets or imitates legitimate protocols to evade signature detection

Related anti-forensic ideas include using disposable infrastructure (burner domains, short-lived VPS), fast-flux DNS, and timing activity during busy periods so anomalies are lost in the noise. The effect is that investigators cannot reconstruct who connected, what was transmitted, or when.

Part (b) — Covering tracks after gaining access (8 marks)

Once inside a system, attackers follow a cleanup routine to erase the signs of their presence. Typical techniques:

  1. Clear logs — delete or forge OS, application, database and web-server logs (e.g., empty the Security event log; edit entries to remove specific events).
  2. Timestomp — change file MAC times (created/modified/accessed) so malicious files appear old or blend with system files.
  3. Remove artefacts — delete uploaded tools, scripts, shell history, temp files, downloaded payloads and cron jobs/scheduled tasks used for persistence.
  4. Disable auditing/monitoring — turn off audit policies, stop agents or disable security services temporarily.
  5. Hide with rootkits — use kernel/userland rootkits to conceal processes, files, ports and network connections from administrators.
  6. Secure deletion — overwrite freed space (shred/wipe) so deleted files cannot be recovered forensically; clear swap/pagefiles and browser caches.
  7. Live off the land — use built-in administrative tools (PowerShell, WMI, net commands) so actions masquerade as normal administration.

Defensive countermeasures (the exam expects balance): forward logs in real time to a central, write-once SIEM/log server that the attacker cannot edit; enable audit policies and file-integrity monitoring; synchronise clocks with NTP; use EDR that detects agent tampering; apply least privilege; and monitor for anomalies such as cleared event logs, timestamp inconsistencies and unexpected outbound connections. Memory forensics can recover evidence that disk cleanup misses.

Exam tip: For (a), group methods as encryption/covert channels, source obfuscation and log/tamper suppression. For (b), give a numbered cleanup sequence, name at least three named techniques (log clearing, timestomp, rootkit, secure deletion) and finish with the defensive lesson — centralised, tamper-proof logging defeats local track covering. Tables plus this attack/defence balance make a full-mark answer.
