01

How questions are set

Read the examiner

Most questions in this course fall into one of a few shapes. Spotting the shape before you write saves time and stops you answering the wrong thing:

  • Define / explain a term — the examiner wants the meaning, in your own words, with one concrete angle (what it protects, what breaks it, how it's done).
  • List the types / phases / categories — ordered, enumerated, with a short note per item so it reads as a list, not a dump.
  • Compare two things — the examiner is checking you know the boundary between them. A two-column table with the same axes for both is the cleanest way to show it.
  • Describe an attack / a process / a system — narrative, step by step, from start to outcome, with the "why" at each step, not just a list of buzzwords.
  • Discuss advantages and limitations — both sides, explicitly. A one-sided "it's great" answer loses marks; the limitation is often where the marks live.
  • "With a neat diagram" — labels matter more than artistic quality. A labelled schematic that shows the flow or layout the question names scores; a pretty but unlabelled one doesn't. See the diagrams built into each module page — they're exactly the shapes examiners expect.
The single most useful reflex: rephrase the question in plain English before you write. "Explain DoS" is really "what is it, how does it work, why does it break availability, what's an example?" If you answer each of those, you've covered the mark scheme.

How to match your answer to the marks

Marks-aware
MarksWhat the examiner expectsWhat to write
3 A tight definition or short list — enough to show you know the term, not a full essay. One sentence of meaning, then one line with an angle (what breaks it, how it's done, one example). Stop when you've said the thing.
5–7 A comparison, a short process, or a "list with notes." Three to five headed points, each with a one-line reason. If it's a compare, use a small table. A worked mini-example helps here.
10–14 A full answer: definition, principle, sub-points, a comparison or diagram if asked, and both advantages and limitations. Lead with the definition, then build structured sub-sections (a/b/c or a table), then close with limits and an example. "With a neat diagram" means a labelled schematic of the shape the question names — draw the one on the module page.
Don't pad. Repeating the same point in different words wastes time and can read as uncertainty. If the question is 3 marks, a 3-mark answer that is accurate beats a 10-mark answer that wanders.
05

Do's and don'ts in the exam

Practical

Do

  • Rephrase the question in plain English before writing.
  • Lead a long answer with a definition or one-line framing.
  • Use a two-column table when a question says "compare" or two things are naturally paired.
  • Give one concrete example or scenario — it usually anchors a mark that a bare list misses.
  • If the question asks for "advantages and limitations," give both, labelled.
  • If it says "with a neat diagram," draw the labelled schematic from the module — labels count.

Don't

  • Pad with buzzwords you can't explain — a misused term reads as guessing.
  • Answer a "compare" as two separate lists with no connecting axis.
  • Stop at the advantages when the question asks for limitations too.
  • Run on past the marks — a 3-mark answer shouldn't be half a page.
  • Leave a "diagram" out because you can't draw well — labels on a schematic are what score, not artistry.
  • Mix up pairs that are frequently swapped (virus/worm, symmetric/asymmetric, IDS/IPS) — those are exactly where a trick question lives.

How to use these notes

Study flow

Read a module page top to bottom once to get the shape — the headings are the skeleton, the tables are the comparisons, and the worked examples are the parts that usually earn marks. Then:

  • For definitions: use the core-definitions table on this page (02) as a checklist — can you say each one in one sentence? If not, that's a gap to close before the exam.
  • For comparisons: rehearse the recurring pairs in section 03 from memory — write the table out once, then close the notes and try again.
  • For attacks and processes: narrate them aloud in your own words, step by step, with the "why" at each step. If you can't say what breaks (CIA goal) or how detection works, go back to the module page.
  • For "with a neat diagram": redraw the labelled schematic on the module page — flat-plate collector, solar cell, OTEC loop, tidal basin, wind turbine, fuel cell, machine guard, fire-class wheel, HAZOP flow. Labels matter more than neatness.
  • For full answers: use the question bank on papers.html as practice — try one, then read the model answer and note what it included that you missed.
The goal isn't to memorise this whole site word-for-word. It's to be able to rebuild each module's key tables and a labelled diagram from memory, and to narrate each attack and process in your own words with the CIA property and an example attached.

Penetration testing — frameworks and steps

PTES phases: pre-engagement → intelligence gathering → threat modelling → vulnerability analysis → exploitation → post-exploitation → reporting OSSTMM: operational security methodology — scope, channels (human/physical/wireless/communications), indicators of trust, controls, process/visibility, ten commandments of hygiene. NIST SP 800-115: planning → discovery → attack → reporting (with remediation). OWASP: risk-focused web testing — information gathering, configuration, authentication, session management, input validation, error handling, business logic, etc.

Types: black-box (zero knowledge), white-box (full knowledge), grey-box (partial); external vs internal; automated vs manual; covert vs overt.

Exam-writing rules

  • For "compare/differentiate", write a two-column table with at least four rows and end with a one-line conclusion.
  • For "explain the process/steps", number every step and state what happens at each stage.
  • For attack questions, always add a countermeasure paragraph — examiners award marks for defence.
  • For "with figure/illustrate", draw a labelled ASCII block diagram; an unlabelled arrow diagram loses marks.
  • Define the term first, even in a 3-marker, then explain the mechanism, then give one example.

Attacking SQL Servers

syllabus gap
Answer

Why it matters. Database servers are high-value targets: they hold credentials, financial data and personal records. The syllabus lists attacking SQL servers under Module III (network attacks) because weak service configuration and unpatched database software let an attacker move from a compromised host to the data layer.

Attack surface and common paths
  1. Service discovery — port scanning finds the database listener (SQL Server default TCP 1433, named-instance UDP 1434; MySQL 3306, PostgreSQL 5432) and banner grabbing reveals version and edition.
  2. Weak authentication — default or blank sa accounts, reused credentials and saved connection strings; attackers try credential stuffing and dictionary attacks, often with the public sqlcmd/client tools.
  3. SQL injection through an application — a web front-end that concatenates user input into a query lets the attacker read or modify tables, enumerate the schema via INFORMATION_SCHEMA, and sometimes escalate to OS commands through database features such as xp_cmdshell if enabled.
  4. Unpatched services and misconfiguration — known CVEs in the database engine, enabled extended stored procedures, overly broad service accounts and unrestricted network access from any host.
  5. Post-exploitation — dump password hashes, map the network through linked servers, pivot to other hosts, and exfiltrate data; the attacker then covers tracks by clearing SQL Agent and Windows event logs.
Defensive controls
  • Parameterised queries / stored procedures and input validation in every application that touches the database — this removes the injection path entirely.
  • Least privilege: remove sa-equivalent use for applications, disable xp_cmdshell and unnecessary features, isolate the DB in a separate VLAN behind a firewall.
  • Strong authentication, credential rotation, MFA for administrative access, and encryption of connection strings and data at rest.
  • Patch management, vulnerability scanning, database activity monitoring, and centrally shipped immutable logs with alerting on failed logins and bulk reads.
Exam tip. Structure the answer as discover → authenticate/inject → escalate → pivot → cover tracks → defend. Mention at least one concrete port (1433) and one concrete hardening step (parameterised queries, disable xp_cmdshell) — both earn marks.

Exploit Writing

asked in Paper c · Q18(b)
Answer

Definition. Exploit writing is the process of developing a reliable piece of code or script that takes advantage of a specific vulnerability to produce a deliberate outcome — arbitrary code execution, privilege escalation, denial of service or information disclosure. In ethical hacking it is done in an authorised lab to prove that a vulnerability is real and to guide remediation.

Typical workflow
  1. Research the vulnerability — read the advisory/CVE, affected versions and the vulnerable code path; identify the exact flaw (e.g. unchecked buffer copy, use-after-free, unsanitised query).
  2. Reproduce in a controlled lab — install the vulnerable version on an isolated VM, confirm the crash or faulty behaviour, and capture it with a debugger.
  3. Understand the trigger — determine the input structure, offsets, required protocol sequence and any authentication needed; for memory bugs find the return address or function pointer to overwrite.
  4. Develop the payload — build the input that triggers the flaw; for code execution choose a shellcode/payload matched to architecture and OS, handle bad characters and available space, and avoid DEP/ASLR with a ROP chain or an information leak where necessary.
  5. Test reliability — run repeatedly against multiple patched/unpatched builds, tune for different service packs or languages, and ensure the exploit does not damage data.
  6. Document and report — record steps to reproduce, impact, CVSS score, affected versions and the remediation; provide a proof-of-concept only to the authorised owner.
Risks and ethics

An exploit is double-edged: the same code that validates a finding can be repurposed by attackers, and a buggy exploit can crash production systems. Written authorisation, scope boundaries, isolated testing and secure handling of PoCs are mandatory. Under KTU/CCT401 ethics questions, state that exploit development is permitted only with consent and that disclosure follows responsible-reporting timelines.

Common mistake. Do not describe exploit writing as merely "running Metasploit". Using a framework module is exploitation; writing an exploit means analysing the flaw and producing or adapting the payload yourself. The syllabus expects that distinction.
Exam tip. Finish with the mitigation side: patching, ASLR/DEP, stack canaries, bounds checking, least privilege and IDS/IPS signatures. That converts a 6-mark description into a full 8-mark answer.
Revision rule. If a topic appears in only one paper, it is still examinable — the ESE takes two questions from every module, and the model paper shows the exact phrasing pattern. Cover the whole syllabus table, not just repeated questions.
07

The exam blueprint, decoded

Plan first

Knowing the syllabus is not the same as knowing the paper. The CCT401 end-semester examination is a three-hour, 100-mark paper built from five modules, and the same arithmetic is repeated in every one of the four solved papers and in the official model paper. Part A carries 30 marks: two 3-mark questions are set from each module and all ten must be attempted. Part B carries 70 marks: two 14-mark questions are set from each module and the candidate answers any one per module, so five full answers are written. The total is 10 × 3 + 5 × 14 = 100. Because Part A is compulsory, its ten short answers must be accurate and fast; there is no opportunity to skip a weak module there.

Work backwards from the marks. At three hours for 100 marks you have roughly 1.8 minutes per mark. A 3-mark answer should take about 5–6 minutes including reading; a 14-mark answer about 25 minutes. Ten short answers at 5–6 minutes plus five long answers at 25 minutes consume roughly 175–185 minutes of a 180-minute paper — at the top of that range you overrun. Staying inside the clock means knowing the short answers cold and having a fixed template for the long ones. This is why the cheat-sheet tables and the recurring-pairs table above are worth memorising: they remove the thinking time from the easiest 30 marks.

The internal tests use a different but related pattern: 50 marks, with Part A containing five 3-mark questions (answer all, 15 marks) and Part B containing seven 7-mark questions (answer any five, 35 marks). Each series test is itself out of 50 marks; the CIE total of 50 is then composed under KTU 2019 regulation R6.4 as tests 50% (25 marks), assignment/class work 30% (15 marks) and attendance 20% (10 marks) — attendance and assignments are components of the 50, not additions to it. The 30/30/40Remember–Understand–Apply split in the assessment pattern tells you that recall and explanation dominate: a well-structured definition plus a correct example earns a large share of the marks, and pure application questions are the minority.

Module 1 — what the examiner is testing

8 hours

Module 1 is a definitions-and-frameworks module. Every Part A question from this module asks either for the elements of information security, the stages of hacking, a hacker category, or a role. The high-mark questions ask for security challenges, the role of a penetration tester, vulnerability assessment, and a comparison of the three penetration-testing methodologies.

Elements and non-repudiation. The CIA triad is the minimum answer; a complete answer adds authenticity (proof that an entity is who it claims), non-repudiation (proof that an action occurred, normally with digital signatures and audit logs), accountability (each action maps to a unique identity) and access control. The frequent trap is confusing the seven elements with the six security challenges — complexity, connectivity, third-party risk, insider threat, rapidly evolving threats and regulatory compliance. They are different lists and both are examinable.

Hacker classes. White hat (authorised, ethical), black hat (malicious, unauthorised), grey hat (mixed), plus script kiddie, hacktivist, insider and red team. The axis to state is permission and intent, not skill: a grey hat may be highly skilled but lacks authorisation, while a novice with a downloaded tool is still a script kiddie. The ethical hacker works inside a signed rules-of-engagement document that fixes scope, timing, permitted techniques and emergency contacts.

The three methodologies. OSSTMM is a detailed operational-security standard organised around channels (human, physical, wireless, communications) and indicators of trust. NIST SP 800-115 is a four-step process — planning, discovery, attack, reporting — that is easy to write under exam conditions. PTES is the seven-phase lifecycle: pre-engagement, intelligence gathering, threat modelling, vulnerability analysis, exploitation, post-exploitation and reporting. OWASP is web-application risk testing (injection, broken authentication, XSS, security misconfiguration and so on). When asked to compare, use the axes scope, phase model, deliverable and typical audience.

Vulnerability assessment versus penetration testing. A vulnerability assessment discovers and ranks weaknesses with scanners and configuration reviews; a penetration test goes further and safely exploits them to prove real impact. The sequence is: define scope, discover assets, scan, validate false positives, rank by severity, remediate and retest. State that scanning alone is not a penetration test — that sentence often earns a mark.

Exam tip. A 14-mark Module 1 answer should contain (1) a definition, (2) a numbered framework or comparison table, (3) one concrete tool or example, and (4) a limitation or ethical caveat. Both OSSTMM/NIST and PTES/OWASP comparisons have appeared in more than one paper.

Module 2 — recon, malware and social attacks

6 hours

Module 2 joins the reconnaissance toolkit to the human and host attack surface. The recurring 3-markers are footprinting, DoS versus DDoS, sniffing and brute force; the recurring 14-markers pair footprinting tools with social engineering, or ask about scanner activity in detail.

Footprinting is passive and active information gathering. Passive techniques never send a packet to the target — WHOIS, DNS records, certificate transparency logs, archived web pages, search-engine dorks, job advertisements and social profiles. Active techniques touch the target — ping sweeps, port scans, traceroute, banner grabbing and DNS zone transfer attempts. Google hacking uses operators such as site:, filetype:, inurl: and intitle: to find exposed documents, admin portals and error pages. The result of good footprinting is a target map of domains, IP ranges, live hosts, open ports, services, versions, user names and e-mail addresses.

Scanning and enumeration turn that map into a vulnerability list. Nmap reports ports, service versions and an operating-system guess; Nessus or OpenVAS match banners against vulnerability databases; enumeration pulls user lists, share names, SNMP community strings and routing tables. Always separate what the scan found from what the attacker does with it.

Malware taxonomy. A virus attaches to a host file and needs a human to run it; a worm is self-propagating across the network; a Trojan hides inside a legitimate-looking program; a backdoor opens a hidden entry; ransomware encrypts data and demands payment; a rootkit hides processes and files; a logic bomb activates on a condition. Compare on host requirement, propagation, payload and concealment.

Proxy and packet filtering sit at different layers. A proxy terminates a connection on behalf of a client and can inspect application data; a packet filter works at layers 3–4, allowing or denying packets by address, protocol and port. Stateful filtering tracks connection state, which stateless filtering does not.

Social engineering targets people rather than code: phishing, spear phishing, whaling, vishing, smishing, pretexting, baiting, quid pro quo, shoulder surfing, piggybacking and dumpster diving. The two goals are to obtain information and to induce an action or gain access. The countermeasure set is training, policy, badges and visitor logs, shredding and secure disposal, screen filters, and a reporting culture — the so-called human firewall.

DoS versus DDoS. DoS is a single-source attempt to exhaust bandwidth, connections, CPU or memory; DDoS orchestrates many compromised hosts (a botnet) so the traffic looks like ordinary clients. Mitigation: rate limiting, SYN cookies, ingress filtering (BCP 38), load balancing, redundancy, a CDN or scrubbing service, and an incident-response plan.

Common trap. "Sniffing" is capture only; "sniffing with ARP spoofing or MITM" also redirects or modifies traffic. Write the mechanism precisely — passive capture on a hub or SPAN port versus active manipulation of the ARP cache or DNS answers.
10

Module 3 — network attack mechanics

9 hours

Module 3 is the largest and most technical. Its questions ask how traffic is intercepted, redirected and hijacked, how services are attacked remotely, and where attackers obtain vulnerability information.

Sniffing types. Classify by placement (software on a NIC in promiscuous mode, a hardware tap, a SPAN/mirror port, or a network-based IDS sensor) and by activity (passive capture versus active capture assisted by ARP poisoning, DHCP spoofing or DNS spoofing). Wireshark and tcpdump are the standard tools. Defences: full-duplex switched networks, dynamic ARP inspection, DHCP snooping, port security, encryption (TLS, SSH, VPN) and detection of promiscuous-mode interfaces.

ARP and DNS spoofing. ARP has no authentication, so an attacker can advertise that a given IP maps to the attacker's MAC address and become a man-in-the-middle for the local segment. DNS spoofing or cache poisoning substitutes a different IP for a hostname, redirecting users to a replica site. Defences: dynamic ARP inspection with DHCP snooping binding tables, static entries for gateways, DNSSEC, DNS cache randomization, and TLS so that a redirected connection still fails certificate validation.

DHCP spoofing. A rogue DHCP server replies before the legitimate one and supplies an attacker-controlled default gateway and DNS server. The victim's traffic then flows through the attacker. DHCP snooping on switches, trusted ports, short lease times and network access control are the standard defences.

Session hijacking. The attacker steals or predicts a session token (cookie) and replays it to impersonate an authenticated user. Techniques include sniffing the cookie on an unencrypted channel, cross-site scripting, session fixation and prediction of weak tokens. Defences: HTTPS everywhere, the Secure and HttpOnly cookie flags, token rotation after login, short idle timeouts, re-authentication for sensitive actions, and binding the session to a client fingerprint.

Brute force and weak authentication. Online guessing is throttled by account lockout, rate limiting, CAPTCHA and MFA; offline cracking is limited by salted, slow hashes (bcrypt, Argon2, PBKDF2). A password spray tries one common password across many accounts to avoid lockout; credential stuffing reuses credentials leaked elsewhere. The mitigation set is MFA, password managers, breached-password screening and monitoring for abnormal login patterns.

Remote service attacks. SMTP abuse uses open relays for spam and phishing; SQL servers are found on TCP 1433 (or UDP 1434 for named instances), attacked through weak sa credentials and SQL injection, and can be escalated with features such as xp_cmdshell. Mitigations: disable or restrict the service, parameterise queries, remove default accounts, patch, segment the database into its own VLAN and log administrative activity.

Vulnerability data sources. NVD is the authoritative US catalogue of CVEs with CVSS scores; CVE provides a common identifier; CERT/CC coordinates incident response and publishes advisories; ISACs share sector-specific information; OVAL is a standard for expressing vulnerability checks in machine-readable form so that scanners can test reliably. Distinguish a known vulnerability (public CVE, patch available) from a zero-day (unknown to the vendor, no patch).

Full-mark shape for a Module 3 question: name the layer and the exact protocol weakness, number the steps of the attack, give one concrete tool or port, add a one-line comparison with the nearest related attack, and finish with at least three defences.
11

Module 4 — protection systems and web attacks

8 hours

Module 4 mixes defensive architecture with application-layer attacks. Expect one Part B question on routers/firewalls/IDS/honeypots, one on SQL injection or XSS, and short questions on buffer overflow, reverse engineering, email hacking and incident response.

Routers and firewalls. A router forwards packets at layer 3 using a routing table; a firewall enforces a policy at layers 3–7, permitting or denying traffic by address, port, protocol, state or application identity. Router security challenges include weak default credentials, unpatched IOS, open management interfaces, SNMP community strings and misconfigured access lists; the controls are hardening templates, SSH-only management, out-of-band management, ACLs, logging and regular patching.

Firewall generations. First generation: stateless packet filters. Second: stateful inspection. Third: application-level proxies. Fourth: next-generation firewalls with deep packet inspection and identity awareness. Fifth: cloud or virtual firewalls with threat intelligence and sandboxing. An IDS is passive and out-of-band — it detects and alerts; an IPS is inline and can block. The IPS therefore has to be tuned carefully to avoid false positives dropping legitimate traffic.

Honeypots. A honeypot is a decoy that appears vulnerable to attract attackers. Production honeypots sit beside real services to improve detection with low false positives; research honeypots collect attacker tooling and behaviour. Low-interaction honeypots emulate services cheaply and are safe but capture little; high-interaction honeypots are real systems and capture rich data but require careful containment. Benefits: early warning, attacker intelligence, diversion and low false-positive alerting. Risks: maintenance cost and the possibility of being used as a pivot if poorly isolated.

SQL injection and XSS. SQL injection inserts attacker-controlled input into a query so the database executes unintended commands; classes are in-band (error-based, union-based), inferential/blind (boolean and time-based) and out-of-band. The fix is parameterised queries (prepared statements) plus input validation and least-privilege database accounts. XSS executes attacker script in another user's browser: reflected (payload in the request, returned in the response), stored (payload saved on the server and served to every visitor) and DOM-based (client-side script writes untrusted data into the page). Defences: context-aware output encoding, Content Security Policy, HttpOnly cookies and sanitisation.

Buffer overflow and exploit writing. A buffer overflow occurs when more data is written to a fixed-size buffer than it can hold, overwriting adjacent memory — potentially the return address — so execution can be redirected. Causes are unchecked copies (strcpy, gets), off-by-one errors and integer overflows. Defences: bounds checking, safe library calls, stack canaries, ASLR, DEP/NX, compiler fortification and fuzzing. Exploit writing is the disciplined process of reproducing a flaw in an isolated lab, finding the trigger and offset, building a reliable payload, testing across builds and documenting proof of concept for the owner.

Incident response. The six steps are preparation, identification, containment, eradication, recovery and lessons learned. An expanded seven-step version adds analysis after detection. Containment is short-term (isolate the host) and long-term (block the account or segment the network); eradication removes the root cause; recovery restores from clean backups and validates; the post-incident report feeds back into controls.

Exam tip. For every Module 4 attack question, close with a defence paragraph. The mark scheme consistently rewards countermeasures, and a missing defence paragraph is the most common reason a otherwise correct answer loses two or three marks.

Module 5 — logging, evidence and anti-forensics

6 hours

Module 5 asks what records a system keeps, how an attacker removes or forges them, and how a defender makes those records trustworthy. It is a short module but it appears in both Part A (event logging, hiding evidence) and Part B (altering logs, defences against log attacks, hiding evidence on a network).

Event logging. An event log is a chronological record of OS, application and device activity — logons, failures, object access, process creation, policy changes and network connections. The classic Windows Server list has six categories: Application, System, Security, Directory Service, DNS Server and File Replication Service — the last three exist only on machines holding those server roles. On a modern client, Event Viewer's Windows Logs node shows Application, Security, Setup, System and Forwarded Events. Each record carries a timestamp, source, event ID and user context. Logs support detection, incident investigation, accountability, compliance and non-repudiation.

Hiding evidence. On a host an attacker may delete records, edit individual entries, clear the entire log, change the system clock, hide files with the hidden/system attributes or NTFS alternate data streams, and hide processes with rootkits. On a network the attacker uses encryption and tunnelling, fragmentation, low-and-slow rates, spoofed addresses, covert channels in DNS or ICMP, and log flooding to bury the real events. Every technique has a footprint: a cleared log has a gap, a disabled agent generates a heartbeat alert, and a changed clock breaks correlation.

Defences. The central principle is that logs must be outside the attacker's control: ship them immediately to a central SIEM or log server, store them on WORM or immutable media, synchronise time with NTP, restrict log-reader and log-clearer privileges, alert on agent silence and log gaps, and protect integrity with hashing or digital signatures. File-integrity monitoring, endpoint detection and network detection round out the control set.

Covering tracks is the anti-forensic phase that follows an attack: disable auditing, clear or edit logs, remove accounts and tools, timestamps and artifacts, and restore changed files. It is the weakest link for an attacker precisely because it creates new, highly suspicious events.

One-line conclusion to use in Part B: logging gives accountability and non-repudiation, but only centralised, time-synchronised, immutable logging survives a attacker who has already gained administrative rights.

Thirty 3-mark answers to know cold

Part A drill

Answer each of these in one sentence of meaning plus one sentence of mechanism, example or consequence. They are the exact shape of the compulsory Part A questions.

  1. CIA — confidentiality, integrity, availability; the three properties every control is judged against.
  2. Elements of InfoSec — CIA plus authenticity, non-repudiation, accountability and access control.
  3. Threat — a potential cause of an unwanted incident with capability and intent.
  4. Vulnerability — a weakness in software, configuration, process or people that an exploit can use.
  5. Risk — likelihood multiplied by impact.
  6. Hacking stages — reconnaissance, scanning, gaining access, maintaining access, covering tracks.
  7. Footprinting — passive and active information gathering to map the attack surface.
  8. Scanning — finding live hosts, ports, services, versions and known vulnerabilities.
  9. Enumeration — extracting users, shares, groups and routes from a confirmed host.
  10. Sniffing — capturing traffic meant for others; passive capture breaks confidentiality.
  11. Spoofing — impersonating an identity or address to redirect or hide traffic.
  12. MITM — secretly relaying or altering communication between two parties.
  13. DoS — exhausting a resource so legitimate users are denied service.
  14. DDoS — the same effect produced by many botnet sources.
  15. Brute force — trying candidate credentials or keys until one succeeds.
  16. Dictionary attack — a wordlist instead of every possible combination.
  17. SQL injection — untrusted input changing a database query.
  18. XSS — attacker script executing in another user's browser.
  19. Buffer overflow — data exceeding a buffer and overwriting adjacent memory.
  20. Privilege escalation — gaining rights beyond those legitimately held.
  21. Social engineering — manipulating people into breaking security procedures.
  22. Phishing — a deceptive message that lures a victim to a fake site or action.
  23. Dumpster diving — recovering sensitive information from discarded material.
  24. Shoulder surfing — observing a screen or keyboard to steal information.
  25. Honeypot — a decoy system used to attract, detect and study attackers.
  26. Firewall — a policy-enforcing barrier between networks.
  27. IDS — detects and alerts on suspicious activity, out of band.
  28. IPS — detects and blocks suspicious activity, inline.
  29. Event logging — a chronological, attributable record of system activity.
  30. Non-repudiation — a party cannot deny an action, proved by signatures and logs.
Timing drill. Give yourself five minutes for any ten of these, in writing. If you cannot produce meaning plus one angle in thirty seconds, that term is a gap worth closing before the exam.

A 48-hour revision plan

Last mile

First day — rebuild the skeletons

  • Rewrite the core-definitions table and the thirty 3-mark drill answers from memory.
  • Draw the five-phase chain, the CIA triad and the recon funnel without looking.
  • Rebuild the ten comparison rows in the table above, two columns at a time.

Second day — timed answers and gaps

  • Write ten Part A answers in fifteen minutes and mark them against the cheat sheet.
  • Write three Part B answers in seventy-five minutes; check that each has definition, mechanism, example, comparison and countermeasures.
