Exam Techniques & Key Facts

How to think about exam questions in this course — what the examiner is really asking, how to match your answer to the marks, and which definitions, tables, and recurring comparisons you should keep ready. Pair this with the Question Bank where the same ideas are worked through as model answers.

01

How questions are set

Read the examiner

Most questions in this course fall into one of a few shapes. Spotting the shape before you write saves time and stops you answering the wrong thing:

  • Define / explain a term — the examiner wants the meaning, in your own words, with one concrete angle (what it protects, what breaks it, how it's done).
  • List the types / phases / categories — ordered, enumerated, with a short note per item so it reads as a list, not a dump.
  • Compare two things — the examiner is checking you know the boundary between them. A two-column table with the same axes for both is the cleanest way to show it.
  • Describe an attack / a process / a system — narrative, step by step, from start to outcome, with the "why" at each step, not just a list of buzzwords.
  • Discuss advantages and limitations — both sides, explicitly. A one-sided "it's great" answer loses marks; the limitation is often where the marks live.
  • "With a neat diagram" — labels matter more than artistic quality. A labelled schematic that shows the flow or layout the question names scores; a pretty but unlabelled one doesn't. See the diagrams built into each module page — they're exactly the shapes examiners expect.
The single most useful reflex: rephrase the question in plain English before you write. "Explain DoS" is really "what is it, how does it work, why does it break availability, what's an example?" If you answer each of those, you've covered the mark scheme.
02

Core definitions to keep ready

Part A material
TermWhat to say (short, precise)
Information securityProtecting information and systems from unauthorised access, use, disclosure, disruption, modification, or destruction — so the CIA goals are met.
CIA triadConfidentiality, Integrity, Availability — the three properties every control is judged against.
ThreatA potential cause of an unwanted incident — a person, event, or thing with the capability and intent (or chance) to harm a system.
VulnerabilityA weakness an attacker can exploit — in software, a config, a process, or a person.
ExploitThe technique or code that takes advantage of a vulnerability.
AttackAn action that harms confidentiality, integrity, or availability.
RiskLikelihood × impact — the chance something bad happens, times how bad it would be.
Penetration testingAn authorised, simulated attack to find real vulnerabilities before an attacker does — scoped, time-boxed, and reported.
FootprintingThe first recon phase — collecting public and passive information about a target to map what's exposed.
SniffingCapturing network traffic to read data meant for others — breaks confidentiality on plaintext channels.
Social engineeringManipulating people into breaking security procedures or giving up information — "human hacking."
HoneypotA decoy system that looks like a real target to attract and study attackers — used for detection, research, and diversion.
MalwareMalicious software (virus, worm, trojan, ransomware, rootkit, bot) — the payload of many attacks.
Non-repudiationA party cannot deny an action they took — achieved with digital signatures and strong audit trails.
When a 3-mark "define" question appears, give the meaning in one sentence, then add one line that shows you know what breaks it or how it's done. That second line is often where the third mark comes from.

04

How to match your answer to the marks

Marks-aware
MarksWhat the examiner expectsWhat to write
3 A tight definition or short list — enough to show you know the term, not a full essay. One sentence of meaning, then one line with an angle (what breaks it, how it's done, one example). Stop when you've said the thing.
5–7 A comparison, a short process, or a "list with notes." Three to five headed points, each with a one-line reason. If it's a compare, use a small table. A worked mini-example helps here.
10–14 A full answer: definition, principle, sub-points, a comparison or diagram if asked, and both advantages and limitations. Lead with the definition, then build structured sub-sections (a/b/c or a table), then close with limits and an example. "With a neat diagram" means a labelled schematic of the shape the question names — draw the one on the module page.
Don't pad. Repeating the same point in different words wastes time and can read as uncertainty. If the question is 3 marks, a 3-mark answer that is accurate beats a 10-mark answer that wanders.
05

Do's and don'ts in the exam

Practical

Do

  • Rephrase the question in plain English before writing.
  • Lead a long answer with a definition or one-line framing.
  • Use a two-column table when a question says "compare" or two things are naturally paired.
  • Give one concrete example or scenario — it usually anchors a mark that a bare list misses.
  • If the question asks for "advantages and limitations," give both, labelled.
  • If it says "with a neat diagram," draw the labelled schematic from the module — labels count.

Don't

  • Pad with buzzwords you can't explain — a misused term reads as guessing.
  • Answer a "compare" as two separate lists with no connecting axis.
  • Stop at the advantages when the question asks for limitations too.
  • Run on past the marks — a 3-mark answer shouldn't be half a page.
  • Leave a "diagram" out because you can't draw well — labels on a schematic are what score, not artistry.
  • Mix up pairs that are frequently swapped (virus/worm, symmetric/asymmetric, IDS/IPS) — those are exactly where a trick question lives.
06

How to use these notes

Study flow

Read a module page top to bottom once to get the shape — the headings are the skeleton, the tables are the comparisons, and the worked examples are the parts that usually earn marks. Then:

  • For definitions: use the core-definitions table on this page (02) as a checklist — can you say each one in one sentence? If not, that's a gap to close before the exam.
  • For comparisons: rehearse the recurring pairs in section 03 from memory — write the table out once, then close the notes and try again.
  • For attacks and processes: narrate them aloud in your own words, step by step, with the "why" at each step. If you can't say what breaks (CIA goal) or how detection works, go back to the module page.
  • For "with a neat diagram": redraw the labelled schematic on the module page — flat-plate collector, solar cell, OTEC loop, tidal basin, wind turbine, fuel cell, machine guard, fire-class wheel, HAZOP flow. Labels matter more than neatness.
  • For full answers: use the question bank on papers.html as practice — try one, then read the model answer and note what it included that you missed.
The goal isn't to memorise this whole site word-for-word. It's to be able to rebuild each module's key tables and a labelled diagram from memory, and to narrate each attack and process in your own words with the CIA property and an example attached.
