01

What Is a Penetration Test?

Authorized attack

A penetration test (pen test) is an authorized, simulated attack on a system to evaluate its security. Testers use the same tools/techniques as attackers to find and demonstrate the business impact of weaknesses.

Types by knowledge of the target

Black-box

No internal knowledge — simulates an external attacker. Most realistic, slowest.

White-box

Full knowledge (source, arch, creds) — deepest coverage, fastest, highest assurance.

Grey-box

Partial knowledge — a balance of realism and efficiency.

Pen test vs vulnerability assessment: a vuln assessment finds and lists weaknesses (often automated); a pen test goes further and exploits them to prove real impact.

Frameworks & Standards

Methodology

OOSSTMM

Open Source Security Testing Methodology Manual — covers Communications, Infrastructure, Applications, Wireless, and the Human (social engineering) channels.

NNIST SP 800-115

Technical Guide to Information Security Testing and Assessment — planning, scanning, exploitation, reporting.

WOWASP

Open Web Application Security Project — focuses on web app risk (the Top 10 below).

Worked mapping — kill chain to OWASP

A pen test walks the same path an attacker would, and each step tends to trip specific OWASP risks:

Test phaseLikely OWASP finding
Recon / scanningA05 Security Misconfiguration (open admin, default creds)
ExploitationA03 Injection (SQLi/XSS), A01 Broken Access Control
Auth testingA07 Auth Failures (weak reset, session fix)
Dependencies checkA06 Vulnerable & Outdated Components
Logging reviewA09 Logging & Monitoring Failures

Real example: scanning /api/user?id=1 and changing the id reveals another user's data → A01 Broken Access Control (IDOR). Fix: server-side ownership checks, not trusting the client parameter.

Phases & Tools

Execution

Typical phases

  1. Planning & scoping (rules of engagement)
  2. Reconnaissance (passive/active)
  3. Scanning & enumeration
  4. Exploitation / gaining access
  5. Post-exploitation (maintain, pivot)
  6. Reporting & remediation

Common tools

  • Nmap — port/ host discovery
  • Metasploit — exploitation framework
  • Burp Suite — web app testing
  • Wireshark — packet analysis

05

Scoping & Rules of Engagement

Before you test

A real engagement is a written contract, not a spontaneous hack. Key clauses:

  • Scope — exact IPs, URLs, apps in (and out of) bounds.
  • Timing — windows when testing is allowed.
  • Test type — black/grey/white box agreed upfront.
  • Out-of-bounds — no DoS, no real PII exfil, no social engineering unless permitted.
  • Reporting — confidential delivery to a named contact.
Pen test vs vulnerability assessment: a vuln scan is automated and lists "you have CVE-X"; a pen test proves "CVE-X lets me reach domain admin," with business impact.
