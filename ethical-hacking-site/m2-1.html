Footprinting, Scanning & Enumeration

The reconnaissance phase of any engagement. Before a single packet is sent against a live target, an attacker (or ethical hacker) maps the organisation's attack surface — quietly gathering what is public, then probing what is exposed, then enumerating what is reachable.

1

Footprinting — Mapping the Attack Surface

Recon
Footprinting is the process of gathering as much information as possible about a target organisation — its infrastructure, employees, technologies and network ranges — to build a profile of its attack surface. It combines passive and active information gathering and is the first step of the classic kill chain / hacking methodology.

Footprinting answers the question "what does this target look like from the outside?" The goal is to discover:

  • Domain names, IP ranges (netblocks) and autonomous systems
  • Publicly reachable hosts, services and open ports
  • Technologies, frameworks and operating systems in use
  • People — names, roles, email formats and social presence
  • Physical locations and third-party providers

The split between passive and active footprinting is the single most important distinction for the exam: passive methods never touch the target directly, so they leave no log trail and are almost impossible to detect; active methods make contact and therefore generate logs and alerts.

2

Passive Footprinting

No contact

Passive reconnaissance collects data from third-party sources — the target is never queried directly, so the activity cannot be traced back to the attacker. It is the safest and quietest phase.

1WHOIS & Registrar Data

Domain and IP whois records reveal registrant details, name servers, creation/expiry dates and the organisation's allocated netblocks. Regional registries (RIRs) expose IP ownership.

2DNS Records

Public DNS (A, AAAA, MX, NS, TXT, CNAME, SOA) shows mail servers, subdomains and sometimes internal host naming conventions. Tools like dig and nslookup query without contacting the target's web server.

3Search Engines

Google site:, filetype: and intitle: operators surface indexed files, directories and error pages. "Google hacking" / dorking finds exposed admin panels and documents.

4Web Archives

The Wayback Machine and cached pages reveal retired subdomains, old technologies and content the organisation thought was deleted — useful for finding forgotten, unpatched assets.

5Social Media & OSINT

LinkedIn, Twitter/X, GitHub and company blogs expose employee names, email patterns, tech stacks and project details that aid phishing and credential attacks later.

6Job Postings

Vacancies disclose internal software (e.g. "experience with Palo Alto, SAP, Windows Server 2019"), giving a precise picture of the technology footprint to research for exploits.

3

Active Footprinting

Direct contact

Active reconnaissance involves direct interaction with the target's systems — sending packets, queries or requests. It is far more detectable: every probe can be logged by firewalls, IDS/IPS and SIEMs. It is used once the passive map is drawn and the attacker wants confirmation.

ADirect Network Probing

Ping sweeps, port scans and banner grabbing are sent straight to the target's IP space. Even "stealth" scans (e.g. SYN half-open scans) are visible to modern monitoring.

BDNS & Host Interaction

Zone transfers (AXFR) against name servers, direct host resolution and traceroutes reveal internal topology and hostnames that passive lookups could not.

CEmail & Social Contact

Directly emailing or calling staff (pretexting) to elicit information is an active, human form of footprinting that bridges into social engineering.

DWeb Probing

Requesting pages, crawling the site and fuzzing parameters interacts with the live web server and application, generating access logs on the target.

4

Scanning

Nmap
Scanning follows footprinting: it takes the discovered IP ranges and hosts and actively probes them to identify live systems, open ports, running services, OS families and software versions. The industry-standard tool is Nmap (Network Mapper).

1Ping / Host Sweep

ICMP echo (and TCP/UDP sweeping) identifies which hosts in a range are alive before deeper probing, shrinking the target list.

2Port Scanning

Determines which TCP/UDP ports are open, closed or filtered. Nmap scan types: -sS SYN (stealth), -sT connect, -sU UDP, -sN/-sF null/fin.

3OS Fingerprinting

Infers the operating system from TCP/IP stack quirks (TTL, window size, flags). Nmap -O uses banner and response-analysis techniques.

4Version Detection

-sV probes open ports to read service banners and exact software versions — the data needed to match a service to a known vulnerability.

Scanning output feeds directly into vulnerability analysis: an open port running an outdated service version is a candidate for exploitation.

5

Enumeration

Extract
Enumeration is the step where the attacker extracts active, identifiable resources from a target — valid usernames, shared resources, network shares, policies and service details — by connecting to services that respond to queries. It is the most "loud" phase and often the most rewarding.

1Usernames & Accounts

Harvesting valid login names via LDAP, SMTP VRFY/RCPT, Kerberos and directory services — the raw material for password attacks.

2SMB / Shares

Server Message Block enumeration lists file shares, sessions and null-session access on Windows networks — a classic path to credentials and data.

3SNMP

Simple Network Management Protocol with default/poor community strings (e.g. public) leaks device configuration, interfaces and topology.

4SMTP

Mail servers reveal valid recipients and relay behaviour through commands like VRFY, EXPN and RCPT TO.

5DNS

Zone transfers expose the full internal host map; even without a transfer, brute-forcing subdomains enumerates hidden assets.

6NFS

Network File System exports can be mounted without authentication if permissions are misconfigured, granting direct file access.

6

Reconnaissance Tooling

Tools

MMaltego

Graphical OSINT tool that maps relationships between people, domains, organisations and infrastructure through transforms.

RRecon-ng

Modular web-recon framework (Python) for automated passive harvesting of hosts, contacts and vulnerabilities from APIs.

TtheHarvester

Collects emails, subdomains, hosts, employee names and virtual hosts from search engines and public sources.

NNmap

The default for host discovery, port scanning, OS and version detection, plus the Nmap Scripting Engine (NSE) for deeper enumeration.

SShodan

A "search engine for the Internet of Things" — indexes banners of internet-connected devices, exposing open services worldwide.

+Others

dig/nslookup (DNS), whois (registration), traceroute (path), and search-engine dorking round out the toolkit.

Scanning & Enumeration

Active recon

Scanning finds what's alive and open; enumeration pulls detail from those services.

ProtocolPortWhat enumeration reveals
SNMP161Device config, interfaces, community strings
SMB445Shares, users, OS version (Windows)
SMTP25Valid usernames via VRFY/RCPT
DNS53Zone transfer (AXFR) of all records
NFS2049Exported filesystems

Minimal Nmap sweep

nmap -sV -sC -oA scan 10.0.0.0/24 — service/version detection + default scripts across a subnet.

A clean methodology: discover hosts → port scan → fingerprint OS/version → enumerate services → note the attack surface.

Defensive Footprinting

From the other side

The same techniques, used by defenders, tell you what an attacker can already see. Before you are targeted, you can footprint your own organisation and close what is exposed:

  • Run your own WHOIS and DNS queries — check what registrar data, name servers and records are publicly visible, and what netblocks you own. Anything you didn't know was exposed is a gap.
  • Search your own domain with the Google operators on this page — site:, filetype:, and inurl: find exposed PDFs, admin panels and documents you intended to keep off public view.
  • Check Shodan / Censys for your own ranges — see which of your hosts and services are indexed and publicly reachable, then decide which should be behind VPN or firewall.
  • Review job posts, press releases and GitHub for accidental tech-stack disclosure, then tighten what recruiters and public repos reveal.
Defender takeaway: attack surface starts with information, not with packets. If your own passive footprint already shows admin panels, version banners or employee names, an attacker has those for free before the first scan. Reduce the public surface first; active monitoring comes after.

Both are legitimate parts of a structured engagement. Passive comes first because it is safe and wide; active comes next because it confirms what the passive map suggests and reveals what passive can't see. An ethical hacker does both, in order, and documents each step — so the client sees the evidence behind every finding.
