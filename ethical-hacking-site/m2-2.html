Deep comparison — virus vs worm (the classic question)

VirusWorm
Needs a host fileYesNo

Worked example — WannaCry (2017): an encrypting worm that used the EternalBlue SMB exploit to spread across networks with no user click, encrypted files, and demanded Bitcoin. It combined worm (self-spread) + ransomware (extort) + exploit (SMB RCE). Patch (MS17-010) + SMB segmentation stopped it — a textbook case of "unpatched + flat network = disaster."

Network Attacks

Layer 3–7

DDoS / DDoS

Overwhelm a target to deny service. Full detail (floods, Smurf, mitigation) on Module 3.

SSession hijacking

Steal a valid session token/cookie to impersonate the user. See M4 (defenses: HTTPS, HttpOnly, regen).

NSniffing

Packet capture on a shared/flat network. Full detail + types on Module 3.

DoS vs DDoS (detail)

DoSDDoS
SourceOne machine / IPMany compromised machines (botnet)

BlockingBlock the single IPHard — IPs are everywhere
Common formsSYN flood, HTTP GET floodVolumetric, amplification (DNS/NTP), app-layer

How it works: the attacker exhausts a resource — bandwidth (flood the pipe), connection table (SYN flood fills the backlog), or CPU (slowloris holds connections open). Mitigation: upstream scrubbing/clean-pipe, rate-limiting, anycast, and blocking amplification by disabling open resolvers. The deeper treatment is on Module 3.

03

How Malware Gets In & Acts

Delivery & payload

Most malware follows: delivery (phish, drive-by, USB) → execution (macro, exploit) → establish (persistence) → action (encrypt, steal, spy) → command & control (call home).

Ransomware kill chain

  1. Entry via phishing or RDP
  2. Disable defenses / spread via SMB
  3. Exfiltrate data (double extortion)
  4. Encrypt files, demand payment

Defending the Endpoint & Network

Controls

Endpoint

  • EDR / next-gen antivirus with behavior analysis
  • Patch management, app allow-listing
  • Restrict macros & admin rights

Network

  • Segmentation + VLANs limit lateral movement
  • DNS filtering blocks C2 call-backs
  • Egress monitoring, offline backups
05

Proxy & Packet Filtering

Network controls

Packet filtering

A firewall function that permits or blocks packets by source/destination IP, port, and protocol (stateless = per-packet rules; stateful = tracks connections). This is the basic "allow/deny" wall between networks.

Proxy server

Intermediary that fetches resources on a client's behalf. It hides the client's real IP, enforces content/URL filtering, and can cache. An application-layer proxy inspects the request content (deeper than packet filters) — the basis of Gen-3 firewalls.

Together they shape what enters and leaves a network: packet filtering at the boundary, proxies for content-level control and anonymity. Covered again under firewall generations in Module 4.
