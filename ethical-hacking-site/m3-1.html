01

Vulnerability Data Resources

Where flaws are tracked
A vulnerability is a weakness that lets an attacker enter and harm a system — a flaw in design or a misconfiguration. To exploit it, the attacker needs a tool or technique that connects to that weakness. The top sources used to trace new vulnerabilities:

1NVD

US-government repository of standards-based vulnerability data using SCAP. Enables automation of vuln management, measurement and compliance; includes checklists, flaws, misconfigurations, product names, impact metrics.

2CVE

International, free dictionary of publicly-known vulnerabilities & exposures. Common identifiers let security products exchange data. Scanning tools use CVEs for classification; SIEMs understand them.

3CERT Notes

CERT Knowledgebase — public Vulnerability Notes Database plus restricted components. Notes include summaries, technical details, remediation, affected vendors.

4VulnDB

Risk-Based Security's commercial feed — 2000+ tracked libraries, RESTful API, email alerting, CVE mapping, VTEM metrics, links to patches/exploits.

5DISA IAVA / STIG

US Defense mapping of CVE IDs to IAVAs; posted on DISA's public STIG site. A must for .gov/.mil work.

6Security Tracker

Third-party DB updated daily; focuses on non-OS flaws (infrastructure & IoT front page most).

7OVAL

Open community standard to assess & report machine state — encode system details, express states, report results; enables interoperable, reproducible metrics.

8National Council of ISACs

Sector-specific Information Sharing & Analysis Centers (MS-ISAC, FS-ISAC, A-ISAC, AUTO-ISAC, ONG-ISAC, NH-ISAC, IT-ISAC) that rapidly share threat alerts between govt and industry.

9Exploit-DB

An archive of exploits for public security — useful for finding weaknesses in your network and staying current on attacks elsewhere (see §02).

02

Exploit Databases & What an Exploit Is

Definitions

DBExploit Database

An archive of exploits for public security — useful for finding weaknesses in your network and staying current on attacks elsewhere. Lets defenders learn attackers' methods.

!Exploit vs Vulnerability

An exploit is a program or piece of code that finds and takes advantage of a flaw — it is not malware itself, but the method used to deliver malware. Defenses: EDR, threat-defense software, pen-testing programs.

KKnown exploits

Once known, the flaw is usually patched and the info goes to security vendors. Public vulns get an ID, description and references.

0Zero-day exploits

Unknown to all but their authors — the most dangerous. The vuln is unknown to the vendor until a hacker is caught exploiting it. Either a patch eventually ships or security software detects/blocks it.

03

Network Sniffing

Listening on the wire

Sniffing monitors and records all packets crossing a network. Admins use it to troubleshoot; attackers use it to capture passwords and account info. A packet sniffer in promiscuous mode gathers all traffic. Can be active (spikes traffic into a switch LAN to monitor) or passive (no interaction; sits on a hub, needs only a LAN account).

Types of network sniffers

MAC sniffers

Sniff data relevant to a MAC-address filter.

Protocol sniffers

Sniff for specific network protocols.

LAN sniffers

Inspect an entire range of internal IP addresses.

IP sniffers

Capture all data for a specific IP filter; logged in human-readable form.

ARP sniffers

Map IP→MAC, enabling packet spoofing / poisoning attacks.

Password sniffers

Harvest credentials from traffic; hits sites without SSL/TLS encryption.

Popular tools: Wireshark, TCPdump, Microsoft Message Analyzer, EtherApe, NetworkMiner. Can capture visited sites, page contents, emails, downloaded files.
04

Man-in-the-Middle (MITM) Attacks

Intercepting traffic

An attacker eavesdrops on (or alters) communication between two legit hosts. Types of MITM:

RRogue Access Point

Attacker sets up an AP with the strongest signal; nearby devices auto-join. All victim traffic is then manipulable — no need to be on a trusted network, just close by.

AARP Spoofing

ARP resolves IP→MAC on a LAN. Attacker answers ARP requests with its own MAC, poisoning both router and workstation caches, sitting silently in the middle. Detect with arp -a (two IPs, same MAC). Prevent with VPN, static ARP, packet filtering.

mmDNS Spoofing

Multicast DNS on a LAN; attacker replies to tv.local-style requests with a fake address it controls; victim caches it as trusted.

DDNS Spoofing

Corrupt DNS cache so the victim sends sensitive data to a malicious host believing it is trusted (e.g. onlinebanking.com). Prevent with DNSSEC, source auth, rate limiting, DNS filtering, monitoring.

05

Denial-of-Service & Remote Attacks

Availability

DDoS vs DDoS

DoS uses a single computer to overwhelm a target. DDoS comes from many distributed sources (e.g. a botnet). Goal: oversaturate capacity so legitimate requests are denied.

FAttack categories

  • Buffer overflow — memory overrun consumes disk/RAM/CPU → crash.
  • Flood attacks — saturate with packets (needs more bandwidth than target).
  • Smurf / Ping flood / Ping of Death — historic ICMP-based attacks.

RRemote attacks

Target a computer/network the attacker is not using. Classified by method: DNS Poisoning, TCP Desynchronization, DoS, ICMP attacks, Port Scanning. Often start with network service scanning for unpatched software; RDP is a common target (credentials left in memory).

MMitigation

  • Network segmentation, firewalls, IDS/IPS.
  • Bandwidth limiting, CDN, anti-malware, regular scans & patching.
  • ISP / scrubbing-center DDoS mitigation.
06

Brute Force & Protocol Attacks

Credential & app layer

BBrute Force types

  • Simple — manual guessing of weak/custom passwords (no software).
  • Dictionary — run words (+symbols/numbers) against a username.
  • Hybrid — dictionary + simple brute force (e.g. SanDiego123).
  • Reverse — start with a known password, hunt matching usernames.
  • Credential stuffing — stolen creds replayed across sites (password reuse).

SAttacking SMTP

Abusing Simple Mail Transfer Protocol lets an attacker send spam/phishing as the victim's domain (reputation damage, blocklisting) and even enable DoS. Enabled by phishing/malware, lost devices, lack of encryption — mitigated with SSL/TLS and user education.

QSQL Server Attacks / SQL Injection

SQLi arises when user input is concatenated into a query without constraint/sanitization. Any user-controlled parameter (GET/POST params, user-agent, cookies, host) may hide a flaw. An attacker crafts SQL to read the DB schema and steal data. (Full SQLi types — In-band Error/Union, Inferential Blind Boolean/Time-based, Out-of-band — are covered on the Module 4 · Web server/SQLi page.) Entry point + exploit are both required.

07

Vulnerability Management Lifecycle

Operational

Finding a CVE is not the end. The lifecycle: discover assets → scan for known issues → prioritize by CVSS score × exposure → remediate (patch/compensate) → verify the fix → report. CVSS ranges: 0.1–3.9 low, 4.0–6.9 medium, 7.0–8.9 high, 9.0–10 critical.

Exploit-DB is read two ways: defenders check whether a public exploit exists for their stack (patch first); attackers use it as a ready toolkit. Either way, "known + unpatched" is the danger zone.

09

DHCP Spoofing & DNS Manipulation

Module 3

A rogue DHCP server on the network hands clients an attacker-chosen gateway and DNS, so the victim's traffic is routed through the attacker (classic MITM). Combined with DNS spoofing, the attacker can map legitimate names (e.g. bank.com) to a fake IP.

Defense

  • DHCP Snooping — switch marks trusted ports; only the real server may answer DHCP.
  • Dynamic ARP Inspection — validates ARP against the DHCP binding table.
  • DNSSEC — cryptographically signed answers foil spoofed records.
  • 802.1X port authentication stops rogue devices joining in the first place.
Attack chain recap: rogue DHCP → bad default gateway/DNS → victim traffic intercepted → DNS hijack to fake sites → credential theft over "HTTP".
