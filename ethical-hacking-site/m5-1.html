Covering Tracks, Logging & Privilege Escalation

Module 5 is the "after access" layer of attacking — and the defender's tools against it: how intruders erase evidence, what event logs record, how files get hidden, and how an attacker moves from a low-privilege foothold to administrator/root.

Covering tracks Event logs Hiding evidence Password cracking Privilege escalation
01

Covering Tracks & Hiding

Anti-forensics

After gaining access, an attacker erases evidence — disables auditing, clears logs, modifies logs/registry, removes created files/folders. This extends the "maintaining access" phase.

Hiding malicious processes

Run under genuine OS process names; Task Manager shows disproportionate resource use. Covert channels tunnel traffic in overlooked protocols (DNS/ICMP) — indicator = large ICMP/DNS volumes, zone transfers.

Why it matters

Anti-forensics slows incident response and lets the attacker keep access. Defenders rely on logging integrity (see §04).

02

Event Logging

What gets recorded

An event log is a file of OS/app/device usage. The six default Windows categories:

CategoryRecords
ApplicationEvents logged by applications/devs
SystemOS and driver events
SecurityLogon, file deletion per audit policy
Directory ServiceDomain controllers only
DNS ServerDNS servers only
File Replication ServiceDomain controllers only

Event Viewer shows date/time, username, computer, source, type. The Security log specifically tracks: Account logon, Account management, Directory service access, Logon, Object access, Policy change, Privilege use, Process tracking, System events.

Defense note: attackers target Windows event logs (anti-forensic, MITRE ATT&CK T1070) to slow response by clearing/tampering with them.
03

Defenses Against Log & Accounting Attacks

Hardening

Activate logging

Turn on auditing so events are actually captured.

Proper permissions

Restrict who can read/modify logs.

Separate logging server

Ship logs off-box (SIEM) so local tampering loses the copy.

Encrypt log files

Prevent casual reading/modification.

Append-only logs

Make deletion/editing impossible without privilege.

Write-once media

Store logs where they cannot be rewritten.

04

Hiding Evidence on Host & Network

Data hiding

A covert channel hides data while it moves. Data-hiding techniques: hidden partitions, file extensions, hidden attribute, bit-shifting, encryption, password protection.

File manipulation

Names/extensions/hidden attribute (e.g. common with FAT systems; place sensitive info on free space).

Disk manipulation

Hidden partitions; mark a good cluster bad using Norton Disk Edit — type B in the FAT entry for that cluster.

Bit-shifting

Old technique: shift bit patterns to alter byte values so files look like binary executable code. Tool: Hex Workshop.

Steganography

"Hidden writing" — insert data into images/text docs (S-Tools, DPEnvelope, jpgx). Very hard to spot without prior knowledge.

Encryption

Password/passphrase protects files; recovery is hard without it. Key escrow lets data be recovered if a passphrase is forgotten or key corrupted.

Cracking encrypted files

Needs expert + powerful computers, or persuading the suspect to reveal the password.

05

System Hacking: Password Cracking

The kill-chain end

System hacking = using technical skills to gain access, exploit vulns, and conceal activity. The system-hacking cycle (6 steps):

#Step
1Enumeration
2Cracking passwords
3Escalating privileges
4Executing applications
5Hiding files
6Covering tracks

Passwords by character class: letters only · numbers only · special only · letters+numbers · letters+special · special+numbers · all three.

Administrator password guessing

  • If NetBIOS TCP/139 is open, the most effective break-in is password guessing.
  • Connect to an enumerated share (IPC$ or C$) and try username/password.
  • Default Admin$, C$, %Systemdrive% shares are a good starting point.
Password sniffing: instead of guessing, sniff credentials off the wire as users log in, then replay them to gain access.

Manual cracking steps

  1. Find a valid user account (Administrator or Guest).
  2. Create a list of possible passwords.
  3. Rank passwords high to low probability.
  4. Key in each password; repeat until success.

Automated: dictionary or brute-force tools.

06

Privilege Escalation

Footprint → root

Gaining elevated rights beyond what's assigned — via a bug, misconfiguration, or weak access control. Five primary methods: Credential exploitation · Vulnerabilities & exploits · Misconfigurations · Malware · Social engineering.

HHorizontal

Access rights of another account with similar privileges ("account takeover"). Lower-level accounts broaden the attacker's sphere — basic lateral movement.

VVertical

Move from low to higher privilege (e.g. via a buffer overflow) to gain admin/root. Also called a privilege-elevation attack.

Attack chain: gain entry → surveil → escalate → clean up (mask source IP, delete logs). Any evidence of presence = an Indicator of Compromise (IoC).
07

Hiding & Anti-Forensics in Practice

Techniques

NTFS Alternate Data Streams

type secret.txt > legit.exe:hidden.txt hides data in a file's stream — invisible in normal dir listings.

Timestomping

Altering file MAC times to match legit files and dodge "recently changed" filters.

Hiding evidence by altering event logs

Attackers target Windows event logs (anti-forensic, MITRE T1070) to slow response — clearing them (wevtutil cl <log>) or editing events to erase their own IOAs. This is the syllabus's "hiding evidence by altering event log."

Rootkits

Kernel/user-mode code that hides processes, files, and network connections from the OS.

Defender counter: collect logs off-box (so local wipe loses the copy), use file-integrity monitoring, and snapshot system state for comparison.
08

Privilege Escalation — Concrete Paths

Linux / Windows

Linux

  • Misconfigured sudo (NOPASSWD on shells)
  • SUID binaries (find / -perm -4000)
  • Writable cron / service files
  • Kernel exploit for unpatched local CVE

Windows

  • Token theft / incognito (Steal-Token)
  • UAC bypass via auto-elevating binaries
  • Weak service perms (unquoted path)
  • DLL hijacking in app directories
Defender view — intrusion timeline: alert → identify IoC → contain (isolate host) → eradicate (remove persistence) → recover (rebuild from trusted image) → review (close the gap).
