1

Footprinting — Mapping the Attack Surface

Recon
Footprinting is the process of gathering as much information as possible about a target organisation — its infrastructure, employees, technologies and network ranges — to build a profile of its attack surface. It combines passive and active information gathering and is the first step of the classic kill chain / hacking methodology.

Footprinting answers the question "what does this target look like from the outside?" The goal is to discover:

  • Domain names, IP ranges (netblocks) and autonomous systems
  • Publicly reachable hosts, services and open ports
  • Technologies, frameworks and operating systems in use
  • People — names, roles, email formats and social presence
  • Physical locations and third-party providers

The split between passive and active footprinting is the single most important distinction for the exam: passive methods never touch the target directly, so they leave no log trail and are almost impossible to detect; active methods make contact and therefore generate logs and alerts.

2

Passive Footprinting

No contact

Passive reconnaissance collects data from third-party sources — the target is never queried directly, so the activity cannot be traced back to the attacker. It is the safest and quietest phase.

1WHOIS & Registrar Data

Domain and IP whois records reveal registrant details, name servers, creation/expiry dates and the organisation's allocated netblocks. Regional registries (RIRs) expose IP ownership.

2DNS Records

Public DNS (A, AAAA, MX, NS, TXT, CNAME, SOA) shows mail servers, subdomains and sometimes internal host naming conventions. Tools like dig and nslookup query without contacting the target's web server.

3Search Engines

Google site:, filetype: and intitle: operators surface indexed files, directories and error pages. "Google hacking" / dorking finds exposed admin panels and documents.

4Web Archives

The Wayback Machine and cached pages reveal retired subdomains, old technologies and content the organisation thought was deleted — useful for finding forgotten, unpatched assets.

5Social Media & OSINT

LinkedIn, Twitter/X, GitHub and company blogs expose employee names, email patterns, tech stacks and project details that aid phishing and credential attacks later.

6Job Postings

Vacancies disclose internal software (e.g. "experience with Palo Alto, SAP, Windows Server 2019"), giving a precise picture of the technology footprint to research for exploits.

3

Active Footprinting

Direct contact

Active reconnaissance involves direct interaction with the target's systems — sending packets, queries or requests. It is far more detectable: every probe can be logged by firewalls, IDS/IPS and SIEMs. It is used once the passive map is drawn and the attacker wants confirmation.

ADirect Network Probing

Ping sweeps, port scans and banner grabbing are sent straight to the target's IP space. Even "stealth" scans (e.g. SYN half-open scans) are visible to modern monitoring.

BDNS & Host Interaction

Zone transfers (AXFR) against name servers, direct host resolution and traceroutes reveal internal topology and hostnames that passive lookups could not.

CEmail & Social Contact

Directly emailing or calling staff (pretexting) to elicit information is an active, human form of footprinting that bridges into social engineering.

DWeb Probing

Requesting pages, crawling the site and fuzzing parameters interacts with the live web server and application, generating access logs on the target.

4

Scanning

Nmap
Scanning follows footprinting: it takes the discovered IP ranges and hosts and actively probes them to identify live systems, open ports, running services, OS families and software versions. The industry-standard tool is Nmap (Network Mapper).

1Ping / Host Sweep

ICMP echo (and TCP/UDP sweeping) identifies which hosts in a range are alive before deeper probing, shrinking the target list.

2Port Scanning

Determines which TCP/UDP ports are open, closed or filtered. Nmap scan types: -sS SYN (stealth), -sT connect, -sU UDP, -sN/-sF null/fin.

3OS Fingerprinting

Infers the operating system from TCP/IP stack quirks (TTL, window size, flags). Nmap -O matches probe responses (TTL, initial window size, TCP option ordering, DF bit) against a database of TCP/IP stack fingerprints. Reading service banners is version detection (-sV), not OS detection.

4Version Detection

-sV probes open ports to read service banners and exact software versions — the data needed to match a service to a known vulnerability.

Scanning output feeds directly into vulnerability analysis: an open port running an outdated service version is a candidate for exploitation.

5

Enumeration

Extract
Enumeration is the step where the attacker extracts active, identifiable resources from a target — valid usernames, shared resources, network shares, policies and service details — by connecting to services that respond to queries. It is the most "loud" phase and often the most rewarding.

1Usernames & Accounts

Harvesting valid login names via LDAP, SMTP VRFY/RCPT, Kerberos and directory services — the raw material for password attacks.

2SMB / Shares

Server Message Block enumeration lists file shares, sessions and null-session access on Windows networks — a classic path to credentials and data.

3SNMP

Simple Network Management Protocol with default/poor community strings (e.g. public) leaks device configuration, interfaces and topology.

4SMTP

Mail servers reveal valid recipients and relay behaviour through commands like VRFY, EXPN and RCPT TO.

5DNS

Zone transfers expose the full internal host map; even without a transfer, brute-forcing subdomains enumerates hidden assets.

6NFS

Network File System exports can be mounted without authentication if permissions are misconfigured, granting direct file access.

Defensive Footprinting

From the other side

The same techniques, used by defenders, tell you what an attacker can already see. Before you are targeted, you can footprint your own organisation and close what is exposed:

  • Run your own WHOIS and DNS queries — check what registrar data, name servers and records are publicly visible, and what netblocks you own. Anything you didn't know was exposed is a gap.
  • Search your own domain with the Google operators on this page — site:, filetype:, and inurl: find exposed PDFs, admin panels and documents you intended to keep off public view.
  • Check Shodan / Censys for your own ranges — see which of your hosts and services are indexed and publicly reachable, then decide which should be behind VPN or firewall.
  • Review job posts, press releases and GitHub for accidental tech-stack disclosure, then tighten what recruiters and public repos reveal.
Defender takeaway: attack surface starts with information, not with packets. If your own passive footprint already shows admin panels, version banners or employee names, an attacker has those for free before the first scan. Reduce the public surface first; active monitoring comes after.

Proxy & Packet Filtering

Network controls

Packet filtering

A firewall function that permits or blocks packets by source/destination IP, port, and protocol (stateless = per-packet rules; stateful = tracks connections). This is the basic "allow/deny" wall between networks.

Proxy server

Intermediary that fetches resources on a client's behalf. It hides the client's real IP, enforces content/URL filtering, and can cache. An application-layer proxy inspects the request content (deeper than packet filters) — the basis of Gen-3 firewalls.

Together they shape what enters and leaves a network: packet filtering at the boundary, proxies for content-level control and anonymity. Covered again under firewall generations in Module 4.

What & Why

Definition

Social engineering = tricking people into breaking security procedures or giving up sensitive info. It works because humans are trusting, helpful, and rushed. The insider threat — a trusted person abusing access — is the most dangerous variant.

The best defense is a "human firewall": trained, skeptical users who verify requests and report suspicious contact.

05

Anatomy of a Phish & the Human Firewall

Dissection

A phishing email has four parts: sender (spoofed/lookalike domain), lure (urgent ask), payload (malicious link/attachment), and goal (creds/C2). Spotting any weak link breaks the chain.

Worked example — a credential phish

  1. Sender: security@micros0ft-support.com — a lookalike domain (zero vs o) impersonating Microsoft.
  2. Lure: "Unusual sign-in detected — secure your account in 10 minutes or it is locked." (authority + urgency).
  3. Payload: a button linking to a cloned login page that sends typed creds to the attacker.
  4. Goal: harvest the password, then reuse it (or the MFA prompt) to enter the real account.

Why the human firewall stops it: the user checks the real sender domain, pauses at the urgency, and verifies via a known bookmark / phone — never the link. MFA (app/TOTP, not SMS) then blunts even a stolen password.

Insider-threat case

A trusted contractor with legit DB access exfiltrates customer records to a personal cloud account over weeks. Controls that catch it: least-privilege access, DLP/ egress monitoring, and off-box logging so the activity is visible even though the person was "authorized."

Building the human firewall: simulated phishing drills, a "verify out-of-band" rule for money/access requests, and a no-blame reporting channel so users flag tries instead of hiding them.
E1

Passive Reconnaissance in Depth

Deep dive · OSINT

Passive reconnaissance is information gathering that never sends a packet to the target. Its power comes from the fact that organisations routinely publish far more than they realise. A domain registration reveals a registrant, a name server, and a date. A certificate reveals every subdomain ever issued a TLS certificate. A job advert reveals the exact firewall and database products in use. A photograph on a social-media profile reveals a badge, a logo, or a building layout. None of this is hacking in the criminal sense; it is open-source intelligence, and it is the safest and often the most productive first step of an engagement.

The first practical step is to inventory the DNS surface. The A record maps a name to an IPv4 address, AAAA to IPv6, MX identifies mail servers, NS identifies authoritative name servers, TXT often contains verification tokens and SPF/DKIM policy, CNAME aliases one name to another, and SOA carries zone metadata. Querying these reveals the structure of the organisation's external presence without contacting its web servers. Certificate transparency logs are a particularly rich source: every publicly issued certificate is recorded, so subdomains that were removed from DNS years ago can still be discovered.

The second step is search-engine discovery. Operators such as site:, filetype:, intitle:, and inurl: turn a search engine into a document index. Searching your own domain for PDFs, spreadsheets, configuration files, and login pages frequently exposes material that was intended for internal use. The third step is the human layer: staff profiles, conference talks, and project repositories reveal names, email formats, technologies, and relationships. Attackers turn this into a target list for phishing; defenders turn it into a list of things to remove.

Active Scanning and Nmap in Depth

Deep dive · probing

Active scanning turns the passive map into a list of live hosts, open ports, services, versions, and operating systems. Nmap is the standard tool because it combines host discovery, port scanning, version detection, OS fingerprinting, and a scripting engine in one framework. Understanding the scan types matters more than memorising command strings, because each type trades speed, stealth, and accuracy differently.

A TCP connect scan completes the full three-way handshake for each port. It works without special privileges and is reliable, but every connection is logged by the target application. A TCP SYN scan, also called a half-open scan, sends only the first SYN and watches for SYN/ACK or RST; because the handshake is never completed, many applications do not record a connection, though firewalls and network sensors still see the packet. A NULL scan sends a packet with no flags, and a FIN scan sends a FIN; RFC-compliant systems respond differently for open and closed ports, so the state can be inferred, though many modern stacks respond identically and make these scans unreliable. A UDP scan probes UDP ports and interprets ICMP port-unreachable replies; it is slow and noisy but essential because many services use UDP.

Version detection sends probes to open ports and reads banners, producing data such as "Apache 2.4.49" that can be matched to known CVEs. OS detection analyses TTL values, initial window sizes, and TCP option ordering to identify the operating system. The Nmap Scripting Engine runs scripts ranging from banner extraction to safe vulnerability checks. A careful tester uses default scripts and version detection (-sV -sC) and saves all output in three formats with -oA so the evidence can be included in a report.

Nmap flagScan typeStealthRequirement / caveat

Worked command, decoded

nmap -sS -sV -sC -O -p 1-65535 --open -oA scan1 10.0.0.0/24

  -sS        SYN scan (half-open, reasonably quiet)
  -sV        probe open ports for service versions
  -sC        run default NSE scripts
  -O         guess operating systems from TCP/IP fingerprints
  -p 1-65535 scan every TCP port, not just the common 1000
  --open     show only hosts/ports that are open
  -oA scan1  save nmap, gnmap and xml output as scan1.*
  10.0.0.0/24 target: 256 addresses, of which ~254 are usable hosts

Attack and defence pair. The attacker uses a fast SYN scan to map the subnet in minutes. The defender sees a single source touching many ports in sequence and alerts on the pattern, enables port-knocking or an allow-list for management ports, and uses a firewall to rate-limit connection attempts. Slow scans can evade simple thresholds, so the defender also correlates with threat intelligence and watches for later stages rather than relying on scan detection alone.

Exam tip: When distinguishing passive from active, remember that even a "stealth" SYN scan is active: it sends packets to the target and can be logged. Stealth is a reduction in logging, not a guarantee of invisibility.
E3

Enumeration in Depth

Deep dive · extraction

Scanning answers "what is open?"; enumeration answers "what can I learn from what is open?" It is the loudest reconnaissance activity because it performs real protocol operations against the target, but it is also the most valuable because it yields names, shares, and configuration details that can be turned into access. The key distinction is between a port being open and a service revealing identities.

SMB enumeration on port 445 can list shares, users, groups, and sessions. A misconfigured null session allows an unauthenticated user to query the same information, which is why null sessions should be disabled. SNMP on UDP 161 is often left with the default community strings public and private; a read-only string is enough to dump interfaces, routing tables, and device inventory. SMTP on port 25 exposes the VRFY, EXPN, and RCPT TO commands, which distinguish valid recipients from invalid ones. LDAP on 389 or 636 can be queried for users, groups, and organisational structure. DNS zone transfers with AXFR reveal the entire internal namespace when a name server is misconfigured, and NFS exports reveal filesystems that can sometimes be mounted without authentication.

Enumeration feeds directly into the next phases. A list of usernames becomes the input for a password-spraying attack. A share full of documents becomes the target of data theft. An old service version becomes a candidate exploit. Because of this, the correct defensive response is not merely to hide banners but to remove the information itself: disable unused protocols, require authentication, restrict queries, and monitor for repeated directory lookups.

E4

Malware: Propagation, Payload, and Analysis

Deep dive · malicious code

Malware is software written with a malicious purpose, and it is classified by how it spreads and what it does. A virus attaches to a legitimate host file and needs that file to be executed; a worm is standalone and propagates across networks by itself; a trojan pretends to be useful software while hiding a malicious function; ransomware encrypts or locks data to extort payment; a rootkit hides the presence of other malware; a backdoor provides secret entry; a logic bomb waits for a date or condition; spyware and keyloggers collect information silently; and a botnet is a collection of infected machines controlled from a command-and-control server. A single sample can belong to several categories, as WannaCry demonstrated by being both a worm and ransomware.

The usual infection sequence is delivery through email, a drive-by download, or removable media; execution through a macro, an exploit, or a user double-click; establishment by writing to startup locations or a scheduled task; action such as encryption or theft; and command and control by contacting the attacker's infrastructure. Each stage creates an opportunity for defence. Email filtering and attachment sandboxing attack delivery. Disabling macros and patching the browser attack execution. Allow-listing and endpoint detection attack establishment. Backups reduce the value of encryption, and DNS filtering blocks command-and-control domains.

Analysts study malware in two ways. Static analysis examines the file without running it: hashes, strings, imported functions, headers, and packer signatures. Dynamic analysis runs the sample in an isolated sandbox and observes file, registry, process, and network activity. Static analysis is safe but can be defeated by packing and obfuscation; dynamic analysis shows real behaviour but the malware may detect the sandbox and stay dormant. In practice the two are combined, and the output is a set of indicators of compromise — hashes, domains, IP addresses, and behaviour patterns — that can be searched across the estate.

Case study — WannaCry, 2017. The worm exploited a Windows SMB vulnerability known as EternalBlue, for which a patch had been available two months earlier. Because it spread without user interaction, it swept through unpatched networks and encrypted files, demanding Bitcoin. Organisations that had applied the patch, blocked SMB between network segments, or disabled SMBv1 were largely unaffected. The lesson for an exam answer is that a famous malware incident is usually a failure of basic hygiene, not of advanced defence.

Attack and defence pair. An attacker sends a macro-enabled spreadsheet that downloads a trojan. The defender blocks macros from the internet, detonates attachments in a sandbox, applies application allow-listing, and monitors for the beacon. If the trojan still executes, endpoint detection isolates the host and the analyst hunts for the same hash elsewhere. Each layer is independent of the email filter.

Exam tip: A virus needs a host and a user action; a worm does not. State that first in any comparison question, then add propagation, detection, and one named example for each.
E5

Denial of Service in Depth

Deep dive · availability

Denial-of-service attacks try to make a service unavailable to legitimate users by exhausting a finite resource. The resource might be network bandwidth, the connection-tracking table of a firewall, the worker threads of a web server, the memory of a database, or simply the operator's attention. A DoS attack originates from one source; a distributed denial of service (DDoS) uses many compromised machines, which makes blocking by source address ineffective and increases the available volume dramatically.

Attacks are commonly grouped into three classes. Volumetric attacks saturate the link with sheer traffic, often using amplification: a small query to an open DNS or NTP resolver produces a much larger reply directed at the victim. Protocol attacks abuse the state machines of network protocols; a SYN flood fills the half-open connection table so legitimate handshakes cannot complete, and a Smurf attack spoofs a broadcast ping so that many hosts reply to the victim. Application-layer attacks send seemingly valid but expensive requests, such as slow headers (Slowloris), which exhausts the server's concurrent-connection and worker-thread pool, or complex searches, which exhaust CPU and database capacity — both using very little bandwidth.

Defence requires capacity and filtering at several points. An anycast content-delivery network spreads traffic across many locations, so a flood is absorbed rather than concentrated. Upstream scrubbing filters malicious traffic before it reaches the customer link. Rate limiting, connection thresholds, SYN cookies, and per-client quotas protect state and application resources. Operationally, an incident plan identifies who contacts the provider and who declares an incident; during an attack is the worst time to discover the phone number.

ClassExampleResource targetedMitigation
VolumetricDNS amplification, UDP floodLink bandwidthAnycast CDN, upstream scrubbing, disable open resolvers
ProtocolSYN flood, SmurfConnection stateSYN cookies, firewall thresholds, disable directed broadcasts
Application layerSlowloris, expensive queriesCPU, threads, databaseReverse proxy, request timeouts, rate limits, caching

Worked example. An attacker sends spoofed DNS queries to open resolvers with the source address set to a game server. Each resolver replies with a large record, so a 60-byte request becomes a 3,000-byte flood at the victim. The site's own firewall cannot help because the link is already full. The fix is upstream: the provider filters the traffic, the resolvers are closed to recursion from the internet, and the game site moves behind a CDN. The exam lesson is that volumetric attacks must be stopped before the bottleneck.

Exam tip: Always distinguish DoS from DDoS by the number of sources, and always pair the attack class with the resource it exhausts. That earns the analysis marks rather than just the definition mark.
E6

Sniffing and Session Hijacking in Depth

Deep dive · interception

A network interface normally accepts frames addressed to it and drops the rest. In promiscuous mode it passes everything to the operating system, allowing a packet sniffer to capture traffic destined for other hosts. On a hub this is trivial because every host sees every frame; on a switched network the attacker must first use ARP spoofing, a rogue access point, or a span port to see traffic that is not theirs. Tools such as Wireshark and tcpdump decode the captured frames into readable protocols.

Active sniffing changes the network so that traffic flows through the attacker, as with ARP poisoning where the attacker announces that the gateway's IP maps to its own MAC address. Passive sniffing only listens, for example on a hub or a wireless network in monitor mode, and is much harder to detect. The distinction mirrors passive versus active reconnaissance. Sniffing is not automatically malicious — administrators use it to diagnose problems — but capturing credentials or personal data without authorisation is an attack.

Session hijacking builds on interception. After a user logs in, the server issues a session token, usually stored in a cookie. An attacker who steals or predicts that token can replay it and impersonate the user without knowing the password. Tokens can be captured on plaintext connections, read by cross-site scripting, predicted if they are sequential, or taken over through a man-in-the-middle proxy. Defences are layered: HTTPS protects the token in transit, the HttpOnly flag stops JavaScript from reading it, the Secure flag stops it being sent over HTTP, long random values stop prediction, and regenerating the identifier at login and privilege change makes a stolen pre-login token worthless.

Exam tip: Encryption is the generic answer to sniffing, but a full answer names the state: TLS for data in transit, plus switched networking and ARP inspection to prevent the attacker from being in the path at all.
E7

Packet Filtering and Proxying in Depth

Deep dive · traffic control

A packet filter makes allow or deny decisions by examining packet headers: source address, destination address, protocol, source port, and destination port. A stateless filter treats each packet in isolation, which is fast but cannot tell whether a packet belongs to an established connection. A stateful filter maintains a state table of active connections and allows return traffic only for connections that were initiated from the trusted side. Stateful inspection is the basis of the traditional firewall and is safer than a simple access-control list.

A proxy works at a higher level. Instead of the client talking directly to the destination, the client talks to the proxy, which makes the request on its behalf. Because the proxy terminates the connection, it can inspect the content of the request, enforce URL policies, cache responses, and hide the client's real address. A forward proxy protects clients leaving a network; a reverse proxy protects servers by sitting in front of them and absorbing or filtering requests; a circuit-level proxy operates at the session layer and is useful for validating connections. The cost is performance and the need to configure clients or applications to use the proxy.

Firewall rules should follow implicit deny: everything is blocked unless explicitly permitted, and the last rule is a log-and-deny catch-all. Rules are ordered, so the most specific permits go first and broad denies go last. A rule that permits HTTP from anywhere to a web server in the DMZ, denies all traffic from the DMZ to the internal LAN, and permits established return traffic is a common and safe pattern. Reviewing rules regularly removes stale entries that quietly widen the attack surface.

ControlLayerSees content?StrengthWeakness

A small ruleset, read top to bottom

10 PERMIT  tcp  any         ->  web-dmz   80,443   # public web
20 PERMIT  tcp  web-dmz     ->  db-lan    1433     # app to DB only
30 DENY    any  web-dmz     ->  internal-lan  any # no DMZ to LAN
40 PERMIT  any  internal-lan -> any        80,443   # staff browsing
50 DENY    log any          ->  any        any      # implicit deny

Rule 30 is placed before rule 40 conceptually because it concerns a different source zone; the ordering within a group matters, and a broad rule placed too early silently makes later denies unreachable. This is why firewall reviews start at the top.

Exam tip: If asked to compare a packet-filtering firewall with a proxy firewall, use three axes: the layer inspected, whether connection state is tracked, and whether content can be filtered. Conclude that a next-generation firewall combines stateful inspection with application awareness.
E8

Social Engineering: Techniques and Psychology

Deep dive · human layer

Social engineering is the manipulation of people into performing actions or revealing information that compromises security. It succeeds because the attacker does not need to defeat encryption or exploit a memory bug; they only need a tired, helpful, or frightened person to make one mistake. The channel may be email, telephone, SMS, a face-to-face conversation, or a physical action such as following someone through a door.

Techniques are distinguished by channel and pretext. Phishing is a broad email lure; spear phishing is personalised to one person; whaling targets senior executives; vishing uses a phone call; smishing uses SMS; pretexting invents a scenario to justify the request; quid pro quo offers a service in exchange for information; baiting leaves an attractive item such as an infected USB drive; tailgating follows an authorised person through a door; shoulder surfing watches a screen or keyboard; and dumpster diving recovers discarded documents or media. The techniques overlap, and a single campaign often combines several.

What makes them work is a small set of psychological levers. Authority makes people obey someone who claims to be from IT or management. Urgency destroys careful thinking by imposing a deadline. Fear pushes a user to act before verifying. Familiarity and liking lower suspicion when the sender appears to be a colleague or a known brand. Scarcity and reward trigger impulse. Helpfulness is the lever that attackers most often abuse in pretexting: most employees want to be useful and will answer a plausible question. Recognising the lever is the first step in resisting the attack.

Worked insider case. A contractor with legitimate database access copies customer records to personal cloud storage over several weeks. The activity looks like normal work because the account is authorised. Controls that reveal it are least privilege, data-loss prevention, egress monitoring, and logs stored outside the contractor's reach. The case shows why "trusted insider" is a threat category and why authorisation alone is not the same as trustworthiness.

Exam tip: For "why does social engineering work?", do not write only "because people are stupid." Write that attackers exploit predictable human tendencies — authority, urgency, trust, helpfulness — and that the corresponding defence is a verification culture plus technical controls that make a stolen secret insufficient.
E9

Building the Human Firewall

Deep dive · defence

The human firewall is the idea that trained, alert staff are a security control as real as a firewall appliance. It rests on three pillars: awareness, so staff recognise common lures; procedure, so they know exactly how to verify a suspicious request; and reporting, so a mistake becomes an alert rather than a secret. A programme that only delivers an annual slideshow fails all three.

Effective awareness is short, frequent, and relevant to the recipient's job. Finance staff need practice with invoice fraud and payment changes; engineers need practice with repository credentials and dependency confusion; everyone needs practice with credential phishing. Simulated phishing campaigns measure click and report rates, but the useful metric is the reporting rate, not the click rate: a culture that punishes clicks teaches staff to hide them, which is worse. The rule should be "verify out of band" — confirm any request involving money, credentials, or access by a separate channel using contact details you already hold, never those supplied in the message.

Technical controls reduce the consequence of a human error. Multi-factor authentication using an app or a hardware key means a stolen password is not enough. Email authentication with SPF, DKIM, and DMARC makes forged sender domains harder to deliver. DMARC monitoring also tells the organisation which legitimate services are sending mail on its behalf. Link scanning and attachment sandboxing stop many payloads before a human ever sees them. Privileged-access controls limit what a compromised account can reach. Together these turn a single mistaken click into a contained event.

Exam tip: When asked for defences against social engineering, give at least one technical control and one procedural or people control, and explain that they are complementary. An answer containing only "train users" loses marks because training is not guaranteed to succeed.
E10

Attack and Defence Pairs

Consolidation

Pair 1 — Scanning. Attack: an Nmap sweep maps every live host and version. Defence: ingress filtering, port allow-lists, rate limits, and alerts on one source touching many ports. Pair 2 — Enumeration. Attack: SNMP with the default community string dumps the network inventory. Defence: SNMPv3 with authentication and encryption, and monitoring of management-protocol access. Pair 3 — Malware. Attack: a macro downloads a trojan. Defence: block internet macros, sandbox attachments, allow-list executables, and isolate on detection. Pair 4 — Denial of service. Attack: an amplified flood saturates the link. Defence: anycast, scrubbing, and disabling open resolvers. Pair 5 — Social engineering. Attack: a targeted email requests a password reset. Defence: MFA, out-of-band verification, and a no-blame reporting channel.

The pattern in every pair is the same: reduce the chance of success, reduce the payoff if it succeeds, and increase the chance of detection. A control that only does one of these is weaker than a set that does all three. When you design a defence, ask which of the three it addresses and what covers the other two.

Exam tip: A table of paired attacks and defences is an efficient way to answer a broad "discuss threats and countermeasures" question. Include the mechanism in each row; naming the control without saying what it does earns only half marks.
E11

What to Write for 3 Marks and for 14 Marks

Exam technique

Three-mark questions

Give three precise statements. For "three differences between passive and active footprinting", write: passive makes no contact and leaves no logs; active sends packets and can be detected; passive comes first to map the surface while active confirms and fills gaps. Each statement is a mark, so avoid combining them into one vague sentence.

Fourteen-mark questions

Structure your answer as a mini report. Define the terms in the first paragraph, use a table for the taxonomy, add a worked tool command or scenario, discuss detection and defences, and conclude with the trade-off between thoroughness and risk of detection. For example, a question on reconnaissance can cover passive sources, active probing, scanning, enumeration, tool categories, the passive-versus-active comparison, defensive use of the same techniques, and an evaluation of which phase is most valuable.

Module glossary

Footprinting — building a profile of the target's attack surface. OSINT — intelligence from publicly available sources. Scanning — actively finding live hosts, ports, and services. Enumeration — extracting identities and resources from services. Promiscuous mode — a network interface accepting all frames. Botnet — many infected machines under remote control. Amplification — a small request generating a large response to a victim. Pretext — a fabricated scenario used to justify a request. Human firewall — staff trained and empowered to verify and report.

Exam tip: The single most repeated distinction in this module is passive versus active. Learn it in three forms — definition, examples, and consequences for detection — so you can answer whichever way the question is phrased.
