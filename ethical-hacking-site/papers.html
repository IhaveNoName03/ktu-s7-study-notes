How to Answer by Marks

Method
  • 3-mark — Define + 2–3 key points (one tight paragraph or 3 bullets). ~40–60 words.
  • 14/15-mark — Full structure: Definition → Working/Mechanism → Types (with table) → Example → Defenses → Diagram note. ~250–400 words.

For a high-mark attack question, the examiner wants how it works, the techniques, real examples, and how to defend — not just a definition.

KTU — Model Question Paper (CCT 401)

Official model from the syllabus · Part A = 3 marks each · Part B = 14 marks each

Part A — Answer all (10 × 3 = 30 marks)

1
What are the different stages involved in hacking? [3] Kill chain
→ M1-2 (Hacker Landscape)
AnswerFive stages: (1) Reconnaissance — gather target info; (2) Scanning & Enumeration — find hosts, ports, services, users; (3) Gaining access — exploit a vuln to get in; (4) Maintaining access — plant backdoor/persistence; (5) Clearing logs — cover tracks. Some lists add privilege escalation between 3 and 4.
2
Define the basic elements of information security. [3] CIA
→ M1-1 (Elements of InfoSec)
AnswerCIA triad: Confidentiality — only authorized parties see the data; Integrity — data is unaltered by unauthorized parties; Availability — authorized users can access it when needed. Extended by AAA: Authentication, Authorization, Accounting.
3
What is foot printing? How is it done? [3] Footprinting
→ M2-1 (Footprinting/Scanning)
AnswerFootprinting = passive + active info gathering to map the target's attack surface. Passive (no packet touches target): WHOIS, DNS, OSINT, archives. Active (touches target): ping sweeps, port scans, banner grabbing, zone transfers.
4
How is Distributed DoS different from DoS? [3] DoS/DDoS
→ M3-1 (DoM/DDoS)
AnswerDoS floods one target from a single source to exhaust resources. DDoS uses many compromised machines (a botnet) at once — far harder to block by IP and much higher volume.
5
Explain network sniffing. [3] Sniffing
→ M3-1 (Network Sniffing)
AnswerSniffing = capturing packets on a network. On a hub or via ARP spoofing (NIC in promiscuous mode) an attacker reads others' traffic — especially plaintext protocols (Telnet, FTP) — to steal credentials. Defense: switched networks, encryption.
6
How is Brute-force attack performed? [3] Brute force
→ M3-1 (Brute Force)
AnswerAn attacker tries many candidate credentials/keys until one works: exhaustive (all combos), dictionary (wordlist), hybrid, credential stuffing, rainbow tables. Defense: lockout, rate-limiting, 2FA, strong passwords.
7
What is SQL injection? How can you find whether the website is affected by SQL injection? [3] SQLi
→ M4-1 (SQL Injection)
AnswerSQLi inserts malicious SQL into an input to manipulate the backend DB. Test with a single quote ' or ' OR '1'='1 in a parameter — a DB error or a changed page (boolean/UNION) shows the input is executed. Fix: parameterized queries.
8
What is cross-site scripting and what are its different variations? [3] XSS
→ M4-1 (XSS)
AnswerXSS runs malicious script in a victim's browser. Stored (payload saved on server, hits every viewer); Reflected (payload in request/URL reflected back); DOM-based (client-side DOM change). Defense: output encoding, CSP, HttpOnly cookies.
9
List out the challenges in password cracking. [3] Password cracking
→ M5-1 (Password Cracking)
AnswerChallenges: large keyspace on strong/long passwords; salting + slow hashes (bcrypt/Argon2); account lockout/rate-limiting blocks online tries; 2FA defeats a stolen password; hard-to-obtain offline hashes.
10
Define Event logging. [3] Event logging
→ M5-1 (Event Logging)
AnswerEvent logging records OS/app/device activity (logons, file access, errors) for auditing and forensics. Windows has six default categories: Application, System, Security, Directory Service, DNS Server, File Replication Service.

12
Role of a penetration tester (8) & how vulnerability assessment is done (6). [14] M1
→ M1-2 · → M1-3
Answer

Role of a penetration tester (8): an authorized security professional who thinks like an attacker to find weaknesses, prove business impact, and recommend fixes — without damaging systems. Bound by a rules of engagement contract (scope, timing, methods, what not to do). Works through the kill chain (recon → scan → exploit → maintain → report), documents evidence, and hands over a remediation plan. Distinct from malicious hackers: permission + ethics + reporting.

Vulnerability assessment (6):

  • Define scope and assets.
  • Run authenticated/unauthenticated scanners (Nessus, OpenVAS).
  • Discover known vulns/CVEs, misconfigurations, weak policies.
  • Rank by severity (CVSS) and exploitability.
  • Produce a remediation report with owners + deadlines.
  • Re-scan to confirm fixes (closure).

Note: a vulnerability assessment finds and lists weaknesses; a penetration test goes further and exploits to prove impact.

13
Dumpster diving social engineering attack (8) & results of foot printing tools (6). [14] M2
→ M2-3 (Social Eng.) · → M2-1
Answer

Dumpster diving (8): retrieving discarded paper/bin to harvest sensitive data — passwords on sticky notes, org charts, network diagrams, letterheads (for spoofing), source code, calendars. It is low-tech but effective because people throw away confidential material. Defense: shredders, no sensitive printouts, clean-desk policy, secure bins.

Results of footprinting tools (6): the attacker builds an attack-surface map —

  • IP ranges, live hosts, domains, subdomains.
  • OS, open ports, running services, versions (banner grabbing).
  • Usernames, emails, employee names (for phishing/targeting).
  • Tech stack and technologies in use (for known exploits).
  • Physical/logical layout clues from job posts and OSINT.

This intelligence drives scanning and the actual attack.

14
Social enumeration (6) & working of network sniffers (8). [14] M2/M3
→ M2-1 (Enumeration) · → M3-1 (Sniffing)
Answer

Social enumeration (6): extracting detailed info from people/services — usernames via SMTP VRFY/RCPT, shares via SMB null sessions, config via SNMP (default public community), DNS zone transfers (AXFR), LDAP queries. Gives the exact accounts/services to target.

Working of network sniffers (8): a sniffer (Wireshark, tcpdump) captures packets on the wire. Normally a switched network delivers frames only to the destination MAC, but the attacker:

  • puts the NIC in promiscuous mode, and/or
  • performs ARP spoofing to become the MITM, so victim traffic is mirrored to them.

They then filter for plaintext protocols (Telnet, FTP, POP3, HTTP) and recover credentials/session data. Types: software vs hardware tap; passive (observe) vs active (inject); filtered vs unfiltered capture. Defense: switched networks, encryption (SSH/TLS/VPN), static ARP, port security.

16
DHCP Spoofing (6) & how SQL Servers are attacked (8). [14] M3/M4
→ M3-1 (DHCP Spoof) · → M4-1 (SQLi)
Answer

DHCP spoofing (6): a rogue DHCP server on the LAN answers client requests first, handing out an attacker-controlled gateway/DNS. The client then routes all traffic through the attacker → MITM (capture, redirect, DNS poison). Defense: DHCP snooping (trust only the real server port), Dynamic ARP Inspection, 802.1X, VLAN segmentation.

Attacking SQL Servers (8):

  • SQL injection via web/app input → read/dump tables, bypass auth, run xp_cmdshell.
  • Weak SA password / default creds brute-forced.
  • Unpatched instances (known CVEs).
  • Sniffed credentials on plaintext connections.
  • Misconfig: public-facing DB, over-privileged service accounts.

Impact: data theft, data deletion, OS-level compromise via the DB engine. Fix: parameterized queries, least-privilege, patching, TLS, network isolation.

18
Bluetooth vs Mobile Phone Hacking (6) & Incident Handling & Response (8). [14] M4
→ M4-1 (Bluetooth / Mobile / IR)
Answer

Bluetooth vs Mobile (6): Bluetooth attacks are short-range radio tricks — Bluesnarfing (steal data), Bluejacking (spam), Bluebugging (take control in discoverable mode), Bluesmacking (DoS). Mobile hacking is harder: sandboxed OS, app signing, few open ports, cellular isolation. Mobile risks are mostly app/phishing/ credential, not raw exploitation.

Incident response — 7 steps (8):

  1. Early detection — SIEM/alert.
  2. Analysis — IoC, triage, scope.
  3. Prioritization — by severity/business.
  4. Notification — internal + external/regulators.
  5. Containment & forensics — isolate, preserve evidence.
  6. Recovery — eradicate, rebuild, restore, patch.
  7. Review — lessons learned, close gaps.

Owned by the CSIRT.

19
Hide evidence by altering event logs (6) & defenses against log/accounting attacks (8). [14] M5
→ M5-1 (Logging / Defenses)
Answer

Hiding/alter evidence (6): attackers target Windows event logs (anti-forensics, MITRE T1070) to slow response — clearing them (wevtutil cl <log>), editing events to erase their own IOAs, or using rootkits/timestomping to hide files and activity. NTFS Alternate Data Streams hide data; covert channels hide network trails.

Defenses against log/accounting attacks (8):

  • Enable auditing everywhere; set the right audit policy.
  • Set tight file permissions on log files.
  • Ship logs to a separate, hardened logging server (so local wipe loses nothing).
  • Encrypt logs; make them append-only / write-once.
  • Use file-integrity monitoring + log-tamper alerts.
  • Sync time (NTP) so timelines are trustworthy.
  • Snapshot system state for comparison.
20
Password cracking for system hacking + one tool (8) & evidence hidden on network (6). [14] M5
→ M5-1 (Cracking / PrivEsc / Hiding)
Answer

Password cracking in system hacking (8): the kill chain within system hacking is enumerate → crack → escalate → execute → hide → cover. Offline: steal the SAM//etc/shadow hash and crack with dictionary/brute force or rainbow tables. Online: guess/replay credentials, sniff auth. Tool: John the Ripper (or Hashcat) — offline hash cracker; Cain & Abel for Windows sniffing/replay.

Evidence hidden on network (6):

  • Covert channels — tunnel data in DNS/ICMP (hard to spot; indicator = odd volume).
  • Encryption — traffic unreadable without keys.
  • Steganography — hide data in images/files.
  • Blend with normal traffic; use non-standard ports.

Defense: DPI, DNS/ICMP volume monitoring, TLS inspection, egress filtering.

4
What is session hijacking? List techniques and defenses. Explain Bluetooth hacking and its types. [15] Session · Bluetooth
→ Module 4 (Session hijacking, Bluetooth)
Answer

Session hijacking: stealing a valid session token/cookie to impersonate a logged-in user (no password). Techniques: sniffing (plaintext), predictable/session ID guessing, MITM, XSS cookie theft. Defenses: HTTPS everywhere, HttpOnly + Secure flags, short idle/absolute timeouts, regenerate session ID on login/privilege change, bind to IP/user-agent, HSTS.

Bluetooth hacking types: Bluesnarfing (steal data — contacts/SMS), Bluejacking (unsolicited messages), Bluebugging (take calls/SMS/control in discoverable mode), Bluesmacking (L2CAP DoS). Prevention: keep non-discoverable, off when unused, reject unknown pairing, update firmware, unpair after use, 2FA, VPN.

5
Explain why mobile phone hacking is cumbersome. List preventive measures for mobile hacking. [15] Mobile
→ Module 4 (Mobile phone hacking)
Answer

Why cumbersome: sandboxed OS (apps isolated), app signing/store review, permission model, few open ports, cellular isolation (no shared broadcast like Wi-Fi), encryption by default, secure boot. This raises the bar versus a PC.

Preventive measures: keep OS/apps updated; avoid unknown/side-loaded apps; permission hygiene; cautious rooting/jailbreaking; strong passcode + password manager; 2FA (avoid SMS/email 2FA — SIM swap); no public Wi-Fi without VPN; lost-device tracking/wipe; clear history; review account activity for signs (fast battery drain, slowness, odd calls).

6
Write short notes on: (a) Exploit writing (b) Reverse engineering. [15] Exploit · RE
→ Module 4 (Exploit writing, Reverse engineering)
Answer

(a) Exploit writing: crafting code that leverages a vulnerability for unauthorized access. Steps: (1) identify the vuln; (2) attach a debugger; (3) try to overwrite the return address; (4) automate with Perl/Python; (5) find a DLL address to inject shellcode. Goal: arbitrary code execution / privilege gain. Defenses: bounds checking, safe functions, ASLR, DEP, stack canaries.

(b) Reverse engineering: analyzing software/hardware to understand its design and function — for vuln discovery, malware analysis, interop. Stages (security view): (1) information gathering, (2) disassembly/decompilation, (3) static + dynamic analysis, (4) documentation. Tools: debuggers (IDA Pro, OllyDbg, gdb, Immunity, WinDbg), disassemblers (IDA, radare2), decompilers, fault-injection tools.

7
Explain brute force attack and its types. Describe the steps of incident response. [15] Brute force · IR
→ M3 (Brute force) · → M4 (Incident response)
Answer

Brute force: trying many credentials/keys until correct. Types: exhaustive (all combos), dictionary (wordlist), hybrid (dict + mutations), credential stuffing (reused creds), rainbow tables (precomputed hashes). Defense: lockout, rate-limiting, 2FA, CAPTCHA, strong unique passwords, slow hashes.

Incident response — 7 steps: (1) Early detection (SIEM), (2) Analysis (IoC/triage), (3) Prioritization, (4) Notification (internal + external), (5) Containment & forensics, (6) Recovery (eradicate, rebuild, restore, patch), (7) Review. Owned by the CSIRT.

8
List the six default event-log categories in Windows. Explain defenses against log & accounting-file attacks. [15] Event logs
→ Module 5 (Event logging, Defenses)
Answer

Six default categories: (1) Application, (2) System, (3) Security, (4) Directory Service (domain controllers), (5) DNS Server (DNS servers), (6) File Replication Service (DCs). The Security log records logon, object access and policy change per the audit policy.

Defenses against log/accounting attacks: enable auditing + correct policy; set file permissions; send logs to a separate, hardened logging server (local wipe loses nothing); encrypt logs and make them append-only/write-once; file-integrity monitoring + tamper alerts; NTP time sync; snapshot state for comparison. This defeats wevtutil cl / log editing / rootkit hiding.

9
Explain different methods to hide files (on host/network). How do attackers examine encrypted files? [15] Hiding files
→ Module 5 (Hiding evidence, Encrypted files)
Answer

On host: hidden attribute, NTFS Alternate Data Streams (type secret.txt > file.exe:hidden.txt), rename to mimic system files, archive/encrypt, rootkits (hide processes/files), timestomping (fake MAC times).

On network: covert channels (tunnel in DNS/ICMP), steganography, encryption, blend with normal traffic.

Encrypted files: without the key they are unreadable; examine via decryption (key escrow/recovery), or password cracking (needs expert + compute and is slow), else only metadata (name, size, timestamps) is visible. Strong crypto (AES) is effectively unbreakable by brute force — so responders rely on key recovery, not decryption.

Explain network sniffing and the types of network sniffers. How does a man-in-the-middle attack work? List MITM types. [15] Sniffing · MITM
→ Module 3 (Sniffing, MITM)
Answer

Sniffing: capturing packets on a network (Wireshark, tcpdump). Sniffer types: software vs hardware tap; passive (observe) vs active (inject/ARP-spoof); filtered vs unfiltered; wired vs wireless (monitor mode).

MITM working: the attacker positions themselves between two parties (relay/alters comms). Classic method: ARP spoofing — send fake ARP replies so both victim and gateway think the attacker is the other, mirroring all traffic through the attacker. They can read (sniff), alter (inject), or drop packets.

MITM types: ARP spoofing, DNS spoofing/poisoning, SSL stripping, session hijacking, evil-twin/rogue AP, email MITM. Defense: HTTPS/HSTS, static ARP/DAI, cert pinning, VPN, 802.1X.

Explain email hacking and its techniques (phishing, spoofing, MITM, session hijacking, brute force). [15] Email hacking
→ Module 4 (Email hacking)
Answer

Email hacking: unauthorized access/manipulation of email. Techniques:

  • Phishing — fake login page steals creds.
  • Spoofing — forged sender (SPF/DKIM/DMARC gap) for fraud.
  • MITM — intercept mail flow (no TLS).
  • Session hijacking — stolen webmail cookie.
  • Brute force — guess password; credential stuffing.
  • Malware — keylogger / mail rule redirect.

Defense: enforce TLS, SPF+DKM+DMARC, 2FA, phishing training, alert on forwarding rules, monitor login anomalies.

7
What is covering tracks? Explain how attackers hide malicious processes and use covert channels. [15] Covering tracks
→ Module 5 (Covering tracks)
Answer

Covering tracks (anti-forensics): after access, disable auditing, clear/modify logs, delete created files, timestomp, so responders can't see what happened.

Hiding malicious processes: run under names of genuine OS processes (svchost.exe, lsass.exe) — looks normal in Task Manager but shows odd CPU/parent; use rootkits to hide from the process list entirely; load as a service/DLL.

Covert channels: tunnel data in overlooked protocols — DNS (lookup exfil), ICMP (ping payloads) — to bypass firewalls/data-loss controls. Indicator: unusual DNS/ICMP volume or encoded queries. Defense: DPI, egress filtering, DNS/ICMP monitoring.

8
Describe the system-hacking cycle. Explain manual password cracking steps and administrator password guessing. [15] System hacking · Passwords
→ Module 5 (System hacking, Password cracking)
Answer

System-hacking cycle (6 steps): (1) Enumeration, (2) Cracking passwords, (3) Escalating privileges, (4) Executing applications, (5) Hiding files, (6) Covering tracks.

Manual password cracking steps: (1) find a valid user (Administrator/Guest); (2) make a list of likely passwords (default, dictionary, guessed); (3) try high-priority first; (4) repeat; (5) if cracked, use it to log in / escalate.

Administrator password guessing: if NetBIOS TCP/139 is open, connect to the hidden Admin$/C$ shares; try default/blank/weak passwords; or sniff the SMB session and replay the hash (pass-the-hash). Defense: disable NetBIOS where unneeded, strong admin passwords, 2FA, SMB signing, network segmentation.

9
Explain the stages of reverse engineering and list reverse-engineering tools. [15] Reverse engineering
→ Module 4 (Reverse engineering)
Answer

Stages (security view): (1) Information gathering — strings, imports, packer ID; (2) Disassembly/decompilation — turn binary to asm/VP code; (3) Static analysis (read code, no run) + Dynamic analysis (run in sandbox, watch behavior); (4) Documentation — map logic, find vulns/IoCs.

Tools: debuggers (IDA Pro, OllyDbg, gdb, Immunity, WinDbg — user/kernel mode), disassemblers (IDA, radare2), decompilers (Ghidra, Jadx), fault-injection tools. Used for malware analysis and vuln discovery.

(Note: the PDF's "3 scan stages" — scanning/point processing/geometric model — describe a different, physical 3-D scanning workflow; the security RE view above is what the exam expects.)

10
Explain web filtering — allow/block lists, DNS/URL/content filtering — and why organizations use it. [15] Web filtering
→ Module 4 (Web filtering)
Answer

Web filtering controls which sites/users may reach.

  • Allow-list — only permitted sites (strict); Block-list — ban known-bad.
  • DNS filtering — block at name resolution (refuse bad domains).
  • URL filtering — by address/category.
  • Content filtering — by page content/keywords.
  • Server-side (gateway/proxy) vs client-side (endpoint agent).

Why organizations use it: block malware/phishing, protect data (stop exfil/unsafe sites), meet compliance, enforce acceptable-use policy, save bandwidth. Pair with DLP and TLS inspection for depth.

Internal Series — First Series (College of Engineering Kallooppara)

Internal assessment · module-wise short & long answers (~8–15 marks)
Q
Define footprinting and scanning. Differentiate passive and active footprinting. [8] Footprinting
→ Module 2 (Footprinting, Scanning & Enumeration)
AnswerFootprinting = passive + active info gathering to map the target. Scanning = finding live hosts, open ports, OS/version (active). Passive leaves no packet on target (WHOIS, OSINT, archives); Active touches the target (ping/port scans, banner grab) and is detectable. Passive is stealthier; active is faster and richer.
Q
Classify malware with examples (virus, worm, Trojan, ransomware, rootkit, logic bomb). [8] Malware
→ Module 2 (Malware & Network Attacks)
AnswerVirus — needs a host file, spreads when run. Worm — self-propagates, no host. Trojan — disguised legit software. Ransomware — encrypts files for ransom. Rootkit — hides presence/tools. Logic bomb — triggers on a condition (date/event). Others: keylogger, spyware, botnet, backdoor. Distinction: needs-host / spreads / goal.
Q
List social-engineering techniques and the concept of a "human firewall". [8] Social engineering
→ Module 2 (Social Engineering)
AnswerTechniques: phishing, spear-phishing, whaling, vishing, smishing, pretexting, baiting, quid pro quo, tailgating, impersonation, shoulder surfing, dumpster diving. Human firewall: trained people who spot and report tries, verify out-of-band for money/access, and follow policy — the last line of defense. Tech fails; aware users catch what filters miss.
Q
Explain the CIA triad and the AAA model. [8] CIA · AAA
→ Module 1 (Elements of InfoSec)
AnswerCIA: Confidentiality (only authorized see it), Integrity (unaltered), Availability (reachable when needed). AAA: Authentication (who you are — password/MFA), Authorization (what you may do — roles/least privilege), Accounting (what you did — logs/audit). CIA is the goal; AAA are the controls that achieve it.
Q
Differentiate white-box, black-box and grey-box penetration testing. Mention OWASP Top 10. [8] Pentest · OWASP
→ Module 1 (Penetration Testing & Frameworks)
AnswerWhite-box = full info (docs/creds); Black-box = no info (true outsider); Grey-box = partial. OWASP Top 10: A01 Broken Access Control, A02 Cryptographic Failures, A03 Injection, A04 Insecure Design, A05 Security Misconfiguration, A06 Vulnerable & Outdated Components, A07 Identification & Authentication Failures, A08 Software & Data Integrity Failures, A09 Security Logging Failures, A10 SSRF. Plus frameworks: OSSTMM, NIST SP 800-115.

Q
Explain buffer overflow and its consequences. How is it exploited? [8] Buffer overflow
→ Module 4 (Buffer overflow)
AnswerBuffer overflow: data exceeding a buffer's capacity overwrites adjacent memory. Consequences: crash, loss of access control, further exploit. Exploited by: overwriting the return address so execution jumps to attacker shellcode → arbitrary code execution / privilege gain. Defenses: bounds checking, safe functions (strncpy), ASLR, DEP, stack canaries, memory-safe languages.
Q
List the sources of vulnerability data (NVD, CVE, CERT, ISACs, OVAL). What is OVAL used for? [8] Vuln DBs
→ Module 3 (Vulnerability resources)
AnswerSources: NVD (US database), CVE (common ID), CERT/CC (coordination), ISACs (sector sharing), OVAL (machine-readable vuln info). OVAL (Open Vulnerability and Assessment Language) standardizes vulnerability/configuration checks so scanners test systems consistently and automatically — turning "is this patch missing?" into a portable, comparable test.
Q
Explain SMTP abuse as an attack vector and mitigation. [8] SMTP
→ Module 3 (Brute force & Protocol Attacks)
AnswerSMTP abuse: open relays let attackers send spoofed/phishing spam; VRFY/EXPN enumerate users; weak SMTP auth is brute-forced; credentials sniffed in plaintext. Mitigation: disable open relay, require auth + TLS, restrict VRFY/EXPN, filter spam, monitor mail logs, DKIM/DMARC on outbound.
Q
Describe the seven steps of incident response. [8] Incident response
→ Module 4 (Incident response)
AnswerSeven steps: (1) Early detection (SIEM alert); (2) Analysis (IoC, triage); (3) Prioritization; (4) Notification (internal + external); (5) Containment & forensics; (6) Recovery (eradicate, rebuild, restore, patch); (7) Incident review (lessons learned). Run by the CSIRT. Goal: minimize damage, recover fast, prevent recurrence.
