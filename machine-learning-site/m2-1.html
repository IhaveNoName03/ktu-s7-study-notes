Module 2 · Supervised Learning · 7 hours

Regression, Logistic Regression, Naive Bayes, Decision Trees

This module is about learning from labelled data — the heart of supervised learning. We cover the two big families: regression (predicting a continuous number, like a house price or temperature) and classification (predicting a category, like spam/not-spam or disease/no-disease). For each we build intuition, see how the model is learned, and understand where things go wrong — especially overfitting and how Ridge and Lasso keep it in check.

01

Regression

Predict a number

Regression is the supervised-learning task of predicting a continuous output value from input features. Given examples where we know both the input x and the correct output y, the model learns a function h(x) ≈ y so that it can predict y for new x it has never seen. The output is a real number — price, temperature, revenue, demand — not a category.

The simplest and most important regression model is linear regression: it assumes the output is (approximately) a weighted sum of the inputs. If that assumption is too simple for the data, we can go to polynomial regression, which still fits a linear model but to transformed (squared, cubed, interaction) features — the fit becomes a curve in the original space.

+Linear Regression — One Variable

The model is a straight line: h(x) = θ₀ + θ₁x. There are two parameters — the intercept θ₀ (where the line crosses the y-axis) and the slope θ₁ (how steep the line is). We choose the θ's so that the line is as close as possible to all the training points.

For one input, the fit is a line. For θ₀ = 0, θ₁ = 1.5, the prediction at x = 2 is h(2) = 0 + 1.5·2 = 3.0.

+Linear Regression — Multiple Variables

With D input features the model becomes h(x) = θ₀ + θ₁x₁ + θ₂x₂ + ... + θDxD. Each feature gets its own weight, and the fit is now a plane (one feature), a hyperplane (many features), not a line. The learning problem is the same in structure — find θ that minimises the prediction error — but the number of parameters grows with D.

For D ≈ 100 (around a hundred independent attributes), the closed-form matrix solution becomes expensive, and gradient descent is typically preferred.

What "linear" really means: linear regression is linear in the parameters (the θ's), not necessarily in the inputs. Polynomial regression — h(x) = θ₀ + θ₁x + θ₂x² + θ₃x³ — is still a linear regression because it is a linear combination of parameters; the curve comes from feeding x², x³ as extra input features. This is why linear methods are more powerful than they first appear.
02

How the Model Is Learned — The Cost Function

Fitting the line

To "learn" the model we need a way to score how bad a particular choice of parameters is. The standard score for regression is the mean squared error — the average of the squared differences between the model's prediction and the true value, over all training examples. Smaller error means a better fit.

J(θ₀,θ₁) = (1/2m) · Σ₁m ( h(x⁽ⁱ⁾) – y⁽ⁱ⁾ )²

1/2mWhy this form

The 1/m averages the error over all m examples, so the score does not grow with dataset size. The 1/2 is a convenience: when we take the derivative to minimise J, the square's factor of 2 cancels the 1/2, leaving clean expressions. It does not change where the minimum is.

SquaredWhy square the error

Squaring makes every error positive (a prediction above and below the truth do not cancel), and it penalises large errors more heavily. It also gives a smooth, differentiable function that gradient-based methods can optimise easily.

Worked numbers: if the training set is {(1,1), (2,2), (3,3)} and we set θ₀ = 0, θ₁ = 1, then h(x)=x exactly matches every point, and J(0,1) = 0. If instead θ₀ = 0, θ₁ = 1.5, the predictions are 1.5, 3.0, 4.5, and the squared errors are (0.5)², (1.0)², (1.5)², so J = (1/6)(0.25+1+2.25) = 3.5/6 ≈ 0.583. Lower J means a better fit; J = 0 means a perfect fit on the training set.
03

Solution Methods — Gradient Descent & Closed Form

Finding the best θ

▼Gradient Descent

An iterative method: start with some θ (often zeros), then repeatedly take a small step in the direction that reduces J the fastest — that is, opposite to the gradient. Repeat until J stops improving. The size of each step is the learning rate α.

θⱼ := θⱼ − α · ∂J/∂θⱼ

Intuition: imagine standing on a hill (high J) and wanting to reach the valley (low J). The gradient tells you which way is steepest uphill; step the opposite way, a little at a time. Eventually you reach a low point.

=Closed-Form (Normal Equation)

A direct formula that gives the optimal θ in one step, without iterating. It solves ∂J/∂θ = 0 analytically. The price is computation: it requires inverting a D×D matrix.

θ = (XTX)−1 XTy

When to prefer which: closed form is exact and simple when D is small. But inverting a D×D matrix costs about O(D³), and with D ≈ 100 (around 100 attributes) it gets expensive and may be numerically unstable. Gradient descent handles large D and large datasets more gracefully, and is the workhorse for most real problems.
Batch vs online gradient descent: batch gradient descent computes the gradient using the entire training set at each step — stable but slow per step on large data. Online (stochastic) gradient descent updates θ using one example at a time — much faster per step, can escape shallow local minima, and is preferred when data is large or arriving in a stream. The trade-off: batch is smoother and more predictable; online is faster and can track a changing distribution but noisier.
04

Overfitting in Regression

The core problem

Overfitting is when a model fits the training data too closely — including its noise and quirks — so that it performs well on the data it was trained on but poorly on new data. In regression, overfitting tends to happen when the model is too flexible for the amount of data: too many parameters, or a polynomial of too high a degree. A 10th-degree polynomial can pass through every training point exactly, but between points it may swing wildly and predict badly.

Underfitting

The model is too simple to capture the pattern — high error on both training and test data. A straight line fit to clearly curved data underfits. The model has high bias: its assumptions are wrong for the data.

Overfitting

The model is too flexible — near-zero error on training data but high error on test data. A high-degree polynomial through every point overfits. The model has high variance: small changes in the training data produce very different fits.

How to spot it: compare training error to test error. If training error is low and test error is much higher, the model is overfitting. If both are high, it is underfitting. The goal is the middle ground — enough flexibility to capture the true pattern, but not so much that noise is memorised. This is the bias–variance trade-off (Module 5).
How to reduce overfitting in regression: (1) gather more training data, (2) simplify the model — fewer features or lower polynomial degree, (3) use regularization — Ridge (L2) or Lasso (L1), covered below, (4) use cross-validation to choose the model complexity, (5) stop training early in iterative methods.
05

Regularization — Ridge (L2) & Lasso (L1)

Keeping the fit honest

Regularization is the standard way to prevent overfitting. The idea is simple: when we choose the parameters, we not only care about fitting the data (small J), but also about keeping the parameters small. A model with huge weights is usually overfitting — it is bending sharply to hit individual points. By adding a penalty on the size of θ, we force the model to prefer simpler, smoother fits.

Jregularized = J(θ) + λ · (penalty on θ)

RidgeL2 regularization

Adds λ Σ θⱼ² — the sum of squared parameters — to the cost. It gently shrinks all weights toward zero but rarely makes them exactly zero. It is the default regularizer for most regression tasks and works well when many features each contribute a little.

J = (1/2m)Σ(h−y)² + λ·Σθⱼ²

LassoL1 regularization

Adds λ Σ |θⱼ| — the sum of absolute parameter values. Because the penalty is on the absolute value, it tends to drive some weights to exactly zero. This performs feature selection: irrelevant features get zero weight and disappear from the model.

J = (1/2m)Σ(h−y)² + λ·Σ|θⱼ|

The role of λ: λ controls the strength of regularization. λ = 0 means no regularization (ordinary regression, prone to overfitting). Very large λ crushes the weights toward zero, which can underfit (the model becomes too simple). The right λ is found by cross-validation. The name λ (lambda) is the regularization parameter — the "knob" that balances fit versus simplicity.
Why regularization works: it is a formal version of Occam's razor — given two models that fit equally well, prefer the simpler one. By penalising large weights, Ridge and Lasso make the model's predictions change less when the training data changes a little, i.e. they reduce variance. The cost is a small increase in bias, but the net effect is usually better generalisation. This is the bias–variance trade-off made concrete.
06

Classification — Predicting a Category

Regression's cousin

Classification is the supervised-learning task where the output is a category (class label) rather than a number. The input is still a set of features x, but now the target y is discrete — e.g. spam / not-spam, disease / healthy, professor / student / staff. The model learns to draw a boundary (or boundaries) between classes in the feature space, so that new points fall on the correct side.

Regression and classification are the two faces of supervised learning. Regression predicts a continuous value; classification predicts a discrete label. Many algorithms exist on both sides — linear regression for continuous outputs, logistic regression for binary classification, Naive Bayes and decision trees for both — but the loss function and the way we evaluate them differ.

TaskOutput typeExampleTypical algorithms
RegressionContinuous numberHouse price, temperature, demandLinear / polynomial regression, Ridge, Lasso
Binary classificationTwo classesSpam vs not-spam, disease vs healthyLogistic regression, Naive Bayes, decision trees, SVM
Multi-class classificationThree or more classesProfessor / student / staff; digit 0–9Logistic regression (one-vs-rest), Naive Bayes, decision trees
Key distinction to remember: Logistic regression is a classification algorithm despite its name — it predicts a probability (between 0 and 1) and then thresholds it to a class. It is called "regression" only because it is built on the same linear form as linear regression; the output is a probability, and the final decision is categorical.

Naïve Bayes — Worked Example (Play-Tennis)

From the handwritten notes

The Naïve Bayes classifier is a probability-based classifier built on Bayes' theorem with the "naïve" assumption that features are conditionally independent given the class. For a test instance with attributes a₁…aₙ it picks the class that maximises:

Classification rule (ArgMax)

ŷ = arg maxvⱼ ∈ Y { P(vⱼ) · ∏i=1n P(aᵢ | vⱼ) }

Worked on the classic 14-day Play-Tennis dataset. Class counts: P(Yes)=9/14, P(No)=5/14. Learned likelihoods (counts ÷ class count):

Test 1 — <Sunny, Cool, High, Strong>

P(Yes)=9/14·2/9·3/9·3/9·3/9 = 1/189 ≈ 0.0053

P(No)=5/14·3/5·1/5·4/5·3/5 ≈ 0.0206

Since P(No) > P(Yes) → predict No (do not play).

Test 2 — <Overcast, Mild, Normal, Weak>

P(Yes)=9/14·4/9·4/9·6/9·6/9 = 32/567 ≈ 0.056

P(No)=5/14·0·2/5·1/5·2/5 = 0

Since P(Yes) > P(No) → predict Yes (play). Note P(Overcast|No)=0 zeroes the whole product.

Decision Trees (ID3) — Entropy & Information Gain

From the handwritten notes

A decision tree is a non-linear model (uses supervised learning) that splits data at each internal node by the attribute that best separates the classes; leaf nodes hold the predicted class. ID3 picks the split using entropy (impurity) and information gain.

Entropy of a set S (binary)

Entropy(S) = −P₊ log₂ P₊ − P₋ log₂ P₋

Worked: S has 9 positive, 5 negative (|S|=14)

P₊=9/14, P₋=5/14

E(S) = −(9/14)log₂(9/14) − (5/14)log₂(5/14) = 0.940

Information Gain of attribute A

Gain(S,A) = E(S) − Σv∈Values(A) (|Sᵥ| / |S|) · E(Sᵥ)

For the Play-Tennis root choice the notes compute (student's numbers): Gain(Outlook)=0.24, Gain(Wind)=0.48, Gain(Temp)=0.032, Gain(Humidity)=0.15. The tree built: root Outlook → Sunny splits on Humidity (high→No, normal→Yes), Overcast→Yes, Rain splits on Wind (strong→No, weak→Yes).
