What Is Machine Learning?

Definition

Machine learning is a branch of artificial intelligence that focuses on developing models and algorithms that let computers learn from data without being explicitly programmed for every task. In simple terms: ML teaches a system to think and understand like a human by learning patterns from examples, rather than following a fixed rule written by a person.

That is the core shift: traditional software says "if X then do Y"; machine learning says "here are many examples of X and the correct Y — figure out the rule yourself." The model is the learned rule, and it is trained on data, then used to make predictions or decisions on new, unseen data.

Key idea: the system improves with experience (data). The more representative the data, the better the model generalises to situations it has not seen before.
02

The Three Core Types of Machine Learning

Paradigms at a glance

SSupervised Learning

Trains models on labelled data to predict or classify new, unseen data. Each training example comes with the correct answer (the label), so the model learns a mapping from inputs to outputs.

Sub-types: Classification (predict discrete labels/categories) and Regression (predict continuous numerical values).

UUnsupervised Learning

Finds patterns or groups in unlabelled data — there is no "correct answer" provided. The model looks for structure on its own, such as clusters of similar items or ways to reduce many features to a smaller set.

Categories: Clustering, Association Rule Mining, Dimensionality Reduction.

RReinforcement Learning

Learns through trial and error to maximise a reward. An agent takes actions in an environment, receives feedback in the form of rewards or penalties, and gradually learns which actions lead to the best long-term outcome.

Ideal for decision-making tasks — e.g. game playing, robotics, resource scheduling — where there is no fixed labelled dataset, just interaction and feedback.

03

Unsupervised Learning — Three Categories

Structure without labels

CClustering

Groups similar data points together so that items in the same group (cluster) are more alike than items in other groups. There is no "correct" label — the grouping emerges from the data itself.

Example: grouping customers by purchasing behaviour, or grouping documents by topic. Common algorithms: k-means, hierarchical clustering, EM.

AAssociation Rule Mining

Discovers rules that describe how items tend to appear together in data. An association rule says "if X happens, Y tends to happen too" — useful for finding co-occurrence patterns.

Classic example: market-basket analysis — "customers who buy bread often also buy butter." Metrics: support, confidence, lift.

DDimensionality Reduction

Reduces the number of features (dimensions) in a dataset while trying to preserve the important information. High-dimensional data is hard to work with and often contains redundant or correlated features.

Helps with visualisation, speed, and avoiding overfitting. Example: Principal Component Analysis (PCA) — covered in detail in Module 4.

04

Reinforcement Learning — Learning by Reward

Interaction + feedback

Reinforcement learning (RL) is different from supervised and unsupervised learning because it learns from interaction. An agent acts in an environment, and after each action it receives a reward (or penalty) — a numerical signal that tells it how good that action was.

The agent's goal is not to maximise the immediate reward, but the cumulative reward over time. This makes RL suited to problems where a short-term sacrifice can lead to a better long-term outcome — exactly the kind of sequential decision-making that shows up in games, robotics, and control systems.

Contrast with supervised learning: in supervised learning you are given the correct answer for each example. In RL you are given a reward signal that tells you how well you did, but not necessarily the one best action. The agent must explore (try new actions) and exploit (use what it already knows works) to learn the best policy.

05

Semi-Supervised Learning

Between the two

Semi-supervised learning sits between supervised and unsupervised learning. It uses a mix of labelled and unlabelled data — typically a small amount of labelled data together with a much larger amount of unlabelled data.

This is useful precisely because labelling data is costly or limited. Getting labels often requires a human expert (e.g. a doctor labelling medical images, or someone transcribing speech), which is slow and expensive. Meanwhile, raw unlabelled data (images, text, sensor readings) is often abundant and cheap.

Why it matters: semi-supervised learning tries to get the benefit of labelled data (the supervision) while also exploiting the structure in the large unlabelled set (the unsupervised part) to improve the model. It is a practical answer to the real-world situation where labels are the bottleneck.

Bayesian Formulation — Thinking in Probabilities

Uncertainty

The Bayesian formulation is the probabilistic way of thinking about learning. Bayes' theorem explains how to update the probability of a hypothesis when new evidence is observed. In machine learning, the "hypothesis" is often the model or the model's parameters, and the "evidence" is the data we observe.

At its heart, Bayesian learning combines prior knowledge with observed data to make better decisions under uncertainty. Rather than producing a single fixed answer, it works with probabilities — how likely a hypothesis is, given what we knew before and what we have now seen.

What Bayesian formulation givesWhy it matters
Handles uncertainty and noisy data effectivelyReal data is rarely perfect; the Bayesian view quantifies rather than ignores uncertainty

Enables learning even with limited dataBy bringing in a prior (what we believe before seeing the data), useful learning is possible even when data is scarce

Simple intuition: Bayes' theorem is the mathematics of "updating your belief." You start with a prior belief, see some evidence, and end with a posterior belief that combines both. In ML, this is the foundation for methods like Bayesian learning and the MAP estimate.
07

Mathematical Formulation of Bayes' Theorem

The formula

Bayes' theorem relates conditional probabilities. In the context of machine learning it is usually written as:

P(H | D) = P(D | H) · P(H) / P(D)

P(H | D)Posterior

The probability of the hypothesis H after observing the data D. This is what we want to compute — our updated belief after seeing the evidence.

P(D | H)Likelihood

The probability of observing the data D if the hypothesis H were true. It measures how well the hypothesis explains the data.

P(H)Prior

The probability of the hypothesis before seeing the data — our initial belief, based on prior knowledge or assumptions.

P(D)Evidence

The probability of the data overall. It acts as a normalising constant so the posterior sums to 1. In many ML settings it does not depend on the hypothesis and can be treated as a constant.

Reading it in words: the posterior (updated belief) is proportional to the likelihood (how well the hypothesis fits the data) times the prior (what we believed before). Bayes' theorem gives the exact way to combine them.

Connecting the Paradigms to Estimation

Why this matters for M2

The paradigms on this page are the what; parameter estimation (covered in the next module) is the how for the supervised and Bayesian parts. In particular:

  • Supervised learning needs a way to fit a model to labelled data — that is estimation: given data, find the parameters (weights, probabilities, tree splits) that best explain it.
  • Maximum Likelihood Estimation (MLE) asks: which parameter values make the observed data most probable? It is a core, general method for fitting models.
  • Maximum A Posteriori (MAP) extends MLE by including a prior — it is the Bayesian version, combining the data (likelihood) with prior belief (prior) to get the most probable parameters.
  • The Bayesian formulation is the bigger picture: learning as reasoning about probabilities of hypotheses and parameters given data.
Bridge to Module 2: the next module takes these ideas and works them out concretely — MLE for specific distributions (binomial, Poisson, exponential, normal), MAP with priors, and the point vs. interval estimation distinction. If the paradigms here feel abstract, the worked examples in Module 2 are where they become concrete.

MLE & MAP — Worked Example (Coin Toss)

From the handwritten notes / CO questions

MLE finds the parameter values that maximise the probability of the observed data. MAP additionally multiplies by a prior and maximises the posterior.

Posterior (Bayes)

\[P(\theta \mid D) = \frac{P(D \mid \theta)\,P(\theta)}{P(D)}\]

Estimators

\[\hat{\theta}_{\text{MLE}}=\arg\max_{\theta}P(D\mid\theta)\cdot\hat{\theta}_{\text{MAP}}=\arg\max_{\theta}P(\theta\mid D)=\arg\max_{\theta}P(D\mid\theta)\,P(\theta)\]

10

Setup & the Recipe

Method

Given i.i.d. samples x₁…xₙ from a distribution with parameter θ, the likelihood is the joint density viewed as a function of θ:

\[L(\theta)=P(D\mid\theta)=\prod_{i=1}^{n}p(x_i\mid\theta)\]

The MLE maximizes it; in practice we maximize the easier log-likelihood:

\[\ell(\theta)=\sum_i\ln p(x_i\mid\theta),\quad\hat{\theta}_{\text{MLE}}=\arg\max_{\theta}\ell(\theta)\]
Recipe (every derivation below): ① write p(x|θ); ② take ln; ③ differentiate w.r.t. θ; ④ set = 0; ⑤ solve. Derivatives of sums turn products into clean linear equations.
11

Poisson (count data)

Derivation

For counts with rate λ > 0, p(x|λ) = e−λ λx / x!. Log-likelihood:

\[\ell(\lambda)=\sum\bigl[-\lambda+x_i\ln\lambda-\ln(x_i!)\bigr]=-n\lambda+\bigl(\sum x_i\bigr)\ln\lambda+\text{const}\]

dℓ/dλ = −n + (Σxi)/λ = 0  ⟹  λ̂ = (1/n) Σ xi = x̄.

Worked: events per hour observed as 3, 5, 4, 6, 2 → x̄ = 20/5 = 4 → λ̂ = 4 events/hour.

12

Exponential (waiting times)

Derivation

For positive waiting times with rate λ > 0, p(x|λ) = λ e−λx. Log-likelihood:

\[\ell(\lambda)=n\ln\lambda-\lambda\sum x_i\]

dℓ/dλ = n/λ − Σxi = 0  ⟹  λ̂ = n / Σ xi = 1 / x̄.

Worked: mean waiting time x̄ = 5 min → λ̂ = 1/5 = 0.2 per minute. (Note: for exponential, the MLE of λ is the reciprocal of the sample mean — the opposite of Poisson.)

13

Gaussian / Normal (two parameters)

Derivation

For N(μ, σ²), p(x) = (1/√(2πσ²)) e−(x−μ)²/(2σ²). Log-likelihood (dropping constants):

\[\ell(\mu,\sigma^{2})=-\frac{n}{2}\ln\sigma^{2}-\frac{1}{2\sigma^{2}}\sum(x_i-\mu)^{2}\]

Differentiate w.r.t. μ, then w.r.t. σ²:

\[\frac{\partial\ell}{\partial\mu}=\frac{1}{\sigma^{2}}\sum(x_i-\mu)=0\;\Longrightarrow\;\hat{\mu}=\bar{x}=\frac{1}{n}\sum x_i\]
\[\frac{\partial\ell}{\partial\sigma^{2}}=-\frac{n}{2\sigma^{2}}+\frac{1}{2\sigma^{4}}\sum(x_i-\mu)^{2}=0\;\Longrightarrow\;\hat{\sigma}^{2}=\frac{1}{n}\sum(x_i-\bar{x})^{2}\]

Worked: samples 2, 4, 6, 8 → x̄ = 5; σ̂² = [(−3)²+(−1)²+1²+3²]/4 = 20/4 = 5. So the MLE is the sample mean and the sample variance (dividing by n).

MLE vs unbiased variance: the MLE uses 1/n (biased); the usual "unbiased" estimator uses 1/(n−1). The syllabus MLE result is the 1/n form — know both and which is which.
14

MAP — Adding a Prior

Contrast

MAP maximizes the posterior instead of just the likelihood:

\[\hat{\theta}_{\text{MAP}}=\arg\max_{\theta}\bigl[\ell(\theta)+\ln P(\theta)\bigr]\]

The prior P(θ) acts as a regularizer. With a Gaussian prior on μ, N(μ₀, τ²), the MAP mean becomes a shrinkage estimate:

\[\hat{\mu}_{\text{MAP}}=\frac{\sum x_i/\sigma^{2}+\mu_{0}/\tau^{2}}{n/\sigma^{2}+1/\tau^{2}}\]

As the prior tightens (τ²→0) μ̂→μ₀; as data grows (n→∞) μ̂→x̄ — the prior loses influence. This is exactly the role of regularization in regression (M2).

Bias of Estimators

Note

A good estimator should be consistent (converges to the truth as n→∞) and, ideally, unbiased. The MLE mean μ̂ = x̄ is unbiased: E[x̄] = μ. But the MLE variance σ̂² = (1/n)Σ(x−x̄)² is slightly biased — its expectation is (n−1)/n · σ², so it underestimates σ². The usual fix is the unbiased sample variance s² = (1/(n−1))Σ(x−x̄)². This is the only place MLE and the "textbook" variance differ; everything else (means, rates, λ) is unbiased. (Bias–variance of predictors is covered in M5.)

The Formal Learning Setup — What Is Being Learned?

Foundations

The informal definition of machine learning ("learning from data without being explicitly programmed") becomes precise once we name four objects. Every algorithm in this course — a Naive Bayes classifier, a linear regression, an SVM, a k-means clustering — is an instance of the same skeleton.

  • Instance space X — the set of all possible inputs (a feature vector x ∈ ℝᵈ, an image, an email).
  • Output space Y — the set of possible answers: ℝ for regression, {0, 1} or {C₁ … Cₖ} for classification.
  • Hypothesis class H — the family of functions we are willing to search: lines h(x) = w·x + b, trees, networks, hyperplanes.
  • Loss function L(y, h(x)) — the price paid for predicting h(x) when the truth is y. Learning is the search for the h ∈ H with the smallest expected loss.
\[R(h)=\mathbb{E}_{(x,y)\sim P}\bigl[L(y,h(x))\bigr]\qquad \hat h=\arg\min_{h\in\mathcal H}\; \hat R(h),\quad \hat R(h)=\frac{1}{n}\sum_{i=1}^{n}L(y_i,h(x_i))\]

R(h) is the true risk; R̂(h) is the empirical risk computed on the sample. The whole of supervised learning rests on the hope that the two are close — that a model which does well on the data we have will also do well on data we do not have. That hope is formalised by the law of large numbers and, more sharply, by concentration inequalities: for a finite hypothesis class, with probability at least 1 − δ,

\[R(h)\;\le\;\hat R(h)+\sqrt{\frac{\ln|\mathcal H|+\ln(1/\delta)}{2n}}\]

The extra term is the generalisation gap. It shrinks as n grows, which is the mathematical reason more data helps, and it grows with |H|, which is the mathematical reason overly flexible models overfit. Keep this inequality in mind whenever an examiner asks "why does regularisation / more data / a simpler model help?" — all three are ways of controlling the two quantities in the square root.

Three losses you must recognise: squared loss L = (y − h(x))² for regression; 0–1 loss L = 1[h(x) ≠ y] for classification; cross-entropy L = −y log h(x) − (1 − y) log(1 − h(x)) for probabilistic classification. Squared error and cross-entropy are smooth and differentiable; 0–1 loss is not, which is why we optimise surrogates instead of accuracy directly.
Exam writing tip: when asked "what is machine learning?", do not stop at the slogan. Write the four objects (X, Y, H, L), the empirical-risk formula, and one sentence on the generalisation gap. That converts a 2-mark definition into a 5-mark answer.

Supervised Learning in Detail — Labels, Noise and the Two Tasks

Paradigm 1

Supervised learning means the training set is labelled: we are given pairs (xᵢ, yᵢ), i = 1 … n, drawn from an unknown joint distribution P(X, Y). The goal is a function h that, given a new x, predicts y. The word "supervised" refers to the presence of the correct answer y — the teacher's signal that tells the learner when it is wrong.

The signal is rarely perfect. Real labels contain noise: a radiologist may disagree with another on a borderline scan, a user may click an ad by accident. We model this as y = f(x) + ε where ε is random. This noise places a floor on achievable error — the Bayes error rate — and is the "irreducible error" that reappears in the bias–variance decomposition of Module 5.

\[\text{Regression target: } f^*(x)=\mathbb{E}[Y\mid x]\qquad \text{Classification target: } f^*(x)=\arg\max_c P(Y=c\mid x)\]

These two identities are worth memorising because they explain the choice of loss. The conditional mean minimises expected squared error (a quick derivation: differentiate E[(Y − a)²] with respect to a and set to zero, giving a = E[Y]). The most probable class minimises expected 0–1 loss. When a classifier outputs a probability p̂(x) rather than a bare label, calibration asks whether p̂ really equals the true P(Y = 1 | x); a model can rank cases perfectly yet be badly calibrated, which is why ROC/AUC and Brier score answer different questions.

Assumption to state explicitly: supervised learning assumes training and test data are drawn from the same distribution (the i.i.d. assumption). If the world changes between training and deployment — covariate shift or concept drift — even a model with tiny training error can fail. Whenever an exam asks for "assumptions / limitations", this is a high-value sentence.

Unsupervised Learning in Detail — Objectives, Association Rules, Reduction

Paradigm 2

Unsupervised learning receives only x — no y. Since there is no external "correct answer" to optimise against, we must define an internal notion of what counts as a good structure. Every unsupervised algorithm is therefore an objective function plus a search procedure, and the objective encodes our subjective idea of what "structure" means.

\[\text{k-means: } J=\sum_{k=1}^{K}\sum_{x_i\in C_k}\lVert x_i-\mu_k\rVert^{2}\qquad \text{GMM/EM: } \max_\theta\prod_{i=1}^{n}\sum_{k=1}^{K}\pi_k\,\mathcal N(x_i\mid\mu_k,\Sigma_k)\]

The first objective rewards tight, spherical groups measured by squared distance; the second rewards data that is likely under a mixture of Gaussians. Change the objective and you change what the algorithm "discovers" — this is why the choice of similarity measure in Module 4 matters so much.

Association rules — the metrics worked out

An association rule has the form X ⇒ Y, read "if a transaction contains itemset X it tends also to contain Y". Given N transactions, the three standard metrics are:

\[\operatorname{supp}(X\Rightarrow Y)=\frac{\#(X\cup Y)}{N},\qquad \operatorname{conf}(X\Rightarrow Y)=\frac{\#(X\cup Y)}{\#(X)},\qquad \operatorname{lift}=\frac{\operatorname{conf}(X\Rightarrow Y)}{P(Y)}=\frac{P(Y\mid X)}{P(Y)}\]

Worked example. In N = 1000 transactions, bread appears 300 times, butter 200 times, and both appear 120 times. Then support(bread ⇒ butter) = 120/1000 = 0.12 (12% of all baskets contain both); confidence = 120/300 = 0.40 (40% of bread buyers also buy butter); lift = 0.40 / (200/1000) = 0.40 / 0.20 = 2.0. A lift of 2 means buying bread doubles the tendency to buy butter relative to the baseline — a genuine association. Lift = 1 means independence; lift < 1 means the items actually discourage each other. Confidence alone can mislead: if butter were in 90% of baskets, a confidence of 0.9 might simply reflect a popular item, and lift would reveal that.

Edge cases for association rules: very low support rules are usually noise and are discarded with a minimum support threshold; the number of candidate itemsets grows exponentially (2ᵈ for d items), which is why Apriori uses the downward-closure property — any frequent itemset must have all of its subsets frequent. Rare-item rules with high confidence are often artefacts of a tiny denominator, so always report support alongside confidence.

Dimensionality reduction — the geometry

If d features are highly correlated, the data effectively lives on a lower-dimensional surface embedded in ℝᵈ. Principal Component Analysis (Module 4) finds the directions of largest variance and projects onto them; the projection keeps the geometry that matters and discards the redundancy. Formally, with centred data matrix X (n × d) and covariance S = XᵀX/(n − 1), PCA solves

\[\max_{\lVert w\rVert=1} w^{T}Sw \quad\Longrightarrow\quad Sw=\lambda w\]

so the optimal directions are eigenvectors of S and the variance captured by each is the corresponding eigenvalue. This is a clean example of the "objective + search" pattern: the objective is variance retained, the search is eigendecomposition.

Exam writing tip: for "explain unsupervised learning", give one concrete objective for each family (within-cluster sum of squares for k-means, likelihood for EM, variance for PCA, support/confidence/lift for association rules). That shows you know these are not just informal ideas but well-defined optimisation problems.

Semi-Supervised Learning — Assumptions, Algorithms and a Worked Trace

Paradigm 3

Let the labelled set be L = {(xᵢ, yᵢ)}ᵢ₌₁ⁿ with n small, and the unlabelled set U = {xⱼ}ⱼ₌₁ᵐ with m ≫ n. Semi-supervised learning trains on both. It can only work because of an extra assumption linking the unlabelled points to the labels — without such an assumption, no algorithm can beat chance when labels are scarce. The three classical assumptions are:

  • Smoothness assumption: points that are close in input space are likely to share a label.
  • Cluster assumption: points in the same cluster are likely to share a label (decision boundaries should lie in low-density regions).
  • Manifold assumption: high-dimensional data lies on a low-dimensional manifold; distance along the manifold is more meaningful than Euclidean distance.

Self-training (self-labelling) is the simplest algorithm. Train a classifier on L; use it to predict pseudo-labels for U; add the most confident unlabelled points (with their pseudo-labels) to L; retrain; repeat.

input: labelled L, unlabelled U, confidence threshold τ, rounds T
for t = 1 .. T:
    fit classifier h on L
    for each x in U:
        p = h(x)
        if max_c p(c|x) >= τ: add (x, argmax_c p(c|x)) to L; remove x from U
    if no point added: break
return h
Worked trace. Suppose L has 2 labelled documents (one spam, one ham) and U has 1000 unlabelled emails. The first classifier is weak, but suppose it predicts spam with confidence 0.97 for 20 emails containing an unusual word cluster. With τ = 0.95 those 20 enter L, and the second classifier now has 22 labelled examples. If the assumption holds (that word cluster really is spam), accuracy climbs; if the cluster was a harmless newsletter, the error is amplified — this is confirmation bias, the central failure mode of self-training. Use a high threshold and keep the original labels untouched.

Two more principled variants: co-training assumes two conditionally independent feature views (e.g. page text and anchor text); each view's classifier labels confident points for the other. Graph-based label propagation builds a similarity graph over L ∪ U and lets labels diffuse along edges, solving

\[F^{*}=\arg\min_{F}\;\frac{1}{2}\sum_{i,j}w_{ij}(F_i-F_j)^{2}+\mu\sum_{i\in L}\ell(F_i,y_i)\]

where the first term enforces smoothness over the graph and the second keeps the fit anchored to the real labels. Setting Fᵢ = yᵢ for labelled nodes gives the harmonic solution; energy minimises when each unlabelled node's label estimate is the weighted average of its neighbours — a discrete Laplace equation.

When semi-supervised helps / hurts: it helps when unlabelled data is abundant, labels are expensive (medical imaging, speech transcription), and the cluster/smoothness assumptions genuinely hold. It hurts when the unlabelled set has a different distribution, contains outliers that create misleading clusters, or when a wrong pseudo-label is confidently reinforced. Always validate on a held-out labelled set.

Reinforcement Learning — MDPs, Bellman Equations and Q-Learning

Paradigm 4

Reinforcement learning formalises learning from interaction. The environment is a Markov Decision Process, a five-tuple (S, A, P, R, γ):

  • S — set of states; A — set of actions;
  • P(s′ | s, a) — transition probability (the Markov property: the future depends only on the current state and action);
  • R(s, a, s′) — expected immediate reward;
  • γ ∈ [0, 1) — discount factor that trades present against future reward.

The return from time t is the discounted sum Gₜ = Σₖ₌₀∞ γᵏ rₜ₊ₖ₊₁. A policy π(a | s) maps states to action probabilities. The state-value and action-value functions are

\[V^{\pi}(s)=\mathbb{E}_{\pi}\bigl[G_t\mid s_t=s\bigr],\qquad Q^{\pi}(s,a)=\mathbb{E}_{\pi}\bigl[G_t\mid s_t=s,a_t=a\bigr]\]

Applying the law of total expectation to the first reward and the continuation value gives the Bellman expectation equations:

\[V^{\pi}(s)=\sum_a \pi(a\mid s)\sum_{s'}P(s'\mid s,a)\bigl[R(s,a,s')+\gamma V^{\pi}(s')\bigr]\]
\[Q^{*}(s,a)=\mathbb{E}_{s'}\Bigl[R(s,a,s')+\gamma\max_{a'}Q^{*}(s',a')\Bigr]\qquad\text{(Bellman optimality for Q)}\]

Q-learning turns the optimality equation into a stochastic, model-free update. After observing (s, a, r, s′):

\[Q(s,a)\;\leftarrow\;Q(s,a)+\alpha\Bigl[\underbrace{r+\gamma\max_{a'}Q(s',a')}_{\text{target}}\;-\;Q(s,a)\Bigr]\]

The bracket is the temporal-difference error: the difference between the new estimate and the old one. α is the learning rate. Notice the structural similarity to the perceptron and to logistic-regression updates seen later: new = old + learning-rate × (target − current). All three are instances of stochastic approximation.

Worked Q-value update

Two states, s₁ and s₂. From s₁, action a₁ gives r = 2 and lands in s₂; from s₂, action a₂ gives r = 5 and terminates. Let γ = 0.8, α = 0.5, and initialise all Q = 0. First update the terminal transition: Q(s₂, a₂) ← 0 + 0.5[5 + 0.8·0 − 0] = 2.5. Then the s₁ transition: Q(s₁, a₁) ← 0 + 0.5[2 + 0.8·max(2.5, 0) − 0] = 0.5[2 + 2.0] = 2.0. Repeating these updates with many samples drives Q toward the true discounted returns; the greedy policy then picks the action with the largest Q.

Exploration vs exploitation: always taking the current best action (exploitation) can lock the agent into a suboptimal policy because untried actions may be better. ε-greedy chooses a random action with probability ε and the greedy action otherwise. Decaying ε from, say, 1.0 to 0.05 explores early and exploits later. This is the RL counterpart of the bias–variance trade-off: exploration reduces the bias caused by insufficient experience; exploitation reduces the variance of the learned policy.
How RL differs from supervised learning — exam version: supervised learning receives the correct output for every example and is given a fixed dataset; RL receives only a scalar reward, often delayed, and the data is generated by the agent's own actions (the training distribution depends on the current policy). This is why RL must handle credit assignment and exploration, and why it is used for sequential decisions (games, robotics, scheduling) rather than one-shot prediction.

Bayes' Theorem — Full Derivation and a Worked Diagnostic Test

Probability engine

Bayes' theorem is not a separate assumption; it is an algebraic rearrangement of the definition of conditional probability. From P(A | B) = P(A ∩ B)/P(B) we get P(A ∩ B) = P(A | B)P(B); swapping A and B gives P(B ∩ A) = P(B | A)P(A). Equating the two expressions for the same joint probability yields

\[P(A\mid B)=\frac{P(B\mid A)\,P(A)}{P(B)},\qquad P(B)=\sum_j P(B\mid A_j)P(A_j)\quad\text{(law of total probability)}\]

Substituting the second line into the first gives the form used all semester, with the hypothesis H and data D:

\[P(H\mid D)=\frac{P(D\mid H)\,P(H)}{\sum_{h'}P(D\mid h')P(h')}\;\propto\;P(D\mid H)\,P(H)\]

The denominator does not depend on H, so when we only need to compare hypotheses we can drop it and work with the unnormalised product likelihood × prior. This single observation is why Naive Bayes (Module 2) and MAP estimation need no evidence term.

Worked example — a medical screening test

A disease has prevalence P(D⁺) = 0.01. A test has sensitivity P(T⁺ | D⁺) = 0.99 and specificity P(T⁻ | D⁻) = 0.95, so the false-positive rate is P(T⁺ | D⁻) = 0.05. A patient tests positive. What is P(diseased | positive)?

\[P(T^{+})=0.99(0.01)+0.05(0.99)=0.0099+0.0495=0.0594\]
\[P(D^{+}\mid T^{+})=\frac{0.0099}{0.0594}=0.1\overline{6}\approx 16.7\%\]

Despite a "99% accurate" test, a positive result implies only about a one-in-six chance of disease. The reason is the tiny prior: false positives from the 99% healthy population (4.95% of all people) vastly outnumber true positives from the 1% diseased population (0.99%). This is the base-rate fallacy, and it is the single most important intuition to carry into Bayesian classification.

Repeat with a second independent positive test: treat the posterior 0.1667 as the new prior. P(T⁺ | D⁺) = 0.99, P(T⁺ | D⁻) = 0.05, so the new posterior is 0.99·0.1667 / [0.99·0.1667 + 0.05·0.8333] = 0.165 / (0.165 + 0.0417) ≈ 0.798. Two positives push belief to about 80%. Bayes updating is sequential: today's posterior is tomorrow's prior.
Connection to classification and evaluation (Module 5): sensitivity is recall/TPR, specificity is 1 − FPR, and PPV (positive predictive value) is precision. The calculation above is exactly the relationship between precision, recall, prevalence and false-positive rate. When an examiner links Bayes' theorem to the confusion matrix, this is the bridge.

MLE Derivation Recipes — Bernoulli, Binomial and the Shape of Likelihood

Worked estimation

The likelihood principle says: given data, prefer the parameter value under which that data was most probable. Formally L(θ) = Πᵢ p(xᵢ | θ) for i.i.d. observations, and the MLE is θ̂ = argmax L(θ). Maximising L is equivalent to maximising ℓ(θ) = log L(θ) because log is strictly increasing; the log converts products into sums and powers into coefficients, which is what makes the derivatives tractable.

Bernoulli / binomial — full derivation

A coin comes up heads with probability θ. Code heads as x = 1, tails as x = 0, so p(x | θ) = θˣ(1 − θ)¹⁻ˣ. For n independent tosses with h heads and n − h tails:

\[L(\theta)=\binom{n}{h}\theta^{h}(1-\theta)^{n-h},\qquad \ell(\theta)=\text{const}+h\ln\theta+(n-h)\ln(1-\theta)\]
\[\frac{d\ell}{d\theta}=\frac{h}{\theta}-\frac{n-h}{1-\theta}=0\;\Longrightarrow\;h(1-\theta)=(n-h)\theta\;\Longrightarrow\;h=n\theta\;\Longrightarrow\;\hat\theta_{\mathrm{MLE}}=\frac{h}{n}\]
\[\frac{d^{2}\ell}{d\theta^{2}}=-\frac{h}{\theta^{2}}-\frac{n-h}{(1-\theta)^{2}}<0\]\]

The negative second derivative confirms a maximum (the log-likelihood is concave). Worked: 7 heads in 10 tosses gives θ̂ = 7/10 = 0.7. The log-likelihood at 0.7 is 10·? — more precisely 7 ln 0.7 + 3 ln 0.3 + ln(120) ≈ 7(−0.3567) + 3(−1.2040) + 4.7875 = −2.4969 − 3.6120 + 4.7875 = −1.3214 (including the binomial coefficient), versus −1.665 at θ = 0.5, confirming the maximum sits at 0.7.

MAP with a Beta prior

Put a Beta(α, β) prior on θ, whose density is proportional to θᵅ⁻¹(1 − θ)ᵝ⁻¹. Multiplying likelihood by prior and taking logs gives ℓ + (α − 1)ln θ + (β − 1)ln(1 − θ), so

\[\hat\theta_{\mathrm{MAP}}=\frac{h+\alpha-1}{n+\alpha+\beta-2}\qquad\text{and the posterior mean}=\frac{h+\alpha}{n+\alpha+\beta}\]

Worked: with a symmetric Beta(2, 2) prior (which gently prefers a fair coin), h = 7, n = 10: θ̂MAP = (7 + 1)/(10 + 2) = 8/12 = 0.6667; the posterior mean is (7 + 2)/(10 + 4) = 9/14 ≈ 0.6429. As n grows the data term dominates and MAP, MLE and the posterior mean converge; when n is tiny the prior dominates. This is the same shrinkage behaviour as Ridge regression, with the prior playing the role of the penalty.

Edge cases: if h = 0, the MLE is θ̂ = 0, a degenerate estimate that assigns zero probability to any future head. Laplace smoothing (add-one, equivalent to a Beta(2,2) prior) avoids this — the same trick that rescues Naive Bayes. If h = n the symmetric problem occurs at the other end. MAP with a proper prior never produces a degenerate 0 or 1.

Poisson, Exponential and Gaussian — Derivations with Second Derivatives and Checks

Worked estimation

Poisson — count data

p(x | λ) = e−λλˣ/x!, so ℓ(λ) = −nλ + (Σxᵢ)ln λ − Σ ln(xᵢ!). Differentiating gives dℓ/dλ = −n + (Σxᵢ)/λ and d²ℓ/dλ² = −(Σxᵢ)/λ² < 0 (for positive counts): a maximum at λ̂ = x̄. Worked: counts 3, 5, 4, 6, 2 give Σx = 20, n = 5, λ̂ = 4 events/hour. The model assumes mean = variance (equidispersion); if the sample variance greatly exceeds the mean the Poisson model is inadequate and a negative-binomial model is preferred — a classic assumption check.

Exponential — waiting times

p(x | λ) = λe−λx for x ≥ 0, so ℓ(λ) = n ln λ − λΣxᵢ, dℓ/dλ = n/λ − Σxᵢ, d²ℓ/dλ² = −n/λ² < 0, giving λ̂ = 1/x̄. Worked: a mean wait of 5 minutes gives λ̂ = 0.2 per minute. Notice the contrast with Poisson: the rate is the mean count but the reciprocal of the mean waiting time. A common exam slip is to write λ̂ = x̄ for the exponential — do not.

\[P(X>s+t\mid X>s)=\frac{e^{-\lambda(s+t)}}{e^{-\lambda s}}=e^{-\lambda t}=P(X>t)\]

This is the memorylessness property: the probability of waiting another t minutes does not depend on how long you have already waited. It is unique to the exponential among continuous distributions and is the reason the exponential is the natural model for inter-arrival times in a Poisson process.

Gaussian — two parameters and the bias of σ̂²

For N(μ, σ²):

\[\ell(\mu,\sigma^{2})=-\frac{n}{2}\ln(2\pi\sigma^{2})-\frac{1}{2\sigma^{2}}\sum_{i}(x_i-\mu)^{2}\]
\[\frac{\partial\ell}{\partial\mu}=\frac{1}{\sigma^{2}}\sum_i(x_i-\mu)=0\Rightarrow\hat\mu=\bar x;\qquad \frac{\partial\ell}{\partial\sigma^{2}}=-\frac{n}{2\sigma^{2}}+\frac{1}{2\sigma^{4}}\sum_i(x_i-\bar x)^{2}=0\Rightarrow\hat\sigma^{2}=\frac{1}{n}\sum_i(x_i-\bar x)^{2}\]

Worked: samples 2, 4, 6, 8 give μ̂ = 5 and σ̂² = [(−3)² + (−1)² + 1² + 3²]/4 = (9 + 1 + 1 + 9)/4 = 20/4 = 5. Why is the MLE variance biased? Write Σ(xᵢ − x̄)² = Σ(xᵢ − μ)² − n(x̄ − μ)². Taking expectations, E[Σ(xᵢ − μ)²] = nσ² and E[n(x̄ − μ)²] = n·(σ²/n) = σ², so E[Σ(xᵢ − x̄)²] = (n − 1)σ² and therefore

\[\mathbb E[\hat\sigma^{2}_{\mathrm{MLE}}]=\frac{n-1}{n}\sigma^{2}\neq\sigma^{2},\qquad s^{2}=\frac{1}{n-1}\sum_i(x_i-\bar x)^{2}\ \text{is unbiased}\]

The factor (n − 1)/n is the loss of one degree of freedom from estimating μ. With n = 4 the MLE variance is 75% of σ². Note the conceptual distinction to examine: this is bias of an estimator (Module 1), not the bias term of the bias–variance decomposition of a predictor (Module 5). Same word, different question.

Consistency and efficiency: all four MLEs above are consistent — as n → ∞ they converge in probability to the true parameter. Among consistent estimators, the MLE is asymptotically efficient: its variance achieves the Cramér–Rao lower bound 1/(n I(θ)), where I(θ) = −E[∂²ℓ/∂θ²] is Fisher information. You do not need to derive the bound in the exam, but naming it shows you understand why MLE is the default estimation method.

Point vs Interval Estimation, MAP Shrinkage and the Bridge to Regression

Synthesis

A point estimate is a single number (θ̂ = 0.7); an interval estimate is a range with a stated confidence, e.g. a 95% confidence interval x̄ ± 1.96σ/√n for a normal mean with known σ. The interval carries information the point cannot: its width shrinks as 1/√n, so doubling precision costs four times the data. A Bayesian credible interval differs in interpretation — it is a statement about the parameter given the data, P(θ ∈ [a, b] | D), whereas a frequentist confidence interval is a statement about the long-run behaviour of the interval-construction procedure.

MAP estimation connects the Bayesian view to regularised regression. With a Gaussian prior μ ~ N(μ₀, τ²) and n observations with known variance σ², the posterior mean (and MAP, which coincide for a Gaussian) is

\[\hat\mu_{\mathrm{MAP}}=\frac{\sum_i x_i/\sigma^{2}+\mu_0/\tau^{2}}{n/\sigma^{2}+1/\tau^{2}}=\frac{n\tau^{2}}{n\tau^{2}+\sigma^{2}}\,\bar x+\frac{\sigma^{2}}{n\tau^{2}+\sigma^{2}}\,\mu_0\]

This is a weighted average of the data mean and the prior mean. As τ² → ∞ (flat prior) it tends to x̄; as τ² → 0 (tight prior) it tends to μ₀; as n → ∞ the data dominates. Worked: σ² = 4, τ² = 1, μ₀ = 0, n = 4, x̄ = 5 gives weight on data = 4·1/(4·1 + 4) = 0.5, so μ̂ = 2.5 — exactly halfway between the data and the prior. Compare with Ridge regression: adding λ||w||² to a least-squares objective is equivalent to MAP estimation with a Gaussian prior on w of variance 1/(2λ). Lasso's λΣ|w| corresponds to a Laplace prior. Regularisation is not an ad-hoc trick — it is Bayesian shrinkage in disguise.
