The complete Module 2: linear and polynomial regression derived from least squares, gradient descent and the normal equation, Ridge/Lasso, logistic regression, Naive Bayes with Laplace smoothing, and ID3 decision trees — with full worked numerical examples and exam-writing guidance.

01

Regression

Predict a number

Regression is the supervised-learning task of predicting a continuous output value from input features. Given examples where we know both the input x and the correct output y, the model learns a function h(x) ≈ y so that it can predict y for new x it has never seen. The output is a real number — price, temperature, revenue, demand — not a category.

The simplest and most important regression model is linear regression: it assumes the output is (approximately) a weighted sum of the inputs. If that assumption is too simple for the data, we can go to polynomial regression, which still fits a linear model but to transformed (squared, cubed, interaction) features — the fit becomes a curve in the original space.

+Linear Regression — One Variable

The model is a straight line: h(x) = θ₀ + θ₁x. There are two parameters — the intercept θ₀ (where the line crosses the y-axis) and the slope θ₁ (how steep the line is). We choose the θ's so that the line is as close as possible to all the training points.

For one input, the fit is a line. For θ₀ = 0, θ₁ = 1.5, the prediction at x = 2 is h(2) = 0 + 1.5·2 = 3.0.

+Linear Regression — Multiple Variables

With D input features the model becomes h(x) = θ₀ + θ₁x₁ + θ₂x₂ + ... + θDxD. Each feature gets its own weight, and the fit is now a plane (one feature), a hyperplane (many features), not a line. The learning problem is the same in structure — find θ that minimises the prediction error — but the number of parameters grows with D.

For D ≈ 100 (around a hundred independent attributes), the closed-form matrix solution becomes expensive, and gradient descent is typically preferred.

What "linear" really means: linear regression is linear in the parameters (the θ's), not necessarily in the inputs. Polynomial regression — h(x) = θ₀ + θ₁x + θ₂x² + θ₃x³ — is still a linear regression because it is a linear combination of parameters; the curve comes from feeding x², x³ as extra input features. This is why linear methods are more powerful than they first appear.
02

How the Model Is Learned — The Cost Function

Fitting the line

To "learn" the model we need a way to score how bad a particular choice of parameters is. The standard score for regression is the mean squared error — the average of the squared differences between the model's prediction and the true value, over all training examples. Smaller error means a better fit.

\[J(\theta_0,\theta_1)=\frac{1}{2m}\sum_{i=1}^{m}\bigl(h(x^{(i)})-y^{(i)}\bigr)^{2}\]

Why this form

The 1/m averages the error over all m examples, so the score does not grow with dataset size. The 1/2 is a convenience: when we take the derivative to minimise J, the square's factor of 2 cancels the 1/2, leaving clean expressions. It does not change where the minimum is.

SquaredWhy square the error

Squaring makes every error positive (a prediction above and below the truth do not cancel), and it penalises large errors more heavily. It also gives a smooth, differentiable function that gradient-based methods can optimise easily.

03

Solution Methods — Gradient Descent & Closed Form

Finding the best θ

▼Gradient Descent

An iterative method: start with some θ (often zeros), then repeatedly take a small step in the direction that reduces J the fastest — that is, opposite to the gradient. Repeat until J stops improving. The size of each step is the learning rate α.

\[\theta_j := \theta_j - \alpha\,\frac{\partial J}{\partial\theta_j}\]

Intuition: imagine standing on a hill (high J) and wanting to reach the valley (low J). The gradient tells you which way is steepest uphill; step the opposite way, a little at a time. Eventually you reach a low point.

=Closed-Form (Normal Equation)

A direct formula that gives the optimal θ in one step, without iterating. It solves ∂J/∂θ = 0 analytically. The price is computation: it requires inverting a D×D matrix.

\[\theta=(X^{T}X)^{-1}X^{T}y\]

Underfitting

The model is too simple to capture the pattern — high error on both training and test data. A straight line fit to clearly curved data underfits. The model has high bias: its assumptions are wrong for the data.

Overfitting

The model is too flexible — near-zero error on training data but high error on test data. A high-degree polynomial through every point overfits. The model has high variance: small changes in the training data produce very different fits.

How to spot it: compare training error to test error. If training error is low and test error is much higher, the model is overfitting. If both are high, it is underfitting. The goal is the middle ground — enough flexibility to capture the true pattern, but not so much that noise is memorised. This is the bias–variance trade-off (Module 5).
How to reduce overfitting in regression: (1) gather more training data, (2) simplify the model — fewer features or lower polynomial degree, (3) use regularization — Ridge (L2) or Lasso (L1), covered below, (4) use cross-validation to choose the model complexity, (5) stop training early in iterative methods.
04

Regularization — Ridge (L2) & Lasso (L1)

Keeping the fit honest

Regularization is the standard way to prevent overfitting. The idea is simple: when we choose the parameters, we not only care about fitting the data (small J), but also about keeping the parameters small. A model with huge weights is usually overfitting — it is bending sharply to hit individual points. By adding a penalty on the size of θ, we force the model to prefer simpler, smoother fits.

Jregularized =\[J_{\text{reg}}=J(\theta)+\lambda\cdot(\text{penalty on }\theta)\]) + λ · (penalty on θ)

RidgeL2 regularization

Adds λ Σ θⱼ² — the sum of squared parameters — to the cost. It gently shrinks all weights toward zero but rarely makes them exactly zero. It is the default regularizer for most regression tasks and works well when many features each contribute a little.

\[J = \frac{1}{2m}\sum(h-y)^{2} + \lambda\sum\theta_j^{2}\]

LassoL1 regularization

Adds λ Σ |θⱼ| — the sum of absolute parameter values. Because the penalty is on the absolute value, it tends to drive some weights to exactly zero. This performs feature selection: irrelevant features get zero weight and disappear from the model.

\[J = \frac{1}{2m}\sum(h-y)^{2} + \lambda\sum|\theta_j|\]

The role of λ: λ controls the strength of regularization. λ = 0 means no regularization (ordinary regression, prone to overfitting). Very large λ crushes the weights toward zero, which can underfit (the model becomes too simple). The right λ is found by cross-validation. The name λ (lambda) is the regularization parameter — the "knob" that balances fit versus simplicity.
Why regularization works: it is a formal version of Occam's razor — given two models that fit equally well, prefer the simpler one. By penalising large weights, Ridge and Lasso make the model's predictions change less when the training data changes a little, i.e. they reduce variance. The cost is a small increase in bias, but the net effect is usually better generalisation. This is the bias–variance trade-off made concrete.
05

Classification — Predicting a Category

Regression's cousin

Classification is the supervised-learning task where the output is a category (class label) rather than a number. The input is still a set of features x, but now the target y is discrete — e.g. spam / not-spam, disease / healthy, professor / student / staff. The model learns to draw a boundary (or boundaries) between classes in the feature space, so that new points fall on the correct side.

Regression and classification are the two faces of supervised learning. Regression predicts a continuous value; classification predicts a discrete label. Many algorithms exist on both sides — linear regression for continuous outputs, logistic regression for binary classification, Naive Bayes and decision trees for both — but the loss function and the way we evaluate them differ.

TaskOutput typeExampleTypical algorithms
RegressionContinuous numberHouse price, temperature, demandLinear / polynomial regression, Ridge, Lasso
Binary classificationTwo classesSpam vs not-spam, disease vs healthyLogistic regression, Naive Bayes, decision trees, SVM
Multi-class classificationThree or more classesProfessor / student / staff; digit 0–9Logistic regression (one-vs-rest), Naive Bayes, decision trees
Key distinction to remember: Logistic regression is a classification algorithm despite its name — it predicts a probability (between 0 and 1) and then thresholds it to a class. It is called "regression" only because it is built on the same linear form as linear regression; the output is a probability, and the final decision is categorical.

Logistic Regression — Odds, Logit & Gradient Descent

Classification by regression

Despite the name, logistic regression is a classification method. It keeps the same linear form as linear regression, wᵀx, but passes it through a sigmoid so the output is a probability in (0,1). The textbook (Alpaydın, logistic discrimination, §10.7 / §11.3) writes the two-class model as:

\[y_t = \sigma(w^{T}x_t) \qquad \bigl(P(C_1\mid x_t)=y_t;\; r_t=1\text{ if }x_t\in C_1,\;0\text{ if }x_t\in C_2\bigr)\]    ( P(C₁|xₜ) = yₜ ;   rₜ = 1 if xₜ∈C₁,   0 if xₜ∈C₂ )

Inverting the sigmoid shows the model is linear in the log-odds (the logit):

\[\log\!\left(\frac{y_t}{1-y_t}\right) = w^{T}x_t\]
Odds & logit: the odds of class C₁ are yₜ ⁄ (1 − yₜ); the logit is their logarithm. Logistic regression therefore models the log-odds as a linear combination of the inputs. A one-unit increase in feature xⱼ multiplies the odds by ewⱼ — this is exactly why the method is called logistic.

The parameters are learned by maximum likelihood: maximize the Bernoulli log-likelihood, equivalently minimize its negative — the cross-entropy:

\[L(r\mid X)=\sum_t\bigl[r_t\log y_t+(1-r_t)\log(1-y_t)\bigr]\]

This is minimized with gradient descent. For a single training instance the online (stochastic) update is:

\[\Delta w_{tj}=\eta\,(r_t-y_t)\,x_{tj}\qquad(j=0,\dots,d)\]
Update rule: η is the learning factor. The batch version sums the correction (rₜ − yₜ)xtⱼ over all instances before updating; the online version updates after each pattern. Both share the same shape — Update = learning-factor × (desired − actual) × input — the perceptron learning rule applied to the cross-entropy error.

Naïve Bayes — the intuition (read this first)

Plain-language lesson

Naïve Bayes is the classifier you reach for when you want a sensible prediction, fast, from very little data. Underneath the formula it is one idea you already use every day:

Start with your best guess. Then let the evidence shift it. That is Bayes' theorem in plain English. Your "guess before evidence" is the prior; "how strongly this evidence points at each answer" is the likelihood; your "updated guess after evidence" is the posterior.

An example you already do. You wake up and guess "probably not raining" — it's usually dry (that's your prior). You look outside and see dark clouds (evidence). Dark clouds are far more common on rainy days than dry days, so the evidence shifts your belief toward "it will rain" (posterior). Naïve Bayes just does this counting-and-shifting maths formally, for any number of features at once.

Why "naïve"?

It assumes each feature is independent of the others once you know the class — e.g. "given that an email is spam, the words 'free' and 'click' don't influence each other." That is usually false in real life (words do correlate). But the naïve shortcut works surprisingly well and needs much less data, because it estimates each feature on its own instead of every possible combination. That trade-off is the entire reason the method exists.

Bayes' theorem, slowly

Bayes' theorem

\[P(\text{class} \mid \text{evidence}) = \dfrac{P(\text{evidence} \mid \text{class}) \cdot P(\text{class})}{P(\text{evidence})}\]

Left to right: how likely is the class given this evidence = how likely is this evidence if the class is true × how common the class is ÷ how common the evidence is overall. When we compare two classes, the bottom term P(evidence) is identical for both — so we drop it and just compare the top:

What we actually compute

\[\hat{y} = \arg\max_{v_j} \bigl\{ P(v_j) \cdot \prod_i P(a_i \mid v_j) \bigr\}\]

P(vⱼ) = how often class vⱼ appears in training (the prior). P(aᵢ | vⱼ) = for that class, how often feature aᵢ shows up (the likelihood). We multiply them all, repeat for every class, and pick the biggest. That is the whole algorithm — no training loop, no gradient, just counting.

When it shines: small datasets, text/spam classification, medical screening — many weak features, little data. When it struggles: features that are strongly correlated (the naïve assumption breaks badly); or a feature value that never appeared in training for a class — a single zero likelihood multiplies the whole product to 0. That is fixed with Laplace smoothing: add 1 to every count so nothing is ever exactly zero.

Decision Trees (ID3) — Entropy & Information Gain

From the handwritten notes

A decision tree is a non-linear model (uses supervised learning) that splits data at each internal node by the attribute that best separates the classes; leaf nodes hold the predicted class. ID3 picks the split using entropy (impurity) and information gain.

Entropy of a set S (binary)

\[\text{Entropy}(S) = -P_{+}\log_2 P_{+} - P_{-}\log_2 P_{-}\]

Information Gain of attribute A

\[\text{Gain}(S,A)=E(S)-\sum_{v\in\text{Values}(A)}\frac{|S_v|}{|S|}\cdot E(S_v)\]

For the Play-Tennis root choice the notes compute (student's numbers): Gain(Outlook)=0.24, Gain(Wind)=0.48, Gain(Temp)=0.032, Gain(Humidity)=0.15. The tree built: root Outlook → Sunny splits on Humidity (high→No, normal→Yes), Overcast→Yes, Rain splits on Wind (strong→No, weak→Yes).

Naive Bayes — the Idea

Classifier

For a class C and feature vector x = (x₁,…,xₙ), Bayes' theorem gives the posterior:

\[P(C\mid x) = \frac{P(x\mid C)\,P(C)}{P(x)}\]

The naive assumption: features are conditionally independent given the class, so P(x|C) = Πi P(xi | C). The classifier picks the class with the largest posterior:

\[\hat{C}=\arg\max_{C}\Bigl[P(C)\cdot\prod_i P(x_i\mid C)\Bigr]\]
Why "naive"? Real features are rarely independent, yet the method works surprisingly well — it is fast, needs little data, and is a strong baseline for text/spam classification.
10

Decision Trees & Entropy

ID3

A decision tree asks a feature question at each node to split the data. ID3 picks the question that most reduces entropy ( disorder / impurity ). Entropy of a set with class proportions pi:

\[H(S)=-\sum_i p_i\log_2 p_i\]

Information gain of splitting on feature A is the drop in impurity after the split — the parent entropy minus the weighted average entropy of the child branches:

\[\text{IG}(S,A)=H(S)-\sum_{v\in\text{Values}(A)}\frac{|S_v|}{|S|}\cdot H(S_v)\]
Formal definition (information gain): if after splitting on A the data partitions into branches v, with |Sv| instances taking branch v, the total impurity after the split is the weighted sum I′(S,A) = − Σv (|Sv| ⁄ |S|) Σi pi,v log2 pi,v (Alpaydın eq. 9.8). Information gain is then IG(S, A) = I(S) − I′(S, A): the split that gives the largest decrease in impurity is chosen. ID3, C4.5 and CART all select the split that minimizes this post-split impurity (equivalently, maximizes the gain).

Entropy is not the only impurity measure. For a two-class problem (p, 1−p), any nonnegative φ(p,1−p) that is maximal at p = ½ and zero at p = 0 or 1 works; the textbook lists three, with little practical difference between them:

Entropy:   \[\phi = -p\log_2 p - (1-p)\log_2(1-p)\]
Gini index:   \[\phi = 2p(1-p) \qquad\text{Gini index}\]    Misclassification error:   \[\phi = 1 - \max(p,1-p) \qquad\text{Misclassification error}\]

The feature with the highest gain is chosen as the root, and the process repeats on each child. (For the tennis set the gains work out roughly: Outlook ≈ 0.24, Wind ≈ 0.48, Humidity ≈ 0.15, Temp ≈ 0.03 — so Wind then Humidity are the strongest splitters after Outlook.)

Overfitting & pruning: a tree grown to full depth memorizes the training data, so it overfits when there is noise. Prepruning stops early — e.g. do not split a node reached by fewer than ~5% of the training set, or once its impurity falls below a threshold θI. Postpruning grows the full tree to zero training error, sets aside a separate pruning set, and replaces each subtree by a leaf if the leaf does no worse on the pruning set; postpruning is faster to state and generally yields more accurate trees than prepruning. C4.5 extends ID3 with continuous features and pruning.

Linear Regression from First Principles — The Normal Equation Derived

Full derivation

Write the training data as a design matrix X (m × (D+1)) whose i-th row is (1, xᵢ₁ … xᵢD) — the leading 1 supplies the intercept — and a target vector y. The hypothesis is h(x) = θᵀx and the residual vector is r = Xθ − y. The cost function is

\[J(\theta)=\frac{1}{2m}\sum_{i=1}^{m}\bigl(h(x^{(i)})-y^{(i)}\bigr)^{2}=\frac{1}{2m}(X\theta-y)^{T}(X\theta-y)\]

To minimise, use two matrix-calculus identities: ∇θ(θᵀAθ) = (A + Aᵀ)θ and ∇θ(bᵀθ) = b. Expanding J = (1/2m)(θᵀXᵀXθ − 2yᵀXθ + yᵀy) and differentiating gives

\[\nabla_\theta J=\frac{1}{m}\bigl(X^{T}X\theta-X^{T}y\bigr)=0\quad\Longrightarrow\quad \boxed{\theta=(X^{T}X)^{-1}X^{T}y}\]

These are the normal equations. Two practical caveats: XᵀX is singular if features are linearly dependent (perfect multicollinearity) or if m < D+1 — use the pseudoinverse or regularisation; and forming the inverse costs O(D³), which is why gradient descent wins for D ≈ 10⁴ or more.

Worked numerical example

Three observations: (x, y) = (1, 2), (2, 3), (3, 5). Then

\[X=\begin{bmatrix}1&1\\1&2\\1&3\end{bmatrix},\quad y=\begin{bmatrix}2\\3\\5\end{bmatrix},\quad X^{T}X=\begin{bmatrix}3&6\\6&14\end{bmatrix},\quad X^{T}y=\begin{bmatrix}10\\23\end{bmatrix}\]

The determinant is 3·14 − 6·6 = 42 − 36 = 6, so (XᵀX)⁻¹ = (1/6)[[14, −6], [−6, 3]] and

\[\theta=\frac{1}{6}\begin{bmatrix}14&-6\\-6&3\end{bmatrix}\begin{bmatrix}10\\23\end{bmatrix}=\frac{1}{6}\begin{bmatrix}140-138\\-60+69\end{bmatrix}=\begin{bmatrix}1/3\\3/2\end{bmatrix}\]

The fitted line is h(x) = 0.3333 + 1.5x, giving predictions 1.833, 3.333, 4.833. Residuals are +0.167, −0.333, +0.167; SSE = 0.0278 + 0.1111 + 0.0278 = 0.1667 and J = SSE/(2m) = 0.1667/6 = 0.0278. Note the residuals sum to zero — a consequence of the intercept column; use this as an arithmetic check in an exam.

Why the 1/2m matters: the 1/m makes J an average rather than a total, so the same J means the same average quality regardless of dataset size; the 1/2 cancels the factor 2 produced by differentiating a square. Neither changes the location of the optimum, so both are conventions — but the derivative expressions become clean, which examiners reward.

Gradient Descent — Derivation, One Iteration by Hand, and Diagnostics

Optimisation

For the one-variable model h(x) = θ₀ + θ₁x the partial derivatives are

\[\frac{\partial J}{\partial\theta_0}=\frac{1}{m}\sum_{i=1}^{m}\bigl(h(x^{(i)})-y^{(i)}\bigr),\qquad \frac{\partial J}{\partial\theta_1}=\frac{1}{m}\sum_{i=1}^{m}\bigl(h(x^{(i)})-y^{(i)}\bigr)x^{(i)}\]

and the simultaneous update is θⱼ ← θⱼ − α ∂J/∂θⱼ. Note the update must use the old values of all parameters — compute both derivatives first, then update both weights.

Worked first iteration

Using the same three points, start at θ₀ = θ₁ = 0 with α = 0.1. Predictions are all 0, so residuals are h − y = −2, −3, −5. Then ∂J/∂θ₀ = (−2 − 3 − 5)/3 = −10/3 = −3.333 and ∂J/∂θ₁ = (−2·1 − 3·2 − 5·3)/3 = (−2 − 6 − 15)/3 = −23/3 = −7.667. The update gives θ₀ = 0 − 0.1(−3.333) = +0.333, θ₁ = 0 − 0.1(−7.667) = +0.767. After one step we are already at θ₀ = 1/3 (the optimal intercept!) and θ₁ is about half of its optimum 1.5; further iterations refine the slope. (With larger α the steps overshoot; with smaller α convergence is slower but steadier.)

# Batch gradient descent
initialise theta = 0 (or small random values), learning rate alpha
repeat until ||J(prev) - J(theta)|| < tolerance:
    grad = 0 vector
    for i = 1 .. m:
        error = dot(theta, x_i) - y_i
        grad += error * x_i
    theta = theta - (alpha / m) * grad
return theta
Choosing α — practical diagnostics: plot J against iteration. A smoothly decreasing curve that flattens is healthy. A curve that rises or oscillates wildly means α is too large (halve it). A curve that barely moves after many epochs means α is too small or features need scaling. A robust trick is feature scaling — standardise each feature to zero mean and unit variance — so that the contours of J are roughly circular and gradient descent does not zig-zag along a narrow valley.
Batch vs stochastic vs mini-batch: batch uses all m examples per update (accurate gradient, expensive); stochastic gradient descent (SGD) uses one example (noisy, fast, can escape shallow local minima); mini-batch uses a small block (the modern default, balancing hardware efficiency and gradient quality). The expected update is the same in all three — only the variance differs.
When least squares is not enough: if residuals grow with x (heteroscedasticity), if the residual histogram is skewed, or if the true relationship is curved, linear regression assumptions are violated. Plot residuals against fitted values first — the pattern is more diagnostic than R². Link this to Module 5: a large train/test gap means variance (regularise or simplify), a small but uniformly high gap means bias (add features or complexity).

Polynomial Regression, Overfitting and Regularisation — Derivations and Worked Penalties

Generalisation

Polynomial regression keeps the linear-in-parameters form but adds transformed features: h(x) = θ₀ + θ₁x + θ₂x² + … + θdxd. With d = 1 a straight line; with d = 3 a cubic. Increasing d reduces training error monotonically (a higher-degree model contains the lower-degree one by setting extra coefficients to zero) but test error follows a U-shape: it falls while bias is reduced, then rises as variance takes over. Model selection by cross-validation picks the bottom of that U.

Regularisation adds a complexity penalty to J. There are three equivalent viewpoints worth stating in an exam:

\[\text{Ridge (L2): } J=\frac{1}{2m}\sum_i(h_i-y_i)^2+\lambda\sum_{j=1}^{D}\theta_j^{2}\;\Longrightarrow\;\theta=(X^TX+m\lambda I)^{-1}X^Ty\]
\[\text{Lasso (L1): } J=\frac{1}{2m}\sum_i(h_i-y_i)^2+\lambda\sum_{j=1}^{D}|\theta_j|\]

For ridge, adding λI to XᵀX makes the matrix invertible even under multicollinearity and shrinks every weight toward zero, with an analytic solution. For Lasso the absolute-value penalty has a corner at zero, so the optimum frequently lands exactly on a coordinate axis — some θⱼ = 0 — giving sparse models and automatic feature selection. Elastic Net combines both penalties and is preferred when many correlated features should be kept or dropped together.

Worked shrinkage calculation

Take a one-feature problem (after standardising) with XᵀX = 100 I and Xᵀy = (80, 60)ᵀ for two weights. Ordinary least squares gives θ = (0.8, 0.6). Ridge with mλI added, taking mλ = 100 so the effective denominator becomes 200, gives θ = (0.4, 0.3): every coefficient is halved. With a stronger penalty mλ = 900 the denominator is 1000 and θ = (0.08, 0.06), nearly zero — an underfit model. Choose λ by k-fold cross-validation: try λ ∈ {10⁻³, 10⁻², …, 10³}, compute mean validation error for each, and take the smallest.

Bias–variance link to remember: regularisation deliberately increases bias (the coefficients are biased toward zero) to obtain a larger reduction in variance, lowering the expected test error. λ is the knob: λ = 0 → high variance, λ → ∞ → high bias. This is the same trade-off as C in SVMs (Module 3) and tree depth in decision trees (Module 2).

Logistic Regression — Sigmoid, Odds, Likelihood and a Numerical Prediction

Classification

Linear regression would produce numbers outside [0, 1] for a probability, so logistic regression passes the linear score through the sigmoid:

\[z=w^{T}x+b,\qquad y=P(C_1\mid x)=\sigma(z)=\frac{1}{1+e^{-z}},\qquad \sigma(-z)=1-\sigma(z)\]

Rearranging y = 1/(1 + e−z) gives the logit (log-odds) form z = ln[y/(1 − y)] = wᵀx + b. The odds y/(1 − y) are multiplied by ewⱼ for a one-unit increase in feature xⱼ; if wⱼ = 0.69 the odds roughly double (e0.69 ≈ 2). This is why logistic regression coefficients are interpretable as log-odds ratios, and why it remains a baseline in medicine and social science.

\[L(r\mid X)=\prod_t y_t^{r_t}(1-y_t)^{1-r_t}\;\Longrightarrow\;\ell=\sum_t\bigl[r_t\ln y_t+(1-r_t)\ln(1-y_t)\bigr]\]

Maximising ℓ (equivalently minimising cross-entropy −ℓ) with gradient descent yields the remarkably simple update

\[\frac{\partial \ell}{\partial w_j}=\sum_t (r_t-y_t)\,x_{tj}\qquad\Longrightarrow\qquad \Delta w_j=\eta\sum_t(r_t-y_t)x_{tj}\]

The gradient is the input multiplied by the error (desired minus actual). Compare the perceptron rule: identical form, but there the "actual" is a hard 0/1 step; here it is a smooth probability, so the update is graded rather than all-or-nothing.

Worked prediction and loss

Let b = −3, w = 2 and x = 2. Then z = −3 + 2·2 = 1, and y = σ(1) = 1/(1 + e−1) = 1/(1 + 0.3679) = 0.7311. The odds are 0.7311/0.2689 = 2.718 = e¹. With a threshold of 0.5 the case is classified positive. If the true label is r = 1, the per-example cross-entropy is −ln(0.7311) = 0.3133; if the true label is 0 it is −ln(1 − 0.7311) = −ln(0.2689) = 1.3133. The gradient contribution for a positive example is (1 − 0.7311)·x = 0.2689·2 = 0.5378, nudging w upward.

Decision boundary: the boundary is where y = 0.5, i.e. z = 0, i.e. wᵀx + b = 0 — a straight line/plane/hyperplane even though the output is curved. Adding polynomial features makes the boundary non-linear in the original space while remaining linear in parameters. This is the same "linear in parameters" trick as polynomial regression.
Multiclass extension: softmax generalises the sigmoid: P(Cₖ | x) = ezₖ/Σⱼ ezⱼ, with one score zₖ = wₖᵀx + bₖ per class. The scores sum to 1 after exponentiation and normalisation; the loss is the multiclass cross-entropy −Σₖ rₖ ln pₖ. One-vs-rest trains K binary classifiers instead; softmax is preferred when the classes are mutually exclusive because it models competition directly.
Common exam traps: (1) "Logistic regression is a regression algorithm" — false; it is a classifier with a regression-shaped linear core. (2) Using squared error instead of cross-entropy — cross-entropy gives a convex objective for logistic regression, squared error does not. (3) Forgetting the bias term b — without it the boundary must pass through the origin.

Naive Bayes — Laplace Smoothing, a Full Spam Calculation and Assumptions

Worked classifier

Naive Bayes applies Bayes' theorem with the conditional-independence assumption P(x₁ … xd | C) = Πᵢ P(xᵢ | C). The classifier is ŷ = argmaxC P(C) Πᵢ P(xᵢ | C). Because the evidence P(x) is the same for every class it is dropped, and because we compare products of many small numbers it is numerically safer to work with log-probabilities and sums:

\[\hat y=\arg\max_C\Bigl[\ln P(C)+\sum_i \ln P(x_i\mid C)\Bigr]\]

Worked spam example with add-one smoothing

Training set: 20 emails, 8 spam and 12 ham, so P(spam) = 0.4 and P(ham) = 0.6. The word "free" appears in 8 of the 8 spam mails and 2 of the 12 ham mails; the word "click" appears in 6 spam and 1 ham. A new email contains both words. Without smoothing P(free | ham) = 2/12, but a zero count anywhere would destroy an entire product. Add-one (Laplace) smoothing therefore adds one to every count:

\[P(\text{free}\mid\text{spam})=\frac{8+1}{8+2}=0.75,\quad P(\text{click}\mid\text{spam})=\frac{6+1}{8+2}=0.583\]
\[P(\text{free}\mid\text{ham})=\frac{2+1}{12+2}=0.214,\quad P(\text{click}\mid\text{ham})=\frac{1+1}{12+2}=0.143\]

Score(spam) = 0.4 × 0.75 × 0.583 = 0.175; Score(ham) = 0.6 × 0.214 × 0.143 = 0.0184. The normalised posterior for spam is 0.175/(0.175 + 0.0184) = 0.905. The email is classified as spam. (In log space: ln 0.4 + ln 0.75 + ln 0.583 = −1.743 versus ln 0.6 + ln 0.214 + ln 0.143 = −3.997; the larger log-score wins.)

Three NB models: Gaussian NB for continuous features (estimate μ and σ² per class per feature and plug into the normal density); multinomial NB for word counts (the example above); Bernoulli NB for binary word-presence features. All share the same argmax structure; only P(xᵢ | C) changes.
Assumptions and failure modes: conditional independence is almost always false in text ("free" and "click" co-occur), yet NB works well because classification only needs the correct ranking, not calibrated probabilities — estimating the full joint would require exponentially more data. It fails badly when a feature is deterministic for a class (hence smoothing), when features are strongly correlated (the evidence is counted twice), and when the training class proportions differ from deployment (prior shift). Correct the prior if deployment prevalence is known.

ID3 Worked End-to-End — Entropy, Gains, the 0.9544 Example and Pruning

Decision trees

Entropy measures impurity: H(S) = −Σᶜ pᶜ log₂ pᶜ, with H = 0 for a pure set and H = 1 for a balanced binary set. Information gain is the reduction in entropy achieved by a split: Gain(S, A) = H(S) − Σᵥ (|Sᵥ|/|S|) H(Sᵥ). ID3 chooses the attribute with the largest gain at each node. Gain is equivalent to mutual information between the attribute and the target.

Full calculation — the "attractiveness" dataset

Eight examples, target Attractiveness with 3 Yes and 5 No:

Entropy(S) = −(3/8)log₂(3/8) − (5/8)log₂(5/8) = 0.9544 Height: short → (1Y, 2N), tall → (2Y, 3N) Remainder = (3/8)(0.9183) + (5/8)(0.9710) = 0.9512 → Gain = 0.9544 − 0.9512 = 0.0032 Hair: red → (1Y, 0N), dark → (0Y, 3N), blond → (2Y, 2N) Remainder = (1/8)(0) + (3/8)(0) + (4/8)(1) = 0.5000 → Gain = 0.9544 − 0.5000 = 0.4544 (highest) Eyes: blue → (3Y, 2N), brown → (0Y, 3N) Remainder = (5/8)(0.9710) + (3/8)(0) = 0.6068 → Gain = 0.9544 − 0.6068 = 0.3476

The root split is Hair (0.4544 > 0.3476 > 0.0032). Hair = red is pure (Yes), Hair = dark is pure (No), and the blond branch splits on Eyes (blue → Yes, brown → No), giving a tree that classifies all eight rows correctly. Height is nearly useless because its subsets have almost the same class mix as the whole set — its gain is essentially zero.

ID3(S, attributes, target):
    if all examples in S have the same target value:
        return a leaf labelled with that value
    if attributes is empty:
        return a leaf labelled with the majority target value
    best = argmax over A in attributes of Gain(S, A)
    create a root node testing 'best'
    for each value v of best:
        Sv = examples of S with best = v
        if Sv is empty: attach a leaf labelled with majority value of S
        else:           attach subtree ID3(Sv, attributes - {best}, target)
    return the node

Alternative impurity measures

\[\text{Entropy: }-p\log_2 p-(1-p)\log_2(1-p)\qquad \text{Gini: }2p(1-p)\qquad \text{Misclassification: }1-\max(p,1-p)\]

All three are maximal at p = 0.5 and zero at p = 0 or 1; empirically they rarely change the chosen split much. Gini avoids the logarithm (faster) and is used by CART; entropy is used by ID3/C4.5. Gain ratio = Gain(S, A)/SplitInfo(A) corrects entropy's bias toward attributes with many values; SplitInfo = −Σᵥ (|Sᵥ|/|S|) log₂(|Sᵥ|/|S|).

Pruning — controlling variance: a fully grown tree has zero training error and high variance. Prepruning stops growth early (e.g. no split if a node has fewer than 5% of examples or impurity below a threshold). Postpruning grows the full tree, then uses a separate pruning set to replace a subtree by a leaf whenever the leaf does no worse. Postpruning usually wins because it avoids stopping a split that becomes useful after a different split. Tree depth, minimum samples per leaf and maximum leaves are the knobs a practitioner cross-validates.
Assumptions and edge cases: ID3 handles nominal attributes; continuous attributes need candidate thresholds (C4.5 sorts values and tests midpoints). Missing values require fractional routing or majority imputation. A zero-gain attribute still gets split unless a threshold stops it. Trees are unstable — a small data change can replace the root split — which is precisely why ensembles of trees (Random Forests, boosting; Module 5) are so effective.
Exam writing tip (from the model paper): state both formulas, compute Entropy(S) once, then tabulate each attribute's subsets, weighted remainder and gain, pick the maximum, and sketch the resulting tree. Include the ID3 pseudocode if asked to "describe the algorithm". Marks are awarded for showing the arithmetic, not just the final attribute name.

Module 2 Synthesis — Choosing a Model and Linking to Evaluation

Exam synthesis

Regression and classification share the same learning loop — choose a hypothesis class, a loss and an optimiser — and differ mainly in the output type and loss. Naive Bayes and logistic regression are both probabilistic linear models but differ in how they obtain probabilities: NB uses counted conditional independences (generative, fast, ignores correlations), logistic regression discriminatively learns decision weights by maximising conditional likelihood. Decision trees are non-linear, need no feature scaling, and are interpretable, but high variance; ensembles fix that (Module 5).

Evaluation discipline (Module 5): never report training accuracy as performance. Hold out a test set or use k-fold cross-validation; choose metrics appropriate to the problem (precision for spam, recall for diagnosis, F1 or AUC for imbalance); select hyperparameters by validation, not by the test set; and check residuals or confusion matrices rather than a single scalar. Every "which classifier is better?" answer must mention the metric and the evaluation protocol.
Five-mark answer template for "compare regression and logistic regression": (1) output type (continuous vs probability); (2) model form (both wᵀx, logistic adds sigmoid); (3) loss (squared error vs cross-entropy); (4) training (normal equation / GD vs likelihood + GD); (5) decision (threshold the probability). Regression Diagnostics — R², Adjusted R² and Residual Analysis

Assessing the fit

Fitting a model is not the same as validating it. The coefficient of determination decomposes the total variation of the target into explained and unexplained parts:

\[SS_{\mathrm{tot}}=\sum_i(y_i-\bar y)^2,\quad SS_{\mathrm{res}}=\sum_i(y_i-\hat y_i)^2,\quad R^2=1-\frac{SS_{\mathrm{res}}}{SS_{\mathrm{tot}}}\]

Worked: for y = (2, 3, 5) the mean is 10/3 and SStot = (2 − 3.333)² + (3 − 3.333)² + (5 − 3.333)² = 1.778 + 0.111 + 2.778 = 4.667. From the fitted line of the earlier section SSres = 0.1667. Hence R² = 1 − 0.1667/4.667 = 0.964: 96.4% of the variation is explained. But R² can never decrease when a feature is added, so it cannot be used to compare models of different sizes. Adjusted R² penalises complexity:

\[R^2_{\mathrm{adj}}=1-\frac{(1-R^2)(n-1)}{n-D-1}\]

With n = 3, D = 1 features plus intercept: R²adj = 1 − (0.036)(2)/(3−1−1) = 1 − 0.072 = 0.928. Related criteria used for model selection are AIC = 2D − 2 ln L and BIC = D ln n − 2 ln L; both trade fit against parameter count, BIC more aggressively.

Residual diagnostics: plot residuals eᵢ = yᵢ − ŷᵢ against fitted values. A random horizontal band around zero supports the model; a funnel shape indicates heteroscedasticity (use weighted least squares or transform y); a curve indicates missing non-linearity (add polynomial terms); a time trend indicates autocorrelation. A Q–Q plot checks normality of residuals, which matters for confidence intervals. Outliers with large residuals and high leverage (unusual x) can dominate the fit — inspect them, do not silently delete them.
Assumptions of ordinary least squares, stated compactly: linearity in parameters, independent errors, homoscedastic errors, zero-mean errors, and (for exact inference) normal errors; no perfect multicollinearity. Under these conditions OLS is unbiased and is the best linear unbiased estimator (Gauss–Markov). Violations bias standard errors more often than they bias coefficients — which is why predictions can still be good while p-values are wrong.

Generative vs Discriminative — Where Naive Bayes and Logistic Regression Differ

Conceptual contrast

Both Naive Bayes and logistic regression end with a posterior probability and a class decision, but they get there in opposite ways. A generative model learns P(x | C) and P(C) and then applies Bayes' theorem; a discriminative model learns P(C | x) directly. Naive Bayes is generative, logistic regression discriminative.

PropertyNaive Bayes (generative)Logistic regression (discriminative)
What is modelledP(C) and P(x | C)P(C | x) directly
ParametersOne per feature per class (few)One weight per feature (few, but optimised)
TrainingCounting — no iterationIterative gradient ascent on likelihood
With little dataOften better; strong prior assumptionsCan be unstable; needs optimisation
With lots of dataBias from independence assumptionUsually better asymptotic accuracy
Can generate new samples?Yes, by sampling the learned modelNo
CalibrationOften poorly calibrated (overconfident)Better calibrated probabilities

There is a formal relationship: under a Gaussian naive Bayes model with shared spherical covariance, the resulting posterior has exactly the logistic (sigmoid-of-linear) form. So logistic regression is a less restrictive version of a generative classifier — it learns the same boundary shape without assuming the feature distributions. Practical rule: use Naive Bayes as a fast baseline for text and tiny datasets; move to logistic regression when data is plentiful and calibrated probabilities matter.

Exam writing tip for "compare NB and logistic regression": write the two factorisations (P(C)·Π P(xᵢ|C) versus σ(wᵀx)), state generative versus discriminative, add the one-line covariance relationship, and finish with the data-size rule. Four sentences earn full marks.

Supervised Model Selection — Loss Functions, Convexity and Nested Validation

Exam synthesis

Choosing a supervised model is a search over three spaces at once: the hypothesis class (which family of functions), the loss (what counts as a mistake), and the optimiser (how we search). Examination answers often lose marks by discussing only the first. A complete answer names all three and says how the choice was validated.

ModelHypothesis classLoss optimisedOptimiserConvexity

Logistic regressionSigmoid of affine functionCross-entropyGradient ascent / NewtonConvex

Decision treePiecewise-constant rulesImpurity / gainGreedy recursive splittingNon-convex, greedy
Neural networkComposed non-linear layersCross-entropy / squaredBackprop + SGDNon-convex

Convexity matters because it guarantees that any local minimum is global. Linear regression, logistic regression and SVM all have convex objectives, so their training is reproducible and examinable in closed form or by a well-understood quadratic program. Trees and networks are non-convex and rely on greedy search or random initialisation; multiple restarts and cross-validation are essential.

\[\text{hinge loss: }\ell(y,f(x))=\max\bigl(0,\,1-y f(x)\bigr),\qquad \text{objective: }\frac{1}{2}\lVert w\rVert^{2}+C\sum_i\max(0,1-y_i(w\cdot x_i+b))\]

The hinge loss is zero for any correctly classified point beyond the margin, so SVM training is driven only by points near or inside the margin — the algebraic counterpart of sparsity. Logistic regression's cross-entropy, by contrast, is never exactly zero, so every point contributes a small gradient; this is why logistic regression is slower on very large datasets but yields calibrated probabilities.

Worked model-selection decision

Imagine a dataset with 500 labelled examples and 200 features, of which only 5 are informative. Cross-validated results: ordinary linear regression (with a threshold) scores 0.78 accuracy; Lasso-regularised logistic regression scores 0.89 with 7 non-zero coefficients; a decision tree scores 0.84; an unregularised network scores 0.81. Since Lasso is both the most accurate and selects a sparse model consistent with the known structure, it is the right choice. Note that the comparison is only valid if every model was tuned inside the same folds — otherwise the reported numbers are not comparable.

Nested cross-validation in one paragraph: the outer loop splits data into (say) 5 folds and produces an unbiased estimate of generalisation; within each outer training set, an inner loop chooses hyperparameters; the chosen model is retrained on the entire outer training set and evaluated on the outer test fold. Averaging the outer fold scores gives the final estimate. This prevents the optimism that comes from tuning λ on the same data used to report performance, and is the rigorous version of the train/validation/test split.
Exam writing template for "how would you build and validate a classifier?": (1) split data, standardise features inside folds; (2) choose a model family appropriate to the output type; (3) write the objective and name the optimiser; (4) tune complexity by inner cross-validation; (5) report precision/recall/F1 or AUC, not accuracy alone if classes are imbalanced; (6) state the bias–variance diagnosis and the remediation. Six lines, six marks.
