01

The Perceptron

The simplest neural unit

The perceptron is the simplest kind of artificial neuron — a binary classifier that makes its decision by taking a weighted sum of its inputs and firing (output 1) or not (output 0) depending on whether that sum crosses a threshold. It is the historical starting point of neural-network research and the building block from which multilayer networks are made.

Structure

A perceptron has n inputs x₁ … xₙ, each with a weight w₁ … wₙ, a bias b, and an output. The net input is

\[z = w_1x_1 + w_2x_2 + \dots + w_nx_n + b\]

The output is a step (threshold) function of z:

\[y = 1\ \text{if}\ z\ge 0,\ \text{else}\ y=0\]

Intuition: each weight says how important its input is; the bias is a threshold adjuster. The perceptron fires when the weighted evidence for "1" is strong enough.

Decision boundary

Because the output is decided by w·x + b ≥ 0, the perceptron separates the input space with a linear boundary — a line (in 2-D), a plane (in 3-D), a hyperplane (in higher dimensions).

Key limitation: a single perceptron can only learn linearly separable problems. It cannot learn XOR, for example. This limitation is what motivated multilayer networks and, later, SVMs.

Perceptron Learning

The perceptron learns by correcting its mistakes. For each training example, if the perceptron's prediction is wrong, the weights are updated in the direction that would have made the correct prediction. The rule is simple and incremental — one pass over the data at a time, repeated until no mistakes remain (if the data is linearly separable).

\[w_j \leftarrow w_j + \eta\,(\text{target}-\text{output})\,x_j,\qquad b\leftarrow b+\eta\,(\text{target}-\text{output})\]    ,    b ← b + η · (target − output)

How to read the rule: if the target is 1 and the perceptron output 0 (missed a positive), the error (target − output) is +1, so each weight moves toward the input values — making it more likely to fire next time. If the target is 0 and output is 1 (false alarm), the error is −1, so weights move away from the inputs — making it less likely to fire. The learning rate η controls the step size.
A worked perceptron step: suppose a perceptron has weights w₁=0.5, w₂=−0.3, bias b=0.1, and inputs x₁=1, x₂=1. Then z = 0.5·1 + (−0.3)·1 + 0.1 = 0.3. Since z ≥ 0, the output is 1. If the target was 0 (a mistake), the error is 0 − 1 = −1. With η=0.1, the new weights are w₁ = 0.5 + 0.1·(−1)·1 = 0.4, w₂ = −0.3 + 0.1·(−1)·1 = −0.4, b = 0.1 + 0.1·(−1) = 0.0. The perceptron is now less likely to fire on (1,1).

\(\text{Worked — forward pass: }x_1=1,\ x_2=3,\ w_1=0.3,\ w_2=0.1;\ \text{binary step activation}.\)

Inputs x₁=1, x₂=3 with weights w₁=0.3, w₂=0.1; output neuron uses a binary step activation.

\[y_{\text{in}}=1\cdot0.3+3\cdot0.1=0.5\]

02

Multilayer Feedforward Network

Stacking neurons

A multilayer feedforward network (also called a multilayer perceptron, MLP) is a network of perceptrons arranged in layers: an input layer, one or more hidden layers, and an output layer. Information flows forward — from input, through the hidden layers, to the output. Unlike a single perceptron, a multilayer network can learn non-linear decision boundaries, because the hidden layers combine several linear splits.

Architecture

Each neuron in a hidden or output layer receives inputs from all neurons in the previous layer. A network with L layers has weights connecting each layer to the next. The first layer holds the raw inputs; the last layer produces the output (one neuron per class for classification, one or more for regression).

Why "feedforward": there are no cycles — connections go only forward from one layer to the next. This is what makes backpropagation (the training algorithm) a clean, layer-by-layer computation.

Universal approximation

A network with at least one hidden layer and a non-linear activation can approximate any continuous function to arbitrary accuracy, given enough hidden neurons. This is the theoretical reason multilayer networks are so powerful — they are not limited to linear boundaries the way a single perceptron is.

The catch: "enough hidden neurons" can be a lot, and training such a network is non-trivial — which is where backpropagation comes in.
A simple 3-layer network: 2 inputs → 4 hidden neurons → 1 output neuron. Each hidden neuron computes a weighted sum of the 2 inputs plus bias, applies an activation, and passes the result to the output neuron. The output neuron does the same with the 4 hidden outputs. The network has 2×4 + 4 = 12 weights plus 4+1 = 5 biases. Training adjusts all 17 numbers to minimise error.

A 2-input, 4-hidden-neuron, 1-output feedforward network. Every neuron in one layer connects to every neuron in the next (fully connected).

Activation Functions

What makes a network non-linear

Each neuron in a multilayer network applies an activation function to its weighted sum z before passing the result on. Without a non-linear activation, a multilayer network would collapse into a single linear transformation — no matter how many layers, the whole thing would be equivalent to one linear model. The activation function is what introduces the non-linearity that gives the network its power.

ActivationFormulaOutput rangeShape / key property
Sigmoid (logistic)f(z) = 1 / (1 + e−z)(0, 1)S-shaped, smooth, bounded. Historically common; saturates at large |z| (gradients vanish).
Tanhf(z) = (ez − e−z) / (ez + e−z)(−1, 1)S-shaped like sigmoid but zero-centred — outputs have mean ≈ 0, which helps the next layer learn.
ReLU (Rectified Linear Unit)f(z) = max(0, z)[0, ∞)Linear for z>0, zero for z≤0. Simple, fast, no saturation for positive z — currently the most used.

Sigmoid (red, 0→1), tanh (blue, −1→1, zero-centred), ReLU (green, 0 for z<0, then linear). The dashed line marks z=0.

Sigmoid

Smooth and differentiable everywhere — nice for gradient-based learning. But it saturates: for large positive z it approaches 1, for large negative z it approaches 0, and in both cases the gradient is near zero. This vanishing gradient slows learning deep in a network.

Tanh

Like sigmoid but zero-centred (mean of outputs near 0), so the 다음 layer receives inputs centred around zero — this tends to make optimisation easier than with sigmoid, whose outputs are all positive. Still saturates at the extremes.

ReLU

The most popular activation today. For z > 0 it is just the identity (f(z)=z), so the gradient is 1 — no vanishing gradient for positive signals. It is sparse (many neurons output exactly 0), and very cheap to compute.

ReLU — the downside

A "dead ReLU" is a neuron that, due to its weights, always receives z ≤ 0 — it outputs 0 forever and never updates (gradient is 0 on the negative side). Also, ReLU is not smooth at z=0 (the derivative jumps), though in practice this rarely matters.

One way tanh is easier than logistic (CO3-Q4): tanh outputs are centred around zero (range −1 to +1), so the inputs to the next layer have mean near zero. Logistic outputs are all positive (range 0 to 1), so they push the next layer's weighted sums consistently positive or negative — this can create zig-zag gradient updates and slow convergence. The zero-centred property of tanh is one concrete reason it can train a bit faster than sigmoid in some networks.
ReLU advantage vs tanh (CO3-Q5a): for z > 0, ReLU's gradient is exactly 1 — it never vanishes for positive signals, so deep networks with ReLU tend to train much faster than with saturating activations like tanh. ReLU is also sparse and computationally cheaper. ReLU disadvantage vs tanh (CO3-Q5b): a dead ReLU (a neuron stuck outputting 0 because its weighted input is always ≤ 0) stops learning entirely, whereas tanh's smooth, everywhere-nonzero gradient means neurons keep updating — and tanh is bounded and smooth, which can be stabilising.

Backpropagation

How a network learns

Backpropagation (short for "backward propagation of errors") is the algorithm that trains a multilayer network. The idea is simple in principle: compare the network's output to the true answer, measure the error, and then propagate that error backward through the layers to figure out how much each weight contributed to the mistake — and adjust the weights to reduce it.

The basic idea (CO3, Part B Q16a — 10 marks): backpropagation is gradient descent applied to a network, where the gradient of the error with respect to each weight is computed efficiently by the chain rule of calculus, working backward from the output layer to the input layer. For each weight, we compute how the total error changes if we nudge that weight — and step the weight in the opposite direction. The "backward" part is the chain-rule pass: the error at a neuron is the weighted sum of the errors at the neurons it feeds into, multiplied by the derivative of its activation.

The algorithm in words

  1. Forward pass: feed an input through the network, layer by layer, to get the output prediction.
  2. Compute the error: compare the output to the true target using a loss function (e.g. squared error for regression, cross-entropy for classification).
  3. Backward pass (chain rule): starting at the output, compute the gradient of the error with respect to each neuron's output, then with respect to each weight and bias, moving backward layer by layer. Each neuron's "error signal" is the weighted sum of the error signals of the neurons it connects to, times its own activation derivative.
  4. Update weights: adjust every weight and bias by a small step opposite to its gradient (learning rate η).
  5. Repeat for each training example (or batch), over many epochs, until the error is small enough.
Why it works: the chain rule lets us reuse computations. The gradient for a weight in an early layer depends on the gradients of all the later layers — backpropagation computes all of these in one backward sweep, rather than estimating each gradient separately. That is what makes training a network with thousands or millions of weights feasible.

Illustrative example — a tiny network

Consider a network with 1 input x, 1 hidden neuron h, and 1 output y. Weights: input→hidden = w₁, hidden→output = w₂; biases b₁, b₂; activation f (say sigmoid) at the hidden neuron, and identity at the output. Given a training input x and target t:

\[h = f(w_1x + b_1),\quad y = w_2h + b_2,\quad \text{error } E = \tfrac{1}{2}(y-t)^2\]   ,   y = w₂h + b₂   ,   error E = ½(y − t)²

The backpropagation steps compute:

\[\frac{\partial E}{\partial y} = (y-t) \;\to\; \frac{\partial E}{\partial w_2} = (y-t)\cdot h \;\to\; \frac{\partial E}{\partial b_2} = (y-t)\]  →  ∂E/∂w₂ = (y−t)·h  →  ∂E/∂b₂ = (y−t)

\[\frac{\partial E}{\partial h} = (y-t)\cdot w_2 \;\to\; \frac{\partial E}{\partial z_1} = (y-t)\cdot w_2\cdot f'(z_1) \;\to\; \frac{\partial E}{\partial w_1} = (y-t)\cdot w_2\cdot f'(z_1)\cdot x\]  →  ∂E/∂z₁ = (y−t)·w₂·f′(z₁)  →  ∂E/∂w₁ = (y−t)·w₂·f′(z₁)·x

Reading this: the error signal (y−t) starts at the output. It flows back through w₂ to the hidden neuron (giving ∂E/∂h), is scaled by the hidden neuron's activation derivative f′(z₁) (the chain rule), and then flows back through x to the input weight w₁. Each weight's gradient is the error signal at the neuron it feeds, times the input that weight multiplies. The weights are then updated: w₁ ← w₁ − η·∂E/∂w₁, and similarly for the others.

Support Vector Machines — Introduction

The maximum-margin idea

A Support Vector Machine (SVM) is a powerful classifier that works on a simple but deep principle: among all the lines (or planes, hyperplanes) that separate two classes, pick the one that leaves the widest possible gap — the maximum margin — between the classes. The points that sit right on the edge of that gap are the support vectors; they are the only points that matter for defining the boundary.

Maximum margin

Imagine two clouds of points, one labelled +1, one labelled −1, separated by a gap. A line right down the middle of the gap is the maximum-margin hyperplane. The margin is the perpendicular distance from the hyperplane to the nearest point of either class. Maximising this margin gives the classifier the best chance of handling new, unseen points correctly.

Why maximise the margin: a wider margin means the boundary is farther from the data points, so small errors or noise in new data are less likely to flip the prediction. It is a formal way of preferring a simple, robust separator over one that threads the needle between the points.

Support vectors

The support vectors are the training points that lie on (or inside, for soft margin) the margin boundaries. They are the "critical" points — if you removed any other point, the max-margin hyperplane would not change. The whole classifier is built from (and named after) these few support vectors.

Three properties of the SVM solution (CO3-Q1): (1) sparsity — the solution depends only on the support vectors, not on the other training points; (2) maximum margin — the hyperplane is the one that maximises the margin; (3) the solution is the unique maximum-margin separator for a given kernel and soft-margin parameter (under the standard convex formulation).

The solid green line is the maximum-margin hyperplane; the dashed lines are the margin boundaries. The circled points on the margin are the support vectors — the only points the boundary depends on.

The Mathematics — Maximum Margin Classification

The optimisation problem

The SVM is not just a good idea — it is a clean mathematical optimisation. We want the hyperplane w·x + b = 0 that separates the classes with the largest possible margin. The margin turns out to be 2 / ||w||, so maximising the margin is the same as minimising ||w|| (or, more conveniently, ½||w||²). The constraint is that every point must be on the correct side of the margin.

The constraints: for each training point xᵢ with label yᵢ ∈ {+1, −1}, we require yᵢ(w·xᵢ + b) ≥ 1. This says: the signed distance from the point to the hyperplane, times the label, is at least 1. Points with y=+1 must satisfy w·x+b ≥ 1; points with y=−1 must satisfy w·x+b ≤ −1. The points that satisfy this with equality (yᵢ(w·xᵢ+b) = 1) are exactly the support vectors on the margin.
Primal (hard-margin) optimisation:

\[\text{minimise}\ \tfrac{1}{2}\,\lVert w\rVert^{2}\]

subject to   \[y_i\,(w\cdot x_i + b) \ge 1,\quad \text{for all }i\]   ,   for all i

Reading it: we search over all possible (w, b) for the one that makes ½||w||² as small as possible while satisfying every point's margin constraint. Small ||w|| means a wide margin (margin = 2/||w||). This is a convex quadratic-programming problem — it has a unique global minimum (for a given separable dataset), and the solution is the maximum-margin hyperplane.
From primal to dual (the key step for kernels): introducing Lagrange multipliers αᵢ ≥ 0 for each constraint and applying the Karush-Kuhn-Tucker conditions leads to the dual problem — an equivalent optimisation that involves only the pairwise dot products of the training points:

maximise   \[\max_{\alpha}\ \sum_i\alpha_i - \tfrac{1}{2}\sum_i\sum_j\alpha_i\alpha_j y_i y_j\,(x_i\cdot x_j)\]

subject to   \[0\le\alpha_i\le C\ \text{(soft margin)},\quad \sum_i\alpha_i y_i = 0\]   (soft margin)   ,   Σᵢ αᵢ yᵢ = 0

Why this matters: in the dual, the training points only ever appear as dot products xᵢ·xⱼ. That is the door that opens to the kernel trick — if we can compute dot products in some (possibly very high-dimensional) feature space without ever constructing the features, we can plug them straight into the dual and get a maximum-margin classifier in that feature space. The αᵢ that are non-zero at the solution are the support vectors.
Recovering the hyperplane: once we have the αᵢ, the weight vector is w = Σᵢ αᵢ yᵢ xᵢ (a weighted combination of the support vectors only — the αᵢ for non-support vectors are zero). The decision for a new point x is: sign( Σᵢ αᵢ yᵢ (xᵢ·x) + b ). The bias b is recovered from any support vector on the margin.
Soft margin — the C parameter: the hard-margin formulation only works when the data is perfectly separable. Real data is not. The soft-margin SVM relaxes the constraint by allowing some points to violate the margin, controlled by slack variables ξᵢ ≥ 0 and a penalty parameter C:

\[\text{minimise}\ \tfrac{1}{2}\lVert w\rVert^{2}+C\sum_i\xi_i\]

subject to   \[y_i\,(w\cdot x_i + b)\ge 1-\xi_i,\quad \xi_i\ge 0\]   ,   ξᵢ ≥ 0

What C does: C is the trade-off between a wide margin and making fewer classification errors. Large C heavily penalises margin violations — the model tries hard to classify every training point correctly, risking a narrow margin and overfitting. Small C is more tolerant of violations — it prefers a wider margin, which can generalise better but may allow some training errors. Choosing C (usually by cross-validation) is a central part of using an SVM in practice.

Non-Linear SVM & Kernels

The kernel trick

A linear SVM can only draw a straight line (or plane). But most real problems are not linearly separable — the classes are tangled. The kernel trick lets an SVM draw a non-linear boundary without ever leaving the comfortable world of dot products: we map the data into a higher-dimensional feature space where it becomes linearly separable, and run a linear SVM there — but we do it implicitly, through a kernel function, never constructing the high-dimensional features.

The kernel trick (CO3-Q2 — why use a kernel instead of projecting directly?): to use a feature space, you would normally have to compute the mapping φ(x) for every point and then take dot products φ(xᵢ)·φ(xⱼ). But the feature space can be very high-dimensional — even infinite-dimensional (as with the RBF kernel). Explicitly constructing and storing φ(x) is impossible or absurdly expensive. A kernel function K(xᵢ, xⱼ) computes φ(xᵢ)·φ(xⱼ) directly from the original inputs, without ever finding φ. The dual SVM only needs these dot products, so we can replace every xᵢ·xⱼ with K(xᵢ, xⱼ) and the whole algorithm runs in the feature space for free.
How to extend an SVM to use kernels (CO3-Q3): take the dual formulation — in which the inputs appear only as dot products xᵢ·xⱼ — and replace every dot product with K(xᵢ, xⱼ). The optimisation is identical in form; only the "similarity" between points has changed. The decision function becomes sign( Σᵢ αᵢ yᵢ K(xᵢ, x) + b ). You have now trained a maximum-margin classifier in the (implicit) feature space of K, without ever constructing that space.
KernelFormulaFeature-space ideaWhen it fits
LinearK(x, y) = x·yNo mapping — stays in original spaceData is (roughly) linearly separable; fast, interpretable
PolynomialK(x, y) = (x·y + 1)dAll monomials up to degree d — interactions between featuresModerately non-linear problems; d is the polynomial degree

Illustrating the Gaussian kernel (CO3-Q3 second part): with K(x,y) = exp(−||x−y||²), points that are close together in input space have K ≈ 1 (very similar in feature space); points far apart have K ≈ 0. The feature space is infinite-dimensional, and the decision boundary in the original space is a smooth, non-linear curve — the SVM can carve out arbitrarily complex regions, built from the "bumps" of the RBF kernels centred on the support vectors.

Maximum-Margin Hyperplane

Primal

For linearly separable data, the decision boundary is a hyperplane w·x + b = 0. The margin is the distance from the boundary to the nearest point; SVM maximizes it. In the hard-margin case:

\[\text{minimize}\ \tfrac{1}{2}\,\lVert w\rVert^{2}\ \text{subject to}\ y_i(w\cdot x_i+b)\ge 1\ \forall i\]   subject to   yi(w·xi + b) ≥ 1   ∀i

Minimizing ½‖w‖² maximizes the margin (margin = 2/‖w‖). The constraints force every point to be at least 1 unit from the boundary in scaled space.

Support vectors: only the points that sit exactly on the margin (the active constraints) matter. Move any other point and the boundary doesn't change — that is why SVMs are memory-efficient at test time.
09

Soft Margin & the Dual

Real data

Real data isn't perfectly separable, so we allow small violations ξi (slack) and trade them off against margin width with a penalty C:

\[\text{minimize}\ \tfrac{1}{2}\lVert w\rVert^{2}+C\sum_i\xi_i\ \text{s.t.}\ y_i(w\cdot x_i+b)\ge 1-\xi_i,\ \xi_i\ge 0\]

The dual form (via Lagrange multipliers αi) reveals the kernel trick:

\[\text{maximize}\ \sum_i\alpha_i-\tfrac{1}{2}\sum_i\sum_j\alpha_i\alpha_j y_i y_j\,K(x_i,x_j)\ \text{s.t.}\ 0\le\alpha_i\le C,\ \sum_i\alpha_i y_i=0\]

The classifier becomes f(x) = sign( ΣSV αi yi K(xi, x) + b ).

C controls bias–variance: large C → few violations, narrow margin, risk of overfitting; small C → wider margin, more tolerance, smoother boundary.

The Perceptron — Convergence, Worked Training Trace and the XOR Limitation

Neuron model

The perceptron computes z = Σⱼ wⱼxⱼ + b = w·x + b and fires y = 1 if z ≥ 0, else 0. Its decision boundary w·x + b = 0 is a hyperplane, so the model can only represent linearly separable functions. The training rule corrects each mistake:

\[w\leftarrow w+\eta\,(t-y)\,x,\qquad b\leftarrow b+\eta\,(t-y)\]

When t = y nothing changes. When t = 1, y = 0 the error is +1 and weights move toward the input; when t = 0, y = 1 the error is −1 and weights move away. This is a stochastic gradient step on the perceptron criterion.

Worked trace — learning the AND function

Inputs (0,0), (0,1), (1,0), (1,1) with targets 0, 0, 0, 1. Initialise w = (0, 0), b = 0, η = 1, and use the convention y = 1 when z ≥ 0. Epoch 1: (0,0) gives z = 0 → y = 1, target 0, error −1, so b becomes −1; (0,1) gives z = −1 → y = 0 (correct); (1,0) gives z = −1 → y = 0 (correct); (1,1) gives z = −1 → y = 0, target 1, error +1, so w becomes (1, 1) and b becomes 0. Two mistakes were made.

Epoch 2: (0,0): z = 0 → y = 1, error −1 → b = −1, w = (1,1). (0,1): z = 1 − 1 = 0 → y = 1, error −1 → w = (1,0), b = −2. (1,0): z = 1 − 2 = −1 → y = 0 (correct). (1,1): z = 1 − 2 = −1 → y = 0, error +1 → w = (2,1), b = −1. Continuing in this way (three mistakes in epoch 3, two in epoch 4, one in epoch 5) we reach w = (2, 1), b = −3 at the start of epoch 6 and make zero mistakes: (0,0) → −3, (0,1) → −2, (1,0) → −1, (1,1) → 0 → fires. The boundary 2x₁ + x₂ − 3 = 0 separates AND correctly.

\[\text{Perceptron convergence theorem: if the data is linearly separable with margin }\gamma,\ \text{the number of mistakes is bounded by }\Bigl(\frac{R}{\gamma}\Bigr)^{2}\]

where R bounds the norm of every input vector. The guarantee is finite but can be enormous for a tiny margin — the bound explains why a large margin (Module 3's SVM) is desirable.

Why XOR cannot be learned

XOR has outputs 0 for (0,0) and (1,1), and 1 for (0,1) and (1,0). For a linear model y = 1[w₁x₁ + w₂x₂ + b ≥ 0] the four inequalities are b < 0, w₁ + w₂ + b < 0, w₂ + b ≥ 0, and w₁ + b ≥ 0. Adding the last two gives w₁ + w₂ + 2b ≥ 0, but the first two give w₁ + w₂ + 2b < 0 — a contradiction. No choice of (w₁, w₂, b) works, so the function is not linearly separable. Historically this observation (Minsky & Papert, 1969) stalled neural-network research until hidden layers and backpropagation showed that a two-layer network can represent XOR by combining two linear splits.

Exam tip: a one-sentence proof of the XOR limitation — "the positive points (0,1),(1,0) and negative points (0,0),(1,1) are not linearly separable because their convex hulls intersect at (0.5, 0.5)" — is a compact, high-scoring answer.

Forward Pass Through a Multilayer Network — Every Number Worked Out

MLP mechanics

In a fully connected layer l, the pre-activation of unit j is zⱼ(l) = Σᵢ wⱼᵢ(l) aᵢ(l−1) + bⱼ(l), and the activation is aⱼ(l) = f(zⱼ(l)). Writing it in matrix form, a(l) = f(W(l)a(l−1) + b(l)). A network with one hidden layer and sigmoid activations therefore computes

\[\hat y=\sigma\bigl(W^{[2]}\,\sigma(W^{[1]}x+b^{[1]})+b^{[2]}\bigr)\]

Worked 2 → 2 → 1 network

Input x = (1, 2). Hidden layer: w[1] = [[0.5, −0.5], [1.0, 0.0]], b[1] = (0, 0). Output layer: w[2] = (1.0, −1.0), b[2] = 0. Sigmoid at every unit.

\[z^{[1]}_1=0.5(1)+(-0.5)(2)=-0.5\;\Rightarrow\;a^{[1]}_1=\sigma(-0.5)=0.3775\]
\[z^{[1]}_2=1.0(1)+0(2)=1.0\;\Rightarrow\;a^{[1]}_2=\sigma(1.0)=0.7311\]
\[z^{[2]}=1.0(0.3775)-1.0(0.7311)=-0.3536\;\Rightarrow\;\hat y=\sigma(-0.3536)=0.4125\]

Every hidden neuron is a soft feature detector: the first responds to the difference x₁ − x₂, the second to x₁. The output neuron subtracts them. A threshold at 0.5 classifies this input as class 0.

Counting parameters

A layer with n inputs and m neurons has m·n weights and m biases. A 784 → 64 → 10 network has 64·784 + 64 = 50,240 parameters in the first layer and 10·64 + 10 = 650 in the second, for 50,890 total. More layers and more neurons increase capacity (the ability to represent complicated functions) but also variance and the data needed to train — the familiar bias–variance trade-off.

Universal approximation theorem (state it carefully): a feedforward network with one hidden layer, a non-linear activation, and sufficiently many units can approximate any continuous function on a compact domain to arbitrary accuracy. It is an existence theorem: it says such a network exists, not that gradient descent will find it, nor how wide the layer must be. Deep networks often represent the same function with far fewer units than a shallow one — this is the practical reason for depth.
Architecture checklist: number of input units = number of features; number of output units = 1 for binary classification/regression, K with softmax for K-class problems; hidden-layer size chosen by validation; activation ReLU (or a variant) in hidden layers; sigmoid/softmax at the output for probabilities. Always normalise inputs — large input scales blow up the pre-activations and saturate sigmoid/tanh units.

Activation Functions — Derivatives, Saturation and a Decision Table

Non-linearity

Without non-linear activations, a stack of linear layers collapses: f(W₂(W₁x + b₁) + b₂) = W̃x + b̃, a single linear map. Activations supply the non-linearity that makes depth useful. Backpropagation needs their derivatives, so learn both the function and its derivative.

Numerical derivative check

At z = 1: sigmoid = 0.7311 and f′ = 0.7311 × 0.2689 = 0.1966; tanh = 0.7616 and f′ = 1 − 0.7616² = 0.4200; ReLU = 1 and f′ = 1. At z = −5: sigmoid ≈ 0.0067 and f′ ≈ 0.0067 — nearly zero: the unit is saturated and learning stalls. At z = 5, sigmoid ≈ 0.9933 and f′ ≈ 0.0067 for the same reason. ReLU at z = 5 still has derivative 1, which is why it trains deep networks faster.

Vanishing gradients: in a deep network the gradient of an early layer is a product of many activation derivatives. If each sigmoid derivative is around 0.1, after ten layers the product is 10⁻¹⁰ — effectively zero. ReLU (derivative 1 for positive inputs) avoids this on the positive path; residual/skip connections and careful initialisation are the other standard remedies.
Dead ReLU: if a unit's weights always produce z ≤ 0, its output and its gradient are both zero forever — it can never recover. Leaky ReLU and variants (PReLU, ELU) give a small nonzero negative gradient. ReLU is nonetheless the default because it is cheap and works well in practice.
Answering the CO questions: "Why is tanh sometimes easier than logistic?" → zero-centred outputs avoid consistently positive inputs to the next layer and reduce zig-zag updates. "Advantage of ReLU over tanh?" → no saturation for z > 0, so no vanishing gradient on positive signals and faster training; sparse, cheap. "Disadvantage?" → dead ReLUs stop learning and ReLU is not differentiable at zero. Give one numerical derivative in each answer to show you can compute, not just recite.

Backpropagation — The Chain Rule Worked with Actual Numbers

Training algorithm

Backpropagation is gradient descent plus the chain rule, organised so that each gradient is computed once and reused. Define the error signal δⱼ(l) = ∂E/∂zⱼ(l). For an output layer with squared error E = ½(y − t)², δ(L) = (y − t) f′(z(L)); for a hidden layer, δ(l) = (W(l+1)ᵀδ(l+1)) ⊙ f′(z(l)). Then

\[\frac{\partial E}{\partial W^{[l]}_{ji}}=\delta^{[l]}_j\,a^{[l-1]}_i,\qquad \frac{\partial E}{\partial b^{[l]}_j}=\delta^{[l]}_j\]

i.e. gradient = error signal at the neuron × input arriving through that weight — the same "delta rule" shape as the perceptron and logistic updates.

Full numerical example

One input x = 0.5, one hidden neuron, one output. w₁ = 0.4, b₁ = 0.1, w₂ = 0.6, b₂ = 0.2; sigmoid at both units; target t = 0.8.

1) Forward:
   z1 = 0.4*0.5 + 0.1 = 0.3 ;  h = sigmoid(0.3) = 0.574443
   z2 = 0.6*0.574443 + 0.2 = 0.544666 ;  y = sigmoid(z2) = 0.632897
   E  = 0.5*(0.632897 - 0.8)^2 = 0.013962

2) Output error signal:
   delta2 = (y - t)*y*(1-y) = (-0.167103)*(0.632897)*(0.367103) = -0.038824

3) Hidden error signal (error travels backward through w2, then the sigmoid derivative):
   delta1 = delta2*w2*h*(1-h) = (-0.038824)*(0.6)*(0.574443)*(0.425557) = -0.005695

4) Gradients:
   dE/dw2 = delta2*h = -0.022302 ;  dE/db2 = delta2 = -0.038824
   dE/dw1 = delta1*x = -0.002847 ;  dE/db1 = delta1 = -0.005695

5) Update with eta = 0.5:
   w1 = 0.4 - 0.5*(-0.002847) = 0.401424
   w2 = 0.6 - 0.5*(-0.022302) = 0.611151
   b1 = 0.1 + 0.5*0.005695 = 0.102848 ;  b2 = 0.2 + 0.5*0.038824 = 0.219412

All four gradients are negative, so every parameter increases — the network's output must rise toward the target 0.8, which it does. (With sigmoid output and cross-entropy loss the output δ simplifies to (y − t), removing the saturating f′ term and often training faster.)

Why backprop is efficient: naively estimating each of P parameters by perturbing it requires P forward passes per example. Backprop computes all P gradients in roughly the cost of one forward pass plus one backward pass, because the chain rule lets a layer's δ be reused for every weight entering that layer. That is the reason networks with millions of parameters are trainable.
Practical issues to mention: use mini-batches for stable gradients; initialise weights small and random (e.g. Xavier/He) to break symmetry — with all-zero weights every hidden unit learns the same thing; clip gradients when they explode; monitor the loss curve; use a separate validation set for early stopping. Early stopping is a form of regularisation (Module 5's bias–variance link).

SVM Margin Geometry — Why 2/‖w‖ and Why Minimise ½‖w‖²?

Mathematics

A hyperplane is w·x + b = 0. The signed perpendicular distance from a point x₀ to it is (w·x₀ + b)/‖w‖ — derived by projecting the vector from the plane to x₀ onto the unit normal w/‖w‖. Scale the canonical constraint so the closest points of each class satisfy w·x + b = +1 and −1. The two margin planes are therefore separated by

\[\text{margin}=\frac{(+1)-(-1)}{\lVert w\rVert}=\frac{2}{\lVert w\rVert}\]

Maximising 2/‖w‖ is the same as minimising ‖w‖, and minimising ½‖w‖² is mathematically equivalent while giving a clean derivative w. The ½ is a pure convenience, exactly like the ½ in least squares.

Worked geometry

Let the separating line be 3x₁ + 4x₂ − 5 = 0. Then ‖w‖ = √(9 + 16) = 5, the margin is 2/5 = 0.4, and the distance from the origin to the line is |−5|/5 = 1. If we multiply every coefficient by 10 the line is unchanged but the constraint values scale too, so the canonical rescaling w ← w/5 restores w = (0.6, 0.8), b = −1, with ‖w‖ = 1 and margin 2. This demonstrates why the scale of w must be fixed by the constraint yᵢ(w·xᵢ + b) ≥ 1 — otherwise the same geometric hyperplane has infinitely many parameter representations.

From the primal problem, form the Lagrangian L(w, b, α) = ½‖w‖² − Σᵢ αᵢ[yᵢ(w·xᵢ + b) − 1]. Setting ∂L/∂w = 0 gives w = Σᵢ αᵢyᵢxᵢ; setting ∂L/∂b = 0 gives Σᵢ αᵢyᵢ = 0. Substituting back removes w and b entirely and yields the dual:

\[\max_{\alpha\ge 0}\;\sum_i\alpha_i-\frac{1}{2}\sum_i\sum_j\alpha_i\alpha_j y_i y_j(x_i\cdot x_j)\quad\text{s.t.}\quad\sum_i\alpha_i y_i=0\]

The KKT complementarity condition αᵢ[yᵢ(w·xᵢ + b) − 1] = 0 says: either αᵢ = 0 (the point is irrelevant) or the point lies exactly on the margin (yᵢ(w·xᵢ + b) = 1). Points with αᵢ > 0 are the support vectors. This is the mathematical origin of sparsity: the classifier is entirely determined by a few critical points, and moving any non-support vector does not change the boundary.

Worked dual intuition: four points (1,1), (2,2) labelled +1 and (−1,−1), (−2,−2) labelled −1. By symmetry b = 0 and w ∝ (1,1). The nearest points have w·x = 2‖w‖/√2; setting the canonical value to 1 gives w = (0.5, 0.5) and ‖w‖ = √0.5 ≈ 0.707, hence margin = 2/0.707 ≈ 2.83. All four points are support vectors. A point far away, say (10, 10), would have α = 0 and could be deleted with no effect on the solution.

Soft Margin, the C Parameter and Kernel Arithmetic

Non-linear SVM

Real data overlaps, so hard constraints are relaxed with slack variables ξᵢ ≥ 0: yᵢ(w·xᵢ + b) ≥ 1 − ξᵢ and the objective becomes min ½‖w‖² + CΣξᵢ. C is the cost of a unit violation: C → ∞ recovers the hard margin; small C tolerates violations and widens the margin. In the dual the only change is the box constraint 0 ≤ αᵢ ≤ C. Since C trades margin width against training errors it directly controls bias–variance — select it by cross-validation, typically on a logarithmic grid.

The dual contains data only through inner products. Replacing xᵢ·xⱼ by a kernel K(xᵢ, xⱼ) = φ(xᵢ)·φ(xⱼ) gives a linear separator in the feature space of φ without ever computing φ — the kernel trick. This is possible because the optimisation and the final decision function need nothing but dot products. The three standard kernels are:

\[\text{linear }K(x,y)=x\cdot y;\qquad \text{polynomial }K(x,y)=(x\cdot y+c)^{d};\qquad \text{RBF }K(x,y)=e^{-\gamma\lVert x-y\rVert^{2}}\]

Worked polynomial kernel — explicit feature space

With c = 1, d = 2, x = (1, 2) and y = (3, 4): x·y = 1·3 + 2·4 = 11, so K = (11 + 1)² = 144. To verify that this really is a dot product in a lifted space, use φ(x₁, x₂) = (x₁², x₂², √2 x₁x₂, √2 x₁, √2 x₂, 1). Then φ(x) = (1, 4, 2√2, √2, 2√2, 1) and φ(y) = (9, 16, 12√2, 3√2, 4√2, 1). Their dot product is 9 + 64 + 48 + 6 + 16 + 1 = 144. The kernel saved us from constructing six-dimensional vectors — and for the RBF kernel the feature space is infinite-dimensional, where explicit construction is impossible.

Worked RBF kernel

With γ = 1, x = (0, 0) and y = (1, 1): ‖x − y‖² = 1 + 1 = 2, so K = e−2 = 0.1353. Points a distance 0 apart give K = 1; far apart they give K ≈ 0. Each support vector therefore contributes a local "bump" around itself, and the decision surface is a sum of such bumps. Small γ (large σ) gives broad bumps and a smooth boundary — high bias; large γ gives narrow bumps and a wiggly boundary — high variance.

Valid kernels: a function is a valid kernel iff its Gram matrix is positive semi-definite (Mercer's condition); otherwise the dual optimisation is not convex and the "feature space" interpretation fails. Linear, polynomial with positive coefficients, and RBF always satisfy it.
Synthesis — SVM vs logistic regression vs neural network: all three learn a decision boundary of the form sign(g(x)). Logistic regression gives a probabilistic linear boundary trained by maximum likelihood; an SVM gives a maximum-margin boundary trained by a convex quadratic program and supports non-linearity via kernels; a neural network learns multiple layers of non-linear features by backpropagation, is far more flexible, but has a non-convex objective and needs much more data. In bias–variance terms: linear models high bias, deep networks high variance, SVMs sit in between with C and γ as the control knobs.
Exam writing tip: for "why use a kernel instead of projecting explicitly?", answer in three steps: (1) the dual uses only dot products; (2) the lifted space can be very high or infinite dimensional; (3) K computes the dot product directly in the original space, giving the same classifier at a fraction of the cost. Add the numerical 144 example and one RBF value to earn full marks.

Training Neural Networks in Practice — Initialisation, Regularisation and Optimisers

Practical training

The theory of backpropagation assumes we can actually make the loss descend. Several engineering choices determine whether that happens. Initialisation: setting all weights to zero makes every hidden unit identical (symmetry is never broken); large initial weights saturate sigmoid/tanh units. Xavier initialisation draws weights with variance 1/nin (or 2/(nin + nout)) for sigmoid/tanh, and He initialisation uses 2/nin for ReLU — both keep the variance of activations roughly constant across layers, preventing exploding or vanishing signals.

\[W\sim\mathcal N\!\left(0,\frac{2}{n_{\mathrm{in}}}\right)\ \text{(He / ReLU)},\qquad W\sim\mathcal N\!\left(0,\frac{1}{n_{\mathrm{in}}}\right)\ \text{(Xavier / tanh)}\]

Optimisers: plain SGD uses one global learning rate. Momentum accumulates an exponentially decaying average of past gradients, vt = βvt−1 + η∇J, and steps along v — this damps oscillation in narrow valleys. RMSProp scales each parameter's step by a running average of its squared gradient. Adam combines momentum and per-parameter scaling; with defaults β₁ = 0.9, β₂ = 0.999 it is the most common choice and usually needs little tuning.

Adam (per parameter, t = iteration):
    m_t = beta1*m_{t-1} + (1-beta1)*g_t        # first moment
    v_t = beta2*v_{t-1} + (1-beta2)*g_t^2      # second moment
    m_hat = m_t / (1 - beta1^t)                # bias correction
    v_hat = v_t / (1 - beta2^t)
    theta = theta - alpha * m_hat / (sqrt(v_hat) + epsilon)
Neural-network regularisation: L2 weight decay adds λΣW² to the loss (the same Ridge penalty as Module 2); dropout randomly zeroes a fraction p of hidden activations each batch, which prevents brittle co-adaptation of neurons and is equivalent to training an ensemble of thinned networks; data augmentation creates extra training examples by label-preserving transforms; early stopping halts training when validation loss stops improving; batch normalisation standardises activations within each mini-batch and has a mild regularising effect. All of these control variance, and all reappear as practical versions of the bias–variance trade-off.
Watch the loss curve: training Loss decreasing but validation loss rising = overfitting (stop early or regularise); both flat and high = underfitting or a learning-rate problem; NaN loss = learning rate too large or exploding gradients (clip them); large gap between training and validation accuracy = high variance. These diagnostics are identical in spirit to the learning-curve reasoning of Module 5.
SVM practical checklist for comparison: scale features (the kernel depends on distances), start with an RBF kernel and standardise γ = 1/(2σ²), tune (C, γ) on a logarithmic grid by cross-validation, and inspect how many support vectors remain — hundreds of thousands suggests overfitting or poor scaling. SVMs excel with clear margins and moderate data; deep nets win when there is enough data to learn features automatically.
