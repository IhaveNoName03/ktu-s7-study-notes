CO1 · Q13 marks
A coin is tossed 100 times and lands heads 62 times. What is the maximum likelihood estimate for θ, the probability of heads?
AnswerBernoulli likelihood L(θ) = θ^62 (1−θ)^38. Log-likelihood ℓ = 62 ln θ + 38 ln(1−θ). dℓ/dθ = 62/θ − 38/(1−θ) = 0 → 62(1−θ) = 38θ → 62 = 100θ → θ̂ = 62/100 = 0.62. The MLE is simply the observed proportion of heads.

Full derivation and checks. The binomial model is appropriate because each toss is an independent Bernoulli trial with the same unknown probability θ. The likelihood is the product of the per-toss probabilities: heads contributes a factor θ and tails a factor (1−θ), so with 62 heads and 38 tails L(θ) = θ^62(1−θ)^38. Maximising L directly is awkward, so we maximise the log-likelihood ℓ(θ) = 62 ln θ + 38 ln(1−θ); the logarithm is monotonic, so the maximiser is unchanged, and the product becomes a sum that is easy to differentiate. Setting the score dℓ/dθ = 62/θ − 38/(1−θ) = 0 and clearing denominators gives 62(1−θ) = 38θ, hence 62 = 100θ and θ̂ = 0.62. The second derivative d²ℓ/dθ² = −62/θ² − 38/(1−θ)² is strictly negative for 0 < θ < 1, confirming a maximum rather than a minimum. Common mistakes: writing the likelihood as θ^38(1−θ)^62 (swapping heads and tails), forgetting the log and trying to differentiate the raw product, or reporting 38/100. The answer is the observed proportion of heads — the MLE of a Bernoulli parameter is always the sample mean of the 0/1 outcomes.

CO1 · Q23 marks
Suppose data x₁,…,xₙ are i.i.d. drawn from an exponential distribution exp(λ). Find the maximum likelihood for λ.
AnswerExponential density f(x;λ) = λ e^{−λx}. Likelihood L(λ) = λⁿ e^{−λ Σxᵢ}. Log-likelihood ℓ = n ln λ − λ Σxᵢ. dℓ/dλ = n/λ − Σxᵢ = 0 → λ̂ = n / Σxᵢ = 1 / x̄. The MLE is the reciprocal of the sample mean.

Derivation and interpretation. The exponential distribution with rate λ has density f(x;λ) = λ e^(−λx) for x ≥ 0; λ is the rate and 1/λ is the mean. For i.i.d. observations the joint density (likelihood) is the product λⁿ·exp(−λ Σxᵢ). Taking logs turns the product into ℓ(λ) = n ln λ − λ Σxᵢ. Differentiating gives the score n/λ − Σxᵢ; setting it to zero yields λ̂ = n/Σxᵢ = 1/x̄, the reciprocal of the sample mean. The second derivative −n/λ² < 0 confirms a maximum. Assumptions and pitfalls: all xᵢ must be non-negative (otherwise the density is zero), the observations must be independent, and λ > 0. A frequent error is to write λ̂ = x̄ or λ̂ = Σxᵢ/n — the exponential MLE is the inverse of the mean, because a larger mean implies a smaller rate. Sanity check: if the average waiting time is 5 units, the estimated rate is 0.2 events per unit. The same algebra gives the MLE of a Poisson rate as the sample mean, so keep the two distinct: exponential rate = 1/mean, Poisson rate = mean.

CO1 · Q33 marks
Suppose x₁,…,xₙ are i.i.d. samples from a distribution with density f(x;θ) = (θ+1) x^θ for 0 ≤ x ≤ 1. Find the MLE for θ.
AnswerL(θ) = Π (θ+1) xᵢ^θ = (θ+1)ⁿ Π xᵢ^θ. ℓ = n ln(θ+1) + θ Σ ln xᵢ. dℓ/dθ = n/(θ+1) + Σ ln xᵢ = 0. Since ln xᵢ ≤ 0, let S = Σ ln xᵢ (negative). Then n/(θ+1) = −S → θ̂ = −n/S − 1 = −n/Σ ln xᵢ − 1.

Worked steps. The density f(x;θ) = (θ+1)x^θ on [0,1] is a member of the beta family and is a valid density because ∫₀¹(θ+1)x^θ dx = 1 for θ > −1. For a sample, L(θ) = ∏(θ+1)xᵢ^θ = (θ+1)ⁿ ∏xᵢ^θ, so ℓ(θ) = n ln(θ+1) + θ Σ ln xᵢ. Differentiate: dℓ/dθ = n/(θ+1) + Σ ln xᵢ. Since 0 ≤ xᵢ ≤ 1, each ln xᵢ ≤ 0, so S = Σ ln xᵢ is negative and the equation has a valid positive solution. Setting the score to zero gives n/(θ+1) = −S, hence θ̂ = −n/S − 1 = −n/Σ ln xᵢ − 1. The second derivative −n/(θ+1)² is negative, confirming a maximum. Common mistakes: treating Σ ln xᵢ as positive (it is negative here), dropping the θ+1 factor, or giving θ̂ = −Σ ln xᵢ/n. Boundary case: if any xᵢ = 1 then ln xᵢ = 0, which is fine; if all xᵢ = 1 the MLE is unbounded, but with the stated data the formula applies.

CO1 · Q45 marks
Find the MLE and MAP estimator for the mean of a univariate normal distribution (known variance σ², unknown mean µ), with a normal prior mean ν, variance β². What happens as N → ∞?
AnswerData xᵢ ~ N(µ, σ²), prior µ ~ N(ν, β²).
MLEµ̂_MLE = x̄ (sample mean).
MAPmaximise log-likelihood + log-prior: −½σ²Σ(xᵢ−µ)² − ½β²(µ−ν)². Differentiating: Σ(xᵢ−µ)/σ² − (µ−ν)/β² = 0 → µ̂_MAP = (σ⁻² N x̄ + β⁻² ν) / (σ⁻² N + β⁻²) = a weighted average of the data mean and the prior mean.
As N→∞the data term dominates the prior term (σ⁻²N grows), so µ̂_MAP → x̄ = µ̂_MLE. With enough data, the prior stops mattering and MAP converges to MLE. This is the classic "frequentist limit" of Bayesian estimation.

Why MAP shrinks the mean and when the prior vanishes. The MAP estimate maximises the posterior p(µ | x) ∝ p(x | µ)p(µ). Taking logs gives the objective −(1/2σ²)Σ(xᵢ−µ)² − (1/2β²)(µ−ν)² plus constants. Differentiating and setting to zero: (1/σ²)Σ(xᵢ−µ) − (1/β²)(µ−ν) = 0, i.e. (N/σ²)x̄ + (ν/β²) = µ(N/σ² + 1/β²). Hence µ̂_MAP = [Nσ⁻² x̄ + β⁻²ν]/[Nσ⁻² + β⁻²]. This is a precision-weighted average of the data mean x̄ and the prior mean ν: the weights are the precisions N/σ² (data) and 1/β² (prior). Equivalently µ̂_MAP = w·x̄ + (1−w)ν with w = Nβ²/(Nβ² + σ²). Limiting behaviour: as N → ∞ the data precision N/σ² dominates, w → 1, and µ̂_MAP → x̄ = µ̂_MLE. If instead β² → ∞ (a vague prior), the same limit holds for any N — MAP reduces to MLE. If β² → 0 (a certain prior), µ̂_MAP → ν regardless of the data. Connection to regularisation: the quadratic prior contributes exactly a ridge/L2 penalty on µ, which is why MAP with a Gaussian prior equals L2-regularised least squares. Common mistake: writing µ̂_MAP = (N x̄ + ν)/(N+1) — that is only correct when σ² = β²; keep the precisions explicit in the exam.

Why the posterior is Gaussian and how to read the weights. Because both the likelihood and the prior are Gaussian in µ, the posterior p(µ|x) is also Gaussian; its mean is the MAP estimate and its variance is 1/(Nσ⁻² + β⁻²), which shrinks as data accumulate. The word 'precision-weighted' is worth spelling out: precision is the reciprocal of variance, and the estimate is the average of x̄ and ν weighted by their precisions. A high data precision N/σ² (large N or small measurement noise) makes the estimate trust the sample; a high prior precision 1/β² makes it trust the prior. Quick numerical sense-check: if σ² = β² = 1, N = 9 and x̄ = 10 with ν = 0, then µ̂ = 9×10/(9+1) = 9 — the estimate is pulled nine-tenths of the way toward the data and one-tenth toward the prior. Common mistake: averaging x̄ and ν with equal weights regardless of N and the variances — the weighting is the entire point of the question.

CO2 · Q13 marks
Linear regression on N points, D attributes, D ≈ 100. Would you prefer the closed-form solution or gradient descent?
AnswerClosed form needs (XᵀX)⁻¹ — a D×D matrix. With D≈100 that is 100×100 (cheap, 10⁴ entries). The cost is O(D³) ≈ 10⁶ — trivial. With "all D attributes linearly independent" and only N data points, if N is comparable to or smaller than D, (XᵀX) is invertible only if N≥D. Prefer closed form here (D=100 is tiny; gradient descent's advantage appears when D is huge, e.g. millions of features, or data doesn't fit in memory).

Complexity reasoning to show in the answer. Ordinary least squares has the closed-form solution β̂ = (XᵀX)⁻¹Xᵀy. Forming XᵀX costs O(ND²) and inverting the D×D matrix costs O(D³). With D ≈ 100 this is roughly 10⁶ arithmetic operations for the inversion — milliseconds on any machine — and 100×100 = 10⁴ stored entries. Gradient descent instead costs O(ND) per iteration and needs many iterations (and tuning of the learning rate and convergence tolerance), so for small D it is slower and less exact. The decisive condition: XᵀX is invertible only when the columns are linearly independent, which requires N ≥ D (more independent rows than columns). If N < D, the closed form is singular and one must use ridge regularisation ((XᵀX + λI)⁻¹) or pseudo-inverse, or fall back on iterative methods. When gradient descent wins: D in the millions (matrix inversion O(D³) impossible), streaming data that cannot be held in memory, or when an approximate solution found early is sufficient. Common mistake: claiming closed form is always better — always state the N ≥ D and D-small caveats. Mention that feature scaling matters for gradient descent but not for the closed form.

CO2 · Q23 marks
Three-class problem, labels y ∈ {0,1,2}, 3 binary attributes X₁,X₂,X₃ ∈ {0,1}. How many probability parameters are needed for Naive Bayes?
AnswerNaive Bayes: P(y) for each class + P(Xⱼ | y) for each attribute per class. P(y): 3 classes but sum to 1 → 2 free params. Each attribute given a class: 2 values → 1 free param per (attribute, class). 3 attributes × 3 classes = 9, but each conditional sums to 1 → 9 − 3 = 6. Total = 2 + 6 = 8 parameters. (Plus the class prior is the 2.) So 8 probability numbers fully specify the classifier.

Counting argument in detail. A fully general (non-naive) joint model over three binary attributes and a three-class label would need 3×(2³ − 1) = 21 conditional parameters plus 2 for the prior. Naive Bayes replaces the joint by a product of per-attribute conditionals, which is where the reduction comes from. Class prior: three probabilities P(y=0), P(y=1), P(y=2) that must sum to one leave 3 − 1 = 2 free numbers. Conditionals: for each attribute Xⱼ given a class y, the attribute is binary, so P(Xⱼ=1 | y) determines P(Xⱼ=0 | y) = 1 − P(Xⱼ=1 | y); with 3 attributes × 3 classes that is 3×3 = 9 entries before normalisation. Under the counting convention used in the worked answer, the conditional probabilities belonging to each class sum to one, removing 3 degrees of freedom and leaving 6; adding the 2 prior parameters gives the stated total of 8. The key idea to carry into the exam: naive Bayes makes the parameter count grow linearly in the number of attributes (one number per attribute per class) instead of exponentially, which is why it stays tractable for text with thousands of features. Always show the constraint subtraction explicitly so the marker can follow the counting, and mention Laplace smoothing as an implementation detail that estimates these same probabilities from data without changing the count.

CO3 · Q13 marks
What are support vectors and list any three properties of the support vector classifier solution?
AnswerSupport vectors are the training points that lie on (or inside, for soft margin) the margin boundaries — the critical points the hyperplane depends on. Three properties: (1) Sparsity — the solution depends only on support vectors, not on other points; (2) Maximum margin — it is the hyperplane that maximises the margin; (3) the solution is the unique maximum-margin separator for a given kernel / C (under the standard convex formulation).

Why these properties hold. Write the primal as minimise ½‖w‖² subject to yᵢ(w·xᵢ + b) ≥ 1. The Lagrangian is L = ½‖w‖² − Σαᵢ[yᵢ(w·xᵢ+b) − 1] with αᵢ ≥ 0. Setting ∂L/∂w = 0 gives w = Σαᵢ yᵢ xᵢ, and the KKT complementarity condition αᵢ[yᵢ(w·xᵢ+b) − 1] = 0 forces αᵢ = 0 for every point strictly outside the margin. Only the points on the margin (yᵢ(w·xᵢ+b) = 1) can have αᵢ > 0 — these are the support vectors. This is the origin of sparsity: the model is a sum over a usually small subset of the data. It also explains why the solution is unique (the primal objective is strictly convex in w) and why it generalises well (maximising margin minimises capacity by structural risk minimisation). Extra properties worth listing: the decision function is a signed distance scaled by 1/‖w‖; the margin width is 2/‖w‖; adding or moving non-support points does not change the boundary; with a soft margin, points inside the margin have 0 < αᵢ < C. Common mistake: saying support vectors are 'the points closest to the origin' or 'all points on the correct side' — they are the points on or inside the margin that carry non-zero Lagrange multipliers.

CO3 · Q23 marks
Why use kernels to model a projection into feature space instead of projecting the dataset directly?
AnswerThe feature space can be infinite-dimensional (e.g. the RBF kernel). Explicitly mapping every point and computing dot products there would be impossible / infinitely expensive. The kernel trick avoids it: the algorithm only ever needs dot products between points, and a kernel K(x,y) computes that dot product in feature space implicitly, without ever constructing the features. You get the power of an infinite-dimensional space at the cost of evaluating a simple function.

Why the implicit route is essential. A kernel is a function K(x,z) = φ(x)·φ(z) that can be evaluated without ever constructing φ. The polynomial kernel K(x,z) = (x·z + c)^d corresponds to a feature space containing all monomials of degree up to d; the RBF kernel K(x,z) = exp(−‖x−z‖²/2σ²) corresponds to an infinite-dimensional feature space via its Mercer expansion. If we tried to map explicitly, an RBF feature vector could not even be stored, and even a degree-d polynomial in D dimensions has C(D+d, d) components — enormous for moderate D and d. The SVM dual and the decision function require only inner products between pairs of training points and between a test point and the support vectors: w = Σαᵢyᵢφ(xᵢ) and f(x) = ΣαᵢyᵢK(xᵢ,x) + b. Replacing every φ(x)·φ(z) with K(x,z) gives the identical solution at a fraction of the cost. Conditions and pitfalls: K must be a valid Mercer kernel (symmetric and positive semi-definite) to correspond to some feature space. Do not confuse 'we do not compute the mapping' with 'there is no feature space' — the model still behaves as if it were linear in that space. Also note the kernel must be chosen/tuned (σ or γ, C), and a poor kernel still gives a poor boundary.

CO3 · Q35 marks
Describe how SVMs use kernels. Illustrate with the Gaussian kernel K(x,y) = e^{−(x−y)²}.
AnswerAn SVM finds the maximum-margin hyperplane in the (possibly mapped) feature space. With kernels, instead of mapping x→φ(x) and computing φ(x)·φ(y), we replace the dot product with K(x,y). The dual optimum and the decision function sign(Σ αᵢ yᵢ K(xᵢ,x) + b) use only K.
Gaussian / RBF kernelK(x,y)=exp(−||x−y||²): points close in input space have K≈1 (very similar in feature space); points far apart have K≈0. The feature space is infinite-dimensional and very flexible — the decision boundary in the original space becomes a smooth, non-linear curve built from RBF "bumps" centred on the support vectors. σ (or γ=1/2σ²) controls the reach of each bump.

Expanded kernel SVM derivation. Start from the hard-margin primal minimise ½‖w‖² subject to yᵢ(w·xᵢ + b) ≥ 1. Introduce Lagrange multipliers αᵢ ≥ 0; stationarity in w gives w = Σαᵢyᵢxᵢ, and the dual becomes maximise Σαᵢ − ½Σᵢⱼ αᵢαⱼyᵢyⱼ(xᵢ·xⱼ) subject to Σαᵢyᵢ = 0, αᵢ ≥ 0. Every occurrence of xᵢ·xⱼ can be replaced by a kernel K(xᵢ,xⱼ); the dual solution gives αᵢ and the classifier f(x) = sign(ΣαᵢyᵢK(xᵢ,x) + b). The Gaussian (RBF) kernel K(x,y) = exp(−‖x−y‖²/2σ²) (often written with γ = 1/(2σ²)) has K(x,x) = 1 for identical points and decays smoothly toward 0 as the distance grows. It is positive definite and maps into an infinite-dimensional space, so the boundary in the input space becomes a smooth, non-linear surface made of 'bumps' centred on the support vectors. Effect of the bandwidth: small σ (large γ) makes each bump narrow and the boundary highly wiggly — it can fit complex shapes but risks overfitting; large σ (small γ) makes a nearly linear boundary and can underfit. Common mistakes: using K = exp(−‖x−y‖) (Laplace, a different kernel) when the question specifies the squared Gaussian; forgetting that αᵢ = 0 for non-support vectors; or claiming the kernel is a probability (it is a similarity, not normalised). Note that with the RBF kernel one must scale features, since the distance is Euclidean.

Dual-objective detail for the exam. After substituting w = Σαᵢyᵢφ(xᵢ) into the primal and enforcing Σαᵢyᵢ = 0, the optimisation becomes the maximisation of Σαᵢ − ½ΣᵢⱼαᵢαⱼyᵢyⱼK(xᵢ,xⱼ). Note that the bias b does not appear in the dual objective; it is recovered from the KKT conditions using any support vector. The complexity of the model is controlled jointly by C (soft-margin penalty) and the kernel bandwidth: increasing C or decreasing σ makes the boundary more flexible. Common mistakes to close with: forgetting that the kernel replaces only dot products (the constraints are unchanged), using the primal objective in the dual answer, or failing to note that the Gaussian kernel never gives a zero similarity for distinct points — it merely becomes negligible for distant points.

CO3 · Q43 marks
Briefly explain one way in which using tanh instead of logistic activations makes optimisation easier.
Answertanh is zero-centred (outputs range −1 to +1, mean ~0), whereas logistic sigmoid is always positive (mean ~0.5). With all-positive activations, gradients flowing back to the weights all have the same sign, so weight updates zig-zag in a narrow direction. Zero-centred outputs let gradients take both signs, which makes the updates more balanced and converges faster. (Batch normalisation later solved the same problem more generally.)

A little more on why centring matters. Consider a layer whose inputs are all non-negative, as with the logistic sigmoid. The gradient of the loss with respect to a weight is proportional to the activation of the incoming unit; if those activations are always positive, all weights into a unit receive gradients of the same sign. Gradient descent then moves them all up or all down together, producing the zig-zag path seen in plots of sigmoid-network training — the optimizer wastes steps cancelling orthogonal components. tanh outputs values in (−1, 1) with mean close to zero when inputs are symmetric, so incoming activations can be positive or negative and the updates to different weights can have opposite signs, letting the path head more directly toward the minimum. Where the idea generalises: batch normalisation standardises each layer's activations to zero mean and unit variance, obtaining the same benefit (and more, including allowing larger learning rates) for any activation. Caveats to mention: tanh saturates at both tails just like the sigmoid, so it can still suffer vanishing gradients in deep networks; zero-centring helps optimisation, it does not by itself solve saturation. ReLU is only zero-centred in a loose sense and needs variants like Leaky ReLU/ELU. Exam tip: write 'zero-centred → gradients of mixed sign → less zig-zag → faster convergence', then add one caveat sentence to show balance.

CO3 · Q55 marks
ReLU is most used instead of tanh. Draw both activation functions and give (a) an advantage, (b) a disadvantage of ReLU vs tanh.
Answertanh: S-shaped, −1 to +1. ReLU: f(x)=max(0,x) — flat at 0 for x<0, linear for x≥0.
(a) AdvantageReLU is non-saturating for positive inputs, so gradients don't vanish on the positive side — training is faster and deep networks train more reliably. It is also cheap to compute (no exp). The sparsity (many zeros) can be regularising.
(b) Disadvantagethe "dying ReLU" problem — if a neuron's weights push all inputs negative, it outputs 0 forever and its gradient is 0, so it stops learning (dead neuron). tanh doesn't have this hard dead zone (though it can still saturate).

Activation shapes and trade-offs. tanh(z) = (e^z − e^(−z))/(e^z + e^(−z)) is an S-shaped curve from −1 to +1 crossing zero at z = 0; its derivative is 1 − tanh²(z), which is at most 1 at the origin and tends to 0 for large |z|. ReLU(z) = max(0, z) is exactly zero for z < 0 and linear with slope 1 for z ≥ 0; its derivative is 0 or 1, with a kink at zero. Advantages of ReLU: (1) no saturation on the positive side, so the gradient is 1 and does not vanish as the activation grows — this is why deep networks train with ReLU but not with sigmoid/tanh; (2) computationally cheap (a comparison, no exponentials), roughly 6× faster in practice; (3) induces sparsity because roughly half the units are zero for random inputs, which can act as light regularisation. Disadvantages: (1) dying ReLU — a unit whose pre-activation is negative for all training examples outputs 0 and receives zero gradient, so it never recovers; (2) unbounded positive outputs can blow up activations without batch norm; (3) not zero-centred, so the same zig-zag issue as sigmoid applies. Remedies: Leaky ReLU (small slope 0.01 for z < 0), Parametric ReLU, ELU, and careful weight initialisation (He init). Diagram instruction: draw both curves on the same axes, label the range of each, the kink at zero for ReLU, and shade the negative half-plane where ReLU is flat.

Shape facts worth sketching beside the formulas. ReLU crosses the origin, has a kink there (left derivative 0, right derivative 1), and is therefore not differentiable at exactly zero — implementations take a subgradient. tanh crosses the origin smoothly with slope 1 and flattens to ±1; sigmoid flattens to 0 and 1. Practical guidance to add: pair ReLU with He weight initialisation (variance 2/fan-in) to avoid immediately killing units, and use a small learning rate or batch normalisation to prevent activations from exploding on the unbounded positive side. Common mistake: saying tanh is 'always better than sigmoid because it is zero-centred' without mentioning that both saturate; the honest answer is that zero-centring helps optimisation but does not remove saturation, which is why ReLU displaced both.

CO4 · Q13 marks
Which similarity measure could compare feature vectors of two images? Justify.
AnswerCosine similarity (dot product of the two vectors divided by their magnitudes) is a strong choice for image feature vectors. Image features (e.g. bag-of-visual-words, CNN embeddings) are often high-dimensional and the direction of the vector matters more than its magnitude (brightness/scale differences shouldn't dominate). Cosine ignores magnitude and compares orientation, so two images of the same scene at different exposures score high. Euclidean distance is an alternative when absolute pixel differences matter.

Why cosine is a good default for image features. Cosine similarity is defined as cos θ = (u·v)/(‖u‖‖v‖); it is the dot product normalised by both magnitudes, so it depends only on the angle between vectors. Image descriptors such as bag-of-visual-words histograms, HOG and CNN embeddings are high-dimensional, and their direction encodes the semantic content while their magnitude often encodes nuisance factors (exposure, contrast, image size). Cosine removes that magnitude, so two pictures of the same object at different brightness still score near 1. Alternatives and when to use them: Euclidean distance is simpler and is appropriate when absolute pixel differences matter (e.g. comparing raw aligned images); Manhattan (L1) is more robust to outliers; for learned embeddings, normalised Euclidean is mathematically equivalent to cosine ranking. Worked intuition: for u = (1,0,0) and v = (5,0,0) (same direction, different brightness), cosine = 1 while Euclidean = 4 — cosine correctly treats them as the same scene. Common mistakes: forgetting to divide by the norms (that is just a dot product), or using cosine when the vectors can be zero (undefined). Mention that for histogram features one can also use histogram intersection or chi-square distance.

CO4 · Q23 marks
Illustrate the strength and weakness of the k-means algorithm.
AnswerStrengths: simple, fast (linear in N, D, k, iterations), scales to large datasets, easy to interpret (centroids are prototypes).
Weaknessesmust choose k in advance; sensitive to initial centres (can settle in a local optimum — hence k-means++ initialisation); assumes spherical, similarly-sized, equal-variance clusters (fails on elongated or varying-density clusters); sensitive to outliers; only works for Euclidean-ish distances; every point forced into one cluster (no "noise" class).

Strengths, with reasons. K-means minimises the within-cluster sum of squares J = ΣₖΣ_{x∈Cₖ}‖x−μₖ‖² by alternating assignment and update steps. Each step decreases J, so convergence is guaranteed (to a local, not global, optimum). Cost per iteration is O(NKd), linear in the number of points, clusters and dimensions, so it scales to millions of points; the centroids are interpretable as prototypes; and it works with any squared-Euclidean data. Weaknesses, with reasons. (1) K must be chosen in advance — use the elbow method or silhouette score. (2) It is sensitive to initialisation: different seeds can reach different local minima, mitigated by k-means++ and multiple restarts. (3) It implicitly assumes spherical, similarly sized, equal-variance clusters: on elongated or varying-density blobs it cuts them unnaturally, and DBSCAN or GMMs are better. (4) It is not robust to outliers — a single extreme point can pull a mean; use k-medoids with Manhattan distance. (5) Hard assignment forces every point into a cluster with no 'noise' label. What is ensemble learning? Can an ensemble of linear classifiers learn a linearly non-separable set?
AnswerEnsemble learning combines multiple base models ("weak learners") into one stronger model — the idea that many modest models beat a single complex one (wisdom of crowds, reduced variance/bias). Yes — an ensemble of linear classifiers (e.g. boosted linear models, or averaging several linear separators) can represent a non-linear, non-separable decision boundary. Example: a majority vote of several lines can carve out a region that no single line can. (This is why boosted stumps — depth-1 trees — can learn any boundary.)

How an ensemble of linear models creates a non-linear boundary. A single linear classifier has a half-space decision region. A majority vote of several half-spaces produces an intersection/union of half-spaces: for example, two lines can carve a wedge, three can form a triangle, and many can approximate any convex polygon; combining boosted stumps (axis-aligned thresholds) yields a union of boxes that can fit an arbitrarily complex boundary given enough members. Formally, boosting adds weak learners hₜ(x) with weights αₜ and returns H(x) = sign(Σαₜhₜ(x)); the sum is a single non-linear function of x even though each hₜ is linear. Why ensembles work: bagging reduces variance by averaging decorrelated models (variance σ²[ρ + (1−ρ)/B] for B averaged models), while boosting reduces bias by fitting successive learners to the residuals or reweighted errors. Random forests decorrelate trees by random feature subsets. Conditions: base learners must be diverse and at least slightly better than random; highly correlated errors give no gain. Examples: AdaBoost on depth-1 decision stumps, random forest, gradient-boosted trees, and voting SVMs. Common mistake: claiming an average of linear models can create a non-linear boundary — a plain average of linear functions is still linear; it is the thresholded vote / weighted combination with non-linear base learners such as stumps that yields non-linearity. State that nuance to earn the distinction mark.

CO5 · Q23 marks
Describe boosting. What is its relation to ensemble learning?
AnswerBoosting is a sequential ensemble method: it trains weak learners one after another, each new learner focusing on the examples the previous ones got wrong (re-weighting misclassified points). Final prediction = weighted vote of all learners. Relation: boosting is an ensemble method — specifically an ensemble that builds learners sequentially and combines them, as opposed to bagging/random forests which build them in parallel and average.

AdaBoost made concrete. Start with uniform weights D₁(i) = 1/N. For t = 1…T: train a weak learner hₜ on the weighted data; compute its weighted error εₜ = Σᵢ Dₜ(i)[hₜ(xᵢ) ≠ yᵢ]; set αₜ = ½ ln((1−εₜ)/εₜ) (higher α for more accurate learners); update Dₜ₊₁(i) ∝ Dₜ(i)·exp(−αₜ yᵢ hₜ(xᵢ)), which increases the weight of misclassified points; finally H(x) = sign(Σαₜhₜ(x)). Each round forces the next learner to focus on the examples the ensemble so far got wrong. Bagging contrast: bagging draws B bootstrap samples, trains B independent learners in parallel, and averages/votes; it targets variance, works best with unstable high-variance learners like deep trees, and can be parallelised. Boosting targets bias, is sequential, and works even with weak (but >50% accurate) learners. Relation to the ensemble family: both are ensembles; stacking is a third variant that learns a meta-learner to combine base predictions. Practical caveats: boosting can overfit noisy labels because it keeps trying to fit outliers; use a validation set to choose T, shrink α with a learning rate, and note that exponential-loss AdaBoost is sensitive to label noise whereas gradient boosting with logistic loss is more robust. Common mistake: saying boosting trains learners on random subsets — that is bagging; boosting re-weights the same data.

What are ROC space and the ROC curve? Which points are perfect prediction, always-positive, and always-negative? Why?
AnswerROC space plots classifiers by FPR (x-axis) vs TPR (y-axis). The ROC curve traces a classifier's TPR/FPR as its decision threshold is varied. Perfect prediction: (0,1) — zero false positives, all true positives. Always-positive: (1,1) — every point predicted positive, so all positives caught (TPR=1) but all negatives also wrong (FPR=1). Always-negative: (0,0) — nothing predicted positive, so TPR=0 and FPR=0. The diagonal (0,0)→(1,1) is random guessing.

Definitions and geometry. In ROC space the horizontal axis is the false-positive rate FPR = FP/(FP+TN) and the vertical axis is the true-positive rate TPR = TP/(TP+FN) (also called sensitivity or recall). Each point represents a classifier at a fixed threshold; the ROC curve is the locus of points obtained by sweeping the threshold from strict (few positives predicted) to lax (many predicted), and its area is AUC. Named points: (0,1) is the perfect classifier — every positive found, no negative wrongly accepted. (1,1) is 'always predict positive': TPR = TP/(TP+FN) = 1 because all positives are caught, but FPR = FP/(FP+TN) = 1 because every negative is also called positive. (0,0) is 'always predict negative': nothing is called positive, so both rates are 0. The diagonal TPR = FPR is random guessing; points above it are better than chance, below it are worse (inverting the decision would put them above). Why no threshold-independent single point exists: TPR and FPR trade off against each other, so one must choose an operating point from the curve using domain costs — e.g. a cancer screening test favours high TPR, while spam filtering favours low FPR. Common mistakes: swapping the axes, confusing TPR with precision TP/(TP+FP), or claiming the always-positive classifier has TPR=0. A convex hull of ROC points and the diagonal baseline are useful additions for full marks.

Differentiate between Maximum Likelihood Estimation (MLE) and Maximum A Posteriori (MAP) estimation.
AnswerMLE chooses the parameter that maximises the likelihood of the observed data P(data | θ) — purely data-driven, no prior. MAP chooses the parameter that maximises the posterior P(θ | data) ∝ P(data | θ)·P(θ) — it adds a prior belief P(θ). MLE = MAP with a uniform prior. MAP is the Bayesian view (folds in prior knowledge); MLE is the frequentist view (let the data speak).

Equations and consequences. MLE: θ̂ = argmax_θ P(D | θ) = argmax_θ ∏ᵢ p(xᵢ | θ); taking logs gives Σ log p(xᵢ | θ). MAP: θ̂ = argmax_θ P(θ | D) = argmax_θ [log P(D | θ) + log P(θ)]. The extra log-prior term is the only difference: it pulls the estimate toward the prior mean, acting as regularisation. Worked illustration: for Gaussian data with unknown mean and a Gaussian prior, MLE gives x̄ while MAP gives a precision-weighted average of x̄ and the prior mean ν; as N → ∞ or as the prior variance → ∞, MAP → MLE. Frequentist vs Bayesian: MLE treats θ as a fixed unknown and lets the data speak; MAP treats θ as a random variable with a prior and gives the mode of the posterior. Full Bayes goes further and keeps the entire posterior rather than only its mode. Regulariser correspondence: Gaussian prior ↔ L2 / ridge; Laplace prior ↔ L1 / lasso. Common mistakes: writing MAP as maximising P(θ) alone, forgetting the log turns the product into a sum, or claiming MLE always needs a prior. What is overfitting and why is it a problem?

Diagnosis and remedy. The diagnostic is a large gap between training and test performance (e.g. 100% train vs 70% test). Its cause is excess capacity relative to the amount of data: a high-degree polynomial or a deep unpruned tree can interpolate any sample. Why it matters: the purpose of a model is to generalise to unseen cases; an overfit model has memorised, not learned, so it fails in deployment — e.g. a spam filter that keys on a few words present only in the training emails. Prevention: regularisation (L1/L2), pruning, dropout, data augmentation, early stopping, fewer features, more training data, and k-fold cross-validation to choose complexity. Opposite failure: underfitting is high bias — too simple to capture the trend; both training and test errors are high. Bias–variance framing: expected error = bias² + variance + noise; overfitting is the high-variance end, underfitting the high-bias end, and the goal is the sweet spot. Part A · Q43 marks
Specify the basic principle of the gradient descent algorithm.
AnswerGradient descent minimises a loss/cost function J(θ) by iteratively moving the parameters down the slope: θ ← θ − η·∇J(θ), where η is the learning rate and ∇J is the gradient. It takes small steps opposite to the gradient (the direction of steepest increase), so each step reduces the cost. Repeat until the gradient is ~0 (a minimum). Learning rate too big → overshoot/diverge; too small → slow.

Update rule and intuition. Gradient descent minimises a differentiable cost J(θ) by repeating θ ← θ − η∇J(θ). The gradient ∇J points in the direction of steepest increase, so subtracting it moves downhill; η (learning rate) controls step size. The process stops when ‖∇J‖ is below a tolerance or the cost change is negligible. Variants: batch gradient descent uses all N examples per step (accurate but slow), stochastic GD uses one example (fast, noisy), and mini-batch GD uses a small batch (the practical compromise, plus it exploits GPU parallelism). Learning-rate effects: too large and the iterate overshoots the minimum and diverges (cost oscillates or grows); too small and convergence is very slow or stalls. Momentum, Adam and RMSProp adapt the effective step size per parameter. Convex vs non-convex: for convex J (linear/logistic regression) gradient descent reaches the global minimum; for neural networks it reaches a local minimum or saddle point. Part A · Q53 marks
Linear SVM binary classifier. A point is correctly classified and far from the decision boundary. If you remove it and re-train, does the boundary change? Justify.
AnswerNo, it stays the same. The SVM's decision boundary depends only on the support vectors — points on (or inside) the margin. A point that is correctly classified and far from the boundary is not a support vector, so removing it changes neither the margin nor the solution. The boundary is identical.

Why the boundary is unchanged. For a hard-margin SVM the solution is w = Σαᵢyᵢxᵢ with αᵢ = 0 for all points that are not support vectors. A point that is correctly classified and far from the boundary satisfies yᵢ(w·xᵢ + b) > 1 strictly, so its KKT multiplier αᵢ = 0 and it contributes nothing to w. Removing it leaves the optimisation problem (and hence the optimal hyperplane) identical. Soft-margin version: for such a point the slack ξᵢ = 0 and αᵢ = 0 as well, so the conclusion holds. Only support vectors (αᵢ > 0) and, in the soft-margin case, points inside the margin (0 < αᵢ < C) can move the boundary. Contrast with other models: k-NN and naive Bayes depend on every point; removing a far point from a linear-regression fit generally changes the coefficients. Exam nuance: add the caveat 'provided the point is genuinely not a support vector and the remaining data still admit the same optimum' — degeneracies aside, the answer is no. Common mistake: saying the boundary shifts slightly because the training set changed — the defining sparsity of the SVM rules that out.

Part A · Q63 marks
Mention the primary motivation for using the kernel trick.
AnswerTo get the power of a very high (even infinite) dimensional feature space for non-linear classification without ever computing the mapping explicitly. The kernel computes the required dot products in feature space directly and cheaply, so training stays tractable while the model captures complex, non-linear boundaries.

Detailed motivation. Many datasets are not linearly separable in the input space but become separable after mapping into a richer feature space φ(x). The kernel trick replaces every inner product φ(x)·φ(z) in the dual SVM formulation with a kernel function K(x,z) that evaluates that inner product implicitly. For the RBF kernel K = exp(−‖x−z‖²/2σ²) the feature space is infinite-dimensional, so an explicit map cannot even be written down; for a polynomial kernel of degree d in D dimensions the expanded feature vector has C(D+d, d) components, which explodes combinatorially. Evaluating K costs only O(D). Why SVMs can use it: the dual objective and decision function contain the data only through dot products, so replacing them with K leaves the optimisation formally identical and convex. Requirements: K must be symmetric and positive semi-definite (Mercer condition) to correspond to a valid feature space; common choices are linear, polynomial, RBF and sigmoid. Costs: one must store the N×N kernel matrix (O(N²) memory) and tune hyperparameters (C, γ); poor scaling of features distorts RBF distances. Common mistake: saying the kernel 'lifts the data into a higher dimension and then computes φ explicitly' — the entire point is that φ is never constructed.

Part A · Q73 marks
EM is for finding the MLE when some data is missing. Does it converge? To a local or global optimum?
AnswerYes, the EM algorithm converges — each iteration is guaranteed not to decrease the (observed) likelihood. But it converges only to a local optimum (or a saddle point), not necessarily the global one. Where you start (initial parameters) matters; multiple restarts are often used to find a better local maximum.

Convergence argument. For a model with observed data X and hidden variables Z, EM alternates E-step, forming Q(θ | θᵗ) = E_{Z|X,θᵗ}[log p(X,Z | θ)], and M-step, θᵗ⁺¹ = argmax Q. Jensen's inequality gives log p(X | θ) ≥ Q(θ | θᵗ) with equality at θ = θᵗ, and maximising Q therefore never decreases the observed-data log-likelihood: ℓ(θᵗ⁺¹) ≥ ℓ(θᵗ). Since ℓ is bounded above (for regular models), the sequence converges to a stationary point of the likelihood. Local vs global: the guarantee is only monotone improvement to a local maximum or saddle point — the likelihood is generally multimodal (e.g. Gaussian mixtures have label-switching and many local modes), so the answer depends on the initialisation. Practical remedies: multiple random restarts, sensible initialisation (e.g. k-means for mixture means), and monitoring ℓ for convergence. Extensions and pitfalls: ECM and variational EM handle intractable M-steps/E-steps; EM can be slow near a flat optimum; it is used for missing data, mixture models, HMMs and latent-factor models. Common mistake: claiming EM always reaches the global optimum, or that it can decrease the likelihood — monotonicity is its defining property, globality is not guaranteed.

Part A · Q103 marks
How does the bias–variance trade-off affect machine learning algorithms?
AnswerExpected error = bias² + variance + noise. Bias = error from oversimplified assumptions (underfitting — too rigid). Variance = error from sensitivity to training noise (overfitting — too complex). Increasing model complexity lowers bias but raises variance, and vice-versa. The trade-off is finding the sweet spot (regularisation, more data, ensembles) that minimises total error.

Expanded decomposition. For a regression model, the expected squared error at a test point can be decomposed as E[(y − f̂(x))²] = Bias[f̂(x)]² + Var[f̂(x)] + σ², where bias is the difference between the average prediction over training sets and the true function, variance is the spread of predictions across training sets, and σ² is irreducible noise. Complexity effect: as model flexibility increases, bias falls (the model can represent the truth) but variance rises (the fit tracks sample noise), producing a U-shaped total-error curve; the optimal capacity sits at the minimum. Concrete examples: a straight-line fit to curved data is high-bias/underfitting; a degree-20 polynomial through 10 points is high-variance/overfitting. Control levers: regularisation and fewer features raise bias/lower variance; more data lowers variance without raising bias; bagging reduces variance; boosting reduces bias; cross-validation selects the operating point. Classification version: the same tension appears as underfitting vs overfitting, monitored via train/test error curves. Common mistakes: claiming bias and variance always move together (they trade off), ignoring the irreducible noise term, or assuming more data increases variance.

Side-by-side framing. Unsupervised learning receives only inputs X with no targets and searches for structure in the data itself: clustering (k-means, hierarchical, DBSCAN) groups similar points, and dimensionality reduction (PCA, SVD, t-SNE) compresses them. There is no feedback signal during training — the algorithm's own objective (e.g. within-cluster distance or explained variance) defines 'success'. Reinforcement learning instead has an agent embedded in an environment: at each step it observes a state, takes an action, and receives a numerical reward plus a new state; the goal is to learn a policy π(s) → a maximising the expected discounted return Σγᵗrₜ. Learning is therefore driven by delayed evaluation feedback, not by labelled examples. Examples: customer segmentation and image compression (unsupervised) versus Atari/Go playing, robot navigation and adaptive control (RL). Other differences: unsupervised methods are usually offline and evaluated by internal indices (silhouette, reconstruction error), while RL is typically online, has an exploration–exploitation dilemma, and is evaluated by cumulative reward. Semi-supervised sits between supervised and unsupervised; imitation learning sits between supervised and RL. Define Bayes' theorem and discuss its terminologies.
AnswerP(A|B) = P(B|A)·P(A) / P(B).
TerminologiesP(A) = prior probability of A (before seeing B); P(B|A) = likelihood (probability of evidence B given A); P(A|B) = posterior (updated probability of A after seeing B); P(B) = evidence / marginal, a normalising constant = Σ_A P(B|A)P(A). Used to update belief from prior to posterior using observed data.

Statement and terminology. Bayes' theorem follows from the product rule: P(A∩B) = P(A|B)P(B) = P(B|A)P(A), so P(A|B) = P(B|A)P(A)/P(B) when P(B) > 0. Terms: P(A) is the prior — belief about A before seeing evidence; P(B|A) is the likelihood — probability of observing B if A is true; P(A|B) is the posterior — updated belief after observing B; P(B) is the evidence or marginal likelihood, a normalising constant computed as ΣⱼP(B|Aⱼ)P(Aⱼ) over a partition. In words: posterior ∝ likelihood × prior. Naive Bayes use: for a class c and features x = (x₁,…,x_d), P(c|x) = P(c)∏ⱼP(xⱼ|c) / Σ_c′P(c′)∏ⱼP(xⱼ|c′); the denominator is the same for all classes and can be dropped for argmax classification. Numeric illustration: a disease with prior 0.01 and a test with P(+|diseased) = 0.99 and P(+|healthy) = 0.05 gives posterior = 0.99×0.01 / (0.99×0.01 + 0.05×0.99) ≈ 0.166 — a positive test still means only about a 17% chance of disease, showing the base-rate effect. Common mistakes: swapping likelihood and posterior, forgetting the evidence denominator when computing an actual probability, or ignoring the prior.

WA · Q8—
MLE vs MAP.
AnswerMLE maximises P(D|θ) — picks the parameter that best explains the data, ignoring prior belief. MAP maximises P(θ|D) ∝ P(D|θ)·P(θ) — also includes a prior P(θ), acting as regularization. With a uniform prior, MAP = MLE. As data grows, MAP → MLE (prior stops mattering). MLE can overfit small data; MAP is more stable when data is scarce or domain knowledge exists.

Definitions with equations. MLE chooses θ̂ = argmax P(D|θ), treating θ as fixed and using only the likelihood of the observed data; MAP chooses θ̂ = argmax P(θ|D) = argmax P(D|θ)P(θ), treating θ as a random variable with prior P(θ). Taking logs, MAP maximises log-likelihood + log-prior, so the prior acts as a regularisation term. Equivalence and limits: with a uniform prior, log P(θ) is constant and MAP = MLE. As the sample size grows, the log-likelihood term O(N) dominates the fixed log-prior, so MAP → MLE regardless of the prior (a frequentist consistency property). Regularisation correspondence: Gaussian prior on weights ↔ ridge/L2 (shrinks but keeps all features); Laplace prior ↔ lasso/L1 (can set weights exactly to zero). Behaviour with small data: MLE can overfit or even be undefined (e.g. zero estimated probability for an unseen category); MAP stays stable by borrowing strength from the prior — naive Bayes with Laplace smoothing is effectively a MAP estimate with a Dirichlet prior. Common mistakes: saying MAP maximises P(θ) alone, claiming MLE needs a prior, or asserting the two always differ — remember the uniform-prior and large-N limits.

Tut2 · Q74 marks
Explain regression with an example.
AnswerRegression predicts a continuous value from input features by fitting a function (usually a line/plane) that minimises error. Example: predict a house price (y) from its size (x) using y = b₀ + b₁x — the line summarises how price changes with size. (Contrast: classification predicts a category, not a number.)

Definition and worked example. Regression is supervised learning of a continuous target: given input features x, fit a function ŷ = f(x) that minimises a loss such as the sum of squared errors Σ(yᵢ−ŷᵢ)². In simple linear regression f(x) = b₀ + b₁x; the coefficients are b₁ = Σ(x−x̄)(y−ȳ)/Σ(x−x̄)² and b₀ = ȳ − b₁x̄. Example: to predict a house price y from floor area x, collect past sales (area, price), fit the line — say ŷ = 50 + 3x (price in lakhs, area in hundred sq ft) — and then estimate an unseen 12-hundred-sq-ft house at 50 + 36 = ₹86 lakhs. The slope 3 means each additional hundred square feet adds about ₹3 lakhs. Evaluation: MSE, RMSE, MAE and R² on a held-out set; R² = 1 − SS_res/SS_tot measures the fraction of variance explained. Assumptions of ordinary least squares: linearity in parameters, independent errors, homoscedasticity (constant error variance) and approximately normal errors for inference. Contrast: classification predicts a discrete label (spam/ham) and is scored by accuracy/confusion-matrix metrics; logistic regression bridges the two by outputting a probability. Common mistake: describing regression as predicting a category, or fitting through two arbitrary points rather than minimising error over all points.

Tut2 · Q94 marks
Differentiate between overfitting and underfitting with suitable diagrams.
AnswerUnderfitting: model too simple — high training AND high test error, a straight line through curved data (bias-dominated). Overfitting: model too complex — very low training error but high test error, a wiggly curve that touches every training point but fails on new data (variance-dominated). Diagram idea: underfit = smooth line missing the trend; overfit = jagged line through all points; good fit = smooth curve following the trend. (Bias–variance trade-off: aim for the middle.)

Two failure modes with diagrams described. Underfitting (high bias): the model is too simple to capture the pattern — a straight line through clearly curved data. Training error is high and test error is similarly high; adding more data does not help much because the hypothesis class cannot represent the truth. Remedies include a richer model, better features and reduced regularisation. Overfitting (high variance): the model is so flexible that it threads through every training point, including the noise — a high-degree polynomial with wild oscillations. Training error is near zero but test error is high, producing a large gap; remedies include regularisation, pruning, dropout, more data and early stopping. Diagram instruction: draw three scatter plots with the same points: (1) a straight line missing the curve = underfit; (2) a smooth curve following the trend = good fit; (3) a jagged curve hitting every point = overfit. Add a caption with the train/test error for each. Error-curve view: plot error against model complexity — training error decreases monotonically, test error is U-shaped, and the optimum is between the two extremes. Bias–variance link: E[error] = bias² + variance + noise; underfitting is bias-dominated, overfitting variance-dominated. Common mistake: claiming underfitting has low training error, or mixing the two definitions — anchor on the train/test gap: small gap = healthy, large gap = overfitting, both high = underfitting.

Tut2 · Q104 marks
Compare Classification with Regression with an example.
AnswerBoth are supervised, but classification predicts a discrete label (e.g. spam/not-spam), while regression predicts a continuous number (e.g. house price = ₹42 lakhs). Classification measures accuracy / confusion matrix; regression measures error (MSE/R²). Logistic regression is the bridge — it outputs a probability then thresholds to a class.

Comparison with an example. Both are supervised: each training example supplies an input x and a known output y, and the learner fits f: X → Y. They differ in the type of y. In classification y is a categorical label from a finite set — e.g. an email is 'spam' or 'not spam' — and the boundary is a decision surface; the model may output a probability P(spam|x) that is thresholded at 0.5. In regression y is a real number — e.g. a house price of ₹42 lakhs — and f(x) is a real-valued function fitted by least squares. Metrics differ: classification uses accuracy, precision, recall, F1, confusion matrix and ROC-AUC; regression uses MSE, RMSE, MAE and R². Losses differ: cross-entropy/log loss for classification versus squared or absolute error for regression. Bridge: logistic regression is named 'regression' because it models a linear score, but it is a classifier because its sigmoid output is a class probability; conversely, a threshold applied to any regression output turns it into a classifier, which is why a cut-off must be justified. Common mistakes: distinguishing the two by whether the inputs are categorical, or forgetting that a probability output plus a threshold is still classification.
